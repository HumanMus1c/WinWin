# 用户空间「数据无法加载」诊断埋点 复盘（2026-10-16）

## 一、现象描述
- 用户反馈「刚刚进入某用户空间出现数据无法加载」（附截图，Agent 未能读取图片内容）。
- 该问题用户**未能再次复现**（2026-10-16 17:18 确认）。

## 二、问题根因（本轮未定位，转为可观测）
- 现状：空间页 `_spaceState` 落 `Error` 时整页走 `_buildError`
  （`lib/pages/member/member_space_page.dart`），文案来自 `MemberHttp.space`
  双通道兜底（APP `/x/v2/space` 4s → Web `/x/web-interface/card` 5s）；任一通道
  失败即 `return Error(...)`。
- 可能根因候选（均**未证实**）：风控 / 隐私 / 封禁码（如 -412 / -352 等）、
  双通道超时、或某 tab 单独失败（「动态加载失败，点击重试」/「加载失败，点击重试」）。
- 因不可复现、且既有原日志无空间页记录，无法从现有一手证据定因 → 依用户偏好
  「先加诊断实机复跑取证」，**先埋点，不猜测修补**。

## 三、修复方法（诊断埋点，不改业务行为）
1. `lib/http/member.dart` `MemberHttp.space()`：APP / Web 两通道均落盘
   `AppLogger.w('MemberHttp.space', ...)`，记录 `mid` / `code` / `message` /
   异常（含 `DioException.type`）。
2. `lib/pages/member/member_space_page.dart`：新增 `_logLoad(scope, msg)`，在各级
   加载失败分支落盘：
   - 整页：`space`；
   - 附带数据：`cardInfo` / `navNum` / `topPhoto`；
   - 分 tab：`videos` / `dynamics` / `fav` / `bangumi` / `liked` / `seasons`。
   均记录 `mid` + 来源 + 错误文案。
- 日志落点：`AppLogger`（运行时 `D:\Documents\logs\runtime.log`，tag =
  `MemberSpace` / `MemberHttp.space`）。

- `AppLogger.w` 为纯写日志，未引入 UI / 行为副作用。

## 六、总结
对不可复现的「空间加载失败」，按「先取证后定因」处理：双通道 + 各 loader 失败
全量落盘，取得 `mid / code / message` 的一手证据；待用户下次触发时回传日志即可
定位。属过渡性可观测改造，**非终态修复**。
