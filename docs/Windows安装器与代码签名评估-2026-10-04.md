# Windows 安装器与代码签名评估

> 日期：2026-10-04 ｜ 关联：`.github/workflows/windows-x64-release.yml`（fastforge + Inno Setup）、`windows/packaging/exe/`
> 结论速览：安装器采用 **Inno Setup 6（经 fastforge）**；**代码签名：本期放弃**（与上游 PiliPlus 实测一致）。

## 1. 安装器方案对比

| 方案 | 实现复杂度 | 签名要求 | 用户体验 | 上游可移植性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **Inno Setup 6（经 fastforge）** | 低 | **无需签名即可分发**（未签名有 SmartScreen 提示） | 现代向导、中文界面、桌面图标/自启/静默安装、卸载器 | **PiliPlus 资产可直接移植**（已落地） | ✅ **一期采用** |
| MSIX（fastforge 亦支持该目标） | 中 | 公开分发需受信任签名（否则需用户信任自签证书） | 干净安装/卸载、App Installer 自动更新、可上架商店（免费重签） | 无现成资产 | 二期（仅当签名与商店诉求成立时） |
| WiX / MSI | 高 | 同上 | 企业向 | 无 | 不采用 |
| Squirrel / Velopack 等更新框架 | 中高 | 视方案 | 自动更新为主 | Flutter 集成成本高（非 .NET 场景） | 暂不采用 |
| 仅便携 zip + winget portable | 极低 | 无 | 免安装 | winget 需另提清单 | 已提供（补充形态） |

**选定**：`fastforge package --platform windows --targets exe`（Inno Setup 6），资产移植自 PiliPlus（`make_config.yaml` / 自定义 `inno_setup.iss` / `ChineseSimplified.isl`），同时保留便携 zip。产物：`WinWin_windows_<ver>_x64_setup.exe` + `WinWin_windows_<ver>_x64_portable.zip` + `checksums.txt`。

设计细节：
- 安装模式 `privileges_required: admin`（per-machine，与上游一致；如需免 UAC 可改 `lowest`）；
- 安装前 `taskkill` 旧进程（防文件占用）；桌面图标（默认勾选）+ 开机自启（默认不勾选，per-machine 安装下写入公共启动项 `{commonstartup}`）；安装后可启动；
- `ArchitecturesAllowed=x64compatible`（原生 x64 与 ARM64 模拟环境均可安装）；
- 已移除 PiliPlus 模板中的 `bilibili://` 协议注册（WinWin 未实现深链，待实现后再补）。

### 升级支持（UsePrevious* 与探测锚点）
- **目录/任务继承（Inno 原生）**：`UsePreviousAppDir` / `UsePreviousTasks` / `UsePreviousLanguage`（默认均 `yes`，模板已显式声明）。安装器启动时按 **AppId** 查找「同一应用」，命中后向导默认目录 = 旧安装目录、默认任务 = 上次勾选。
- **AppId 纪律**：AppId 是升级识别锚点，**跨版本不可变更**；仅在新产品线时才更换。
- **自有探测锚点**：安装时写入 `HKLM\Software\WinWin` → `InstallPath={app}`、`Version=<版本>`（卸载时清除）。`InitializeSetup` 启动期读取并写安装日志（`/LOG` 可见）：`升级探测：检测到已安装的 WinWin <版本> → <路径>（将执行覆盖升级）`；旧目录被手动删除时追加警告；未命中则记录「按全新安装处理」。探测结果存入全局变量，供后续向导页/数据迁移扩展。
- **升级验证方法**：先自定义目录安装一次，再次运行安装器——目录页应默认旧路径、任务沿用、日志出现探测行、卸载项唯一不重复。

## 2. 代码签名评估

### 2.1 上游实测（2026-10-04）
对 PiliPlus 最新版 2.1.5 的官方安装器 `PiliPlus_windows_2.1.5+5410_x64_setup.exe` 进行核验：
- 字节数 33,333,512 与官方一致；SHA-256 `135240b94d93f91b8e22a6d38972e7bb71884c82cc72c9a05c1a9744ff6d25d5` 与发布摘要一致（确认为官方原件）；
- `Get-AuthenticodeSignature` 结果：**`NotSigned`（无数字签名、无签名证书）**；
- 构建侧佐证：`win_x64.yml` 无签名步骤、`inno_setup.iss` 无 `SignTool` 指令；上游仅 Android 配置 keystore 签名，iOS 明确 `--no-codesign`，macOS / Linux 产物亦未签名。

### 2.2 签名选项（背景调研，留档）

| 选项 | 成本 | 中国个人开发者可用性 | SmartScreen 行为 |
| --- | --- | --- | --- |
| 不签名 | 免费 | ✅ | 首次运行强提示（可用「更多信息 → 仍要运行」放行） |
| 自签名 | 免费 | ✅ | 公开分发不可行（仅测试） |
| SignPath Foundation | 免费（开源） | 需申请审核（公开仓库等资格） | OV 级，信誉累积 |
| Azure Artifact Signing | ~$9.99/月 | ❌ 个人仅限美/加 | 信誉累积 |
| OV 证书（含 Certum 开源档 €69） | $150–300/年 | ✅ 全球 | 信誉累积 |
| EV 证书 | $400+/年 | ✅ 全球 | 2024 起无即时豁免，不建议 |
| 上架 Microsoft Store（MSIX） | 免费 | ✅ 全球 | 无警告（微软重签），需上架流程 |

### 2.3 决策：放弃安装器数字签名
- **决策**：本期不引入代码签名（与上游 PiliPlus 现状一致）；构建与发布流程（含 Release 工作流）不含任何签名步骤。
- **理由**：
  1. 上游以相同方式分发（19k star、安装器累计数千次下载），未签名的实际影响仅为首次运行 SmartScreen 提示，不影响安装、功能与分发渠道；发布说明附放行指引即可；
  2. 对中国个人主体的可行签名路径均有明显成本/流程门槛（SignPath 需申请审核、Azure 个人不适用、OV 含年费与硬件介质），与现阶段收益不匹配；
  3. 签名与否不影响安装器技术选型；未来如条件成熟（获 SignPath 资助、上架商店等），可基于 §2.2 调研再评估，届时再补签名流程与文档。
