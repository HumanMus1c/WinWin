# 根页面 Tab 栏背景模糊补齐复盘-2026-10-19

> 主题：除首页外，其它根页面的分类 Tab 栏缺失「类似首页搜索框 + 分类器合并栏」的
> 背景模糊效果，本轮补齐。
> 归属：B7 封板（MD3 库级退役收官）之后的**实机反馈修复**；承接同页上一轮
> `docs/动态页顶栏Tab顺序修复复盘-2026-10-19.md`（Tab 栏顺序修正）。

## 一、现象

用户实机反馈：首页顶部「搜索框 + 分类器合并栏」有**可见**的背景模糊（毛玻璃），
而**除首页外的其它根页面**的 Tab 栏没有同样的模糊效果。诉求：补齐该效果。

**范围核定**：五个根页面（首页 / 动态 / 历史 / 消息 / 我的）中，**仅「动态」页**有
真正意义上的 Tab 栏（全部 / 视频 / 追番 / 专栏，`AppTabView` → `AppTabBar`）；
历史 / 消息 / 我的 页面内均无 Tab 栏（消息页为 4 项入口行、我的页为分区列表），
故无「Tab 栏模糊」可补。本轮交付面 = **动态页分类 Tab 栏**。

## 二、定因（根因链）

1. `AppTabBar` 默认 `blurBackground: true`：内部把标签条底色置透明，并外套共享件
   `MiuixFrostedSurface`（`BackdropFilter(blur 16)` + 半透明底 + 1px 描边 + 圆角 12
   + 下投影）——**材质本身早已具备**。
2. 但 `AppTabView` 原实现是 `Column[AppTabBar, Expanded(AppTabBody)]`：标签栏在内容
   **之上**、占据独立一行，**栏背后没有任何内容**。
3. `BackdropFilter` 只对「其后方**已绘制**的像素」做模糊；栏后是纯色页面底
   （`AppScaffold` 的透明宿主 → Miuix 页底）⇒ 模糊结果 = 纯色 ⇒ **视觉上等同于
   「没有模糊」**（栏仅呈现为一块半透明圆角面板）。
4. 对照首页：`_HomeHeader`（搜索框 + 分类器合并栏）由 `HomePage.build` 放进 `Stack`
   并 `Positioned(top: 0)` **浮在**滚动 feed 之上，feed 内容从栏后穿过 ⇒ 毛玻璃可见。
   两者是同一个「可见性」原理。

**结论**：根因不在材质配置，而在**布局层级**——Tab 栏未与滚动内容发生「层叠」，
毛玻璃采样不到可模糊的内容。

## 三、方案

给 `AppTabView` 增加**浮动态**（`floating: true`）：`Stack[内容(铺满), 标签栏(浮于
顶部)]`，使内容可滚动到栏后 ⇒ 毛玻璃可见；动态页改用该档。要点：

- **复用共享件、不改材质**：`AppTabBar` / `MiuixFrostedSurface` 一行未动
  （P4「每个概念只在一处定义」），仅改宿主布局。
- **外缩对齐首页合并栏**：浮动态标签栏外缩
  `EdgeInsets.symmetric(horizontal: Style.lg, vertical: Style.sm)`（= 首页
  `_HomeHeader` 口径），并加 `RepaintBoundary`（同首页，隔离栏的 hover / 按压重绘）。
- **内容顶部避让落在滚动区内部**：新增
  `AppTabView.floatingTopReserve = Style.sm × 2 + AppTabBar.defaultHeight + Style.sm = 66`，
  施加于 `_DynTabPage` 的 `SliverPadding`（列表态 / 骨架态）与错误态 `Padding`。
  **必须设在滚动区内部**：若设在滚动区**外部**（如给 `AppTabBody` 包 `Padding`），
  内容会被压到栏下方、永远滚不到栏后，毛玻璃又不可见。
- **空态不额外改**：`_buildEmpty` 已有 `SizedBox(height: 120)` > 66，天然避让。
- **栏外缩区域的指针穿透**：`Padding` 非不透明，事件仍可抵达后方内容（与首页一致）。

## 六、遗留与踩坑

1. **范围口径**：用户原话为「除首页外的**其它根页面**（复数）的 Tab 栏」，但五个根
   页面中**仅「动态」有真实 Tab 栏**；历史 / 消息 / 我的 均无 Tab 栏，未做改动。
   若用户所指为「消息页 4 项入口行」「我的页分区标题」等**类 Tab 元素**，需另行确认
   后再补。
2. **`AppTabView` 浮动态 vs 非浮动态**：非浮动态（默认，`Column`）下 `AppTabBar` 的
   毛玻璃**必然不可见**（背后无内容）；凡要求「可见模糊」的根页面 Tab 栏都必须走
   浮动态，且调用方须在**滚动区内**预留 `floatingTopReserve`。该口径已写入组件注释。
3. **`AppScaffold` 顶部安全行收缩联动**：向下滚动时标题安全行收缩至 0，浮动态 Tab 栏
   随之上移到贴顶，内容仍从其后穿过（观感连续）；无需额外处理。
4. **未跑 `flutter test`**：本轮按 `dev-workflow-spec` 的验证目标（`dart analyze` +
   debug / release 双编译）执行；本机 `flutter test` 仍受环境变量缺失影响（沿用既有登记）。
5. **`AppTabView` 既有消费面**：全仓仅动态页一处使用（`lib/pages/dynamics/view.dart`），
   故浮动态改动无其它页面回归风险。

## 七、总结

首页合并栏之所以「看得见模糊」，是因为它用 `Stack` 浮在滚动 feed 之上、内容从栏后
穿过；而动态页 Tab 栏此前用 `Column` 排在内容**之上**、栏后是纯色底，`BackdropFilter`
只能采样到纯色 ⇒ 视觉上等同无模糊。本轮给 `AppTabView` 增加浮动态（`Stack` +
顶部外缩 + 内容滚动区顶部避让 `floatingTopReserve`），动态页改用它，使 Tab 栏毛玻璃
与首页合并栏同观感；共享材质件（`AppTabBar` / `MiuixFrostedSurface`）未改动。
