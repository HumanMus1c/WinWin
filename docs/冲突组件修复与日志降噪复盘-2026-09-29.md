# 冲突组件修复与日志降噪复盘（2026-09-29）

**范围**：程序运行日志审计（runtime.log / trace.log / `.winwin_logs.json` 588 条报告）"第二类：冲突 / 崩溃组件"结论的 A/B/C 三项修复。

## 一、分析根因（证据链）

1. **A — Get.snackbar 与 MaterialApp 架构冲突**：`account_mgr.toast()` 的"请求错误"提示使用 `Get.snackbar`；本应用为纯 `MaterialApp`（非 `GetMaterialApp`），桌面端无 GetX Overlay。崩溃报告实证：9/26–9/27 新增 15 条（`SnackbarController._configureOverlay` Null check ×3 + `_removeEntry` LateInit ×12；代码注释另记历史 28 条）。表现：提示不显示 + 无法捕获的异步异常（外层 try-catch 拦不住）。库内其余 `Get.` 仅 `Get.put`（DI 用途），无此问题。
2. **B — 表情预取 404 上报**：`emote_picker._precacheEmotes()` 调 `precacheImage` 未提供 `onError`，SDK 语义（已核源码）：失败且 onError 为 null 时走 `FlutterError.reportError` → Catcher2 落盘。实测同一失效表情 URL（`i0.hdslb.com/bfs/emote/14b2d6a5….webp@64w_64h_1c`）9/28×5、9/29×1。渲染层 `Image.network` 已有 `errorBuilder` 占位，不受影响。
3. **C — fvp `state not changed!` [E] ×24**（9/24–9/28）：引擎幂等状态通知，集中在播放完成（如 9/28 19:00:22、22:11:41 紧邻 "Playback completed"）与快速开合场景；无任何功能影响（对应时段播放/退出均正常）。

## 二、设计修复计划与实现

- **A**：新增 `lib/core/app_messenger.dart`：`appScaffoldMessengerKey`（挂 `MaterialApp.scaffoldMessengerKey`）+ `showAppSnackBar(message)`（最新优先：`hideCurrentSnackBar` + `showSnackBar`；未挂载时静默）。`main.dart` 挂载；`account_mgr` 改用 `showAppSnackBar('请求错误：$res\n$url')` 并移除 `package:get` 导入。
  关键决策：用"最新优先"而非排队——错误提示应反映最近一次错误，避免陈旧队列在页面切换后闪现。
- **B**：`precacheImage(..., onError: (Object _, StackTrace? _) {})` 接管失败；顺带移除永不触发的 `.catchError`（SDK 文档明确该 Future 不会以错误完成）。
- **C**：`main.dart` mdk 日志映射：`msg.endsWith('state not changed!')` → `AppLogger.d`（debug 可见、release 不落盘）；其余 error 级日志原样保留。
