# 极验弹窗透明化调整复盘（2026-10-02）

**范围**：修复用户实机反馈的两点 —— ①「验证码仍被一个更大的容器控件承载」；②「初始化处于亮色主题再切换为暗色主题」的闪烁。
**方案方向**：按用户要求**容器透明化**（容器不铺底、WebView 页面底透明）。
**调整链**：不透明全屏白页（`e62ce5f`）→ 灰蒙层 + 近全屏内容区（`f2e9ecc`）→ **透明化（本次 `d77c715`）**。

---

## 一、分析根因

### 1.1 现象与根因链

| 现象 | 根因链 |
|---|---|
| 验证码被"更大的容器"承载 | 内容区 `Material` 铺了**不透明白底**（`color: Colors.white`）→ 96%×88% 区域整体是一块可见的白色面板 |
| 初始化亮色 → 切换暗色 | 初始化阶段可见两处白色来源：① 上述**白底容器**（加载态）；② **WebView2 默认页面底为白色**（页面未声明透明底）→ 极验页主题（暗）就绪后整体切换为暗色 |

### 1.2 关键取证（为什么之前"不能"半透明）

| 事实 | 取证 |
|---|---|
| Windows 插件**支持**页面底透明 | `flutter_inappwebview_windows` C++ 侧：`in_app_webview.cpp:276-277` —— `transparentBackground` 为真时 `put_DefaultBackgroundColor({0,255,255,255})`（alpha=0）；运行时更新见 `:3052-3054` |
| 插件**未暴露** `preferredColorScheme` | 平台接口与 Windows 实现均未找到该设置 → WebView2 配色方案不可从 Flutter 侧显式指定（已记录，作为后续可能的增强点） |
| 结论 | 半透明**可以做到**：需要"容器不铺底 + 页面底透明 + HTML 透明底"三者齐备（此前只差这些） |

---

## 二、设计修复计划（关键决策）

| 决策 | 选择 | 说明 |
|---|---|---|
| 容器底色 | `Material(color: Colors.transparent)` | 不铺底；登录页在验证码周围/间隙处透出（压暗 42% 由路由 barrier 提供） |
| WebView 页面底 | `transparentBackground: true`（initialSettings） | WebView2 `DefaultBackgroundColor` alpha=0；同时消除初始化白屏 |
| HTML 底 | `html,body{margin:0;height:100%;background:transparent !important;}` | 覆盖浏览器默认白底 |
| `_ErrorView` 文字 | 恢复主题色（撤销白底专用的 `black87`） | 容器不再假设白底 |
| 契约 | `showDialog` / `await` 返回值 / Esc layer1 / `barrierDismissible:false` **不变** | 调用点与诊断按钮零改动 |
