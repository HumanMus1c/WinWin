# 番剧片尾跳过「吞掉片尾后内容」复盘（2026-09-26）

> 触发场景：《凡人修仙传》第 193 集（正片）自动跳过片尾时，**片尾之后的整段内容被一并跳过**。
> 修复文件：`lib/pages/bangumi/bangumi_player_page.dart`

---

## 1. 分析根因

### 1.1 现象描述

播放《凡人修仙传》第 193 集正片，进度到达片尾区间起点（1084s）时，页面不是「跳过片尾继续播后面的内容」，而是**直接切到下一集条目**，导致片尾本身及其后 539s（≈9 分钟）内容全部被跳过。

### 1.2 取证证据

**（1）实机日志** `D:\Documents\logs\trace.log`（2026-09-26 会话，pid 1276 / 33204）

| 时间 | 证据行 | 含义 |
|---|---|---|
| 14:59:22 | `MANIFEST ... vDur=1711s` + `DUAL-PLAYER ... 42162064891` | 开始播放 cid=42162064891（=ep 3854817，193 正片），媒体时长 1711s |
| 15:16:38 | `BEAT #217 ... uiPos=1083200 uiDur=1710120` | 播放到 **1083.2s**（≈18:03） |
| 15:16:39 | `PlayerCtrl: setMedia video: ... 42203087474 ...` | **整集被切走**，切到 cid=42203087474 |
| 16:16:56 | `ENDED source=statePaused pos=42880 dur=42920` 之后无任何换集动作，16:17:08 直接 dispose | 43s 条目**自然播完不会自动下一集** |

**（2）官方剧集数据** `pgc/view/web/season?season_id=28747`（凡人修仙传，303 条目）

| ep_id | 标题 | duration | skip.op | skip.ed | 列表位置 |

> 193 集：片尾区间 1084–1172s（88s），**1172–1711s 仍有 539s 内容**；192 集片尾后只剩 12s，所以此前一直没暴露。
> 该 cid 弹幕在 20–28 分钟仍有分布（52/15/19/10/15/13/17/9/12，共 162 条），佐证片尾后确有内容。

**（3）对照实现** BiliPai `feature/bangumi/policy/BangumiEpisodeSkipPolicy.kt`（本项目该逻辑的移植来源）

```kotlin
resolveBangumiSkipRange(skip?.ed, durationMs)?.let { range ->
    if (!endingAlreadySkipped && safePositionMs >= range.first && safePositionMs < range.last) {
        return BangumiEpisodeSkipAction(kind = ENDING, seekToMs = range.endInclusive)
    }
}
```
- ENDING 动作 = **seek 到区间结束点**，**不切集**；`end` 先 `coerceAtMost(durationMs)`；命中条件带 `pos < end` 上界。
- 其单测 `ending range clamps seek to player duration` 明确断言 `seekToMs == min(ed.end, duration)`。

### 1.3 根因链

1. **片尾分支丢失 `ed.end`**：`_checkOpEdSkip()` 写成 `posMs >= ed.start*1000 → _playNextEpisode()`，只按下界判定、动作是换集。于是「进片尾」= 「整集结束」，片尾（88s）及其后的 539s 全部被吞。
   - 同时缺少 BiliPai 的 `pos < end` 上界与 `end = min(end, duration)` 收敛。
2. **「自然播完 → 下一集」链路实际失效**（使换集成了唯一通路，也解释了当初的写法）：`ctrl.duration.addListener(_checkEpisodeEnd)` 中判断 `pos >= dur - 800`，但 `duration` 只在媒体 `buffered` 状态赋值一次（`player_controller.dart:751`），`ValueNotifier` 同值不再通知 ⇒ 回调仅在加载时执行一次，播完永不触发。实证即 1.2(1) 的 16:16:56 会话。

## 2. 设计修复计划

### 2.1 方案（最小改动，对齐 BiliPai）

1. **片尾改 seek 到片尾结束点**：
   `edEndMs = durationMs > 0 ? min(ed.end*1000, durationMs) : ed.end*1000`；命中条件 `edEndMs > ed.start*1000 && posMs >= ed.start*1000 && posMs < edEndMs`；动作改为 `ctrl.resumeTo(edEndMs)` + 「已跳过片尾」提示；保留 `_lastEdSkippedEpId` 防重。
2. **片头同步收敛**：`opEndMs = min(op.end*1000, durationMs)`，命中条件与片尾一致（原有 `< op.end*1000` 上界保留）。
3. **补回自然播完换集**：`_initPlayerForEpisode` 中把监听从 `ctrl.duration` 换成 `ctrl.completed`（`ValueNotifier<bool>`），`_checkEpisodeCompleted()` 在 `completed == true` 时调用 `_playNextEpisode()`；删除失效的 `_checkEpisodeEnd()`。
4. 新增私有静态工具 `_clampSkipEndMs(endMs, durationMs)`。

### 2.2 关键决策与取舍

| 决策 | 理由 / 取舍 |
|---|---|
| 片尾只 seek 不换集 | 与 BiliPai 语义一致：`ed.end` 之后的内容属于本集，跳过范围应严格等于数据给出的区间；是否进下一集交由「自然播完」决定 |
| 换集改挂 `completed` | 对标 BiliPai `playbackEndListener`；`completed` 由控制器在「位置已在片尾 1500ms 内 + 非 seek 冻结」时置位，信号本身已带误判门控 |
| `end` 按 duration 收敛 | BiliPai 明确要求（`coerceAtMost`）；避免数据越界导致 seek 超出媒体长度（本次193集 ed.end=1172s 未越界，但属于必要防御） |
| 不加 OP/ED 跳过设置项 | 保持最小改动，不以「顺手加需求」扩大改动面（BiliPai/PiliPlus 的 SkipType 开关属于独立特性，未在本轮范围内） |
| 不加 seek 埋点 | 成本低但非必需；验证走 trace.log 现有 SEEK/RAW 行即可判断是否落点为 1172s |

## 4. 本轮修复总结

**改动面**：`lib/pages/bangumi/bangumi_player_page.dart` 单文件 3 处——`_checkOpEdSkip()`（片头/片尾命中条件与跳跃目标 + 片尾不再换集）、`_initPlayerForEpisode()`（监听从 `duration` 换为 `completed`）、`_checkEpisodeEnd()` → `_checkEpisodeCompleted()`；另加 `_clampSkipEndMs()` 工具函数。

**行为预期**：
1. 片尾跳过 = 只跳过片尾区间，片尾之后的彩蛋/预告等内容继续播放（修复 193 集吞掉 539s 的问题）；
2. 下一集由自然播完驱动，恢复「播完自动连播」；
3. 片头跳过语义不变，仅补齐 end 收敛与上界判定。

**遗留项（本轮未做，供后续决策）**：
- 剧集列表顺序里「194」是 43s 先行条目（API 顺序即如此），自然播完会进入该条目而非 194 正片——属于数据源顺序问题，非本 bug；
- 无 OP/ED 自动跳过的用户开关（BiliPai/PiliPlus 有 `SkipType`：禁用/总是跳过/仅一次/手动），如需可另开一轮；
- 片尾跳过走 `resumeTo()`（与片头一致，直接 `player.seek`），未走控制器的 seek 冻结/音画对齐流程；如后续观察到跳片尾后的音画漂移，可考虑改走 `ctrl.seek()`。
