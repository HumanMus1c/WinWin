# 搜索态扩充动效与合并栏阴影复盘（2026-10-21）

> 承接《搜索页顶栏就地扩充复盘-2026-10-19》与《搜索页顶栏就地扩充-设计文档-2026-10-19》。
> 本轮是 CVO 对「顶栏就地扩充」观感的**两处定向修正**，不改数据口径与交互出口。

## 一、现象描述

CVO 反馈（2026-10-21 14:25）两点：

1. **将搜索态的扩充过渡动画改为 Miuix 的非线性动画** —— 当前扩充（顶栏就地长高 +
   分类标签收起）呈「多项式缓动」手感，不是 Miuix/HyperOS 的弹簧物理动效。
2. **将背景压暗改为「搜索 TAB 合并栏」的整体悬浮四向辐射阴影** —— 搜索态原先把
   整页（含顶部「首页」安全行）压成半透明暗色，观感重；改为让**合并栏本身**浮起来，
   沿栏体轮廓向四向辐射阴影来建立层级。

## 二、问题定因

### 2.1 动效：用的是多项式缓动，不是 Miuix 弹簧

原实现三处动画：

- `AnimatedPositioned`（顶栏随安全行上移）`curve: MiuixMotion.standardDecelerate`；
- `AnimatedSize`（Row2 在「32 高分类标签」↔「扩充面板」间切换）`curve: MiuixMotion.standardDecelerate`；
- 遮罩 `AnimatedOpacity`：**未指定 curve ⇒ 线性**。

`MiuixMotion.standardDecelerate` = `DecelerateEasing(1.0)` = `1-(1-x)²`，是**多项式缓出**。
Miuix/HyperOS 语境下的「非线性动画」本体是 **弹簧物理动效**（`folmeSpring`：临界阻尼 ×
自然周期，见 `MiuixSpringDefaults`），由 `MiuixSpringEngine` 逐帧解算，起手更快、长尾收敛，
观感与多项式缓动明显不同。⇒ 定位为「动效曲线用错体系」，根因不是时长。

### 2.2 压暗：整页遮罩与「悬浮合并栏」设计语言相冲

原搜索态用 `Positioned.fill` 的 `ColoredBox(scrim α0.38)` 压暗整页（连带骨架安全行），
这是「模态遮罩」语义；而合并栏（`AppTopBarSurface`）本身是**浮于内容之上的毛玻璃悬浮栏**。
CVO 要求改为**合并栏自身的四向辐射阴影**：用阴影在栏体四周造出深度，既保住悬浮层级，
又不牺牲背景可读性。

## 三、修复方案

### 3.1 新增 Miuix 弹簧非线性曲线（唯一实现，P4）

新增 `lib/theme/app_motion.dart` 的 `MiuixSpringCurve`：

- 用 **Miuix 自带的 `MiuixSpringEngine`**（临界阻尼 × `standardSpringPeriod`）离屏跑一遍
  0→1 的落定过程并采样成归一化曲线；
- Flutter 隐式动画（`AnimatedSize` / `AnimatedPositioned` / `TweenAnimationBuilder`）只接受
  `Curve`，不接受 `SpringDescription`，故需此薄适配层——**物理仍是 Miuix 的**，未自造公式；
- 采样量程取 1000（像素级）而非 1：引擎落定判据是「距目标 < 1」，量程为 1 时首帧即误判落定；
- `transformInternal` 对采样表做线性插值，`t==1` 精确返回 1（隐式动画须拿到终值）。

`home_page.dart` 三处动画统一改用 `MiuixSpringCurve.standard`：`AnimatedPositioned`、
`AnimatedSize`、以及新增的合并栏阴影淡入淡出。

### 3.2 压暗 → 合并栏四向辐射阴影

- `AppTopBarSurface` 新增**可选** `shadow`（默认空列表 = 原行为，**消息中心零影响**）；
  阴影画在 `ClipRRect` 之外、沿可见栏体外轮廓辐射；
- `_HomeHeader` 用 `TweenAnimationBuilder<List<BoxShadow>>` 对阴影做隐式插值
  （`BoxShadow.lerpList` 对**长度不等**的两个列表不做插值 ⇒ 起点用同长度的**透明配对阴影**，
  否则会硬切）；
- 阴影值：`offset: Offset.zero`（四向等量辐射）+ `blurRadius 22` + `spreadRadius 1`，
  色 `Color(0x3D000000)`；搜索态淡入、常态淡出；
- **保留一层透明命中层**（`GestureDetector(behavior: opaque)`）承接「点空白处收起搜索态」，
  语义与旧遮罩一致（feed 在搜索态仍不可交互，符合《…复盘-2026-10-19》已接受的副作用）。

## 五、遗留与踩坑

1. **沙箱缺 `ProgramFiles(x86)` 导致 `flutter build windows` 失败**：本轮 `flutter build windows
   --debug` 首次直接报 `%PROGRAMFILES(X86)% environment variable not found.` 即止；补齐
   `ProgramFiles(x86)`/`LOCALAPPDATA`/`APPDATA`/`USERPROFILE`/`HOME` 后两次构建均正常。
   —— 与《…开发流程规范》记录的「`flutter test` 需补齐环境变量」同源，**构建同样需要**，
   本篇补正该结论（旧记录称 build 不受影响，实测有误，原位指正）。
2. **阴影顶部被裁**：合并栏距浮层顶仅 `Style.sm`(8px)，`Stack` 默认 `clipBehavior:
   hardEdge` ⇒ 向上辐射的阴影在窗口最顶被裁去约十余像素。因该处已是窗口顶缘（且顶部
   被标题栏占用），观感可接受；如需完整四周辐射，可给浮层 `Stack` 设 `clipBehavior: none`
   （另需评估其它页零回归）。
3. **未做弹簧的「打断续接」**：`Curve` 是无状态纯函数，无法像真弹簧那样在动画中途反向时
   保留速度连续性。本轮以曲线拟合弹簧形状，满足观感要求；若后续需要「中途打断顺滑续接」，
   需改用显式 `AnimationController.animateWith(SpringSimulation(...))` 并重写高度测量。

## 六、总结

这两处都不是「修 bug」，而是把搜索态的**动效体系**与**层级语言**拨回 Miuix 轨道：
扩充动效从「多项式缓动 → 弹簧物理动效」（新增 `MiuixSpringCurve` 作为设计语言令牌，
用 Miuix 自己的引擎采样，不改调用点结构），层级表达从「整页压暗 → 合并栏四向辐射阴影」
（`AppTopBarSurface` 增可选 `shadow`，默认零影响）。数据口径、交互出口（Esc / 点空白 /
提交）**一字未动**，`dart analyze` 0/0、Debug/Release 双 √。

## 七、第二轮追加：展开动画"顿挫"修复（2026-10-21）

### 7.1 现象

CVO 追加反馈：展开动画途中，**经过渲染「大家都在搜」板块时会顿挫一下**，导致整体展开过渡不流畅。

### 7.2 定因（源码链路，非推测）

1. 展开 = `AnimatedSize`（Row2 高 32 ↔ 面板高）驱动；
2. 面板 `initState` 发起异步 `_loadTrending()`，加载中只渲染很矮的加载态（原为 spinner），数据回来后才换成约 300px 高的热搜网格；
3. **核心**：Flutter `RenderAnimatedSize._layoutStable()`
   （`D:\flutter\packages\flutter\lib\src\rendering\animated_size.dart:283-294`）——
   **动画运行中只要子尺寸变化**，就 `_sizeTween.begin = size; _sizeTween.end = child.size;
   _restartAnimation()`，而 `_restartAnimation()` = `_controller.forward(from: 0.0)`
   ⇒ **尺寸动画从 0 重跑**。这就是那一下"顿挫/重来"。
4. 为什么**固定**砸在「大家都在搜」处：面板里**唯一异步**且会大幅改高度的就是热搜块（历史词 / 用户胶囊都是同步的），而它从"很矮的加载态"跳到"约 300px 的网格"，且热搜接口常 100–300ms 返回，正好落进 220ms 的动画窗口。
5. `SearchHttp.searchTrending` 原本**无缓存**，面板每次进入都重建重取 ⇒ 稳定复现。
6. 次要放大：数据到达那一帧里**首次构建 20 个热搜格 + 工具提示 + 图片解码**，与"重跑帧"叠加。

> 说明：这跟本轮换的弹簧曲线无关——旧曲线同样是 `forward(from:0)` 重跑，只是起手更慢把顿挫藏得深些。

### 7.3 方案（A+B+D 一体；C 被结构性覆盖）

- **A｜等高骨架**：`hot_keyword.dart` 抽出单元格几何**唯一口径**（`cellPadding` /
  `cellLineHeight`）+ 新增 `HotKeywordSkeleton`（与网格**同几何**：同列 / 行间距、同留白、
  同名称行高；行数取真实条数、未知时按接口上限 20）。热搜加载态由「spinner」改为
  「标题行 + 骨架」，使**加载态与已加载态逐像素等高** ⇒ 子尺寸不再跳变 ⇒ 不触发重跑。
- **B｜缓存 + 预取**：新增 `search_trending_cache.dart`（TTL 5 分钟、并发请求去重、
  `invalidate()`）；`HomePage.initState` **首帧静默预取**；面板命中缓存则直接就绪，从源头
  减少竞态。
- **D｜动画期不挂重内容**：`_HomeHeader` 改 `StatefulWidget`，用 `AnimatedSize.onEnd`
  （+ 一个与动画同时长的兜底 `Timer`，防"高度恰好没变而不触发"）置 `_settled`，
  仅在 `_settled == true`（`contentReady`）后才把骨架换成热搜网格——高度不变、无跳变，
  且重布局 / 解码被挪出动画帧。
- **为何不再叠 C（显式控制器 + 锁定目标高度）**：C 的目标（动画与内容高度解耦）已被 A+D
  **结构性达成**——面板内唯一异步高度源就是热搜块，等高后动画目标自始至终稳定。再叠一层
  显式控制器属冗余且会与 A/D 打架（P4「概念只在一处定义」），故本轮不引入。

### 7.4 验证

- `dart analyze`：No issues found（0/0）
- `flutter build windows --debug`：√ 42.1s ｜ `--release`：√ 74.8s
- 实机：首页点搜索框 → 展开过程中「大家都在搜」处**不再顿挫**，整体连续顺滑；展开落定后
  骨架瞬时变真身（等高，无二次生长）；「刷新」仍强制重拉。
- 提交：`7cc6c2d`（[fix](home)：修复搜索态展开动画"顿挫"，按全局开发规定补记）；回滚：`git reset --hard 77463bd`。

### 7.5 遗留

- 骨架**行数**依赖真实条数（未知时按上限 20）；若接口返回条数波动很大，落定后的换真身
  可能出现一次**小幅**高度校正（已不在动画窗口内，非顿挫）。已知可接受。
- C（显式控制器解耦）留作后备：**若日后出现"热搜以外"的动态高度源**，再上该方案。

## 八、第三轮追加：残余"顿挫"取证与修复（2026-10-21）

### 8.1 现象（§七 之后仍存在）

CVO 复测：**仍有顿挫**——"最后两行上方顿一下，才会完全展开"，并给出两个猜测：①
「大家都在搜」行数判断错误；②每次展开都要重新计算展开高度。

### 8.2 取证（最小复现测试，非推理）

新增 `test/pages/search_trending_height_test.dart`，在相同宽度下量出骨架与真实网格的高度：

| 条数 | 骨架 | 网格 | 差 |
|---|---|---|---|
| 20 | 313.0 | 315.0 | **2.0** |
| 16 | 249.4 | 251.0 | **1.6** |
| 10 | 154.0 | 155.0 | **1.0** |

差 / 行数 = **0.2px / 行**恒定 ⇒ 每格高度不同。

### 8.3 根因

**文本行盒有整像素取整**：`TextStyle(fontSize: 14, height: 1.2)` 名义行高
`14×1.2 = 16.8`，但 Flutter 文本排版把它取整到 **17.0**。而我在 §七 的骨架里写的是
`SkeletonLine(height: 16.8)`（`Container` 精确高度、不经文本排版）——于是**每格比真身矮
0.2px**，10 行累计 **2px**。

展开动画跑完（`AnimatedSize.onEnd`）那一刻换成真身，子高度 +2px ⇒
`RenderAnimatedSize._layoutStable` 判定子尺寸变化 ⇒ `_restartAnimation()` ⇒
`controller.forward(from: 0)`。注意它是**从当前尺寸**（不是从 32）再 ease 一遍 220ms ⇒
表现就是 CVO 说的"最后那一下顿一下、再缓一次才到底"。**这正是 CVO 猜测的"每次展开都要重新
计算展开高度"**（`AnimatedSize` 每帧重量测 + 尺寸一变就重跑），而行数判断/手写常量对不准是它的
触发源。

### 8.4 修复

1. **`HotKeywordGrid` 增 `placeholder` 模式**（`hot_keyword.dart`）：占位格走**同一套布局**
   ——同 `Wrap`、同 `cellPadding`、名称用**同 `TextStyle` 的透明 `Text` 撑行盒**，其上覆盖
   `SkeletonBox`。行盒既由真实 `Text` 产生，就天然含字体 / DPR / textScaler / **整像素取整**，
   与真身**逐像素一致**。删掉手写常量 `cellLineHeight`（对不准）。
2. **`HotKeywordSkeleton` 改为"网格占位模式"**（单一布局来源，P4）。
3. **面板加固**（`search_content_panel.dart`）：
   - 骨架行数**首次取值即锁定**（`_skeletonPin`）——动画途中数据到达也不改行数；
   - 标题行两态**同构**（同 `onRefresh`，去掉「刷新」按钮出现 / 消失带来的高度微变）；
   - `_loadTrending` 命中缓存时**首帧直接落字段**（`_built` 标志区分），避免
     `setState` during build。

### 8.5 验证

- **最小复现测试转为断言**：`skeleton==grid` —— 315/315、251/251、155/155 **全部通过**。
- `dart analyze`：No issues found（0/0）
- `flutter build windows --debug`：√ 27.3s ｜ `--release`：√ 65.0s
- 实机：点搜索框 → 展开至**完全展开全程连续顺滑**，末段**不再有二次缓动 / 顿挫**；
  骨架换真身无高度变化。
- 提交：`7cc6c2d`（§七）＋ `0d64314`（本轮，按全局开发规定补记）；回滚：`git reset --hard ee738f7`。

### 8.6 遗留

- §七 的 A/B/D 仍有效（消除了"加载态→内容态"的大跳变）；本轮补上其**触发源**（骨架线高
  与文本行盒的 0.2px/行差）。两轮合起来才彻底：**大跳变**（§七）＋**微跳变**（本轮）。
- 教训：**凡"自绘占位要与文本逐像素等高"，一律复用真实文本布局，不要手写字号×行高常量**
  ——文本行盒有整像素取整。
