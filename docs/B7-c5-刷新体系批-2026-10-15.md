# B7-c5 刷新体系批 复盘：下拉刷新面零 material_ui 自绘（用户选定「零视觉变更」）— 2026-10-15

> 触发：B7 剩余批次 **b7-c5 = 刷新体系批** —— 把「下拉刷新」这一整面从 `material_ui`
> 退役，同时**观感与手感零变更**。
> 前置：**b7-c4 Tab 体系批 反馈轮 5**（`91cbe5e`，回填 `4995753`）已推送；闸门 **65**。

## 1. 现象描述

1. **刷新面仍强依赖 material_ui**：`common/widgets/refresh_indicator.dart` 的
   `AppRefreshIndicator` 只是 material `RefreshIndicator` 的薄封装
   （透传 `displacement * 0.8`、`strokeWidth: 2.2`、`edgeOffset`，并以
   `show RefreshCallback, RefreshIndicator` 从 `package:material_ui/material_ui.dart` 取符号）。
2. **16 处**页面直接用**裸** material `RefreshIndicator`（`fav` / `follow` / `history` /
   `hot` / `rcmd` / `member_relation` / `search_panel` / `toview` / `like_detail` /
   `msg_feed` / `sys_msg` / `session_list` / `ui/profile`），参数面为 material 默认或
   显式 `color: biliPink` / `displacement: 12 + edgeOffset: 120`。
3. **8 处**已用 `AppRefreshIndicator`（仅传 `onRefresh` + `child`，依赖默认值）。
4. **2 处**已被用户验收为 `AppMiuixRefresh`（`pages/video/detail_page.dart` 评论区、
   `pages/whisper/view.dart` 会话列表）。
5. 目标：上述 ① ② 的全部 material `RefreshIndicator` 依赖清零，且**视觉/手感 1:1**。

## 2. 根因

1. **直接原因**：刷新指示器是 material `RefreshIndicator` 的完整状态机 + 绘制
   （拖动 arc / 箭头 / 吸附 / 不定态旋转 / 圆底阴影 / 反弹收起），项目此前以"薄封装 +
   裸用"方式直接复用，故该面无法在不换实现的前提下脱库。
2. **方向约束（决定性）**：可选替代并非只有一条路 —— 但
   - flutter_miuix 的 `MiuixPullToRefresh`（下推灰环 + 状态文案）已在
     **2026-10-03 被用户实机复测明确否掉**（"原已有的下拉视觉更好"，
     见 `docs/flutter_miuix修复轮2-刷新视觉回退与字重滑块复盘-2026-10-03.md`，回退提交
     `e84a157`），**不可作为全站替代**；
   - 若"全站统一到 Miuix 下推式"，会把已被否掉的视觉强推给其余 16+8 个页面。
   ⇒ 本批向用户提出三档方案，用户选定 **A：零视觉变更**（保留观感；2 处已验收的
   `AppMiuixRefresh` 不动；其余 material 紧凑环改为**自绘**、观感 1:1）。

## 3. 修复方案

### 3.1 核心：自绘零-material 紧凑指示环（硬约束下的自研，已注释说明理由）

`lib/common/widgets/refresh_indicator.dart` 整体重写（−75 / +600 行量级）：

| 部件 | 说明 |
|---|---|
| `AppRefreshIndicator`（StatefulWidget） | 移植上游 material `RefreshIndicator` **状态机**：`drag → armed → snap → refresh → done / canceled`；`_positionController` 驱动 `_kDragSizeFactorLimitTween`（0→1.5）/ `_threeQuarterTween`（0→0.75）；`_scaleController` 驱动 `_oneToZeroTween`；`_shouldStart` 仅认 `depth == 0` 的**用户拖拽**（`ScrollStartNotification.dragDetails != null`）；`_checkDragOffset` 用 `viewportDimension × 0.25` 作分母、越阈后 `arms`；`show({atTop})` 保留 |
| 视觉常数 | `_kDragContainerExtentPercentage=0.25`、`_kDragSizeFactorLimit=1.5`、吸附 `150ms`、收起 `200ms`、不定态周期 `1333×2222ms`、圆底 `41`、外边距 `4`、内边距 `12` |
| `_AppRefreshRing`（自绘环） | 移植上游 `RefreshProgressIndicator`：`_strokeHeadTween` / `_strokeTailTween`（`Interval` + `SawTooth(pathCount)`）/ `_offsetTween` / `_rotationTween` / `_convertTween`（`Interval(0.1,0.33)`）/ `_additionalRotationTween`（`TweenSequence` −0.1→−0.2→1.35）；拖动进度经 `_convertTween` 映回不定态时间轴；`arrowheadScale = Interval(0.1,0.33).transform(value)` |
| `_AppRefreshRingPainter` | 移植上游 painter：`arcStart = -π/2 + tail·3/2π + rotation·2π + offset·π/2`、`arcSweep = max(head·3/2π − tail·3/2π, .001)`、`strokeCap = StrokeCap.square`、`strokeAlign = 0`（中心，即 `Offset.zero & size`）、箭头三角由 `arcEnd` 单位向量推出；**无轨道弧**（上游 `trackColor` 为 null） |
| 圆底容器 | `SizedBox.square(41) → PhysicalModel(circle, surface, elevation: 2) → Padding(12) → Opacity → Transform.rotate → CustomPaint`（上游用 `Material(type: circle, elevation: 2)`；此处以 `PhysicalModel` 复刻阴影机制，见 §5 残差 1） |
| 颜色解析 | 前景 `widget.color ?? MiuixTheme.maybeOf(context)?.colors.primary ?? 0xFFFA7298`（= biliPink，与 Miuix 语义 `primary` 同值）；圆底 `MiuixTheme.maybeOf(context)?.colors.surface ?? 白色`；拖动期前景按 `ColorTween(alpha 0→原值) + CurveTween(Interval(0, 1/1.5))` 淡入 |
| `temperature`（兼容面） | 新声明本地 `typedef RefreshCallback = Future<void> Function()`（与上游同签名），替代 material 导入 |
| `AppMiuixRefresh` | **不动**（2 处已验收站点保持） |

**API 面**：新增 `color` / `strokeWidth` 两个显式参数；`displacement` 语义从
「×0.8 后传给上游」改为**直接逻辑位移**（默认 32，即原 `40 × 0.8` 的等效值），
`edgeOffset` 沿用。

## 5. 遗留与踩坑

- **踩坑 1（重要，易静默出错）**：`material_ui` 长期充当这些文件的**框架符号源**
  —— `package:flutter_miuix/miuix.dart` 多以 `show` 白名单只导出 Miuix 组件，故
  `State` / `StatefulWidget` / `ScrollController` 等其实是从 `material_ui`
  （其 `export 'package:flutter/widgets.dart'`）来的。**摘除 import 必须同时补
  `package:flutter/widgets.dart`**，否则会出现 700+ 条 `undefined_identifier` /
  `override_on_non_overriding_member` 雪崩（本批首次尝试即复现 742 条）。该补法在
  b7-c1 已有先例（50 → `flutter/widgets`）。**且**：`flutter_miuix` 亦导出 Flutter
  Material 的同名符号，故**不能只靠 analyze 判定**——必须先用符号白/黑名单扫描，
  否则 `Scaffold` / `AlertDialog` 会"静默降级"为 Flutter 原生 Material 控件（观感变化）。
- **残差 1（亚感知级）**：上游圆底用 `Material(type: circle, color: surface, elevation: 2)`
  —— Material 的 elevation 会叠加 surfaceTint 并自绘阴影；本实现用
  `PhysicalModel(..., elevation: 2)` 复刻阴影形状与半径，但**不含** surfaceTint 那一层
  极轻的染色。已按"阴影机制一致"取近似。
- **残差 2（参数口径变更，已等价化）**：旧 `AppRefreshIndicator` 内部 `displacement × 0.8`；
  新版改为**直接逻辑位移**。所有调用点已按等效值固化，故**渲染位移零变化**；但今后新增
  站点须按"直接值"书写（默认 32）。
- **残差 3**：`RefreshCallback` 由本文件本地 `typedef` 承接（同签名），外部调用方
  （`follow` 等传 `controller.onRefresh`）不受影响。
- **未覆盖**：`AlertDialog` / `ChoiceChip` / `ColorScheme` / `FloatingActionButton` /
  `Divider` / `Material` / `Theme` 等 material 符号 ≈ 10 个刷新站点仍在 → b7-c6。
- **有意不变**：`pages/video/detail_page.dart`、`pages/whisper/view.dart` 的
  `AppMiuixRefresh`（用户已验收）不回归。
