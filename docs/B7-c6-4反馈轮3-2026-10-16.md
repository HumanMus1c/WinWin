## 1. 现象

用户反馈：**音量滑条超过 100%、增益文本出现的那一刻，滑条会"瞬间偏移"，导致误操作。**

即：拖动音量条从 100% 继续向右到 >100% 时，拇指/轨道整体横向跳一下，此时手指仍按在轨道上，落点与视觉不再对齐 —— 松手即得到非预期音量。

## 2. 定因

弹层结构（`lib/pages/video/player_panel.dart` → `_buildVolumePopup()`）：

```
AppAnchoredPopup(anchor: 音量按钮矩形, child: GlassCapsule(
  Row(mainAxisSize: MainAxisSize.min, [ 图标(18)  间距8  滑条(150)  间距8  文本 ])
))
```

关键链路：

1. 文本内容随数值变化：`'$rounded%'`（≤100）→ `'$rounded% (增益)'` 且 `fontWeight: bold`（>100）。
   文本宽度**一次性增加约 40px**（后缀 `" (增益)"` + 粗体字宽增量）。
2. `Row` 为 `MainAxisSize.min`，胶囊宽度**由内容内在宽度决定** ⇒ 文本变宽 ⇒ **整个胶囊变宽**。
3. 弹层由 `AppAnchoredPopup` 的 `_AppAnchoredPopupLayout` 定位：**水平方向在锚点（音量按钮）上居中**，超出屏幕边距才 clamp。胶囊变宽时，居中算法按**新宽度**重算左右边界 ⇒ 胶囊整体在原位基础上左右各延伸 Δ/2。
4. `Row` 内左侧的图标与滑条相对胶囊左边距固定 ⇒ 胶囊一动，**滑条连同拇指也跟着动约 Δ/2 ≈ 20px**。

即：位移根因不是滑条自身，而是「**内容宽度变化 → 弹层高度变化 → 锚定居中重算 → 承载滑条的容器整体平移**」的整链传导。

排除项（逐一核实非变量）：

- 图标：`ContrastIcon(size: 18)`，三态（`volumeOff` / `volumeDown` / `volumeUp`）同为固定 18px，宽度不随状态变化。
- 滑条：`SizedBox(width: 150)` 固定。
- 胶囊内边距、圆角、模糊：常量。
- 数值位数变化（9→10、99→100）同样会带来数像素级位移，同属本类问题，本次一并由"固定槽位"覆盖。

## 3. 方案

**给标签加"宽度恒定槽位"：用一枚不可见但保留尺寸的最宽标签撑住槽位宽度，可见标签左对齐贴在槽位左边。**

`player_panel.dart` 尾部标签块由「单个 `ValueListenableBuilder` + `ContrastText`」改为：

```
Stack(
  alignment: Alignment.centerLeft,
  children: [
    if (Pref.maxVolume > 100)
      Visibility(
        visible: false,
        maintainSize: true,
        maintainAnimation: true,
        maintainState: true,
        child: ContrastText('${Pref.maxVolume.round()}% (增益)',   // 最宽形态：粗体 + 上限三位数 + 后缀
          style: TextStyle(color: AppColors.white, fontWeight: FontWeight.bold, fontSize: 12),
          shadows: ContrastStyle.glyphShadows),
      ),
    ValueListenableBuilder<double>(           // 可见标签：样式/文案一字未改
      valueListenable: c.volume,
      builder: (context, vol, _) { ... },
    ),
  ],
)
```

要点：

- `Visibility(maintainSize: true, maintainAnimation: true, maintainState: true)` ⇒ 子项照常参与布局（占位）但不绘制、不接受命中 ⇒ `Stack` 以"最宽标签"为宽度基准。
- `Stack` 默认 `StackFit.loose` ⇒ 取最大子项尺寸；配合 `alignment: Alignment.centerLeft`，可见标签左边缘与占位标签左边缘对齐 ⇒ **可见文本起始 x 与修改前完全一致**，数值变化只影响文本自身右侧。
- 占位字符串用 `'${Pref.maxVolume.round()}% (增益)'` **动态取上限**，而不是硬编码 200：用户若调整音量上限（`Pref.maxVolume` 默认 200.0，见 `lib/core/storage/storage_pref.dart`），槽位宽度随之自适应；数字字形等宽，故"三位数上限"即最宽情形。
- 加 `Pref.maxVolume > 100` 守卫（与 `keyPoints` / `showKeyPoints` 同一守卫）：上限 ≤100 时增益后缀永不出现，则不占用槽位宽度（同步保持 `MiuixSlider` 关键点关闭）。
- 之所以用"同款 `ContrastText` 的不可见兄弟"而不是 `TextPainter` 预量宽度：`Text` 的最终字体会与祖先 `DefaultTextStyle` 合并（未显式指定 `fontFamily`），而 `TextPainter` 独立测量拿不到该上下文，跨字体/跨机可能量偏 —— 用真实 widget 占位则天然同字体、同缩放、同 `MediaQuery.textScaler`。

**被评估但未采用的选项**：

- 去掉 `" (增益)"` 文案，仅以琥珀色 + `volumeUp` 图标表达增益（改动最小且零占位宽度，但会削减一档既有信息量）；如用户更倾向此口径，可将上面 `Stack` 与可见标签里的后缀一并删除，属一行级切换。
- 改 `AppAnchoredPopup` 的水平定位策略（左对齐锚点 / 按内容宽度固定中心）：会同时影响投币浮层等其它锚定浮层，且音量按钮位于播放条右侧、贴边 clamp 情形下仍会位移，不是通用解。
- 固定整个弹层宽度（外层 `SizedBox(width: 常量)`）：能稳定宽度但需硬编码总宽、且需把所有子项按新宽度重排，属于"以更多常量换同效果"，不取。

## 7. 实机复验指导

1. 播放视频 → 点开音量按钮 → 弹层应仍**贴按钮上方**且水平居中于按钮（反馈轮 1 成果不回归）。
2. 慢慢把音量拖过 100%：**滑条与拇指不应有任何横向跳动**，`(增益)` 文案为在预留槽位内"长出"，文字左边缘与 "100%" 时一致；越过时颜色转琥珀、图标转音量放大。
3. 100% 处仍应有**磁吸**（反馈轮 2 成果：标记点可见 + ±6 内吸附）。
4. 上限 ≤100 的配置下（若设置中可调）：无增益后缀、无预留空位、无关键点。
5. 附带回归：投币浮层仍为内容宽（约 264px）且贴"投币"按钮上方。

## 8. 总结

- 本轮教训（W6 追根因）：**"随状态变化的文本 + 自适应宽度的浮层 + 以锚点居中"三者叠加 = 拖动过程中的位置漂移**。凡是"拖动/滑动过程中会变长的内容"，其所在浮层必须给该内容**固定尺寸槽位**，把宽度变化冻结在槽位内部；否则内容一变，整个浮层重排，操作热区就跟着跑。
- 该模式可推广到本项目全部锚定浮层（音量、投币、画质/音轨/倍速弹层）：**锚定浮层内不得存在"随值变化的自适应宽度元素"**，这条已写入本轮复盘，供后续批次评审时对照。
