# 收藏面板列表自挂项目自绘滚动条 — 复盘（2026-10-21）

- 日期：2026-10-21
- 快照基准：`refs/snapshots/latest` = `05efea5`（改动前状态；回滚见第五节）
- 触发：CVO「为添加收藏的面板的列表增加自研自绘的滚动条」。紧接同一轮「图标全局反色 + 收藏面板搜索框」改动（`ea95140`）。

## 一、现象

「添加到收藏夹」底部面板的收藏夹列表在**长于面板可视高**时**没有任何滚动条** —— 既没有项目自绘滚动条，也没有 Flutter 框架默认条，用户滚动时无位置指示。

## 二、定因

项目对滚动条是「一处收口」：`AppShell` 的 `AppScrollBehavior.buildScrollbar` 为桌面平台每个**竖向** `Scrollable` 套 `AppScrollBar.attach`（`lib/common/widgets/app_scroll_bar.dart`）。按理该面板列表也会自动获得 —— 但 `AppScrollBar.build` 里还有一道**「页面级」比例门控**：

```
mainExtent < windowMain * AppScrollBar.pageLevelExtentRatio(0.5)
  ⇒ return _suppressFrameworkBar(widget.child);   // 不绘项目条，且关掉框架条
```

面板 `Container(constraints: maxHeight 500)`，列表又位于 `Expanded` 内、实际高度还要再减去标题栏/搜索框/底栏，故 `mainExtent` 远小于「窗口高 × 0.5」⇒ 命中门控 ⇒ **既不绘项目条、又被 `_NoFrameworkScrollBar` 关掉框架条**，结果是完全无条。

门控的由来（注释记载）：早期实现是「为滚动条**预留 12px 独立通道**」，为弹层/面板/局部小列表预留会抢走布局（用户实测视频卡片「更多操作」弹层被撑坏），故加此门控。之后通道已改为**覆盖层形态**（`_buildLane` 用 `Stack` + `Positioned`，不占位、不撑开布局，见源码 428-433 行注释），「预留撑坏布局」的直接成因已消除，但门控**未同步放开**。

## 三、方案

1. `AppScrollBar` 新增开关 `forceLane`（`bool`，默认 `false`）：置 `true` 时**跳过**上述比例门控、直接走 `_buildLane` 绘制覆盖层滚动条。默认值保持既有全局行为不变（其余小面板/弹层不受影响）。
2. 收藏面板列表**显式自挂**：`_FavPanelState` 增 `ScrollController _listController`，`ListView.builder` 指定该 controller，并外包 `AppScrollBar(controller: _listController, forceLane: true, child: ListView...)`；`dispose` 同步释放 controller。

## 遗留与踩坑

- **全局挂载与面板自挂会「套两层」`AppScrollBar`**：外层来自全局 `AppScrollBehavior`（`forceLane` 默认 false，命中门控 ⇒ 不绘条，仅承担框架条抑制）；内层是本次自挂（`forceLane: true` ⇒ 绘制）。两层不产生「双滚动条」，但外层仍会跑一遍滚动通知监听（无副作用）。
- **覆盖层通道宽 12px 贴列表右缘**，会遮住该条带内行的 hover/点击（`HitTestBehavior.opaque`）—— 一切覆盖式滚动条的固有代价；本面板行右侧主要留白，影响有限。
- **门控仍为全局默认**：本轮只对「被要求的面板」开启 `forceLane`，其余弹层/小列表维持原状（无条）。是否把「弹层内局部列表」统一开放项目滚动条，属产品口径，留待 CVO 决策。
- 本仓未纳入 UI 用例，未跑 `flutter test`。

## 总结

面板列表无滚动条并非「没挂」，而是被 `AppScrollBar` 内部的「页面级」比例门控**主动抑制**（且顺手关了框架条）—— 该门控为早期「预留通道」方案而设，在通道改覆盖层后已成历史包袱。本轮以最小面改动破局：给 `AppScrollBar` 加 `forceLane` 显式开关（默认不变），面板列表据此自挂项目自绘滚动条，覆盖层形态不占位、不撑布局。`dart analyze` 0/0、Debug 与 Release 双 √ Built，可一键回退 `05efea5`。
