# 播放页进入时延取证（2026-11-06）

## 一、现象

用户反馈：点击首页视频卡片后要数秒才进入播放页，本次运行整体响应偏滞后。

## 二、已排除项（当日日志与实测）

1. 单实例运行（仅 Release PID 10560），空闲 CPU 约 1.6%，无忙等。
2. B 站 `view` 接口 3 次实测：420ms / 237ms / 223ms，服务端无异常。
3. 播放器 `setMedia → prepare → ready` 在历史日志中均为 0.6~1s（如 21:04:13.123 → 13.792）。
4. 今日日志无 `device-loss` / GPU 恢复记录。
5. 首页卡片 `onTap` 为同步 `Navigator.push`，无异步前置等待。

## 三、本轮埋点（定位点击→首帧→解析→起播各段耗时）

- `Nav: tap rcmd bvid=...`：首页卡片点击时刻
- `DetailPage: open bvid=...`：详情页 initState 时刻（push 生效）
- `DetailPage: first frame Xms`：详情页首帧耗时
- `DetailPage: videoIntro ok/fail in Xms`：稿件详情接口耗时
- `PlayerController: playurl ok/fail in Xms qn=...` / `playurl cache hit qn=...`：播放地址接口耗时

以上均为 W 级（Release 可见），仅在真实播放链路触发，不逐帧输出。

## 六、遗留

- 若 `tap → open` 间隔大：点击/路由层问题；

## 七、总结

现有证据未发现服务端或播放器准备阶段的明显瓶颈，延迟发生在"点击→详情页可用"这段尚未埋点的区间。本轮已补齐该链路的 W 级计时日志，待一次实机点击后按段定位，再决定优化项。

## 八、实测结果（2026-11-06 21:27~21:30，三次点击）

| 阶段（最后一次 21:30:35） | 耗时 |
|---|---|
| tap → DetailPage.open | 2ms |
| open → first frame | 8ms |
| videoIntro（`/x/web-interface/view`） | 154ms |
| playurl（`/x/player/wbi/playurl`） | 285ms |
| setMedia → prepare ok（fvp 起流） | 612ms |
| prepare → ready（playing） | 135ms |
| **tap → 起播合计** | **≈1.19s** |

三次点击的 tap→起播分别为 ≈0.77s / 0.60s / 1.19s；详情页首帧均为 5~10ms，页面本身即刻可见。用户体感的「约 2 秒」= 1.19s 管线 + 路由转场/视觉反馈与主观计时的余量；波动主要来自 `videoIntro`（111~235ms）、`playurl`（235~291ms）与 fvp `prepare`（104~612ms）。

结论：**非本次改动引入的回归**；链路固有成本 = 两次串行 HTTP（cid 需从 videoIntro 取得，无法提前请求 playurl）+ fvp 起流。

## 九、可选优化（按收益/成本排序）

1. **卡片预取 videoIntro（推荐）**：列表可见/悬停时预拉详情，点击后直接命中 → 省 110~235ms。
2. **缩短详情页路由转场时长**：只改善主观"进入"速度（不影响真实起播）。
3. **prepare 波动治理**：612ms 样本偏高，排查 fvp open 缓冲参数/共享播放器复用时机。
4. **播放器实例预热**：进入详情页即创建并预热共享 player（已有 400ms teardown 延迟，可评估提前量）。
5. 并行化 videoIntro/playurl：受 cid 依赖限制，除非卡片模型自带 cid，否则不可行。

## 十五、二分结论与文本选中能力重做（2026-11-07）

- 结论：用户实机复测连续进出播放页 5~6 次**不再冻结** ⇒ 锁定 `8eba425` 的区域级 `AppSelectionArea`（`SelectableRegion` 包裹容器/交互子树）为触发源。
- 机理（与 §十三 证据对齐）：
  1. `SelectableRegion` 的区域级选择手势识别器参与每个指针事件的命中测试与选择几何计算，计算量随子树深度上升；详情页为全库最重的交互树（播放器、弹幕、评论、滚动列表）。
  2. 其选择手势与子树内滚动/点击识别器同处手势竞技场，桌面选择手柄控件叠加后易僵持或产生持续指针取消。
  3. 区域内既有 `AppSelectableText`（单文本选择区域）形成嵌套 `SelectionContainer`，指针事件重复注册与计算。
  4. 退出播放页回首页时树重建 + 区域选择重建放大上述路径，冻结后 `Pointer` 无记录（§十三）。
- 为何 `AppSelectableText` 自 v0.1.2 起从未冻结：它只包单个文本节点，命中半径就是一行文字，不与滚动容器同事，竞技场冲突面极小。
- 重做原则：**只包末端静态文本，绝不包容器/交互子树**；交互容器（如 `MiuixPressable` 内的协议条款行）不启用选择。
- 落地范围（4 文件）：
  - `lib/pages/video/detail_page.dart`：简介、错误卡片 bvid/原因/说明；
  - `lib/pages/setting/about_page.dart`：品牌名、技术栈、版本号；
  - `lib/pages/download/download_page.dart`：占用空间、存放路径（保留 `maxLines: 2` 省略）；
  - `lib/pages/onboarding/user_agreement_page.dart`：欢迎标题、副标题、底部说明；条款行保持普通 `Text`。
