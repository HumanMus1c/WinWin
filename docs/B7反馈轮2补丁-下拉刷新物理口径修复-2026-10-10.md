# B7 反馈轮#2 补丁：评论区/消息中心下拉刷新物理口径修复 — 2026-10-10

> 承接 `docs/B7反馈轮2-三问题修复复盘-2026-10-10.md`（`359d50d`）：
> 换用 `MiuixPullToRefresh` 后两处下拉完全失效，本补丁修复。

## 1. 现象描述

反馈轮#2 实机复验：评论区与消息中心**完全无法下拉刷新**——连指示器都不出现。

## 2. 根因（探针实证）

- 临时探针（真实结构 `MiuixPullToRefresh` + 鼠标拖拽 + 控制器状态与滚动通知打印）：
  - **修复前**：拖拽 280px，控制器恒 `idle / dragOffset=0`；滚动通知日志显示
    列表像素直接跑到 **-80**（无边界反弹）、且**全程无 `OverscrollNotification`**；
  - 根因：两处目标列表写的是**裸 `AlwaysScrollableScrollPhysics()`**——无 parent 时
    边界行为取基类 `ScrollPhysics`（**基类 `applyBoundaryConditions` 恒 0 = 无边界条件**），
    像素可无限越界且**不产生过卷通知**；
  - `MiuixPullToRefresh` 的状态机**完全依赖 `OverscrollNotification`** 驱动头部
    （其设计即"列表不动、头部增长下推内容"，见组件注释与 `_handleScrollNotification`）；
    material `RefreshIndicator` 不依赖过卷通知（自行跟踪拖拽细节）——替换组件后
    才暴露该物理口径缺陷。
- 修复验证（同探针）：改用 `ClampingScrollPhysics(parent: AlwaysScrollableScrollPhysics())`
  后——过卷通知出现（overscroll=-80/-120/-80）→ `dragOffset` 69.8→140.7→169.7 →
  状态 `thresholdReached` → 释放弹簧收口 → **`onRefresh` 触发 ✓**（状态机
  refreshing → refreshComplete 走完）。

## 3. 修复方案

- `pages/whisper/session/session_list_section.dart`（会话列表 CustomScrollView）与
  `pages/video/detail_page.dart`（`_buildReplyListView`）的 `physics` 改为：

  ```dart
  const ClampingScrollPhysics(parent: AlwaysScrollableScrollPhysics())
  ```

- 其它 `AppRefreshIndicator`（material）站点不受影响，不动。

## 5. 遗留与踩坑

- 踩坑①：Flutter 物理参数**不能裸用** `AlwaysScrollableScrollPhysics()`——须包一层
  **有边界条件**的物理（Clamping/Bouncing），否则过卷被静默吞掉；
- 踩坑②：替换下拉组件时必须核对**通知依赖面**——material `RefreshIndicator` 与
  `MiuixPullToRefresh` 对 `OverscrollNotification` 的依赖不同；
- 探针须等弹簧动画走完（多泵几帧）再断言释放路径，否则误判"未触发"。

## 6. 总结

两处下拉刷新恢复可用：物理口径改为 Clamping 包裹 AlwaysScrollable，过卷通知
恢复上报，Miuix 下拉状态机全链路贯通（拖拽 → 阈值 → 释放触发 → 完成复位）。
