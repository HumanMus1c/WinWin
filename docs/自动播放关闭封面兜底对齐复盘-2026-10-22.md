# 「自动播放」关闭的封面兜底对齐复盘 · 2026-10-22

关联基线：`d2722c5`（改动前 HEAD；工作树干净，`git stash create` 为空，快照即 HEAD）。

## 〇、一句话结论

当「自动播放」设置**关闭**（默认值）时，播放器进入页面先以**视频封面整屏遮盖**播放面（对齐上游 PiliPlus），
用户点击后首次起播起，封面**永久退出**、不再介入视频流——起播后的渲染与原先完全一致。

## 一、现象描述

- 设置项「自动播放」（`Pref.autoPlayEnable`，默认 `false`）关闭时，进入视频/番剧详情页不自动起播，
  这是既有设计。
- 但 **WinWin 未对齐上游 PiliPlus 的兜底表现**：上游在关闭自动播放时，画面上呈现的是**视频封面**（整屏 + 点击播放）；
  而 WinWin 仅把封面当作「加载期首帧占位」，一旦媒体加载完成、首帧就绪，封面即 240ms 淡出，
  **露出解码后的暂停首帧**（叠加中央播放按钮），与上游观感不一致。

## 二、问题根因

WinWin 的封面可见性只由「加载态」决定，**没有一处按 `autoPlay` 分支**。

- 封面渲染：`lib/pages/video/player_panel.dart::_buildVideoSurface`
  ```dart
  final coverVisible = gateHeld || !hasFrame;   // 仅「启动闸门 || 尚无解码帧」
  ```
  即封面是「首帧占位」语义：加载/闸门/缓冲/弱网重试期遮盖，首帧就绪后淡出。
- 起播入口：`lib/pages/video/detail_page.dart:566` `ctrl.load(gateForResume: true, autoplay: Pref.autoPlayEnable)`；
  番剧 `lib/pages/bangumi/bangumi_player_page.dart:155` 同源。
- 关闭自动播放时，媒体仍被加载、闸门释放后停在 0 位、`hasFrame` 为真 → 封面淡出 → 显示暂停首帧。

上游 PiliPlus 做法（`PiliPlus/lib/pages/video/view.dart`，作为对齐目标）：

- `videoPlayer()` 的 Stack：`if (!videoDetailController.autoPlay)` 时以
  `Positioned.fill(GestureDetector(onTap: handlePlay, child: NetworkImgLayer(src: cover)))`
  **整屏封面 + 点击播放**覆盖播放面；
- `plPlayer()`：`!autoPlay` 时返回 `SizedBox.shrink()`（**不挂载播放器**）；
- `manualPlayerWidget()`：`!autoPlay` 时只保留顶部工具栏 + 右下角 `PlayIcon()`。
- 状态源：`controller.dart:125` `final RxBool _autoPlay = Pref.autoPlayEnable.obs;`，
  点封面 → `handlePlay()` 置 `_autoPlay=true` 并起播。

## 三、修复方法

**实现来源**：移植上游 PiliPlus（`view.dart` 的非自动播放封面分支语义），保留 WinWin 既有「首帧占位」结构增量融入。

改动集中在 `lib/pages/video/player_panel.dart`（唯一播放器面板，视频详情页与番剧页共用）：

1. **新增状态 `_coverFallbackActive`**，`initState` 按 `!Pref.autoPlayEnable` 初始化——
   自动播放开时恒为 `false`（**该路径行为零变化**）。
2. **首次起播永久解除**：监听 `controller.playing`，首次 `playing==true` 时 `setState` 置 `false`
   （只解除、不回盖）；`dispose` 注销监听。
3. **封面可见性并入兜底**：`coverVisible = gateHeld || !hasFrame || _coverFallbackActive`——
   未起播前封面常驻整屏遮盖暂停首帧；起播后标志置假，回落到原「首帧占位」逻辑。
4. **兜底期不渲染弹幕层**：`if (!_coverFallbackActive)` 包裹弹幕 `Positioned.fill`，
   避免静态封面叠动弹幕（对齐上游「播放器未挂载故无弹幕」）；起播后弹幕照常。

点击播放沿用既有手势层 `_onVideoTap → playOrPause()`，中央播放按钮（`_buildCenterPlayButton`）
在就绪且暂停时本就显示于封面之上，充当点击播放入口，无需新增控件。

- `desktop_pip.dart`（桌面画中画）未纳入本次兜底范围：PiP 由用户显式触发、不存在「未起播静置封面」场景，暂不处理。

## 六、总结

- 用户判断成立：**上游 PiliPlus 在关闭自动播放时确实以视频封面作兜底**（整屏封面 + 点击播放，播放器不挂载）。
- WinWin 采用**更轻量**的对齐方式：不拆播放器挂载，仅在既有「首帧占位」上并入一个
  `_coverFallbackActive` 分支，实现「未起播先见封面、点击即起播、起播后封面永久退出」。
- 设计上以「首次起播即永久解除」这一单调翻转，保证**起播后的正常视频流零影响**，
  并让自动播放开启路径完全不进入新分支（零行为变化）。
