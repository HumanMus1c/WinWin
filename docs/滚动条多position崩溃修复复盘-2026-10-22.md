# 滚动条多 position 崩溃修复复盘（AppScrollBar · Bad state: Too many elements）

> 日期：2026-10-22　｜　触发：CVO「分析日志，继续推进下一阶段」
> 日志来源：`D:\Documents\.winwin_logs.json`（崩溃 NDJSON）、`D:\Documents\logs\runtime.log`
> 代码提交：`352a253`　｜　快照基准：`aca461b`

## 一、现象描述

日志分析：`runtime.log` 1512 行**全为 `[W]`、零 `[E]`**；但崩溃库 `.winwin_logs.json` 末段出现**新增**崩溃：

```
Bad state: Too many elements          （release，2026-10-21T15:36:54 / 21:53:46 / 21:54:48，共 3 次）
  #0 List.single                     (dart:core-patch/growable_array.dart:363)
  #1 ScrollController.position       (flutter/src/widgets/scroll_controller.dart:173)
  #2 _AppScrollBarState._position    (common/widgets/app_scroll_bar.dart:228)
  #3 _AppScrollBarState._buildLane closure (:384)
```

与更早（10-17）已修的 `Null check operator`（同文件 `:339`，`hasContentDimensions/hasPixels` 守卫修复）**不是同一路径**。

## 二、问题根因

`app_scroll_bar.dart` 的 `_position` getter 用 `widget.controller.position`：

```dart
ScrollPosition? get _position {
  if (!widget.controller.hasClients) return null;
  final position = widget.controller.position;   // ← 崩溃点
  ...
}
```

而 `ScrollController.position`（`scroll_controller.dart:172-173`）语义为「**唯一** position」：

```dart
assert(_positions.length == 1, 'ScrollController attached to multiple scroll views.');
return _positions.single;
```

⇒ 当**同一 `ScrollController` 被 >1 个滚动视图 attach**（页面转场期间新旧视图短暂并存、同一 controller 被多列表复用等）时：debug 触发断言 `_positions.length == 1`，**release 去除断言后 `_positions.single` 抛 `Bad state: Too many elements`**。

既有守卫（`hasClients` / `hasContentDimensions` / `hasPixels`）只覆盖「未 attach」「未布局」两态，**未覆盖「多 position」态**。

## 三、修复方法

`lib/common/widgets/app_scroll_bar.dart` —— `_position` 不再使用 `controller.position`，改为遍历 `controller.positions` 取第一个「已就绪」者：

```dart
ScrollPosition? get _position {
  if (!widget.controller.hasClients) return null;
  for (final position in widget.controller.positions) {
    if (position.hasContentDimensions && position.hasPixels) return position;
  }
  return null;
}
```

语义保持：未就绪一律视为不可用（null）；单挂载行为完全不变；多挂载时**不再崩溃**（取首个可用 position 驱动滑块）。

## 五、遗留与踩坑

- 崩溃 NDJSON 的 `dateTime` 字段在解析脚本首轮因键名未知而显示 `?`；实际字段为 `error / dateTime / stackTrace / platformType / deviceParameters / applicationParameters`（后续脚本据此解析）。
- 本次修复只处理「多 position」这一新增态；`app_scroll_bar.dart` 现存三类守卫分别对应：未 attach（`hasClients`）、未布局（`hasContentDimensions/hasPixels`）、多 position（本次）。后续若出现其它 controller 生命周期态，应继续在此 getter 收敛。
- `runtime.log` 全 `[W]` 无 `[E]`，且 13:40 出现 `dpr=1.0→1.25` —— 侧面印证 **scaled-binding 界面缩放在实机生效**（DPR 被真实缩放）。

## 六、总结

日志分析直接暴露一个**未被此前修复覆盖的新崩溃态**：`ScrollController` 被多视图 attach 时，`controller.position`（`_positions.single`）在 release 抛 `Bad state: Too many elements`。修复方式是把取 position 从「唯一」语义改为「遍历取首个就绪」，并在既有守卫体系上补齐第三态。全程遵循「复现（先红）→ 根因（多 position）→ 修复（遍历就绪）→ 验证（后绿 + 双编译）」，改动最小、语义不变。
