# 表情面板官方分包修复复盘（2026-09-29）

**范围**：用户实机反馈——表情面板「缺少好多官方表情」、且「某些表情没有正常渲染」（截图：`[再见]` 单元格退化为文字 + 悬停 tooltip）。另确认：用户侧看不到 404 报错（此前 onError 静默与占位兜底已生效）。

## 一、分析根因（现象 + 取证 + 根因链）

- **数据源缺失**：面板（`common/widgets/comment/emote_picker.dart`）只用内置静态表（`utils/bilibili_emotes.dart`：52 条 URL / 28 条显示）——`ReplyHttp.getEmoteList`（`/x/emote/user/panel/web`）存在但**零调用**（移植未挂接）⇒ 官方全量分包（小黄脸等）从未展示。
- **坏链实测**：静态表 44 条 URL 逐个 HEAD 探测 → **3 条 404**：`[再见]`、`[保佑]`、`[2333]`（与截图 `[再见]` 渲染失败吻合；面板 errorBuilder 退化为文字）。
- **接口实测**：
  - `/x/emote/user/panel/web?business=reply`：登录态返回用户全部表情包（PiliPlus 同源实现一致）；**游客返回 `packages: null`**（带 buvid3 亦然）⇒ 必须有本地回退；
  - **`/x/emote/package?business=reply&ids=…` 免登录可用**：ids=1 →「小黄脸」**225 条**当前有效链接；ids 1..80 → 34 包 912 条；`[2333]` 全部无命中（已下架）；
  - 替代链接 HEAD 200：`[再见]`=`fc510306…65b9.png`、`[保佑]`=`fafe8d3d…fb30.png`。

## 二、设计修复计划与实现

1. **模型**：`lib/models/common/emote_package.dart`（`EmotePackage{id,text,url,type,emote[]}`、`EmoteInfo{text,url,type,size,alias}`；type=4 颜文字）；
2. **接口**：`ReplyHttp.getEmoteList` 升级为类型化返回；新增 `getEmotePackagesByIds`（`/x/emote/package`）；`Api.emotePackage` 常量；
3. **EmoteStore**（`lib/core/emote/emote_store.dart`）：三级数据源——① 登录面板接口 → ② 免登录包明细 `ids=1` → ③ 内置静态表；内存缓存 + 在途去重 + 失败静默（30s 重试冷却）+ AppLogger 留痕；`urlOf(code)` 供评论渲染复用；
4. **面板改造**：打开即 `ensureLoaded()`；有服务端数据 → 多包时文字 Tab（横向滚动）+ 网格**可滚动**（maxHeight 236、7 列、懒加载，不再全量预取）；颜文字包按文本渲染；**静态优先、加载完成后原地切换**（不闪加载态）；插入仍为 `[code]`；面板高度估算 240→340；
5. **评论渲染链**（`reply_content_view.dart`）：`content.emote` → **EmoteStore 官方缓存** → 内置静态表；
6. **静态表修复**：`[再见]`/`[保佑]` 更新为实测有效链接；`[2333]`（已下架）移除。
