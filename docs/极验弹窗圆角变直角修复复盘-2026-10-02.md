## 一、分析根因

### 1.1 现象描述

极验弹窗（360×480）在**加载态**为圆角（由主题 `dialogTheme.shape` 决定），WebView 配置拉取完成、内容出现后变为**直角矩形**（用户截图 2→1 对比）。

### 1.2 根因链（取证）

1. `lib/pages/login/geetest_webview_dialog.dart:116` 的 `Dialog` 未设置 `clipBehavior`；
2. `material_ui` 的 `Dialog` 默认 `clipBehavior = Clip.none`（`dialog.dart:114`），解析链为 `clipBehavior ?? dialogTheme.clipBehavior ?? defaults`（`dialog.dart:297`）；本项目 `app_theme.dart` 仅定义了 `dialogTheme.shape`（M3/Miuix 各自圆角），**未定义 `clipBehavior`** → Material 只绘制圆角背景，**不裁剪子级**；
3. 内容树 `SizedBox(360×480) → Stack → InAppWebView`：Windows 实现为 **Texture 纹理合成**（`flutter_inappwebview_windows/.../custom_platform_view.dart:492`），纹理为直角、不透明、铺满整卡；
4. 加载态只有 Flutter 绘制的 spinner（落在圆角背景上，故仍圆角）；纹理就位后盖住圆角 → 「圆角变直角」。

### 1.3 非回归取证

- 文件结构 2026-08-09（`0e01513`）引入，其后仅 import 替换（`9a7b769`）与设置字段删除（`395cd9e`），无布局变更；
- `Dialog.clipBehavior` 默认值在 material_ui **1.0.0 与 1.5.0 逐字一致**（均 `Clip.none`）→ **与本次 1.5.0 升级及迁移无关**；属既有缺陷，本次诊断首次暴露（该弹窗此前未在 Windows 上做过视觉核对）。

## 二、设计修复计划（关键决策）

| 方案 | 决策 | 理由 |
|---|---|---|
| **`Dialog(clipBehavior: Clip.antiAlias)`（采用）** | Material 按主题 shape 裁剪子级，纹理随之圆角化 | 1 行；圆角来源唯一（`app_theme.dart` 的 `dialogTheme.shape`），M3/Miuix 自动适配，不硬编码半径 |
| 备选 A：内容层手包 `ClipRRect` | 不选 | 需手动同步半径值，与主题形状来源重复 |
| 备选 B：全局 `dialogTheme.clipBehavior` | 不选 | 影响全库所有 Dialog，爆炸半径大 |
| 意外回退 | 若实测纹理未被裁剪（引擎级异常）→ 回退内容层 `ClipRRect` 并回报 | 纹理裁剪是引擎既有能力，预期可行 |
