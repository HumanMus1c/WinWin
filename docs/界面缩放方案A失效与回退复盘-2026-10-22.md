# 界面缩放（方案 A · 整树 Transform）失效与回退复盘

> 日期：2026-10-22　｜　范围：`uiScale` 整树缩放（批次 2 引入）
> 代码提交：`03c6401`（止血回退）　｜　关联：`d627bbf`（批次 2 引入方案 A）
> 触发：CVO 2026-10-22 00:41 实机反馈

## 一、现象描述

批次 2 的「界面缩放」（方案 A：`MediaQuery.size` 覆盖 + `Transform.scale`）实机暴露两类错误：

1. **窗口控件漂移 / 底部入口不可见**：窗口控制器（标题栏按钮等）漂移至窗口之外；「我的」页面最下方的**切换账户 / 设置**入口完全看不到。
2. **弹层严重偏离触发原点**：右键视频卡片的「更多操作」弹层、消息中心对话的「更多选项」弹层，均严重偏离右键触发位置。

CVO 期望语义：缩放应**相对于窗口**（窗口不变，界面按比例缩放适配），而非"绝对固定值缩放"。

## 二、问题根因

多源取证（Flutter SDK 源码 + flutter_miuix 1.3.0 源码 + 本项目实现）：

- `Transform.scale` **只改变绘制**，**不改变"坐标空间"**。`localToGlobal` 返回的是**含缩放的根坐标**。
- **Miuix 弹层**（`flutter_miuix-1.3.0`）：`MiuixPopupPositionProvider` 注释明确「所有坐标均为**相对于窗口左上角的逻辑像素**」「同一算法用于 Overlay 与**窗口级 host**」；实现用 `box.localToGlobal(Offset.zero)`（见 `miuix_dropdown_menu.dart:398`、`miuix_list_popup_host.dart` 的 `Overlay.maybeOf(context, rootOverlay: true)`）。⇒ 它把"含缩放的根坐标"当作"窗口空间坐标"使用，两空间相差 `uiScale` 倍 → **弹层偏移**（问题 2）。
- **窗口控件 / 底部入口**：自绘标题栏与依赖窗口空间的定位，与"缩小后的逻辑空间"错配 → **漂出窗口 / 被裁掉**（问题 1）。
- 补充验证：`View`（`view.dart:275`）用 `MediaQuery.fromView` 建立 MediaQuery，`WidgetsApp` **不会**重建它（`widgets/app.dart:369/461/1207` 注释），故我们的 `MediaQuery.size` 覆盖**是生效的**——问题不在"覆盖被吞"，而在 `Transform` 只做绘制缩放、与"窗口级参照"空间不一致。

**结论**：纯 Flutter 层无法让整树（含 `Overlay` 与窗口级参照）统一缩放；`Transform.scale` 与本项目"弹层锚定触发位置"的验收标准（见 `coding-conventions.md`）天然冲突。

## 三、修复方法（止血）

| 文件 | 改动 |
|------|------|
| `lib/core/shell/app_shell.dart` | 移除 `LayoutBuilder` + `MediaQuery.size` 覆盖 + `Transform.scale`；**仅保留 `textScaler`**（官方 textScaler 只改文字度量、不改坐标系，安全）；根因详细注释留档 |
| `lib/pages/setting/models/style_settings.dart` | 停用并隐藏「界面缩放」设置项（避免留下无法生效的**假开关**）；`SettingBoxKey.uiScale` / `Pref.uiScale` / `AppearanceNotifier.uiScale` 全部保留 |

止血目标：**恢复 UI 完全可用**（弹层归位、窗口控件与底部入口正常），同时不删存储与通知通道，为后续原生实现预留。

## 五、遗留与踩坑

- **整树缩放待原生实现**：正确做法是在 **Windows runner 层**以原生 DPI 缩放等效实现（逻辑尺寸 = 物理 / (dpr · scale)），使内容 / Overlay / 自绘标题栏**共享同一坐标空间**。需改 `windows/runner` 并实测与 `window_manager`（全屏/DPI）的交互，属较大改动，**待 CVO 确认方向后实施**。
- **`textScaler` 保留**：字体大小项不受本问题影响（textScaler 是官方支持的"仅文字度量"通道）。
- **假开关处理**：界面缩放项隐藏而非留死开关，符合批次 3「免假开关」原则。
- **教训**：`Transform.scale` 做"整树 UI 缩放"看似通用，实则与任何"用 `localToGlobal` + 窗口空间定位"的弹层（含 Miuix）不兼容——**方案设计阶段应将"弹层锚定"纳入缩放方案的风险清单**（本次方案文档已标注"命中测试风险"，但低估为"边缘情况"，实为**结构性冲突**）。

## 六、总结

方案 A（Transform 整树缩放）在本项目**结构性失效**：`Transform` 只缩放绘制，Miuix 弹层与窗口控件却基于"窗口坐标空间"，两者相差 `uiScale` 倍，导致弹层偏移与控件漂移。本次先**止血回退**（移除 Transform、隐藏设置项、保留全部存储/通知通道），恢复 UI 可用；整树缩放的正确路径是**原生 DPI 缩放**，待 CVO 确认后再实施。核心教训：涉及全局坐标/浮层的功能，**必须在方案期把"浮层锚定"当作一级约束**，不能仅视为边缘命中测试风险。
