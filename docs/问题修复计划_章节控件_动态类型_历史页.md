## 问题一：播放有章节的视频时，播放器没有章节控件按钮

### 1.1 现状调研结论

章节功能的主链路在代码层面**已经完整实现**，并非功能缺失：

| 环节 | 文件 / 位置 | 状态 |

| API 调用 | `lib/http/video.dart` L238-267（`VideoHttp.playInfo` → `/x/player/wbi/v2`，含 WBI 签名 + 风控参数） | ✅ 已实现 |
| 详情页注入 | `lib/pages/video/detail_page.dart` L281-313（`_applyPlayInfo` → `ctrl.setViewPoints()`） | ✅ 已实现（与 `ctrl.load()` 并行） |
| 控制器状态 | `lib/pages/video/player_controller.dart` L121-123（`viewPointsNotifier`）、L825-827（`setViewPoints`） | ✅ 已实现 |
| 章节按钮 | `lib/pages/video/player_panel.dart` L1252-1302（`_buildChapterButton`，挂在底部控制条 L737） | ✅ 已实现 |

| 进度条章节竖线 | `lib/pages/video/player_panel.dart` L902-917 + L1638-1675（`_ChapterMarkerPainter`） | ✅ 已实现 |

章节按钮的显示条件只有一个：`player_panel.dart` L1257

```dart
if (chapters.isEmpty) return const SizedBox.shrink();
```

即 **`viewPointsNotifier` 为空列表时按钮隐藏**。UI 挂载点（L733-738 控制条按钮行：音频标签 → 画质 → 倍速 → 章节 → 字幕 → 功能按钮）确认无误。

### 1.2 根因分析（按可能性排序）

既然 UI 链路完整，按钮不显示等价于"运行时 `viewPoints` 为空"，根因只能在 API 数据侧：

- **假设 A（最可能）：`/x/player/wbi/v2` 实际响应中 `view_points` 为空 —— 服务端风控降级。**
  `lib/http/video.dart` L242-244 的注释已记载该已知问题："缺 dm_img_* / gaia 参数时会被风控拒绝或降级，表现为字幕列表/章节标记静默丢失"。当前虽已补参数，但：
  - `dm_img_str` / `dm_cover_img_str` 由 `Utils.base64EncodeRandomString` 纯随机生成（`lib/utils/utils.dart` L55-59）。真实浏览器该值是特定格式的指纹串（base64 解码后以 `WebGL - ...` 等开头，长度也有特征），随机串存在被风控识别为异常的风险。
  - 请求参数只有 `bvid + cid`，**缺少 `aid`**。参考实现（PiliPlus `videoHttp.playerInfo` / BiliPai）同时传 `aid + bvid + cid`，部分风控路径对参数完整性敏感。
- **假设 B：playInfo 请求失败或返回非 0 code，被 `detail_page.dart` L310-312 的空 `catch (_)` 静默吞掉**，导致无从感知失败原因（该 catch 同时吞掉了假设 A 的现象）。
- **假设 C：目标视频的章节确实存在但接口下发条件不满足**（如 AI 章节需特定登录态/buvid3 激活状态）。

### 1.3 修复方案（按步骤执行）

**步骤 1：诊断（必做，先于任何修复）**

- `lib/pages/video/detail_page.dart` `_applyPlayInfo` 的 `catch (_)` 改为记录错误日志（`AppLogger`/`LogCollector`），并在 `infoRes` 为 `Error` 时记录 `errMsg`。
- `lib/http/video.dart` `playInfo()` 成功分支临时记录：`code`、`view_points` 的原始 JSON 长度与首条内容（注意脱敏，走 `log_sanitizer`）。
- 播放一个确认有章节的视频（如官方教程类多章节稿件），根据日志判定：
  - `view_points` 有数据 → 转查 UI 侧（可能性极低，ValueListenableBuilder 链路已确认）；
  - `view_points` 为空数组 → 假设 A 成立，执行步骤 2；
  - 请求失败/code!=0 → 假设 B 场景，执行步骤 2。

**步骤 2：对齐参考实现的请求参数**

- `VideoHttp.playInfo()` 增加 `aid` 参数（`detail_page.dart` L248 已有 `response.aid`，调用处 L287 传入）。
- 视需要补充 `try_look: 1`（未登录可查，对齐 PiliPlus）。
- 若步骤 1 证实仍被降级，将随机 `dm_img_str`/`dm_cover_img_str` 替换为浏览器真实指纹的固定格式样本（BiliPai `WbiUtils.appendRiskFingerprintParams` 的做法），保留长度扰动。

**步骤 3：收尾（可选增强，不阻塞本问题）**

- `lib/core/storage/storage_key.dart` L77 已定义 `showViewPoints` 键但全项目未引用：在播放设置中接线"显示章节标记"开关，默认开启。
- 诊断日志保留 `Error` 分支的（永久有用），删除响应体打印（临时）。

### 1.4 验证标准

1. 播放确认有章节的视频：底部控制条出现"章节"chip 按钮；进度条出现章节起始竖线；点击按钮右侧滑出章节面板；点击章节行跳转正确；当前章节高亮。
2. 播放无章节视频：按钮不显示，无布局抖动。
3. 弹幕开关、字幕按钮等相邻控件不受影响。

## 问题二：动态页未区分动态类型

### 2.1 现状调研结论

动态页（`lib/pages/dynamics/view.dart`）当前**仅有效支持视频稿件一种类型**：

- Tab 仅"全部 / 视频"两个（L38-41），类型分发只靠 `_isVideoTab`（L110）。
- 解析层 `lib/http/dyn.dart` L158-175：`DynItemModel.fromJson` 只读取 `module_author`、`module_dynamic.desc.text`、`module_dynamic.major.archive`（且仅当 `major.type == 'MAJOR_TYPE_ARCHIVE'`，L214-225）。
- 全部 tab 的综合卡 `_DynCard`（L506-713）唯一的类型分支在 L577：`if (item.isVideo && archive != null ...)`。非视频动态一律降级为"作者行 + 最多 4 行正文"。
- 以下字段被完整丢弃：`orig`（转发原动态）、`major.opus/article/draw/live_rcmd/courses`、`additional`（商品卡等附加卡）、`desc.rich_text_nodes`（富文本节点）、`module_stat`（点赞/评论/转发数）。
- `DynItemModel` 类注释（dyn.dart L131）声称"保留原始 raw 供按需解析"，**与实现不符（无 raw 字段）**。
- 请求参数 `features` 仅 `itemOpusStyle`，而 `lib/common/constants.dart` L42-43 已有完整 `dynFeatures` 常量未使用。
- 关联影响：`lib/pages/follow/controller.dart` L29 固定 `type: 'video'`，关注流同样只出视频稿件。

### 2.2 目标类型矩阵

| 动态类型 | type 常量 | major 类型 | 渲染目标 | 优先级 |

### 2.3 修复方案（分三层、两阶段）

**阶段 A：解析层扩展（`lib/http/dyn.dart` + 新建模型）**

1. `DynItemModel` 增加 `orig` 字段：`orig: json['orig'] is Map ? DynItemModel.fromJson(...) : null`（递归解析，天然支持转发嵌套；渲染层只递归一层防止转发套转发无限嵌套）。
2. `major` 多类型解析（新增并行模型，不动现有 `DynArchive`）：
   - `DynOpus`：解析 `major.opus`（title、summary.text、pics、内嵌 video 的 bvid/cover/duration）；
   - `DynArticle`：解析 `major.article`（title、cover、desc、id/cvid 用于跳转）；
   - `DynDraw`：解析 `major.draw.items`（src/width/height 图片列表）；
   - `DynLiveRcmd`：解析 `major.live_rcmd.content`（JSON 字符串，含 title/cover/uname/online，需二次 `jsonDecode`）。
3. `desc.rich_text_nodes` → `List<DynRichTextNode>`（text/rich 节点，jump_url 保留），为商品/视频链接点击打基础。
4. `additional` → `DynAdditional`（先支持 `type: ADDITIONAL_TYPE_GOODS` 的商品卡：title、cover、price、jump_url）。
5. `module_stat` → 点赞/转发/评论计数（卡片底部互动行，可后置）。
6. 请求 `features` 参数改用 `constants.dart` 的完整 `dynFeatures` 常量（opus 大封面等特性）。
7. 类型常量集中定义：新建 `lib/models/dynamics/dyn_type.dart`（或直接在 dyn.dart 顶部 const），消除硬编码字符串比较；顺手修正 L131 与实现不符的注释。

**阶段 B：渲染层重构（`lib/pages/dynamics/view.dart`）**

1. `_DynCard.build` 改为按 `item.type` + `major` 类型分发到子构建器：
   - `_buildForwardContent(item)`：转发评论 + 缩进圆角引用块内嵌原动态卡（原动态复用类型分发，深度 ≤1）；
   - `_buildDrawGrid(pics)`：1/4/9 宫格（`GridView`/`Wrap` + `AspectRatio`，图片用现有 `network_img_layer` 缓存层）；
   - `_buildArticleCard(article)` / `_buildOpusCard(opus)`：封面 + 标题 + 摘要卡；opus 含图片网格与内嵌视频行（点击跳视频详情）；
   - `_buildLiveCard(live)`；
   - `_buildGoodsCard(goods)` / `_buildRichText(nodes)`（P2，链接点击走 `bilibili_url_parser` 解析后路由跳转）。
2. 视频 tab 保持现状（`DYNAMIC_TYPE_AV` 过滤由服务端 `type=video` 完成）；"全部" tab 获得完整类型渲染。
3. 网格布局注意：`lib/utils/grid.dart` L55-66 `dynCardDelegate` 目前按视频卡纵横比定高，图文/转发卡高度弹性大 —— 方案：全部 tab 改为 `SliverList`（每条动态一行，B 站官方动态流即为纵向列表形态），或维持网格但仅对 AV 类型出卡。**推荐改 SliverList**，与 B 站动态流形态一致，也规避动态高度差异问题。

## 问题三：历史页面只加载出布局，无法加载视频信息

### 3.1 根因（已确认，非猜测）

**根因 1（致命）：首次加载被守卫拦截，API 从未被调用。**

`lib/pages/history/history_page.dart`：

- L39：`bool _loading = true;`（初始即 true）
- L47：`initState` 调用 `_load()`（`refresh` 默认 `false`）
- L80：非刷新分支守卫 `if (!_hasMore || _loading || _isLoadingMore) return;` —— `_loading == true` 直接 return

→ `HistoryHttp.historyList()`（L94）永不执行；`_loading` 永远为 true、`_items` 永远为空 → `build()`（L228-229）永远走 `_buildSkeleton()` 骨架屏分支。且骨架屏（L307-364）为 `NeverScrollableScrollPhysics` 且不带 RefreshIndicator，用户无法自救。**与"只加载出 DOM 布局而无法加载视频信息"的症状完全吻合。**

**根因 2（潜在，修复根因 1 后大概率暴露）：`kid` 字段类型转换抛异常。**

`lib/models/history/history_models.dart` L73：`..kid = json['kid'] as int?` —— B 站 `/x/web-interface/history/cursor` 返回的 `kid` 实际为字符串（如 `"archive_12345678"`，其格式与 `delKid` getter L87 的 `business_kid` 拼接预期一致），`String as int?` 抛 `_TypeError`，被 `history.dart` L35 catch 后整页变错误态。

**根因 3（次要）：游标未使用服务端 cursor。**

`HistoryData.fromJson`（history_models.dart L10-17）未解析 `data.cursor`；翻页游标由 `list.last.history.oid/viewAt` 推算（history_page.dart L110-111），对非 archive 业务（直播/番剧）可能翻页异常。

### 3.2 修复方案

1. **修根因 1**：`initState` 改为 `_load(refresh: true)`（最小改动）；同时将 L80 守卫收窄为 `if (!_hasMore || _isLoadingMore) return;`（`_loading` 语义是"首页加载中"，不应阻止首次加载；双保险防止同类回归）。
2. **修根因 2**：`kid` 改为兼容解析（参照 `play_info.dart` 底部 `_asInt` 工具函数的模式）：
   ```dart
   kid: json['kid'] is int ? json['kid'] as int : int.tryParse('${json['kid'] ?? ''}')
   ```
   注意：若 `kid` 本身就是 `"archive_12345"` 完整串，`int.tryParse` 得 null —— `delKid` getter 同步改为：`kid` 可直接作后缀时用原值，否则用解析值，保证删除接口拼接正确。稳妥方案：`kid` 字段改存原始值 `Object?`/`String?`，`delKid` 逻辑按实际响应格式适配。
3. **修根因 3**：`HistoryData` 增加 `cursor` 解析（`max`/`view_at`），`_load()` 优先用 `response.cursor`，为空时回退现推算逻辑。
4. 骨架屏兜底：骨架屏外层包 `RefreshIndicator`（或点击重试），彻底消除"永久骨架屏无法自救"的形态。

### 3.3 验证标准

1. 进入历史页：骨架屏短暂显示后出现历史列表（封面/标题/UP主/观看时间/进度）。
2. 滚动到底自动加载下一页，游标无重复无遗漏；下拉刷新正常。
3. 含直播/番剧/专栏混合类型的历史记录不崩溃、可翻页。
4. 删除单条历史记录（若页面已实现删除，`delKid` 拼接正确）。
