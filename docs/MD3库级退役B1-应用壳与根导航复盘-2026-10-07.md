## 一、分析根因（为什么 B1 必须先做"装配面"）

1. `MaterialApp` 是库级退役的第一个骨架阻碍：应用的 `ThemeData`/`Theme`/`AnimatedTheme`、
   `ScaffoldMessenger`、`DefaultSelectionStyle`、Material 本地化委托、`scrollBehavior`、
   `pageRouteBuilder`（路由工厂）均由它隐式提供；
2. 仓内 **251 处 `Theme.of(`、424 处 `colorScheme`** 消费者仍依赖它——若直接删除 MaterialApp 而不
   提供等价面，全站配色/文本会静默退回默认主题；
3. `ThemeNotifier` 持有的 `ThemeMode` 是 **Material 类型**，是壳层切换的直接依赖项；
4. `appScaffoldMessengerKey`（`GlobalKey<ScaffoldMessengerState>`）除挂载点外**无任何消费者**
   ——死句柄，随壳切换一并清除。

**MaterialApp 等价面清单（逐项核对 material_ui/src/app.dart 后确认）**：
`Theme`/`AnimatedTheme`（+`DefaultSelectionStyle` 选择色）、`ScaffoldMessenger`、
`localizationsDelegates`（Global 三件套）、`scrollBehavior`、`pageRouteBuilder`、`title`/`color`。

## 二、设计修复计划（方案与关键取舍）

| 项 | 方案 | 取舍 |
| --- | --- | --- |
| 应用壳 | `AppShell`（WidgetsApp）承载：`pageRouteBuilder → AppRoute`（Miuix 转场）、`AppThemeHost`（Token 通道）、`ScrollConfiguration`、显式 `DefaultTextStyle`、既有 builder 链（MiuixThemeScope → MiuixToastHost → ImmersiveTitleBarShell → AppEscapeScope） | 不复制 MaterialApp 的 `ScaffoldMessenger`（项目 Toast 走 MiuixToastHost，且句柄为死代码） |
| **过渡期 Material 主题** | `AppShell.theme`（`ThemeData`）+ `AnimatedTheme` + `DefaultSelectionStyle`，由 `main.dart` 按解析后的明暗传入 | **避免"一次性大爆炸"**：B2 迁完 `Theme.of` 消费者后删除该参数（B7 摘 material_ui）。若省掉这层，251 处消费者当即失效 |
| 本地化 | `AppShell` 显式装配 `GlobalMaterialLocalizations` / `GlobalCupertinoLocalizations` / `GlobalWidgetsLocalizations` | 与 MaterialApp 默认一致；`flutter_localizations` 已于 L0 升为直接依赖 |
| 主题模式 | `ThemeNotifier` 由 `ValueNotifier<ThemeMode>`（Material 类型）改为项目枚举 `ThemeModeType`（含 `typeIndex` 持久化映射与 `resolveIsDark`）；`Pref.themeMode` getter 下线（改用 `Pref.themeType`） | 去掉 material 依赖的源头；`ThemeModeType` 原已存在（设置页用），本次吸收 `toThemeMode/fromMode` 桥接 |
| 死代码 | 删 `appScaffoldMessengerKey` | 全库唯一消费点即 `MaterialApp.scaffoldMessengerKey`，无 `.currentState` 读取 |

**主题消费者口径（重要，B1 期间不变）**：应用侧页面/组件走 **material_ui** 的 `Theme.of`
（过渡期由 `AnimatedTheme` 提供）；**SDK material 的 Theme 仅服务 flutter_miuix 内部组件**
（经 `MiuixCompat` 局部提供）——测试中对两者分别断言，避免口径混淆。

## 六、修复轮（2026-10-07 实机反馈：Material 环境等价面缺本地化）

### 6.1 现象（用户实机）

1. 首页搜索框变成**灰色长条矩形**，点击无响应；
2. 全局返回按钮样式丢失，变成**方形灰色方块**，点击无响应（键盘 Esc 仍可返回）；
3. 设置项的选择对话框（SelectDialog）**弹不出来**（运行日志显示打开逻辑确实执行了 6 次）。

### 6.2 根因（实证）

- release 下"灰块 + 不可点"是 **ErrorWidget** 的表现：该子树构建期抛异常；
- 探针复现（新壳下）拿到确切断言：
  `No MaterialLocalizations found. TextField widgets require MaterialLocalizations ...`
- **根因链**：material_ui 的 `MaterialApp` 默认委托是 **material_ui 自己的**
  `DefaultMaterialLocalizations.delegate` + cupertino_ui 的 `DefaultCupertinoLocalizations.delegate`
  （见 material_ui `app.dart:964-969`）；而 B1 首次实现误用了 **flutter_localizations 的 Global\***
  ——它们实现的是 **SDK 类型**的 `MaterialLocalizations`，与 material_ui 的类型**不可互换**，
  因此应用侧 Material 控件（`TextField`/`IconButton`/`showDialog`+`Dialog`）取不到本地化而抛异常；
- 测试漏网原因：B1 的等价面用例断言了 `legacy.MaterialLocalizations`（SDK 类型）——恰好被
  Global\* 满足，掩盖了 material_ui 侧的缺失（断言口径错误）。

### 6.3 处置

- `app_shell.dart`：本地化委托改为与 material_ui `MaterialApp` **逐项一致**
  （`DefaultMaterialLocalizations.delegate` + `DefaultCupertinoLocalizations.delegate`；
  widgets 层由 WidgetsApp 自带）；`flutter_localizations` 依赖保留——它仍是 **MiuixCompat**
  为 flutter_miuix 内部 SDK TextField 提供 SDK `MaterialLocalizations` 的来源（作用域不同）；
- 修正等价面用例断言口径为 **material_ui 的** `MaterialLocalizations`；
- 新增回归门槛 `test/core/shell/app_shell_material_parity_test.dart`（3 例）：
  新壳下 material `TextField`（首页搜索框形态）、`AppBackButton`、`showDialog + Dialog`
  （SelectDialog 形态）**必须无异常构建**——本组用例在修复前精确失败（探针实证）。
