## 1. 分析根因

### 1.1 现象（按时间顺序）

| 阶段 | 现象 |
|---|---|
| 双轨（原实现） | 快退后画面极速追赶回 seek 前位置；快进先出声音、画面数秒后才出现；缓冲时声音慢放 |
| 单源 HLS（本轮） | 快进稳定、时钟与画面同轨；**快退约一半概率失败**：画面自动回退到 seek 前位置并加速追赶 |

### 1.2 取证证据（探针 `SEEK#… END` 结论行）

双轨（2026-09-20 复测，`aTracks=0`）：
```
SEEK#3 target=25000 backward=1 posAfter=25000 posMin=25000 posMax=60700   ← 时钟回跳 seek 前位置
（runtime.log）01:06:26.307 clock settled → skip remount；01:06:26.440 pos=480499
```

单源 HLS（2026-09-24，`aTracks=1 dur=540000`）成功与失败并存：

| 请求 | flags | 落点证据 | 判定 |
|---|---|---|---|
| `target=60000 backward=1` | 258 | `posMin=60000 posMax=61032 steadyRate=1.00` | ✅ 正常 |
| `target=75000 backward=1` | 258 | `posMin=75000 steadyRate=1.00` | ✅ 正常 |
| `target=20000 backward=1` | 258 | `posAfter=20000 posMin=69583 posMax=93784 aheadMax=70831` | ❌ demuxer 停在旧位 |
| `target=30000 backward=1` | 258 | `posAfter=94679 posMin=79983 behindMax=18729` | ❌ |
| `target=25000 backward=1` | 2 | `posMin=60262 posMax=65040 aheadMax=37802` | ❌ |
| `target=30000 backward=1` | 2 | `posAfter=70884 posMin=70927` | ❌ |

即：**失败与 flags 无关（Accurate 与 keyFrame 都出现过），是清单粒度问题**。

### 1.3 根因链

1. **mdk 的「主视频 + 外挂音轨」是两条独立播放图/两个时钟**：seek 时外挂音轨不跟随，音频主时钟留在旧位置，视频向旧时钟高速追赶。上游 fvp issue #355 明确「分离外挂音轨 ≠ 内嵌音轨」，作者结论是「合并成单一源（master/manifest）才正常」。→ 解释了历史上 9 次在 seek 参数/重挂时序上打补丁均无法收敛。
2. **单一源后第一层问题消失**：`MEDIA vTracks=1 aTracks=1`（同一 AVFormatContext 内双轨），快进/快退的时钟与画面同轨，`steadyRate≈1.00`。
3. **单一源的第二层问题（本轮遗留主因）**：为保持清晰度，我们采用「整条 m4s = HLS 的 1 个分段」的清单形态；HLS 设计上每个分段应为独立可寻址单元，而整段形态下 seek 只能靠内部 demuxer 做字节级定位 → **间歇失效**，表现即「自动回退到原位 + 画面加速追赶」。
4. **一次由排查引入的回归**：曾试「解冻前轮询 `buffered()`/`mediaStatus` 做视频就绪门控」，该轮询落在 seek 后瞬态窗口（与历史上「瞬态读取 position 死锁」同类），实测使快退退回旧故障（`aheadMax≈34s`）→ 已回滚，并在代码中留注释。

### 1.4 路径排除（都有实测依据）

- **MPD（dash demuxer）不可用**：mdk 自带 `ffmpeg-9.dll` 未编译 dash 解复用器——DLL 内查无 `Dynamic Adaptive Streaming over HTTP` 与任何 libxml2 符号（dash 需要 libxml2）；应用实测 `setMedia(stream_*.mpd)` → `fvp: reader open error` + `prepare ret=-1` → 渲染面创建失败。生成的 MPD 本身合法（无 BOM、48 个 `&amp;` 转义、PowerShell XML 解析通过、2 个 AdaptationSet）。
- **本地路径直开不可用**：Windows 绝对路径在 hls/dash 解复用器的协议白名单下被误判（实测 "No such file or directory"）→ 改为 127.0.0.1 HTTP 暴露清单，与线上 http 分片路径一致。

## 2. 设计修复计划

### 2.1 已落地：合成 HLS 主清单（单一源）

`lib/core/player/hls_manifest.dart`：

```
master:  #EXTM3U / #EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="aud",URI="…aud.m3u8"
         #EXT-X-STREAM-INF:BANDWIDTH=…,CODECS="…",AUDIO="aud" / …vid.m3u8
variant: #EXT-X-TARGETDURATION:<ceil(dur)> / #EXT-X-PLAYLIST-TYPE:VOD
         #EXTINF:<dur>, / <CDN URL> / #EXT-X-ENDLIST
```
三份清单写入应用日志目录，经 `http://127.0.0.1:<随机端口>` 暴露给 mdk；`manifestMode`（`Documents/logs/seek_probe.json`）控制开关，默认关闭。

### 2.2 关键决策与取舍

| 决策 | 取舍 |
|---|---|
| 选 HLS 而非 MPD | mdk 的 ffmpeg 无 dash 解复用器（硬约束）；HLS 解复用器存在且不需 libxml |
| 经本地 HTTP 暴露清单 | 规避 Windows 绝对路径的协议白名单误判；与线上 http 分片路径一致 |
| 单源快退改用 keyFrame | 先规避「Accurate 段内定位间歇失效」；代价是落点对齐关键帧（可能早几秒） |
| 不采用 durl（方案 2） | 清晰度上限受限，仅作保底通道 |
| 不采用双播放器（方案 3） | 需 patch fvp 暴露 `onSync`，抖动/复杂度最高 |
| 保留双轨代码路径 | `manifestMode` 关闭时行为与改动前一致，便于对照与回退 |

### 2.3 本轮实现（2026-09-24 第二笔：方案 A 主线 + 方案 B 兜底）

按「A 主线 + B 兜底」落地，全部在 `manifestMode` 开关内，默认关闭：

| 顺序 | 形态 | 实现 | 说明 |
|---|---|---|---|
| A 主线 | HLS **sidx 分段**清单 | `HlsManifest.publishSegmented()`：Range 读每条 m4s 头部（≤4MB）解析 `moov`/`sidx`，生成 `#EXT-X-MAP`（init 段 `"<moovEnd>@0"`）+ 逐段 `#EXT-X-BYTERANGE`（字节偏移/长度来自 sidx 引用）+ 精确 `#EXTINF` | seek 走 HLS 原生「选段 + 段内定位」；sidx 总时长与 API 时长差超 20% 视为索引异常 |
| 兜底 1 | HLS 整段清单 | 上一笔的实现（整条 m4s 当 1 段） | 已知 seek 约一半失败，仅作降级 |
| 兜底 2（B） | durl 合并流 | playurl 请求 `fnval` 由 `4048` 改为 `4049`（加 bit0），取 `durl[0]` 作为单一 URL | 音视频合并流，走已验证可用的主媒体 seek 路径；清晰度上限较低 |
| 最终兜底 | 双轨 | 原实现 | 三者都不可用时保持改动前行为 |

控制器同时记录 `MANIFEST mode=hls-segmented|hls-single|durl|dual-track` 便于判定实际生效形态。

### 2.4 后续可选优化（未做）
- 单源快退的落点对齐关键帧（keyFrame 定位的固有代价）；如需精确落点可在视频缓冲就绪后做二次精确定位（必须在事件驱动下进行，禁止在瞬态轮询）。
- seek 落地后约 2.9s 的「画面一帧帧补」窗口：由 demuxer 首次 Range 拉取关键帧导致，可考虑预取（在冻结窗口内主动 range 预读目标附近数据）。

## 4. 本轮修复总结

- **改动面**：新增 `lib/core/player/hls_manifest.dart`；控制器增加单源分支与单源 flags；`dash_manifest.dart` 因 dash 解复用器缺失而删除；探针判定改为轨迹相对（`aheadMax/behindMax/noProgress`）、视频解码渲染事件常开记录。
- **行为预期**：`manifestMode` 关闭时与改动前完全一致；开启时走单源 HLS（快进稳定、快退待修）。
- **回滚**：解冻门控已移除（原因见 1.3.4）；如需整体回退到本轮之前，使用第 5 节快照 SHA。
- **遗留项**：① HLS 单段 seek 不可靠（主因，按 2.3 处理）；② seek 落地后约 2.9s 的「画面一帧帧补」窗口（`noProgress=1`，待 sidx 分段后复测）；③ 探针与验证开关待修复定型后移除。
