# 左右滑动切换 TAB 复盘（2026-11-07）

## 一、现象

1. 播放页右侧「评论 / 相关推荐」用鼠标左右拖动**完全无法切换**（触摸屏、触控笔仍可滑）。
2. 其余使用 PageView 主体的 TAB 页（番剧播放页、空间页、搜索结果、动态页、弹幕屏蔽设置）同样只能点选，不能拖动翻页。
3. 首页分类、历史分类、直播分区、番剧首页分类、消息中心筛选这五类分类页只有点击切换，内容区不能左右滑动切换分类。

## 二、定因

- `AppTabBody` 在 `1065265`（响应式 TAB 两形态）中被加上宽屏限制：整窗宽度 ≥ `kAppTabBreakpoint`（700）时给 `PageView` 传入 `_AppTabPageScrollBehavior`，其 `dragDevices` 只保留 `touch / stylus`，鼠标拖动因此不再参与手势竞技。
- 播放页右栏（评论/相关推荐）**只在宽屏布局出现**，整窗宽度必然 ≥ 700，所以该 PageView 始终处于「鼠标禁止拖」的状态。
- 后续 `05f0ba7` 把行为从 `ScrollConfiguration` 改为 `PageView.scrollBehavior`，只修复了「子页下拉刷新被连带禁用」的继承问题，宽屏剔除鼠标的限制仍然保留。
- 分类型页面使用 `AppTabStrip` + `IndexedStack`（或按分类重新请求的列表），本来就不存在 PageView，因此没有滑动能力。

## 三、方案

1. **恢复 PageView 鼠标拖动**：删除 `_AppTabPageScrollBehavior` 与宽屏分支，`AppTabBody` 直接使用全局滚动行为（鼠标/触摸/触控板/触控笔全部可拖）。继续禁止用 `ScrollConfiguration` 包裹 PageView（`dragDevices` 为继承属性，会连带禁用子页内滚动视图）。
2. **新增 `AppTabSwipeArea`**（`lib/ui/components/app_tab_view.dart`）：在分类页内容区外层监听水平拖动，累计位移 ≥ 70px 或松手速度 ≥ 320px/s 时切到相邻分类；`count ≤ 1` 时不注册手势。手势只挂在本层，不改子树 `ScrollBehavior`，内容区内部横滑视图会先赢得手势竞技。
3. **接线五类分类页**，把「点击分类」与「滑动切换」收敛到同一入口：
   - 首页：新增 `_selectCategory`（原分类条回调改为复用它），内容区包 `AppTabSwipeArea`；
   - 历史：抽出 `_tabEntries` getter（分类条与滑动共用），`_buildTabBar` 改为接收 entries；内容区包 `AppTabSwipeArea`；
   - 直播：新增 `_selectTab`；
   - 番剧首页：新增 `_selectSubTab`；
   - 消息中心：公开 `kSessionFilterCategories`（原 `_categories`），宿主按 `type ↔ index` 换算后包 `AppTabSwipeArea`。
4. 不新增依赖、不改全局 `AppScrollBehavior`，改动集中在 Tab 体系与上述页面。

## 六、遗留与踩坑

1. 分类页采用「滑过阈值即切换」，**无跟手位移动画**（本轮确认范围）。若要跟手，需要把各分类页 `IndexedStack`/单列表迁移为 PageView，并处理懒加载与滚动状态保留。
2. 恢复 `AppTabBody` 鼠标拖动后，若某 Tab 子页内存在可选文本，鼠标拖选会先被文本选择识别器接管，与 PageView 翻页存在竞争；本轮未观察到评论/推荐正文受影响，后续实机如出现再按「文本优先」处理。
3. 独立私信列表页 `SessionListPage` 仍使用 `AppChoiceChip` 分类（非 TAB 栏），未纳入本轮范围。
4. 分类页手势包在内容区外层，内部横滑卡片列表仍按内层优先；若后续新增横向可滚动控件，无需额外改手势层。

## 七、总结

播放页右栏与所有 PageView 型 TAB 页恢复鼠标左右拖动切换；首页、历史、直播、番剧首页、消息中心的分类栏补齐「滑过阈值切换相邻分类」手势。静态分析、单测与 Windows debug/release 双编译全部通过。
