## 二、问题根因

### R1 —— 头图被顶栏"下推 56px"（上一轮 2-A 的回归）

`lib/pages/member/member_space_page.dart` 上一轮的 sliver 顺序是：

```
SliverAppBar(pinned, toolbarHeight: 56, 背景透明)   ← 占据 y ∈ [0, 56)，背后是页面底色
SliverToBoxAdapter(SizedBox(330, 头图))            ← 头图从 y = 56 才开始
SliverToBoxAdapter(详情卡)
SliverPersistentHeader(标签条, pinned)
body: AppTabBody
```

「顶栏与封面解耦」把封面做成了**独立 sliver**，于是**头图整体被下推 56px**；
顶栏那 56px 背后露出 `AppScaffold` 的页面底色（白），而 `SliverAppBar.backgroundColor`
又被设为透明 → 视觉上等价于「头图顶部被裁掉 56px」。

对照 `b7-c4` 之前的原始结构 `SliverAppBar(expandedHeight: 330, flexibleSpace:
FlexibleSpaceBar(background: 头图))`：头图天然铺满 `[0, 330)`、**从屏幕最顶端开始**，
顶栏按钮透明地浮在其上——所以当时不会白。

### R2 —— `_tabBandMerged` 用**绝对全局坐标**判定（恒 false）

上一轮判定（`member_space_page.dart:355`）：

```dart
bool get _tabBandMerged {
  final box = _tabBandKey.currentContext?.findRenderObject() as RenderBox?;
  if (box == null || !box.attached || !box.hasSize) return false;
  return box.localToGlobal(Offset.zero).dy <= _topBarHeight + 0.5;   // ← 绝对值 ≤ 56.5
}
```

`localToGlobal` 返回的是**相对整窗**的坐标，其中含窗口层 / `MaterialApp` 层 /
页面内边距等**公共偏移**。标签条即使真实吸顶，其全局 dy 仍 `> 56.5` → 判定**恒 false**
→ 顶栏毛玻璃带永不出现。与用户观察（吸附动作发生、但顶栏始终纯透明）逐字一致。

## 三、修复方法（1-A + 2-A）

`lib/pages/member/member_space_page.dart` 单文件，+170/−106：

1. **1-A（头图铺到顶 + 顶栏与封面解耦）**：
   - 封面回到 **`SliverAppBar.flexibleSpace`**：`SliverAppBar(pinned: true,
     expandedHeight: _coverHeight(330), toolbarHeight: _topBarHeight(56), elevation: 0,
     scrolledUnderElevation: 0, backgroundColor/surfaceTintColor: 透明,
     automaticallyImplyLeading: false, flexibleSpace: FlexibleSpaceBar(background: 头图))`
     —— 头图重新铺满 `[0, 330)`，从屏幕**最顶端**开始，不再被下推 56px。
   - 上一轮的**独立封面 sliver**（`SliverToBoxAdapter(SizedBox(330, 头图))`）**删除**。
   - 返回/分享/更多按钮 + 「按需毛玻璃带」抽到**页面级覆盖层** `_buildTopBarOverlay()`
     （`Positioned(top:0,left:0,right:0,height:56)`），在 `build()` 里以
     `Stack(fit: StackFit.expand, children: [滚动视图, 覆盖层])` 叠加 →
     **顶栏与封面在 widget 树上彻底解耦**，头图铺顶不再受影响。
   - 覆盖层层内顺序：**毛玻璃带在下、按钮在上**（对齐 `flutter` 的 `AppBar` 内部次序
     `flexibleSpace` 在下、工具栏内容在上，见 `app_bar.dart:1196-1214`），避免半透明带盖住按钮。
2. **2-A（合并判定改同坐标系相对比较）**：
   - 新增 `final GlobalKey _topBarKey`，挂在覆盖层的 56px 容器上。
   - `_tabBandMerged` 改为**两个 RenderBox 的相对位置**：

```dart
final barBottom = bar.localToGlobal(Offset(0, bar.size.height)).dy;  // 顶栏下沿
final tabTop    = tab.localToGlobal(Offset.zero).dy;                 // 标签条顶沿
return tabTop <= barBottom + 0.5;
```

   - 二者处于**同一全局坐标系**，公共偏移（窗口 / `MaterialApp` / 页面内边距）**相减抵消**
     → 与窗口尺寸、自绘标题栏高度无关，吸附时判定必为真。
3. 更新 `build()` 注释（顶栏为页面级覆盖层）；`SliverAppBar` 处的层位注释同步改写。

## 五、遗留与踩坑

- **踩坑（延续）**：双编译前必须确认无本产物 `winwin.exe` 在跑（本轮再次命中：
  上一轮启动的 PID 26100 会锁 `WebView2Loader.dll`）；按 PID 精确结束本产物进程即可。
- **踩坑（本轮核心）**：`localToGlobal` 的返回值含**整窗公共偏移**，**不能**直接与页面内
  的固定像素值（如 `56`）比较；跨层判定必须取**两个 RenderBox 同坐标系相对比较**。
- **设计取舍（待实机确认）**：1-A 让顶栏成为**页面级覆盖层**（真解耦），代价是覆盖层脱离
  `SliverAppBar`，滚动时不参与折叠动画；覆盖层常态只有按钮（命中区不拦截空白处点击），
  合并时才出现毛玻璃带。备选（未采用）是把封面 sliver 加 `Transform.translate(0,-56)`
  上移——有被 `RenderSliverSingleBoxAdapter` 裁剪 / 露 56px 空白的风险。
- **判定基于上一帧布局**：`_tabBandMerged` 读的是当前帧已布局的 RenderBox，
  视觉上可能 1 帧滞后，不可感知。
- 命名冲突（仍未决）：`b7-c4` 同时用于"输入条统一共享批 / Tab 体系批 / 反馈轮 1·2·3·4·5"，
  建议封板前统一改号。
- 本轮未动其余 4 个 Tab 页；闸门维持 65。
