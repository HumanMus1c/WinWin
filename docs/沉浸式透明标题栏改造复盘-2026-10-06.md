# 沉浸式透明标题栏改造复盘（标题栏背景纯透明 · 完全沉浸）

- 日期：2026-10-06
- 类型：界面改造（桌面窗口标题栏）
- 需求：使标题栏背景**纯透明**，视觉上**完全沉浸**（应用内容接管窗口顶部、系统标题栏消失）

---

## 一、现象与取证（为什么直接改原生标题栏做不到）

1. 现状：应用默认显示 **系统原生标题栏**（`TitleBarStyle.normal`），由 DWM 绘制。
   `lib/core/window/title_bar_controller.dart` 仅切换 `DWMWA_USE_IMMERSIVE_DARK_MODE`（深浅色同步）。
2. 历史取证（commit `2756ea0`）：曾把 `DWMWA_CAPTION_COLOR` 设置为应用背景同色以"消除色差"，
   结果出现 **DWM 最大化白色硬直角边框 + 缩放僵硬**，被完整回退（提交信息
   "align window maximize transition with piliplus, eliminate white border and stiff resize"）。
3. 根因结论：
   - **DWM 原生标题栏不支持透明通道**（`DWMWA_CAPTION_COLOR` 无 alpha；不存在任何官方属性可让
     标题栏显示应用自身内容）；
   - 因此"纯透明 + 完全沉浸"只有一条技术路径：
     **去掉系统标题栏（客户区扩展到窗口顶部）+ 应用自绘一条透明标题条（内嵌窗口按钮）**。

## 二、方案设计（关键决策与取舍）

### 2.1 总体方案（零原生代码改动，复用成熟实现）

| 层 | 做法 |
| --- | --- |
| 窗口样式 | `TitleBarStyle.hidden`（window_manager 0.5.2 已实现：NCCALCSIZE 移除标题栏、保留左/右/下 8px 原生 resize 边框、最大化防裁切补偿、Win10 顶部 1px 修正） |
| 沉浸标题条 | 新增 `ImmersiveTitleBarShell`（`lib/ui/components/immersive_title_bar.dart`），高 `kWindowCaptionHeight`=32 逻辑像素（Win11 标准），背景纯透明（露出应用主题背景） |
| 窗口三键 | 复用 `WindowCaptionButton`（Win11 原生风格 46×32，悬停/按下/关闭红底 #C42B1C，最大化/还原图标联动） |
| 拖动/双击 | 复用 `DragToMoveArea`（`startDragging` → 原生 caption 移动循环，贴边吸附、拖至顶部最大化等原生行为保留） |
| 右键菜单 | 标题条右键 → `windowManager.popUpWindowMenu()`（对齐原生标题栏行为） |
| 顶边拉伸 | 复用 `DragToResizeArea`（top/topLeft/topRight，`startResizing`；最大化/全屏时禁用） |
| 挂载位置 | `MaterialApp.builder` 链上（壳层包住 Navigator）→ 所有路由与弹窗上三键恒可用 |
| 全屏联动 | 对标 PiliPlus：进入显示器原生全屏时隐藏标题条 **并临时 `setTitleBarStyle(normal)`**，规避隐藏分支给客户区加 8px 内缩导致全屏四周出现边缘带的回归；退出恢复 |
| 逃生舱 | 设置-外观新增「使用系统原生标题栏」（`useNativeTitleBar`，默认关=沉浸式，需重启；壳层启动时锁定，与窗口样式决策一致） |
| 视频页适配 | 全屏/网页全屏时标题条背景跟随转纯黑（`titleBarBackdrop` + 所有权令牌，避免旧页面误清新页面） |

### 2.2 明确取舍

- ✅ 标题栏背景纯透明、完全沉浸；此前修复（最大化白边/缩放僵硬/动效）零触碰（不再设置任何 DWM 标题栏颜色属性）。
- ❌ 失去：最大化按钮**悬停时的 Snap Layouts 浮出菜单**——系统限制（客户区扩展后不再触发；
  VS Code / Discord / Chrome 等自绘标题栏应用同样没有）。Win+Z、拖拽贴边、Win+方向键**全部保留**。
- 窗口按钮由应用自绘（观感与尺寸仍为 Win11 原生标准）。

### 2.3 过程发现（两处值得记录）

1. **PrintWindow 抓图盲区**：排查期间用 `PrintWindow(PW_RENDERFULLCONTENT)` 抓取实机窗口，
   顶部扩展客户区内的自绘三键**不可见**（其余内容正常），一度误判为"按钮未绘制"；
   经用户实机确认三键正常显示。结论：该区域的自绘内容不能用 PrintWindow 取信，
   实机验收以用户截图为准。
2. **设置项语义修正**：壳层最初每帧读取设置项，运行中切换会即时隐藏标题条但窗口样式仍待重启
   （语义不一致）；改为**启动时锁定**（`late final _immersive`），与 `TitleBarStyle` 的启动决策对齐。

## 七、反馈第二轮（2026-10-06 复查修复）

### 7.1 反馈与处置

| # | 反馈 | 根因 / 处置 |
| --- | --- | --- |
| 1 | 标题条"WinWin"名称出现**黄色双下划线**（曾出现过的老问题） | 根因：壳层位于 `Material` 之外，`Text` 取到 **WidgetsApp 的默认错误文本样式**（黄绿双下划线）。处置：与项目既有同款处理一致（`app_messenger.dart` / `miuix_context_menu.dart`），以 `DefaultTextStyle(decoration: TextDecoration.none)` 覆写文本基底。 |
| 2 | 三键反色**不及时**：进出视频页全屏/网页全屏时，需鼠标掠过才瞬间变色 | 根因：`window_manager` 的 `WindowCaptionButton` 字形画笔 `shouldRepaint` 恒返回 `false`，底色翻转后不触发重绘，旧颜色残留直到有其它原因重绘（悬停）。处置：按钮行加 `ValueKey(brightness)` 强制随亮度重建重绘。 |
| 3 | 全屏/网页全屏浮层返回按钮**语义与 Esc 不一致**（点击直接退回首页、退出播放页） | 处置：改为与 Esc 完全一致——二级浮层优先关闭；否则按页面语义级联（优先退显示器全屏 → 退网页全屏 → 返回上一级）；按钮 tooltip 明确为「退出全屏（Esc）/退出网页全屏（Esc）」；同时移除已无用的 `onBack` 参数与页面回调（避免两套语义并存）。 |
