# 弹幕开关图标替换 + 控制栏「发弹幕」控件移除 复盘（2026-10-23）

## 一、需求 / 现象
1. 播放器控制栏**「弹幕开关」胶囊的图标**观感不对——需要一个真正的「弹幕」图标并替换。
2. **移除控制栏里的「发弹幕」控件**，但**保留其后端能力**。

## 二、定因（现状分析）
- `AppIcons.danmaku({active})` 返回 `CupertinoIcons.chat_bubble / chat_bubble_fill`（码点 `0xf3fb / 0xf8be`）。
- 这两个码点**同时命中官方矢量层** `kOfficialIconPaths`（`0xf3fb`、`0xf8be` 均在表内），而图层优先级为
  `BDC → Web → BiliSite → 官方 → 手绘美术 → 三集映射 → 内置等价`，故**官方层抢先**，实际渲染的是
  **Material Symbols 的通用「对话/消息」气泡**（本仓原本为弹幕开关手绘的美术被遮蔽）。
- 实测 `0xf3fb` 与 `0xf8be` 两条 path 前缀完全相同 → **开/关几何同形**，仅靠颜色区分。
- 结论：弹幕开关用的是“泛化消息气泡”，不表达“弹幕”，即用户要替换的对象。

## 三、方案（选定「甲·官方保真」）
- 在 `lib/theme/app_icons.dart` 新增**弹幕语义专用覆盖** `_danmakuGlyphArt()`，置于 `miuixVectorForGlyph`
  解析链**最前**：对 `chat_bubble` / `chat_bubble_fill` 两个载体字形直接返回
  **B 站官网「弹幕」气泡美术**（web 层 `kWebIconPaths[0xf3fd]`，与元数据行「弹幕数」同源，
  造型为“气泡内两行「点+横线」”）。
- 开/关两态**沿用控件既有的颜色区分**（`biliBlue` / 白 85%）与「开/关」文案，与替换前一致（替换前 Material
  对亦为同几何、仅颜色区分）。
- 移除控制栏「发弹幕」按钮：
  - `lib/pages/video/player_panel.dart`：删掉 `AppIcons.sendDanmaku()`「发弹幕」按钮块，并移除随之
    变为未使用的 `send_danmaku_panel.dart` import。
  - `lib/common/widgets/demo_player_chrome.dart`：同步删掉 `_barIcon(AppIcons.sendDanmaku())`，
    保持演示态与正常态 **1:1**。
- **后端能力保留**：`lib/pages/video/send_danmaku_panel.dart`（`showSendDanmakuPanel` /
  `SendDanmakuPanel.inline`）**原样不动**；视频页底部内联发弹幕条（`detail_page.dart:1236`）、
  番剧页（`bangumi_player_page.dart:1109/1190`）照常可用。`AppIcons.sendDanmaku()` 方法亦保留备后用。

## 五、遗留与踩坑
- 弹幕开关**开/关仍为同几何、以颜色区分**（与替换前一致）；若要求“未选描边 / 选中实心”的**几何双态**，
  需再补一版描边美术（本仓既有 `_bubbleOutline/_bubbleFilled` 为“气泡+三点”造型，可改造）。
- 弹幕开关图标与元数据行「弹幕数」**同源同形**（均 B 站官方弹幕气泡），属预期（同为“弹幕”）。
- `showSendDanmakuPanel` 移除按钮后**暂无调用点**（`D` 键是弹幕开关、非发弹幕），即“保留但暂不可达”的后端能力。
- 构建坑：上一轮启动的 Release `winwin.exe`（PID 24136）占用 `WebView2Loader.dll` 导致首次 release 编译
  失败（MSB3027/MSB3021）；按 PID 结束该单个实例后重跑成功（不按进程名杀）。

## 六、总结
弹幕开关此前渲染的是 Material 通用「消息气泡」而非“弹幕”图标，根因是官方层对 `chat_bubble` 载体的抢先解析。
本轮按“官方保真”口径，为弹幕语义新增最高优先级的专用覆盖，改用 **B 站官网弹幕气泡**造型；同时移除控制栏
「发弹幕」按钮（演示态同屏删除以保持 1:1），**后端发弹幕能力与各内联入口完整保留**。
