# 历史续播「闪开头」修复复盘（2026-09-29）

**范围**：用户复测报告——从播放历史时间点恢复时，先闪一下视频开头（0 位）的画面和声音几帧，再缓冲到历史点。

## 一、分析根因（现象 + 取证 + 根因链）

- **现象与取证**（15:22–15:25 五次续播实测，`trace.log`）：`setMedia → prepare/ready(~0.2s) → 立即 0 位起播 → playInfo 并行返回 → resumeTo 才发起定位 seek`——**五次间隔稳定为 700–750ms**；
- 该窗口内：视频 0 位首帧一解码、封面即撤下（`player_panel.dart:737` 仅按"有无首帧"判据）；音频实例在 0 位短暂起播 ⇒ 构成"闪一下开头画面和声音几帧，再缓冲到历史点"。
- **历史**：`docs/视频历史续播点前跳修复复盘-2026-09-27.md` 的遗留项已记录该瞬态（"维持现状（属另一议题）"）；本次关闭。

## 二、设计修复计划与实现

1. **启动闸门**（`player_controller.dart`）：`load(gateForResume: true)` 时挂闸——prepare 后**不起播**（用户意图仍为播放）；UI 观察口 `startupGate` + 3s 兜底定时器；
2. **放闸条件**：`resumeTo` 定位完成（`seek-done`）/ playInfo 无续播点（`no-history`）/ 已近播完（`near-end`）/ 查询失败（`info-error`）/ 异常（`info-exception`）/ 放弃恢复（`resume-abort`）/ 超时（`timeout`）/ 用户交互（播放/暂停/拖进度/中央按钮，`user-*`）；
3. **闸门期间防护**：面板封面（cover 为空时黑屏）**遮盖置顶**；音频实例音量置 0（`releaseStartupGate` 恢复）；音频起播对齐与轻量归位**均不抢先恢复**（两处恢复条件加闸门）；缓冲恢复推回让位（resume-push 加闸门）；
4. **页面接入**：`detail_page.dart`（初次 load 挂闸 + `_applyPlayInfo` 各分支放闸）；`bangumi_player_page.dart`（仅 `startPos == null` 时挂闸 + 同分支放闸；已知起点直载无需）。
5. 取证标记：trace 出现 `STARTUP-GATE arm` 与 `STARTUP-GATE release reason=…`。
