## 一、现象

- 「硬件解码模式」（自动/D3D11/DXVA2/软解）切换后播放行为无差异；
- 「视频同步模式」切换后播放行为无差异。
（原调查列此项为"无法得知"——即无从验证其是否生效。）

## 二、定因

- `hardwareDecoding`：`Pref` getter 存在但**零调用方**（B 类断裂）。内核 `player_controller._createPlayer` 只用 `Pref.enableHA` 总开关在"硬解全列表 / 纯软解"间二选一，**完全不读 `hardwareDecoding`**。
- `videoSync`：同样零调用方（B 类）。

## 三、方案（先取证，再接线）

**取证（mdk 官方 wiki，只读依赖源码/文档）**
- `fvp-0.38.1/lib/src/video_player_mdk.dart`：Windows 硬解优先列表 = `['MFT:d3d=11','D3D11','DXVA','CUDA','hap','FFmpeg','dav1d']`（项目 `enableHA` 分支即此）。
- `mdk-sdk wiki/Decoders`、`wiki/Player-APIs`：decoder 名可带 `key=val` 参数；FFmpeg 类后端经 `hwaccel`/`hwcontext`（`d3d11va`/`dxva2`/…）选择。**无 mpv 式 `--video-sync`（audio/display-resample/display-desync/display-vdrop）语义**，仅 `avsync.*` 属性。

**接线（硬件解码模式）**
- `player_controller.dart`：`_createPlayer` 改由 `Pref.enableHA ? _videoDecodersForMode(Pref.hardwareDecoding) : ['FFmpeg','dav1d']` 决定 `videoDecoders`；新增静态 `_videoDecodersForMode`：
  - `auto` → 硬解优先全列表（逐级回退软解）；
  - `d3d11va` → `['D3D11','FFmpeg','dav1d']`；
  - `dxva2` → `['DXVA','FFmpeg','dav1d']`；
  - `no` → `['FFmpeg','dav1d']`。

**隐藏（视频同步模式，按 CVO 决策）**
- `video_settings.dart`：移除「视频同步模式」`NormalModel`（mdk 无对应语义，接线=假开关），**存储键与 `Pref.videoSync` 保留**（不删数据）。
- 同步移除「硬件解码模式」中 mdk 无对应的 `auto-copy` 档（避免假档位）。

## 六、遗留与踩坑

1. **语义鸿沟**：PiliPlus 的硬件解码/同步选项源自其 **mpv 后端**，与 WinWin 的 **mdk 内核**并不一一对应。"照搬选项名接线"会引入假开关——故本批对 `VideoSync` 取**隐藏**而非硬接。
2. `mapping` 依据 mdk wiki 的**后端名**（非 mpv 属性名）；`auto` 档的 `hap` / `MFT:d3d=11` 为 Windows 专有，跨平台（未来）需按 os 分支。
3. 硬解后端均保留 `FFmpeg/dav1d` 尾部回退，避免个别显卡/驱动不支持时黑屏。
4. `videoDecoders` 仅主实例设置（第二实例为纯音频，无需视频解码器）。
5. 待办：`auto-copy` 若后续确认 mdk 的 copy 模式语法（wiki 提及 "copy mode"），可恢复该档。
