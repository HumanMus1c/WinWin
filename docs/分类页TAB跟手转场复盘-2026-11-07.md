# 分类页 TAB 跟手转场复盘（2026-11-07）

## 一、现象

上一轮接入后，首页、历史、直播、番剧首页、消息中心的分类条已经可以左右滑动切换，但内容是**滑过阈值后直接换页**（类似点击的硬切），没有评论区/相关推荐、动态页、用户空间那种跟手平移转场。

## 二、定因

上一轮的 `AppTabSwipeArea` 是“外层监听水平拖动 + 松手 setState 换分类”的手势层。这些分类页的内容区是**单个** `IndexedStack`（首页/直播/番剧）或**单个按分类重载的列表**（历史/消息），一次只能渲染一页；即使拖动时位移当前页，也没有相邻页可同时呈现，因此无法做出真正的跟手双页转场。

## 三、方案

1. 新增 [AppTabPager](file:///d:/Documents/GitHub/WinWin/lib/ui/components/app_tab_view.dart)（`PageView.builder` + 页面保活）：
   - 手势翻页由 `PageView` 原生承担，与 `AppTabBody`（评论/推荐、动态、空间）完全同款跟手转场；
   - 每页用 `AutomaticKeepAliveClientMixin` 包装，滑出后 State 不销毁，滚动位置与数据保留；
   - `pageKey` 按业务键（首页分类枚举、直播分区 id、番剧枚举、历史 type、消息 session_type）绑定页面，避免分类顺序热更新时状态错位；
   - 点击切换相邻页走 250ms 动画，跨多页直接 `jumpToPage`（不经过中间页，避免连带构建与请求）。
2. 五个分类页迁移：
   - 首页：`IndexedStack` + `_visitedTabs` → `AppTabPager`，按需构建各分类页；
   - 直播：`IndexedStack` + `_visitedIndices` → `AppTabPager`，页面键用分区 id；
   - 番剧首页：`IndexedStack` + `_visitedTabs` → `AppTabPager`，页面键用 `PgcSubTab`；
   - 历史：删除单例 `ScrollController`，按分类拆分独立控制器与 `_HistoryTabState`；`_load/_onScroll/_checkAutoLoad` 全部 type 化；某分类页首次滑入时才发起首屏请求（`started` 标记），每页独立保活；
   - 消息中心：单 `SessionListSection` + 单 `GlobalKey` → 每分类一个 `SessionListSection` 实例与 `GlobalKey`，页面键用 `session_type`；下拉刷新改为重载当前分类列表。
3. 删除 `AppTabSwipeArea`（本轮起不再使用），避免双套手势语义。

## 六、遗留与踩坑

1. 首页外层 `PageView` 内嵌直播/番剧二级分区 `PageView`：内层先赢得手势，二级分区滑到边界时不会把外层首页翻页带走（嵌套 PageView 的通行行为）。如需边界穿透，需额外做手势转发。
2. 跨多页点击分类直接跳转（无平移动画），换取不构建/不请求中间分类。
3. 分类页首次滑入即发起该分类请求（与“切到才加载”一致），滑回时使用保活缓存不再重复请求。
4. 消息中心每分类独立实例，最多 8 个列表实例并存；仅访问过的分类会创建，账号切换时已创建实例各自重载。
5. 历史页分类顺序由服务端下发，顺序变化时按 `type` 键重新绑定页面，极少数情况下会重建该页状态。

首页、历史、直播、番剧首页、消息中心的分类切换已统一为 `PageView` 跟手平移转场，与评论区/相关推荐、动态页、用户空间一致；静态分析、290 项单测、Windows debug/release 双编译全部通过。
