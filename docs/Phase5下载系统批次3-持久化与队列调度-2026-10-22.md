## 二、定因（拆批依据）

批次1/2 只落了「纯模型 + 纯策略 + 纯引擎」，三者均无状态持有者：谁把任务存下来、谁在并发上限内排队、谁在重启后复位——均缺失。若直接做 UI，UI 无处读写任务，会倒逼 UI 临时承担持久化与调度职责，违反「单一职责 / 概念只在一处定义」。

因此批次3 先补齐**无 UI 的逻辑底座**：持久化仓储（单一事实源）+ 队列调度器（编排引擎）。二者均可离线单测，为批次4 的 UI/入口/离线播放提供稳定契约。

## 三、方案（改动清单）

新增 `lib/core/download/download_store.dart`：

- `DownloadTaskStorage`：最小存储契约（`read`/`readAll`/`write`/`delete`/`clear`），与批次2 的 `DownloadTransport` 抽象同构——持久化/传输/编排三层各自可注入、可单测。
- `HiveDownloadTaskStorage`：Hive box 实现（生产用）。
- `DownloadStore`：仓储单一入口；`loadAll` 按 `createdAt` 升序、同值按 `id` 升序（与队列选队规则一致）；对单条脏记录容错跳过，避免一条坏数据毁掉整个列表。

新增 `lib/core/download/download_queue.dart`：

- `DownloadQueueCoordinator`：串联 `DownloadStore` + `DownloadEngine`（工厂注入）+ `DownloadQueuePolicy`（并发/选队）。
- 生命周期：`restore()` 载入持久化任务并把上次中断的 `downloading`/`merging` 复位为 `queued`（保留已落盘字节，交引擎续传）；**不自动 `pump`**，避免启动即静默下载，由调用方显式 `pump()`。
- 操作：`enqueue` / `pause`（运行中先请求取消、收尾转 `paused`）/ `resume` / `retry` / `remove` / `clear` / `dispose`。
- 进度落盘**节流**（默认 1s 窗口），避免高频进度回调抖动 Hive；终态无条件落盘。

改动 `lib/core/storage/storage.dart`：新增 `download` box（`GStorage.download`），并入 `init()`/`compact()`/`close()`。**刻意不并入**设置导入导出与全局 `clear()`——下载记录是用户内容引用而非「设置」，避免"清缓存"误删任务记录。

改动 `lib/models/download/download_task.dart`：`copyWith` 增加 `clearErrorMessage`（重试/成功时清除旧错误，Dart `copyWith` 无法用 `null` 覆盖非空字段的通用难题）。

## 六、遗留与踩坑

1. **批次4（UI 层）待做**：下载页 UI + 详情页下载入口 + 离线播放接线 + **生产接线**（`DioDownloadTransport` 实例、Cookie/Referer 头经 `resolveHeaders` 注入、`downloadPath` 设置落地 `resolveSavePath`、App 启动时 `restore()`）。
2. **不自动 `pump`**：有意设计。启动即自动开跑会静默消耗带宽，交由调用方（设置/入口）显式决定。
3. **release 编译的文件锁**：运行中的 `winwin.exe` 会锁 `WebView2Loader.dll` 导致 `MSB3027`。解法=双编译前按 **PID** 结束单实例（严禁按进程名批量杀，严禁碰 OfficeAce/node 宿主）。
4. **装填下载 box 不影响旧数据**：`download` box 为新增，旧用户无该 box，Hive 首次 `openBox('download')` 即创建，向后兼容。
5. **未做**：`shouldRefreshStaleDownloadUrls`（陈旧地址刷新）目前仍是纯策略，未接入调度器执行前钩子——留待批次4 与生产接线一并接线。
