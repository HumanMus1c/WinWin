# 视频详情页 / 番剧播放页 顶栏「过渡 / 吸顶」不可达修复复盘（2026-10-17）

- 触发：用户实机反馈「过渡中和吸顶状态不符合，请修复」，追问定界为「**完全没有效果**」。
- 类型：交互驱动修复（顶栏三态可达性），非样式调整。
- 起点 HEAD：`16d4ffc`；改动前快照 `refs/snapshots/latest = 16d4ffc`。

---

## 一、现象描述

1. 视频详情页顶栏的三态（未滚动透明 / 过渡中渐变翻色 / 吸顶毛玻璃实底）**在实机上完全看不出效果**：滚动页面时顶栏基本不变。
2. 窄屏单列布局能看到效果，**宽屏两栏布局（窗口宽 ≥ 900，最大化时必然如此）看不到**。

## 二、问题根因

顶栏三态只有**一个驱动量**，且该量在宽屏布局下**永远走不到阈值**。

1. 驱动链：
   - `lib/pages/video/detail_page.dart:1151` `_scrollRatio.value = r`
   - ← `VideoHeader.onScrollRatioChange`
   - ← `lib/common/widgets/sliver/video_header.dart:60-61`
     `ratio = shrinkOffset / (maxExtent - minExtent)`
     —— 即**播放器从「展开」收缩到「pin」的进度**（分母 ≈ 0.44 × 视频高，约需 400+px 行程才到 1.0）。
2. 三态阈值（`detail_page.dart` `_buildGradientTopBar`）：
   - `opacity < 0.5`：黑渐变 + 白字（浮在视频上）；
   - `0.5 ≤ opacity < 0.95`：背景色渐变 + 深字；
   - `opacity ≥ 0.95`：整条毛玻璃（BackdropFilter blur16 + 底边线）。
3. 宽屏（`width ≥ kDetailNarrowBreakpoint = 900`）走两栏 `Row(左 65% / 右 35%)`，
   **评论区被迁到右栏 Tab**，左栏（`_buildLeftColumn(appendRelated: false)`）只剩
   视频 + 弹幕条 + 信息/简介/标签 → 左栏可滚动余量通常只有 100~200px，
   远小于播放器收起行程（≈0.44×视频高）→ 收缩比例**封顶在 ~0.3**，
   0.5 翻色点与 0.95 吸顶阈值**永不可达** → 观感上就是「完全没效果」。
4. 窄屏单列（`appendRelated: true`，评论追加在左栏尾部）可滚余量大 → 比例能到 1 → 效果正常。

> 结论一句话：**顶栏状态被绑在「播放器收缩进度」上，而宽屏两栏布局里播放器根本收不起来**，
> 所以两态永远触发不了。

## 三、修复方法（方案 A：滚动吸收）

- 顶栏不透明度改由**左栏滚动位移**驱动，与播放器收缩解耦：
  `opacity = clamp(scrollController.position.pixels / absorb, 0, 1)`，
  其中 `absorb = maxScrollExtent.clamp(24, 56)`
  （行程 = 一条工具栏高 56；**不足一条工具栏的窗口按实际可滚范围收敛**，保证吸顶可达；下限 24 防抖）。
- 重建触发由 `ValueListenableBuilder<double>(valueListenable: _scrollRatio)`
  改为 `AnimatedBuilder(animation: scrollController)`：**滚动即刷新**，不依赖收缩比例的 plumbing。
- 三态**视觉零改动**（黑渐变+白字 → 背景渐变+深字 → 毛玻璃+底边线全部保留）。
- **同类一轮修完整类**：两处同源实现一并修 ——
  `lib/pages/video/detail_page.dart` 与 `lib/pages/bangumi/bangumi_player_page.dart`。
- `_scrollRatio` 保留（仍供 `_handleCollapseAutoPause` 折叠自动暂停使用），仅不再充当顶栏驱动。

## 五、遗留与踩坑

1. **沙箱环境坑（新增确认）**：`flutter build windows` 同样依赖 `%PROGRAMFILES(X86)%`，
   与 `flutter test` 同法需补环境变量：
   `LOCALAPPDATA` / `APPDATA` / `USERPROFILE` / `ProgramFiles(x86)` / `HOME`，否则
   直接报 `%PROGRAMFILES(X86)% environment variable not found.` 构建失败（与代码无关）。
2. **实机手感待用户确认**：宽屏左栏可滚余量本就很小，`absorb` 收敛到实际范围后
   「滚到底即吸顶」；若觉得过快/过慢，可再调上下限。
3. **窄屏语义变化（需实机确认）**：窄屏原本是「播放器完全收起才吸顶」，
   本方案统一改为「滚动吸收」，窄屏下手感会更灵敏（约滚一条工具栏高即吸顶）。

## 六、总结

顶栏三态此前只被「播放器收缩比例」驱动，而该比例在宽屏两栏布局下因左栏可滚余量不足
而永远封顶在 ~0.3，导致 0.5 翻色点与 0.95 吸顶阈值不可达 —— 这正是用户实机看到的
「过渡中 / 吸顶完全没有效果」。修复把驱动源换成**左栏滚动位移**（吸收行程随实际可滚范围
收敛），使任意窗口/布局都能完整走完「渐变 → 翻色 → 吸顶」，视觉规范零改动；
视频详情页与番剧播放页两处同源实现一并收口，三件套验证全绿、闸门不变（19）。
