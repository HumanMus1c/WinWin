# 弹层 1px 描边收口（MiuixPopupMenu 补白边）复盘 — 2026-10-16

> 承接 `docs/毛玻璃浮层面板边缘无渐变复盘-2026-10-16.md`（同属「统一弹层材质/边线口径」主题）。
> 本文记录**播放器控制栏弹层缺白边**的定位与修复（方案 A：描边单一来源 + 补边）。
>
> **快照基准**：`refs/snapshots/latest = 550683c`（改动前 HEAD，回滚 `git reset --hard 550683c`）。

## 一、现象

播放器控制栏的弹层（倍速 / 清晰度 / 弹幕设置等）与**首页视频卡片右键弹层**观感不一致：

- 首页卡片弹层：四周有**一条稳定可见的 1px 白（浅色主题为黑）描边**，边界清晰；
- 播放器控制栏弹层：**没有描边**，四周只有阴影软过渡，与卡片弹层并排看像「少了一圈边」。

## 二、定因

两条弹层走的是**不同渲染路径**，材质口径不同：

| 弹层 | 组件 | 材质 | 描边 |
|---|---|---|---|
| 首页视频卡片弹层 | `MiuixOverlayPanel` | `MiuixFrostedSurface(outline: true)` | **有** 1px（`foregroundDecoration` 画在裁剪层外） |
| 播放器控制栏弹层 | `MiuixPopupMenu._PopupOverlay` | `MiuixSurface(border: null)` | **无**（`border == null` → squircle `side` 取 `BorderSide.none`） |

即：不是「弹层样式参数被写错」，而是**同一种视觉语义（浮层边线）在两个组件里各写了一份、其中一份缺失**。

## 三、方案（方案 A：描边单一来源 + 补边）

保持两组件各自的圆角/材质不动（最小爆炸半径），只做两件事：

1. **描边色收敛为单一来源**：在 `MiuixFrostedSurface` 上抽出
   ```dart
   static Color outlineColor({required bool isDark}) => isDark
       ? AppColors.white.withValues(alpha: 0.18)
       : AppColors.black.withValues(alpha: 0.12);
   ```
   面板自身改调该来源（消除重复定义）。
2. **给 `MiuixPopupMenu` 的 `MiuixSurface` 补 1px 描边**：
   ```dart
   border: Border.all(color: outlineColor, width: 1),
   ```
   描边色取自上面的单点来源（`AppThemeHost.of(context).isDark` 解析明暗）。

**炸半径（有意为之，需实机复验）**：全部 `MiuixPopupMenu` 调用点一并获得描边 ——
播放器控制栏 ×3、直播间 ×3、登录、个人空间、消息中心「更多」菜单。

## 六、遗留与踩坑

- **描边口径仍有三套**：`MiuixFrostedSurface`（α0.18/0.12 1px）、`MiuixPopupMenu`（本批已对齐前者）、
  `MiuixDialogShell`（`outlineVariant α0.25 / 0.5px`，第三套口径，**本批未动**）。后续一致性批次可评估是否统一。
- **Toast（`lib/core/app_messenger.dart`）仍无描边**，未纳入本批。
- 方案 A 是「补边」而非「材质真收敛」：两组件圆角仍为 12（面板）/16（菜单，squircle），
  属**有意保留**（真收敛风险大，见方案 B 未采纳原因）。
- 视觉修复需**实机肉眼复验**；自动化像素分析对 1px 边线不稳定（上轮曾据此误判），最终以实机为准。

## 七、总结

「播放器控制栏弹层缺白边」的根因不是样式参数错误，而是**同一视觉语义（浮层 1px 边线）在两套弹层组件里各写一份、其中一份缺失**。本批把描边色收敛到 `MiuixFrostedSurface.outlineColor` 单一来源，并给 `MiuixPopupMenu` 补齐 1px 描边，使两类弹层边线口径一致；圆角与材质保持不动以控制爆炸半径。静态分析零问题、Debug/Release 双编译通过。剩余的三套描边口径（含 `MiuixDialogShell`、Toast）留作后续一致性批次。
