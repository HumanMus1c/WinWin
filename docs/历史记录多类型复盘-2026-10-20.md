# 历史记录多类型支持复盘（2026-10-20）

> 主题：历史页补齐官方接口剩余类型 + 补齐上游 PiliPlus 的 tab 其余分类
> 改动前基线：`7a4a2a5`（工作树干净，无未提交改动，故未产生新快照对象；回滚命令：`git reset --hard 7a4a2a5`）
> 涉及文件：`lib/pages/history/history_page.dart`（唯一改动文件）
> 状态：**已实现，四级验证全绿，待实机复验**

## 一、现象（需求）

历史页当前**只能浏览与打开普通视频（稿件）**：

- 分类栏缺失：`HistoryData.tab`（服务端下发的分类列表）在模型层已解析，但页面从未渲染；
- 恒拉「全部」：`historyList` 调用不传 `type`，永远 `all`，无法按官方分类（视频/直播/专栏）筛选；
- 点击受限：`_openItem` 仅放行 `business == archive` 且有 `bvid` 的记录，追番(pgc)/直播(live)/专栏(article) 一律弹「暂不支持打开该类型记录」。

需求：**补齐官方接口支持的剩余类型**（`type` 分类筛选），并**补齐上游实现的 tab 其余分类**（按服务端下发分类切换 + 各类型可打开）。

## 二、定因（现状核对）

三层证据核对（官方文档 + 上游源码 + 本仓代码）：

| 层面 | 结论 | 证据 |
|---|---|---|
| 官方接口 | **支持** | `/x/web-interface/history/cursor`：`type=all/archive/live/article`；`business=archive/pgc/live/article-list/article`；响应 `data.tab[]` 动态下发分类（bilibili-API-collect `docs/historytoview/history.md`） |
| 上游 PiliPlus | **完整支持** | `lib/http/user.dart` `historyList(type:)`；`lib/pages/history/view.dart` 用 `data.tab` 生成 TabBar；`lib/pages/history/widgets/item.dart` `onPushHistory` 覆盖 视频/pgc/live/article/cheese |
| WinWin | **仅差页面接线** | 模型（`history_models.dart` 已含 tab/badge/live_status/uri 等）与 HTTP（`history.dart` 已支持 `type`）**均已就绪**；缺口全在 `history_page.dart`：不渲染 tab、不传 type、`_openItem` 只认 archive |

**根因**：本仓历史页是「单列表 + 单游标」的单类型实现，从未把已具备的 `type`/`tab`/`business` 能力接线到 UI。

## 三、方案（已实现）

在 `lib/pages/history/history_page.dart` 一处完成，**不改模型/HTTP**：

1. **按 type 分页 + 分类独立缓存**
   - 新增 `_type`（当前分类）与 `Map<String, _HistoryTabState> _tabStates`（每分类独立 `items/max/viewAt/hasMore/loading/error/loaded`），对齐上游「每 type 一个 Controller 保活」；切回已加载分类直接展示、不重拉、不闪烁。
   - `_load` 改用 `HistoryHttp.historyList(type: _type, ...)`；分类栏仅在 `all` 首次刷新时从 `response.tab` 捕获（官方仅在默认分类下发 tab）。

2. **分类栏（对齐上游 tab）**
   - 标题下新增**吸顶胶囊分类栏**：`全部` + 服务端下发分类（`{type,name}`，如 视频/直播/专栏），样式复用 `live/view.dart` / `pgc/view.dart` 的既有胶囊栏模式（`MiuixPressable` + `AnimatedContainer` + `AppTransparentHost`），保持产品视觉一致。
   - 切换分类 → `_switchType`：置 `_type` 并首次拉取或直接展示缓存。
   - **演示模式不显示分类栏**（演示为本地假数据，避免伪造正常模式产生不了的状态）。

3. **点击跳转补齐（按 `history.business` 分发）**
   | business | 落地页 |
   |---|---|
   | `archive`/空 | `VideoDetailPage(bvid)`（现状保留，带续播 hero） |
   | `pgc`（追番/影视） | `BangumiDetailPage(epId: history.epid)` |
   | `live`（直播） | `LiveRoomPage(roomId: history.oid)`；`liveStatus != 1` → 提示「直播未开播」 |
   | `article`/`article-list`（专栏/文集） | `ArticlePage(id: ...)`；文集取 `history.cid`，其余取 `history.oid` |
   | `cheese`（课程） | 暂不支持（见「五、遗留与踩坑」） |

4. **卡片类型角标**：封面左上角渲染 `PBadge`（`isFav==1` → 「已收藏」/ 否则用服务端 `badge`，如「番剧」「直播」），让类型可辨识。

## 五、遗留与踩坑

- **遗留 1（课程 cheese）**：`business == 'cheese'`（PUGV 课程）WinWin **尚无课程落地页**，维持「暂不支持打开该类型记录」。上游走 `viewPgcFromUri(uri)`。若需支持，须先新建课程详情页（另立议题）。
- **遗留 2（tab 名称不写死）**：分类名称完全来自服务端 `data.tab`，故「专栏/直播/视频」等文案随官方下发变化，不要硬编码。
- **踩坑 1（分析告警）**：`business ?? 'archive'` 后 `business == null` 恒假 → `unnecessary_null_comparison`，条件式兜底后要清理冗余判空。
- **踩坑 2（环境）**：见上「构建环境注意」。
- **未做**：pgc 记录的历史进度续播（上游用 `playbackProgress` 传给 `viewPgc`）——WinWin `BangumiDetailPage` 未接续播进度参数，本轮未传，属可选增强。

## 六、总结

官方接口与上游 PiliPlus 的「多类型历史」能力早已存在，本仓只差**页面接线**。本轮在**单文件**内完成三件事：按 `type` 分类分页（含分类级缓存）、渲染服务端下发分类栏、按 `business` 补齐 pgc/live/article 点击跳转，并加类型角标。四级验证全绿，唯一遗留是 WinWin 缺课程页导致的 `cheese` 类型暂不可打开。改动最小、可回滚（基线 `7a4a2a5`）。
