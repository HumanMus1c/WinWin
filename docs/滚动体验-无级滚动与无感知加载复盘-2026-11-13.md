# 滚动体验复盘：无级滚动与无感知加载（2026-11-13）

## 一、现象

CVO 实机反馈两条：

1. **滚动视图观感不舒服**：鼠标滚轮一格一格「硬跳」，没有位移过渡；快速连滚时尤其明显。
2. **滚动加载时滚动条异常**：滑块缩短没有过渡（瞬间变短），并且会上下抖动；部分页面加载失败/到底时整页内容会跳一下。

## 二、定因

### 2.1 滚轮：SDK 原生就是「立即跳变」

- `ScrollPositionWithSingleContext.pointerScroll` 对滚轮直接 `forcePixels`（`scroll_position_with_single_context.dart` L209-236），一帧内完成整格位移。
- `ScrollBehavior` 只开放 `buildScrollbar / buildOverscrollIndicator / getScrollPhysics`，**没有滚轮钩子**；且 `buildScrollbar` 的产物包在 `Scrollable` 自身 Listener **外层**（`scrollable.dart` L996-1008），所以 `AppScrollBar` 也拦不到内容区滚轮。
- 结论：无级滚动只能通过官方扩展点 `ScrollController.createScrollPosition` 替换 `ScrollPosition` 实现；PiliPlus 也没有可移植实现（`CustomScrollBehavior` 只关闭了框架滚动条）。

### 2.2 滚动条：几何直读实时 `maxScrollExtent`

`AppScrollBar` 原实现每帧按 `viewport / (maxScrollExtent + viewport)` 计算滑块长度、按 `pixels / maxScrollExtent` 计算偏移：

| 事件 | 原表现 |
|---|---|
| 加载追加内容 | 内容总长突增 → 滑块瞬间变短、瞬间上移 |
| 瀑布流逐列估算 extent | `maxScrollExtent` 分多帧增长 → 滑块分步缩、分步跳 |
| footer 状态切换 / 加载失败 | 内容总长变小 → 位置回弹/夹紧 → 内容上跳、滑块反向跳 |
| 顶栏安全行收起 | 视口高度 −50px → 滑块长度再跳一次 |

### 2.3 加载：footer 高度不固定 + 触发时机混乱

- 多个列表 footer 是「转圈（约 56px）↔ 没有更多（约 49px）↔ 空白（0px）」三态切换。贴底时内容总长变化会触发位置回弹，即「上下抖」。
- 触发方式混用：`itemBuilder` 里构建最后一张卡就触发（hot/follow/dynamics/pgc/live/search，距底仅约 250px）、滚动监听阈值 240/300px、`ViewportLoadBudget` 1 屏；同一页还可能双触发。
- 贴底时每帧都重新命中「距底不足阈值」，请求空手而归（服务端去重）后 `isLoading` 立即复位 → 每帧重发请求，加载时机完全随机。

### 2.4 两个放大器

- `AppScaffold` 安全行用「单帧 delta > 8px」收起/展开 50px；该高度属于滚动视口，来回滚时反复改变视口 → 内容与滑块一起抖。
- `MainLayout` 底栏隐藏用「单帧 delta > 4px」。滚轮改平滑后单帧位移只有几像素（高刷屏更小），该阈值会时灵时不灵。

## 三、方案（已实施）

### 3.1 输入层：滚轮补间（新增 `lib/common/widgets/app_scroll_controller.dart`）

- `AppScrollController.createScrollPosition` 返回 `AppScrollPosition`。
- 覆写 `pointerScroll(delta)`：
  - `|delta| < 24`（触控板/高精度）→ 基类立即位移，保持零延迟；
  - 否则以「动画目标累加」续追（动画途中再滚从目标继续加，不回到当前像素重算）；
  - `animateTo(target, duration = clamp(distance × 2.2, 90, 260)ms, Curves.easeOutCubic)`；
  - 世代号 + `whenComplete` 清理目标；`jumpTo` / 拖拽 / 惯性取消自动打断。
- 页面级 `ScrollController()` 全部换为 `AppScrollController()`（首页/热门/关注/动态/番剧/直播/收藏/稍后再看/历史/搜索/关注粉丝/空间/详情/消息/直播聊天等，共 20 个文件、23 处）。
- `AppScrollBar` 通道补 `Listener.onPointerSignal` 转发：悬停在右侧 12px 滚动条通道上滚轮也滚页面（此前完全无效），并复用同一套补间。

### 3.2 滚动条层：内容总长补间（`lib/common/widgets/app_scroll_bar.dart`）

- 新增 `_extentAnim`（200ms / easeOutCubic），对 `maxScrollExtent + viewportDimension` 做补间；滑块长度与偏移都用补间后的值计算。
- 触发源用 `NotificationListener<ScrollMetricsNotification>`（布局结束后微任务派发，一帧最多一次），不在 build 内起动画。
- 1.5px 死区：小于该值不重定向补间，避免瀑布流估算抖动导致补间反复重启。
- 拖拽命中仍用实时 metrics（跟手），绘制用补间值。

### 3.3 加载层：门闩 + 恒高 footer

- 新增 `lib/utils/load_more_gate.dart`：`LoadMoreGate`
  - 从「距底 > 1 屏」跨入「≤ 1 屏」只放行一次；
  - 回滚超过 1.5 屏、或内容总长变化（新批次落地）后重新武装；
  - 同位置 450ms 冷却：服务端整批去重（返回 0 条）后继续滚动仍可重试，但不会每帧重发。
- 新增 `lib/common/widgets/list_load_footer.dart`：恒高 56px 槽位（转圈 / 没有更多 / 错误重试 / 空白），状态切换不改变内容总长。
- 移除 `itemBuilder` 内所有加载副作用（rcmd/hot/follow/dynamics/pgc/live/search/relation/session），统一改为滚动监听 + 门闩。
- 首页/热门/关注/动态/番剧/直播/收藏/稍后再看/历史/搜索/关注粉丝/消息中心全部接入；刷新时 `reset()` 门闩。

### 3.4 放大器修复

- `AppScaffold`：安全行改**位置 + 滞回**——`pixels > 96` 且向下才收起；回滚超过 120px 或回到 24px 内才展开。
- `MainLayout`：底栏隐藏改**同方向累计位移 > 12px**，方向翻转清零。

## 六、遗留与踩坑

1. **覆盖范围**：无 controller 的滚动视图（少数弹层小列表）仍走 SDK 即时滚轮；SDK 没有全局滚轮钩子，不引入三方包的前提下只能接受。
2. **通知频率变化**：平滑滚动把「每刻度 1 次通知」变成「每帧 1 次」，所有按单帧 delta 判断的消费者都必须同步改（本轮已改安全行与底栏；后续新增滚动联动组件需按「累计位移 / 绝对位置」判断）。
3. **滑块补间与拖拽命中**：过渡期 200ms 内绘制值与实时值最多差几像素，拖拽命中仍用实时值，实测无感。
4. **`ScrollDirection` 导入**：它定义在 `rendering/viewport_offset.dart`，`widgets.dart` 不导出，自定义位置文件需显式 `import 'package:flutter/rendering.dart' show ScrollDirection;`。
5. **`ScrollMetricsNotification` 深度**：只在 `depth == 0` 处理，避免嵌套滚动视图（如弹层内列表）误触发页面级滑块补间。

## 七、追加修复（第二轮反馈：过渡已平滑但仍上下抖动）

### 7.1 现象

CVO 复测：滚轮过渡已平滑，但加载时滑块仍然「上下抖」。

### 7.2 定因

旧映射 `偏移 = pixels / maxScrollExtent × (track − 长度)` 中，长度与偏移同源：

1. 内容追加 → 长度变小、`(track − 长度)` 变大 → 滑块被**向上推**；
2. 用户仍在向下滚 → `pixels` 增大 → 滑块被**向下拉**；
3. 两者方向相反、同一时间窗内叠加（200ms 补间把上推摊开），视觉即上下抖。

首页一次补货约 +20 张卡（≈1 屏），从 20 条涨到 40 条时长度约从 50% 掉到 25%，
位移幅度大；连续滚动可触发多次补货 → 锯齿状抖动。

**骨架占位不能解决**：固定行高页面的 `SliverGrid` 总高是精确值
（`computeMaxScrollOffset(childCount)`），不存在行数估算跳变；提前插骨架只是把
「内容变长」从数据到达时提前到触发时，滑块仍会因总高变化而移动。瀑布流的高度
未知，骨架只能估平均，真数据替换后还会再跳一次。

### 7.3 修复

`AppScrollBar` 改为「滚动中冻结几何 + 偏移与长度解耦」：

- **冻结**：滚动/拖拽开始时记录当前绘制的内容总长 `_frozenContentExtent`，期间
  收到的 `ScrollMetricsNotification` 只写入 `_pendingContentExtent`，不改变绘制；
  滚动中滑块长度完全不变，只随 `pixels` 跟手移动。
- **结算**：停手 220ms（[`geometrySettleDelayMs`]）后用 200ms 把长度补间到最新值；
  拖拽则在松手时立即结算。滚动中重复加载只会累加待结算值，停手后一次性收一下。
- **解耦**：偏移改为 `pixels / 内容总长 × track`（再夹紧到 `[0, track − 长度]`），
  端点仍然严格等价（到底时 = `track − 长度`），但长度补间不再推动滑块。
- reverse 列表以滑块底边为锚点（`pixels = 0` 在视觉底部），拖拽反向映射同步更新。

### 7.5 取舍说明

冻结期间若用户持续滚动超过「开始滚动时已加载的内容末端」，滑块会停在轨道底部
（表示已到已知内容的末尾）；停手后结算才展开。这替代了此前的反向抖动，属于
无限流滚动条的常见表现。

## 八、总结

滚轮从「SDK 立即跳变」改为按距离补间（90–260ms，触控板小增量仍零延迟），滚动条对内容总长做 200ms 补间并在通道上支持滚轮，加载改为「1 屏提前量 + 滞回门闩 + 恒高 footer」且清除 build 内副作用；顶栏收起与底栏隐藏改为位置/累计位移判定以适配平滑滚动。第二轮进一步改为「滚动中冻结滑块几何 + 偏移与长度解耦」，消除加载与滚动两个反向运动叠加造成的上下抖。自动化验证全绿（analyze 0 issue、324 测试、debug/release 双编译），实机手感待 CVO 验收。
