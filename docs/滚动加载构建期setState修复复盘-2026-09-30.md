## 一、分析根因

### 1.1 现象

崩溃账本（`.winwin_logs.json`）于 **2026-09-30T18:13:11.994** 新增一条：

```
setState() or markNeedsBuild() called during build.
This MemberSpacePage widget cannot be marked as needing to build because the framework
is already in the process of building widgets.
```

崩溃报告自带完整堆栈，直接指到行：

```
#3  _MemberSpacePageState._loadMoreVideos      (lib/pages/member/member_space_page.dart:312)
#4  _MemberSpacePageState._buildVideosTab.<anonymous closure>  (:1329)
#7  SliverMultiBoxAdaptorElement.createChild
#16 RenderSliverGrid.performLayout
```

### 1.2 根因链（三层）

1. **触发点**：`SliverChildBuilderDelegate` 的 `itemBuilder` 中，当 `index == _videos.length - 1`
   （即构建到列表最后一项）时**同步**调用 `_loadMoreVideos()`；
2. **关键陷阱**：`_loadMoreVideos()` 虽声明为 `async`，但 `setState` 位于**第一个 `await` 之前**——
   Dart 的 `async` 函数体在首个 `await` 前是**同步执行**的，因此 `setState` 落在了 build 阶段
   （作者可能误以为 `async` 会让它自动延后）；
3. **框架约束**：`SliverChildBuilderDelegate` 的 builder 在 **layout 阶段**被调用，此时框架
   正处于构建流程中 → 触发 `markNeedsBuild` 断言。

### 1.3 为何长期未暴露（重要）

该断言包裹在 `assert(() { … }())` 内，**只在 debug 构建生效**：

- 此前若干轮复测均跑 **Release** 构建 → 断言不执行，静默通过（仅多一次构建期冗余重建，
  通常无可见症状）；
- 2026-09-30 18:02 那次复测首次跑 **Debug** 构建 → 断言执行并被 Catcher2 捕获入账本。

**非历史回归**：整本崩溃账本中该签名历史计数为 **0**（首次出现）；引入该行的提交是
`b53db78 [snapshot] 视频详情页评论完整功能`（**2026-08-06**）。

## 二、设计修复计划与实现

### 2.1 修复范式：先用项目内既有解法（不新造轮子）

项目内**已有同构解法**：`lib/pages/whisper/session/session_list_section.dart:320-329`

```dart
if (index == _sessions.length) {
  // 加载更多指示器 - 使用 addPostFrameCallback 避免在 build 中调用 _load
  if (_hasMore && !_isLoadingMore) {
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (mounted && _hasMore && !_isLoadingMore) { _load(); }
    });
  }
  ...
}
```

其形状特征：**调度前先判守卫 + 回调内再判 `mounted` 与守卫**（双保险，且避免每帧重复调度）。
本次修复严格对齐该形状。

### 2.2 同类站点统一排查（用户明确要求的"一次修完"）

以 `if (index == … .length - 1) { <触发加载/滚动> }` 为特征全库扫描，命中 6 处，逐处核验被调函数
在**首个 `await` 之前是否 setState**：

| `season_series_detail_page.dart:210` | `_loadVideos()` | **是**（`:65` 无条件，`refresh` 与否都走） | ⚠️ 同型缺陷 | **已修** |
| `bangumi_player_page.dart:1338` | `_maybeLoadMoreReplies()` | —（函数**自身内部已用** `addPostFrameCallback` 包裹，`:1310`） | ✅ 已安全 | 不动 |

### 2.3 两处修复实现

**共同写法**（以 member_space_page 为例）：

```dart
if (index == _videos.length - 1) {
  // 加载更多 - 使用 addPostFrameCallback 避免在 build 中调用 _loadMoreVideos
  // （同 session_list_section 范式）：_loadMoreVideos 首行即 setState，
  // 而 SliverChildBuilderDelegate 的 builder 在 layout 阶段被调用，
  // 直接调用会触发「setState() called during build」断言（Debug 才暴露）。
  if (!_loadingVideos && !_videoEnd && !_videoFailed) {
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (mounted && !_loadingVideos && !_videoEnd && !_videoFailed) {
        _loadMoreVideos();
      }
    });
  }
}
```

`season_series_detail_page.dart:210` 同构（守卫用该页自身字段 `_loading` / `_isEnd`，
**严格对齐 `_loadVideos` 自身的早退条件**，不新增额外门控，避免改变既有行为）。

**语义等价性**：守卫条件与被调函数的内部早退条件一致 → 只是把调用时机从「build 期间」
推迟到「本帧结束后」，不改变加载时机语义（仍在滚动到最后一项时触发）。
