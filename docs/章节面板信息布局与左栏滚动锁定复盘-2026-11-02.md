# 章节面板信息布局与左栏滚动锁定复盘（2026-11-02）

> 任务来源：CVO 五条反馈（缩略图比例 / 条目信息 1.6x / 面板背景 0.6 / 弹层打开锁定左栏 / 当前小节动态循环图标）。
> 目标：逐条落实为播放器章节面板的最终视觉与交互，并走完整验证序列（analyze / test / Windows Debug+Release 双编译）。

---

## 一、现象描述（CVO 反馈）

1. **缩略图圆角过大**：章节条目缩略图为 44×25 固定尺寸 + 4px 圆角，观感是大圆角小图，
   未体现视频原画面的直角矩形比例。
2. **条目信息偏小**：序号 12、时间胶囊 11、标题 13、缩略图 44×25，面板信息密度偏低，
   要求全部信息统一放大到当前的 1.6 倍。
3. **面板背景过于不透明**：背景为 `Color(0xF2141414)`（alpha≈0.95），几乎完全盖住底层画面，
   要求不透明度降到 0.6。
4. **弹层打开时背景仍可滚动**：播放器的章节面板 / 音量弹层 / 画质·音轨·倍速菜单 /
   弹幕·字幕设置 / 截图预览打开后，鼠标滚轮仍能把左栏信息流（简介、评论、相关推荐）滚走，
   弹层视觉上脱离锚点。
5. **当前小节图标语义弱**：正在播放的章节用静态播放三角替换序号，无法直观传达
   「这一段正在播放」。

## 二、问题定因

### 2.1 缩略图（`lib/pages/video/player_panel.dart` `_buildChapterPanel`）

条目内使用 `ClipRRect(borderRadius: 4)` 包 `NetworkImgLayer(width: 44, height: 25)`：
圆角固定、尺寸固定，且宽高比 44/25=1.76 只是巧合地接近 16:9，没有读取真实视频帧
`controller.videoSize`，因此不是「原画面比例」。

### 2.2 字号与间距

序号 `fontSize: 12`、时间胶囊 `fontSize: 11`、标题 `fontSize: 13`、缩略图高 25、
行内 padding `Style.sm`、间距 `Style.xs` 全部为写死原值，没有统一缩放系数。

### 2.3 面板背景

`Container` 背景写死 `Color(0xF2141414)`，alpha 通道 0xF2=242/255≈0.95。

### 2.4 左栏滚动

`PlayerPanel` 的 `_popupSuspend` 只用于「挂起控制条自动隐藏」，计数变化没有向宿主页面
广播；`DetailPage` / `BangumiPlayerPage` 的左栏 `CustomScrollView` 也没有弹层态，
因此滚轮事件始终能作用于背景列表。

### 2.5 当前小节图标

`isCurrent ? AppIcon(AppIcons.play(active: true))` 是纯静态字形，播放/暂停/面板开合
都没有动态反馈。

## 三、方案

### 3.1 条目视效统一 1.6x（`player_panel.dart`）

- 新增常量 `_kChapterItemScale = 1.6`，条目内全部信息以该系数换算：
  - 序号字号 12→19.2，序号列宽 22→35.2；
  - 缩略图高 25→40，宽度按原画面比例换算；
  - 时间胶囊字号 11→17.6，内边距 6/2→9.6/3.2，圆角 4→6.4；
  - 标题字号 13→20.8；
  - 行内边距 `Style.sm`→12.8，元素间距 `Style.xs`→6.4，列表内边距 4→6.4。
- 缩略图取消 `ClipRRect`，改为 `NetworkImgLayer(borderRadius: BorderRadius.zero)`；
  宽高比取 `controller.videoSize`（首帧未就绪时回退 16:9），实现「原画面直角比例」。

### 3.2 单行→两行布局（参考 PiliPlus `ViewPointsPage`）

1.6x 后「序号 + 缩略图 + 时间胶囊 + 标题」单行所需固定宽度约 285px，面板内只剩
30~70px 给 21px 标题，实际不可读。改为移植 PiliPlus `ViewPointsPage._buildItem`
的纵向信息结构（标题在上、时间在下）：

- 左侧保留序号 / 动态指示器 + 原比例缩略图；
- 右侧 `Expanded(Column)`：标题（最多 2 行）+ 时间胶囊（左对齐）。
- 面板宽度 clamp 下限由 240 抬到 320（仍维持宽屏 1/3、上限 560），
  保证两行内容不被裁切；弹层遮罩、滑出动画、Esc/TapRegion 行为不变。

### 3.3 背景不透明度 0.6（`player_panel.dart`）

`Color(0xF2141414)` → `Color(0x99141414)`（alpha 0x99=153/255=0.6），
保留 16px 毛玻璃模糊、左侧描边与投影。

### 3.4 弹层打开锁定左栏（`player_panel.dart` + 两个播放页）

- `PlayerPanel` 新增 `onPopupOpenChanged`（`ValueChanged<bool>`）：
  - `_beginPopupSuspend()` 在计数首次 0→1 时回调 `true`；
  - `_endPopupSuspend()` 在计数 1→0 时回调 `false`；
  - 截图预览对话框改用 `_openSuspending` 包裹，纳入同一计数，覆盖「任何弹层」。
- `DetailPage` / `BangumiPlayerPage` 新增 `_playerPopupLocked`：
  - 弹层打开 → 左栏 `CustomScrollView.physics = NeverScrollableScrollPhysics()`；
  - 全部关闭 → physics 恢复 `null`（默认）。
  - 弹层自身的章节 `ListView` / 音量面板 / 菜单不受影响，仍可正常滚动。
- 覆盖弹层：章节面板、音量弹层、画质/音轨/倍速 `MiuixPopupMenu`、
  弹幕设置、字幕设置、截图预览。

### 3.5 当前小节动态循环图标（`player_panel.dart`）

新增私有 `_ChapterPlayingIndicator`：

- 3 根 5px 宽均衡器竖条，高度按 `sin(phase + i * 2.1)`（8~26px）以 900ms 周期循环；
- 仅在「章节面板可见」且 `controller.playing == true` 时 `repeat()`，
  暂停或面板收起时 `stop()` 停帧，避免后台空转；
- 替代原静态播放三角，序号列保持同一宽度，当前行高亮与时间胶囊高亮不变。

## 五、遗留与踩坑

- **演示模式未同步**：`DemoPlayerChrome` 的章节面板为独立精简实现（无缩略图、假数据），
  背景仍为 0xF2、条目仍为旧字号、当前小节仍为静态三角；本轮聚焦真实播放器，
  演示面板待后续统一（需同步移植 `_ChapterPlayingIndicator` 与弹层滚动广播）。
- **番剧窄屏未锁**：`BangumiPlayerPage._buildNarrowLayout` 是 `NestedScrollView`，
  需同时接管外层与内层三个 Tab 列表的 physics 才能完整锁定；本轮只处理宽屏双栏
  （用户所指「左栏」），窄屏单列暂不锁定。
- **面板最小宽度 320**：在播放器宽度小于 320 的极端窗口下会溢出；当前最小窗口远大于此，
  未做额外兜底。
- **弹层销毁不补发 false**：`PlayerPanel.dispose` 不回调 `onPopupOpenChanged(false)`，
  避免在 build / 卸载阶段触发宿主 `setState`；全屏切换等路径会先被 `TapRegion`
  消费外部点击并关闭弹层，因此不会留下悬置锁。若后续出现「弹层销毁时页面仍锁定」，
  应改为宿主侧 `ValueNotifier` + 卸载顺序保护，而非直接在 dispose 里 setState。
- **原画面比例依赖首帧**：`videoSize` 未就绪时缩略图回退 16:9，首帧到达后随位置轮询
  重建自动校正；纯音频 / 无画面稿件保持 16:9。
- **条目放大后与单行布局不兼容**：若未来要求恢复单行，必须同步把面板宽度放大到约 480px 以上，
  否则标题会被时间胶囊挤到不可读。

## 七、总结

本轮把章节面板从「小圆角小字密集列表」升级为「原比例直角缩略图 + 放大后的两行信息」，
并用均衡条动态图标精确表达播放态；同时把播放器弹层状态从「只影响控制条」提升为
「页面级滚动锁」，消除弹层打开时背景信息流被滚轮带走的问题。核心经验：

1. 全局倍率变更必须同步检查横向空间，单行结构在放大后会挤压标题，应优先移植上游
   已验证的纵向信息结构（PiliPlus `ViewPointsPage`）。
2. 播放器内部弹层状态需要一个统一出口（`_popupSuspend`）对外广播，而不是页面各自判断；
   新增弹层只要纳入该计数，就自动获得滚动锁与控制条常显。
3. 高频动画（均衡条）必须绑定「可见 + 播放中」两个条件启停，不能只靠 widget 是否存在。
