## 二、定因（根因）

`ScrollController.hasClients` **为真 ≠ 位置已具备内容尺寸**：

- 滚动视图一被构建即 `attach` 到控制器 ⇒ `hasClients == true`；
- 而 `ScrollPosition._maxScrollExtent` / `_viewportDimension` / `_pixels` 仅在滚动视图
  **完成布局**（`applyContentDimensions`）后才写值（`scroll_position.dart`：
  L239 `maxScrollExtent => _maxScrollExtent!`、L243 `hasContentDimensions`、
  L264 `pixels => _pixels!`、L271 `viewportDimension => _viewportDimension!`）。

存在「**已挂载、未布局**」窗口：此时读 `maxScrollExtent` 即触发 release 空断言。
`AppScrollBar._position` 原先仅守卫 `hasClients` ⇒ **守卫不足**是本崩溃的根因。

> **确定性复现**（探针，非猜测）：构造伪 `ScrollContext` 并把裸
> `ScrollPositionWithSingleContext` 直接 `attach` 到 `ScrollController`，再挂 `AppScrollBar`，
> 稳定复现 `hasClients=true / hasContentDimensions=false` ⇒
> `Null check operator used on a null value`（与生产栈同型）。
> 反例排除：直接包裹、生产 `buildScrollbar` 路径、`Offstage` 包裹**均不崩**——因为
> `AppScrollBar._buildLane` 内层 `LayoutBuilder` 把通道构建推迟到其自身布局（晚于被包裹滚动视图），
> 尺寸已就绪；崩溃窗口只在「位置先于尺寸存在」时打开（如页面重建/切换命中该窗口）。

## 三、方案

`lib/common/widgets/app_scroll_bar.dart` — `_AppScrollBarState._position` 收口：

```dart
ScrollPosition? get _position {
  if (!widget.controller.hasClients) return null;
  final position = widget.controller.position;
  if (!position.hasContentDimensions || !position.hasPixels) return null;
  return position;
}
```

- **双重守卫**：`hasContentDimensions`（`_min/_maxScrollExtent` 均就绪）用于
  `maxScrollExtent`/`viewportDimension` 读数；`hasPixels`（`_pixels` 就绪）用于 `pixels` 读数。
- **单点收口**：全部读点（`canScroll`、`_thumbLength`、`_thumbOffset`、`_jumpToThumbOffset`、
  拖拽起手 `p.maxScrollExtent <= 0`、`AnimatedBuilder` 内 `canScroll`）均经 `_position` ⇒
  一处守卫全覆盖；`_onScrollNotification` 只置标志位、不读位置，天然安全。
- **口径一致**：未就绪一律视为「不可滚动」（与既有 `canScroll == false` 分支一致：滑块退化为
  满轨/不绘制），无视觉回归。
- 回归测试：新增 `test/ui/components/app_scroll_bar_test.dart`（3 例，含「已挂载无尺寸」确定性复现例）。
