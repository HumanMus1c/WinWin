## 2. 语义定义（对齐路线图 §6 原文）

路线图 §6 原文对 (a) 的口径为：**「lib 除 compat 桥外零 material 导入」**。本批次把它落为可机检的五条不变量：

| # | 不变量 | 覆盖目标 | 归属 |
| --- | --- | --- | --- |
| ① | `lib/` 零 `package:material_ui/material_ui.dart` 导入 | 应用侧不回归第三方 MD3 包 | B7 封板（原有） |
| ② | `pubspec.yaml` 零 `material_ui` 依赖声明 | 依赖清单不回归 | B7 封板（原有） |
| ③ | `lib/` 零 `app_glyphs.g.dart` 引用 + 该文件不存在 | MaterialIcons 字形载体退役 | Phase A（原有） |
| ④ | **`lib/` 内 SDK `package:flutter/material.dart` 导入仅限白名单** | **应用侧零 Material 消费**（Q4 新增） | 本批 |
| ⑤ | **`pubspec.yaml` 不得回挂 `uses-material-design: true`** | 防 SDK MaterialIcons 字体回捆绑（Phase A 反悔闸） | 本批 |

**白名单**：`_sdkMaterialWhitelist = { 'lib/core/shell/miuix_compat.dart' }` —— 该文件是 Miuix⟷SDK 唯一许可的兼容桥（flutter_miuix 内部 SDK `TextField` 需 `MaterialLocalizations` 祖先），在"应用侧零 Material 消费"中**显式豁免**。

> 边界口径：本门槛锁的是**应用代码（`lib/`）**的消费面，**不锁依赖树**——flutter_miuix 等上游在过渡期内部依赖 `material_ui` 属允许范围。这是 Q3/Q4 决策的一致性要求。

## 3. 现状核实（改动前硬事实）

- `lib/` 内 SDK `package:flutter/material.dart` 导入 = **恰好 1 处**：`lib/core/shell/miuix_compat.dart:1`（`import 'package:flutter/material.dart' as legacy;`）。
- `lib/` 内 `MaterialIcons` 字面 = 3 处，均在 `lib/theme/app_icons.dart`：两处注释 + 一处 `_fontFamilyTag` 字符串比较（`if (glyph.fontFamily == 'MaterialIcons') return 'material';`）——**非字体消费**，不触发不变量 ④。
- `pubspec.yaml`：无 `material_ui`、无 `uses-material-design`（Phase A 已摘）、含 `cupertino_ui: 1.0.0`。
- `test/` 侧另有 `test/core/shell/app_shell_layer_test.dart` 导入 `flutter/material.dart as legacy`（对照双），**不属应用侧**，不纳入门槛。

## 4. 实现要点

1. 门槛文件由"3 条不变量"扩为"5 条"，头部注释重写以说明 Q4 语义与"不锁依赖树"边界。
2. 新增两个 `test(...)`：
   - `lib 内 SDK material 导入仅限白名单桥（④）`：递归扫 `lib/**.dart`，命中 `_sdkMaterial` 的文件按白名单二分 → `offenders` 必须为空；**且白名单必须被真实命中**（`hitWhitelist == whitelist`），避免桥被拆后白名单空放失效；白名单文件须真实存在。
   - `pubspec 不得回挂 uses-material-design（⑤）`：正则 `^\s*uses-material-design\s*:\s*true\s*$`（多行、忽略大小写）须不命中。
3. 抽出 `_rel(FileSystemEntity)` 助手统一路径分隔符（`\` → `/`），全文件复用，消除重复的 `replaceAll('\\','/')`。
