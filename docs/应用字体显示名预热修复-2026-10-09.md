# 复盘：应用字体 subtitle 常态缺中文名（2026-10-09）

## 1. 现象描述

设置→外观→"应用字体"行：未打开过字体选择对话框时 subtitle 显示
`当前：PingFang SC`（英文族名裸奔）；打开一次对话框关闭后变为
`当前：苹方-简 (PingFang SC)`（预期形态）。用户截图图 1/图 2 对照确认。

## 2. 根因

`AppFontNotifier.displayName` 的中文标签来自 `SystemFontScanner.getByFamily`，
读的是内存 `_cache`；而该缓存只在 `_FontPickerDialogState._loadFonts()` 里
填充——对话框从未打开过时缓存恒冷，`getByFamily` 返回 null，
回退分支直接返回英文族名。对话框打开一次即"自愈"，故具迷惑性。

## 3. 修复方案

`AppFontNotifier.refresh()` 末尾加 `_warmFontLabels(value)`：
非常驻字体（排除自定义/Windows 默认/空值）时后台 `SystemFontScanner.scan()`，
完成后若中文标签与族名不同则 `notifyListeners()` 一次。
根节点（`main.dart:191`）本就监听该 notifier，会自动重建应用壳刷新 subtitle；
不阻塞启动；`_labelsWarmed` 防重复；失败静默回退英文名。
对话框后续的 `scan()` 命中热缓存，近乎瞬时。

## 5. 遗留与踩坑

- 遗留：启动后极短窗口（后台扫描完成前）进设置页仍可能先见英文名，
  扫描落盘后自动刷新一次；可接受，不做启动阻塞。
- 踩坑：`refresh()` 有多条早退分支，但早退值（自定义/默认/空）的显示名
  均不依赖扫描——只需在末尾正常路径预热，无需每处 return 补调用。

## 6. 总结

一处调用＋一个守卫方法，修复"开过对话框才正常"的缓存时序 bug，
无 UI 结构改动，零视觉回归面（除 subtitle 文本本身变正确）。
