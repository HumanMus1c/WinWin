# 播放期内存持续增长根因与修复复盘（2026-09-28）

> 触发场景：用户报告「播放中时内存占用上升到 400MB 左右，并且**持续上升**」。
> 修复文件：`lib/core/player/seek_probe.dart`（demux 缓存关闭 + 读缓冲默认 15s）、
> `lib/main.dart`（图片缓存上限 128MB）。诊断工具（临时脚本）均已清理。

---

## 1. 分析根因

### 1.1 现象描述

| # | 现象（用户实测） | 说明 |
|---|---|---|
| 1 | 播放 4K 视频，任务管理器可见内存**一点一点持续上升** | 非稳态占用，而是持续增长 |
| 2 | 16 分钟播放：261MB → **1284MB**（+1023MB ≈ 3MB/s） | 增长速率 ≈ 视频码率 |
| 3 | **播完（EOS）后停止增长**（2 分钟仅 +6MB 噪声） | 与"是否在下载数据"绑定 |
| 4 | 1080P 播放同样会涨（速率慢 5~6 倍） | 用户判断正确：与码率成正比 |

### 1.2 取证证据（时间序列 + 分区排除）

| 观测项 | 数据 | 结论 |
|---|---|---|
| Dart 堆 | 61~68MB 稳定（全程） | ❌ 非 Dart 侧 |
| GPU / 纹理内存 | 975→675→**460MB**（播完释放） | 稳态、无增长 |
| NOCACHE 映射 | 播放中稳定（564.3MB 多次一致） | ❌ 非纹理/映射侧 |
| **普通私有内存** | **+190MB / 75 秒** | ✅ **增长在原生堆（播放器）** |
| 进程 IO（播完） | 262 B/s（≈归零） | 增长与"下载活跃"同步 |
| 退出播放页 | GPU -206MB、线程 -32 | 播放器资源管理正常（非资源泄漏） |

### 1.3 根因链

1. 项目为「seek 加速、杜绝转圈」开启了 mdk 的 demux 数据包缓存
   （`demux.buffer.ranges='16'`，`player_controller.dart` 经 `SeekProbe.demuxBufferRanges` 注入）；
2. mdk 官方文档（`mdk-sdk/Player.h`）明确其语义：
   **"为网络流缓存下载数据（download data only once），加速 seek"**；
   "缓存范围因 seek 到未缓存位置而增加，**因重叠合并与 LRU 而减少**"；
3. **连续单向播放时"缓存范围"数量始终很少 → LRU 从不触发 → 已下载的媒体数据
   在内存中持续累积**；
4. 累积速率 = 视频码率（4K ~20-30Mbps ≈ 3MB/s；1080P 慢 5~6 倍）——与所有观测完全吻合。

## 2. 设计修复计划

| # | 项目 | 方案 | 取舍 |
|---|---|---|---|
| 1 | **demux 缓存泄漏（主修复）** | `demux.buffer.ranges: '16' → '0'`（**mdk 官方默认值**） | 代价：seek 时可能多一次网络加载；B 站 CDN 快，用户实机验证无体感差异 |
| 2 | **图片缓存上限** | 256MB → 128MB（`main.dart`） | 实测峰值用量 ~86MB，128MB 足够覆盖滚动窗口；防重度浏览后位图常驻膨胀 |
| 3 | **读缓冲** | 30s → 15s，**固化代码默认值**（`SeekProbe.bufferMaxMs = 15000`） | 4K 播放省 ~50MB；用户实机验证播放/seek 无体感差异 |

## 4. 本轮修复总结

### 4.1 改动面

- `lib/core/player/seek_probe.dart`：`demuxBufferRanges` 常量改 `'0'`（关闭）+ `bufferMaxMs` 默认 `30000→15000`；
- `lib/main.dart`：图片缓存上限 `256→128MB`；
- 本地诊断配置：`Documents/logs/seek_probe.json` 的 `bufferMaxMs` 同步为 15000（与代码默认一致，双保险）。

### 4.2 行为预期

- 播放中内存不再随播放时长累积（受控于码率）；4K 播放内存下降 ~100MB（缓存关闭 + 缓冲减半）；
- seek 行为：关闭 demux 缓存后，拖动进度条可能多一次网络加载（用户已验证无体感差异）。

### 4.3 遗留项

1. **根页面懒加载**（省 ~30MB，首次切页变慢）——可供后续选择；
2. **`d3d11.sync.cpu=1` A/B**（收益未知，撕裂风险需目视验证）——暂缓；
3. 若后续需要"seek 加速"回归：可评估"小值 ranges（2~4）"或"播放中周期重置"方案（需先确认其淘汰语义）。
