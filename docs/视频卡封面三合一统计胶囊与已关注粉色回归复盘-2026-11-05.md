# 视频卡封面三合一统计胶囊与已关注粉色回归复盘（2026-11-05）

## 一、现象

1. 首页竖卡的点赞量原本是信息区底部的独立胶囊，与封面左下角的播放/弹幕统计分离；要求把点赞量并入同一封面胶囊，三项用三种低亮度、较低饱和度的配色区分；统计胶囊、时长胶囊及内部文本放大到与视频卡标题一致；若两枚胶囊过长互相侵入/叠加，自动回落尺寸与字号避让。
2. 底部原点赞位要求只显示被官方 API 打上的「热门」章，尺寸同样与标题字体一致。
3. UP 名称旁的「已关注」从仿官方网页的粉色胶囊变成了灰色胶囊，要求改回。

## 二、定因

1. **已关注变灰**：迁移前 MD3 调色板的 `secondaryContainer = #FFDADA`（浅粉）、`onSecondaryContainer = #5F1212`（深玫红），`已关注` 走 `PBadgeType.status` 时呈浅粉胶囊；切到 Miuix 桥接后 `secondaryContainer = #E8E2E6`（中性灰）、暗色 `#48434A`，`status` 再叠 0.45/0.55 alpha，粉色语义随调色板迁移丢失。并非有意改设计。
2. **角标与标题不一致**：封面统计/时长角标字号固定 10、内边距固定 5/1，标题随基底继承 14；三项统计若直接塞进现有胶囊，在约 228px 卡宽下必与右下时长角标重叠。
3. **热门章位置与信息口径分裂**：`rcmd_reason` 是官方下发的推荐理由，之前整枚放在封面左上角；「热门」与「百万播放/人气飙升」等定性理由混在一处，点赞数另由 `stat.like` 拼装，同一卡同一条信息分散在两个位置。

## 三、方案

1. `lib/common/widgets/video_card/video_cover_stat_badge.dart` 新增 `VideoCoverStatBar`：
   - 单一 70% 黑底圆角胶囊，内含播放 / 弹幕 / 点赞三项；三项分别使用低饱和柔彩 `#8FB4CC`（柔蓝）/ `#9AC4A8`（柔青绿）/ `#D9A8BA`（柔玫红），图标与数字同色；时长胶囊仍为黑底白字。
   - 名义字号默认取 `DefaultTextStyle`（与标题同源 14）；内边距、图标、项间距均按 `MediaQuery.textScalerOf` 的**实际渲染字号**等比推导，UI 缩放时保持比例。
   - `LayoutBuilder + TextPainter` 实测宽度：按 `[1.0, 0.94, 0.88, 0.82, 0.76, 0.70, 0.64]` 逐级回落字号（下限 9），保证「统计胶囊 + 8px 安全间距 + 时长胶囊」不超过封面可用宽度；极端窄卡/超大字号仍放不下时，再用 `FittedBox(scaleDown)` 整组等比兜底，杜绝 RenderFlex 溢出与叠压。
   - 横向卡共用的两数据版 `VideoCoverStatBadge` 保持原样，不受影响。
2. `lib/common/widgets/video_card/video_card_v.dart`：
   - 封面底部改为 `Positioned(left: 7, right: 7, bottom: 6)` 的单条 `VideoCoverStatBar`；点赞取 `stat.like`（App 流回退时为推荐理由解析值）。
   - 底部原点赞胶囊移除；同一位置在 `rcmd_reason.trim() == '热门'` 时渲染 `PBadge('热门')`，`fontSize` 取标题名义字号（14）、内边距按字号等比；`rcmd_reason` 仍为「热门」时不再上封面，其余定性理由（非点赞/非关注类）继续留封面左上角。
   - 演示卡同步：稳定随机理由只保留「热门 / 高播放 / 宝藏新作」，热门进底部章位、其余上封面；点赞量进封面统计胶囊。
3. `lib/common/widgets/p_badge.dart` 新增 `PBadgeType.followed`：
   - 浅色 `#FFDADA` 底 + `#5F1212` 字，暗色 `#5D3F3F` 底 + `#FFDADA` 字，逐位恢复迁移前 MD3 粉色胶囊。
   - `已关注 / 新关注` 的智能推断同步指向 followed；`VideoCardV`（正常 + 演示）与 `demo_mask.dart` 的 `DemoVideoCard` 已关注胶囊切到该类型。

## 六、遗留与踩坑

1. 横向卡（`VideoCardH`、收藏、稍后再看、历史）仍用两数据 10px `VideoCoverStatBadge`；本轮只改首页竖卡口径，未动横向封面 16:9 的宽度预算。
2. 「热门」只认 `rcmd_reason` 原值完整等于「热门」。热门列表接口 `/x/web-interface/popular` 实测多为「百万播放 / 5万点赞 / 人气飙升」，因此热门页卡片通常不会出现底部「热门」章——这是“只有官方打上才显示”的预期行为。
3. 三项统计 + 时长在约 228px 卡宽、14px 字号下多数组合可容纳；长数字（如 `8765.4万`）会触发 0.82 档回落（约 11.5px）。这是按“过长即回落”要求的预期表现。
4. `PBadgeType.followed` 保留独立语义，后续若换品牌粉浅底样式只需改一处；`PBadgeType.status` 继续服务「已收藏」等辅助状态，未受影响。
5. `DemoVideoCard` 与正常竖卡仍有历史结构差异（UP 行与热门章同行）；本轮只同步章位、配色与统计口径，未重排 demo 整卡结构。

## 七、总结

点赞量并入封面统计胶囊、三色区分且字号对齐标题并带自动回落；原点赞位改为仅官方 `rcmd_reason == '热门'` 时出现的「热门」章；已关注恢复迁移前的浅粉胶囊。静态分析、288 项单测、Windows debug/release 双编译全部通过，等待实机复看配色与回落观感。
