# 全局返回按钮与 Esc 分层返回体系修复复盘（2026-09-28）

> 需求：统一任意非根页面的所有左上角返回按钮，使其在**任一界面**都可通过 Esc 返回上一级；
> 若处于输入框则 Esc 先取消聚焦（消耗一次 Esc）；若打开了 popups / overlays / flyouts 等
> 二级控件，Esc 直接不保存并关闭该控件（消耗一次 Esc）。

---

## 1. 分析根因

### 1.1 问题①：Esc 在绝大多数页面失灵 —— 全局兜底挂错层级（根因已取证）

`lib/ui/app.dart` 原有一个全局 Esc 兜底 `Focus`，但它挂在 `MaterialApp.home` 路由**内部**（AgreementGate → AppRoot）。Flutter 在路由 push 时会把焦点移入新路由子树（框架源码 `routes.dart:1691` `didPush → setFocusScopeNode`），该兜底 `Focus` 不在新路由的焦点祖先链上 —— **搜索页/设置页/个人空间/收藏等全部压栈页面收不到 Esc**。

框架自身的 `Escape → DismissIntent` 也兜不了底：`MaterialPageRoute.barrierDismissible = false`（`material/page.dart:44`），`_DismissModalAction.isEnabled` 直接返回 `route.barrierDismissible`（`routes.dart:981-983`），普通页面永远禁用。

### 1.2 问题②：返回按钮五种写法并存（行为/视觉不统一）

| 写法 | 数量 | 位置示例 |
|---|---|---|
| `AppBackButton`（统一组件，maybePop） | 5 | dynamics/detail、live_room、bangumi_detail、search_page、search_result |
| 手写 `IconButton(AppIcons.back)` | 4 | video/detail（**直接 `Navigator.pop`**）、bangumi_player、member_space、live_room 全屏栏 |
| 框架 `BackButton()` | 1 | member_space 错误态 |
| AppBar 自动 leading | ~16 | download/article/fav/setting/whisper 系（主题已统一图标，行为即 maybePop） |
| `Icons.close` | 1 页 | login_page（fullscreenDialog 却用了裸关闭图标，未走自适应组件） |

### 1.3 问题③：二级浮层不响应 Esc（无路由承载，框架机制覆盖不到）

- 表情面板 `common/widgets/comment/emote_picker.dart`（OverlayEntry，全站复用：视频/动态/直播/番剧）；
- 弹幕样式浮层 `pages/video/send_danmaku_panel.dart`（OverlayEntry 内联模式）；
- 章节面板、音量弹层 `pages/video/player_panel.dart`（Stack 伪浮层）。

### 1.4 问题④：输入框内 Esc 直接弹页（无焦点守卫）

- 番剧播放页 `bangumi_player_page.dart:683` `_handleKey` 无输入守卫：评论框里按 Esc **直接退出页面**，空格/←→ 还会误触播放器；
- 视频页 `player_focus.dart` 同样无守卫：内联弹幕框聚焦时快捷键泄漏；
- 直播页原有 `_danmakuInputFocusNode.hasFocus` 守卫（思路正确，本次统一为共享判定）。

## 2. 设计修复计划（已按此实施）

### 2.1 统一 Esc 分层语义（每层消耗一次 Esc，不级联）

| 顺序 | 场景 | 行为 |
|---|---|---|
| 1 | 路由级弹层在最上层（对话框/底部弹层/菜单/下拉，`PopupRoute`） | `Navigator.maybePop()` 关闭，不保存 |
| 2 | 自定义二级浮层已打开（表情/弹幕样式/章节/音量） | LIFO 关闭最上层一个（`EscapeLayerRegistry`） |
| 3 | 焦点位于文本输入框（`EditableText` 系） | `primaryFocus.unfocus()` 取消聚焦 |
| 4 | 可返回的非根页面 | `Navigator.maybePop()` 返回上一级 |
| 5 | 其他（根页面等） | 不处理（透传框架，如 tooltip 消除） |

内层消费者优先：视频/番剧/直播播放器、图片画廊、`MenuAnchor` 菜单的 Esc 处理均位于焦点链更内层，先于本链执行（已逐条核对框架源码：`menu_anchor.dart:71-73` 菜单自带 Esc 映射；`shortcuts.dart:922-937` 禁用 action 返回 `ignored` 且 `modal=false` 默认）。

### 2.2 挂载点：`MaterialApp.builder` 内包一层 `AppEscapeScope`

`builder` 的结果被 `WidgetsApp` 的 `Shortcuts`（`app.dart:1813-1854`）包裹，因此该位置：
- 对**任意路由（含对话框）的焦点链都是祖先** → 任一界面都能收到未消费的 Esc；
- 位于内层消费者**之后**、框架 `Escape→DismissIntent` 映射**之前** → 既有语义不破坏，无需平台层键盘钩子（未引入 `HardwareKeyboard`/win32 钩子）。

## 4. 本轮修复总结

- **改动面**：13 个文件（2 新增 + 10 修改 + 1 测试 + 1 文档），+178 / -87（不含文档）。
- **行为预期**：
  1. 任一界面按 Esc 均遵循「弹层关闭 → 浮层关闭 → 取消聚焦 → 返回上一级」的分层语义，每层只消耗一次；
  2. 非根页面返回按钮统一走 `AppBackButton`（默认 `maybePop`，全屏对话框路由自动渲染关闭图标与 tooltip）；
  3. 播放器页与键盘 Esc 语义完全一致（全屏 → 网页全屏 → 退出页面的逐级退出保持不变）。
- **已知行为变化**：
  1. 极验验证码弹窗（`barrierDismissible:false`）现在可被 Esc 关闭（等效“取消验证”，登录页已优雅处理 null 结果）；
  2. 输入框内 Esc 不再触发页面返回（此前属缺陷）；
  3. 文本选择工具栏：Esc 优先“取消聚焦”（工具栏随焦点消失而收起）；
  4. 视频/番剧返回按钮保留 `pause + detachListeners` 即时停止副作用；Esc 直弹路径由
     `WinWinPlayerController.dispose`（先置 `stopped`，见《返回按钮控件导致程序崩溃》修复）兜底安全。
- **遗留项**：
  1. 搜索页联想列表在 Esc 取消聚焦后仍可见（按规格“仅取消聚焦”字面实现，如需一并收起可追加）；
  2. geetest 为 WebView2 平台视图，若其聚焦时键盘事件被平台层吞掉，Esc 可能无效（平台限制）；
  3. AppBar 自动 leading 的 ~16 页与封面黑圆返回按钮保留现有视觉（行为/图标已统一），未做无效改动。
