# 下拉刷新失效复盘（首页 / 动态 / 消息中心）— 2026-11-02

## 一、现象

用户实机反馈：**首页（推荐/热门/关注/番剧）、动态页、消息中心**三个页面下拉刷新完全无响应
（指示环不出现、数据不重新拉取）；其余页面（关注列表、收藏、搜索等）未受影响。

## 二、定因

三处实际是两个**同类**缺陷 —— 「为某个滚动视图（或其容器）定制的 `ScrollBehavior`，
用 `ScrollConfiguration` 包住了一大片子树」：

1. **首页 / 热门 / 关注 / 番剧（`AppScrollBar` 内层）**
   `lib/common/widgets/app_scroll_bar.dart` 原用一个**新建的** `_NoFrameworkScrollBar`
   （`class _NoFrameworkScrollBar extends ScrollBehavior`，只重写 `buildScrollbar`）包住
   子树。`ScrollBehavior` 的 `dragDevices` 默认**不含 `PointerDeviceKind.mouse`**，
   而 `dragDevices` 是**继承**属性：手动 `AppScrollBar(...)` 包裹的页面，其
   `CustomScrollView` 位于这层 `ScrollConfiguration` 之下 ⇒ 鼠标按住下拉不再产生
   `ScrollStart/Overscroll` 通知 ⇒ `AppRefreshIndicator` 的 `_shouldStart` 永不成立。
   （滚轮不受影响，所以「能滚动、不能下拉刷新」。）

2. **动态页（`AppTabView` 子页）**
   `lib/ui/components/app_tab_view.dart` 宽屏分支用
   `ScrollConfiguration(behavior: _AppTabPageScrollBehavior())` 包住**整个 `PageView`**。
   该行为只重写 `dragDevices`（剔除鼠标，用于「关闭鼠标拖动翻页」），于是各 tab 子页里的
   滚动视图同样继承「无鼠标」⇒ 下拉刷新失效。窄屏（< `kAppTabBreakpoint`）不包，故只在
   宽屏桌面复现。

3. **消息中心（指示环被合并栏盖住）**
   页面结构为 `Stack[Positioned.fill(AppRefreshIndicator), Positioned(top:0, 合并栏)]`，
   合并栏（互动入口 + 分类条，实测约 180px）绘制在内容之上，而指示环 `edgeOffset` 默认 0
   （环体落在 y≈32~81）⇒ 刷新其实**已触发**，但环被面板整块遮住，实机表现为「没反应」。

> 佐证：以 `test/support/app_test_host.dart`（与 `AppShell` 同构、含全局
> `AppScrollBehavior`）为宿主，用**鼠标**拖拽复刻三种页面结构 —— 修复前「裸结构」（A）与
> 「Stack 叠层」（D）可触发，`AppScrollBar` 包裹（B）与 `AppTabView` 子页（C）均 `called == 0`；
> 修复后四项全部通过。触摸设备默认就在 `dragDevices` 里，普通 `tester.drag`（触摸）测不出该缺陷。

## 三、方案

| # | 文件 | 改动 |
|---|------|------|
| ① | `lib/common/widgets/app_scroll_bar.dart` | 删除 `_NoFrameworkScrollBar`；`_suppressFrameworkBar` 与 `_buildLane` 改用 `ScrollConfiguration.of(context).copyWith(scrollbars: false)` —— 只关框架条，`dragDevices` / `getScrollPhysics` 全部委托环境行为（`AppScrollBehavior`） |
| ② | `lib/ui/components/app_tab_view.dart` | `AppTabBody` 的宽屏「禁用鼠标拖动翻页」改为 `PageView(scrollBehavior: _AppTabPageScrollBehavior())`（只作用于 PageView 自身的 `Scrollable`），不再用 `ScrollConfiguration` 包整棵子树 |
| ③ | `lib/pages/dynamics/view.dart` | `AppRefreshIndicator` 增加 `edgeOffset: AppTabView.floatingTopReserve`（避让浮动态 Tab 栏） |
| ④ | `lib/pages/whisper/view.dart` | `AppRefreshIndicator` 增加 `edgeOffset: _headerHeight ?? _headerReserve`（避让顶部浮动合并栏，取实测高度） |
| ⑤ | `lib/core/shell/app_shell.dart` | 注释同步（`_NoFrameworkScrollBar` 已删除，改为 `copyWith(scrollbars: false)` 口径） |
| ⑥ | `test/ui/components/pull_to_refresh_drag_test.dart`（新增） | 2 项回归：`AppScrollBar` 包裹、宽屏 `AppTabView` 子页内，**鼠标**下拉均可触发 `onRefresh` |

## 六、遗留与踩坑

1. **`dragDevices` 是继承属性**：任何「只想改某个滚动视图行为」的 `ScrollBehavior`，
   都必须经组件自带的入口（`PageView.scrollBehavior` / `Scrollable.scrollBehavior`）注入，
   不要用 `ScrollConfiguration` 包大子树；确实需要包子树时用
   `ScrollConfiguration.of(context).copyWith(...)` 委托环境行为。
2. `_TabRailScrollBehavior`（TAB 轨道）仍用 `ScrollConfiguration` 包裹，但其子树只有
   标签条本身（无内容列表），且轨道为横向，不影响下拉刷新 —— 保持不变。
3. 消息中心若用户**从合并栏面板上**起手下拉，手势不会到达列表（面板是独立叠层、含可点条目）。
   本轮只解决「列表区下拉看不见反馈」；把面板做成可下拉的一部分会与条目点击冲突，暂不做。
4. 触摸/触控笔路径此前未受影响（默认 `dragDevices` 本就含触摸类设备），故该缺陷只在桌面鼠标下暴露。

## 七、总结

三页下拉刷新失效是两个同类根因（`ScrollConfiguration` 把「无鼠标」的 `dragDevices` 继承给了
内容列表）叠加一处观感问题（指示环被浮动面板遮挡）。改为 `copyWith(scrollbars: false)` 委托
环境行为、`PageView.scrollBehavior` 局部注入、并给两个浮动栏页面补 `edgeOffset`；新增鼠标拖拽
回归测试锁定，全量单测与 Windows 双编译均通过。
