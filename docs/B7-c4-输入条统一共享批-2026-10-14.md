## 一、现象描述

底部「输入条」在多个页面各有一套私有实现，容器高度与内边距各不相同，控件未真正共享：

- **直播互动输入条**（`live_room_page.dart` `_buildChatInputBar`）：总高固定 **8+40+8=56**，背景 `surfaceContainerHighest α0.35`、字段外套**固定 40px / r20 胶囊**、发送键 `64×40 / r20`。
- **评论输入条**（视频页 `_buildCommentInputBar`、共享 `SimpleCommentInputBar`、番剧页、弹幕内联条）：上下 `Style.xs` 留白，背景 `surface`、顶部 0.5 描边，发送键 `56×34 / r10`。

实机对比（用户截图）：直播间互动输入框聚焦态的**承载边框容器高度**与评论区输入框不一致 —— 即二者输入框控件口径不同源、未共享。

## 二、问题根因

- `SimpleCommentInputBar`（`lib/common/widgets/comment/comment_input_bar.dart`）虽为「共享」命名，但**只覆盖专栏/动态两页**；视频页、直播页、番剧页、弹幕内联条**各自复制了一套容器骨架与按钮口径**。
- 直播页刻意做成「严格等高 40px 胶囊」的**另一套设计**，与评论条口径（`Style.xs` 留白 + 紧凑 34 高按钮）分叉，导致同一「底部输入条」语义出现两套承载容器。
- 结论：问题不在单个页面的像素，而在**组件未真正普适**——同类控件存在多条重复/分叉代码路径。

## 三、修复方法

1. **共享组件升级**：`SimpleCommentInputBar` → **`CommentInputBar`**（同文件），收敛为全站统一底部输入条，新增 hook 以覆盖各处差异：
   - `onPressed`（点击前置动作，如视频页登录校验）
   - `suffix`（右侧自定义后缀，如「取消回复」）
   - `showClear`（文本非空即显示一键清空，直播弹幕用）
   - `requireText`（发送键要求文本非空才可用，直播弹幕用）
   - `showEmote`（是否展示左侧官方表情按钮）
   - `sendLabel`（发送键文案）
   - `onSend` 回调类型 `Future<void> Function()` → `VoidCallback`（兼容 void/Future 两种返回）
2. **视频页**：`_buildCommentInputBar` 改为**薄适配器**，仅传入本页参数（controller/焦点/发送态/登录校验/hint/suffix），容器与骨架全部来自 `CommentInputBar`（**零视觉变化**）。
3. **直播页**：`_buildChatInputBar(cs, tokens)` → `_buildChatInputBar()`，内部返回 `CommentInputBar`，容器口径整体对齐评论条（`surface` 底 + 顶部 0.5 描边 + `Style.xs` 上下留白 + `56×34/r10` 发送键）；`requireText:true`、`showClear:true`、`enabled:_isLiving && !_isSendingDanmaku` 保留原逻辑。
4. **专栏/动态**：调用点类名同步为 `CommentInputBar`。
5. **导入清理**：随条收敛移除失效导入 3 处（video/live 的 `emote_picker`、video 的 `app_components`）。
