# 动态页顶栏与Tab栏顺序修复复盘-2026-10-19

> 主题：动态根页面的「顶部安全行（标题「动态」）」与「分类 Tab 栏（全部/视频/追番/专栏）」
> 垂直顺序与其它根页面相反，本轮修正为「标题在上、Tab 栏在下」的根页面标准顺序。
> 归属：B7 封板（MD3 库级退役收官）之后的**实机反馈修复**。

## 一、现象

用户实机反馈（附截图）：**动态页的顶栏与 Tab 栏位置反了**。实机可见：分类 Tab 栏
（全部 / 视频 / 追番 / 专栏）渲染在最顶部，而页面标题「动态」反而出现在 Tab 栏**下方**；
其它根页面（首页 / 历史 / 消息 / 我的）都是一致的顺序——**顶部安全行（标题）在上 → 内容在下**。
用户诉求：使动态页符合其它根页面的布局顺序。

## 二、定因（根因链）

1. `DynamicsPage.build`（`lib/pages/dynamics/view.dart`）把分类 Tab 栏放进了
   `AppScaffold(topBar: AppTabBar(...), title: '动态', body: AppTabBody(...))` 的 **`topBar` 槽**。
2. `AppScaffold`（`lib/core/shell/app_scaffold.dart`）把 `topBar` 透传给
   `MiuixScaffold.topBar`。
3. `MiuixScaffold`（`scratch/flutter_miuix_src/.../miuix_scaffold.dart`）的布局中，
   `_ScaffoldSlot` 的入列顺序为 `body → topBar → …`，即 **topBar 绘制在 body 之上**；
   同时把内容内边距的 `top` 设为 `topBarSize.height`（`onPadding(EdgeInsets.fromLTRB(...))`）。
4. `AppScaffold` 的**顶部安全行（标题所在行）在内容内部**（`content` 的 Column 首行），
   会随内容内边距被整体下移到 topBar 之下。
5. **净结果**：动态页的实际顺序为 `[Tab 栏] → [顶部安全行「动态」] → [内容]`，
   与其它根页面的 `[顶部安全行（标题）] → [内容]` **恰好相反**（顶栏与 Tab 栏互换）。

> 旁证：`AppScaffold` 文档注释已写明 2026-10-08 起「项目去除页面标题栏」，`topBar` 槽
> **仅保留给个别必需场景（如分类 Tab 栏）**；而根页面标题由**顶部安全行**承载——两者本应
> 「安全行在上、Tab 在下」，把 Tab 放进 topBar 槽即破坏了这一顺序。

## 三、方案

**最小改动**：把分类 Tab 栏从 `topBar` 槽移入 `body`，用现成组件 `AppTabView`
（= `Column[AppTabBar, Expanded(AppTabBody)]`，`lib/ui/components/app_tab_view.dart`）承载，
使顺序回归「顶部安全行（标题「动态」）在上 → Tab 栏 → 内容」。

理由与取舍：
- **复用既有组件** `AppTabView`（P4「每个概念只在一处定义」），不新造 Tab 头/体组合；
  头体本可分别落位（组件注释已说明用途），此处头体上下并列 → 正好用 `AppTabView`。
- **不动 `AppScaffold` / `MiuixScaffold` 语义**：`topBar` 槽的既有行为（渲染在安全行之上、
  给内容留内边距）保持不变，其它页面零影响。
- Tab 栏以 **Column 式**排布（不叠压内容），故**无需**给 `_DynTabPage` 增加避让 padding
  （与原先在 topBar 槽时「内容被内边距下推、不重叠」的观感一致）。
- 未采用「Stack 浮动 Tab 栏」方案：那会让内容从 Tab 栏后穿过，需给 `_DynTabPage` 补顶部
  padding，改动面更大、风险更高，收益无差。

## 六、遗留与踩坑

1. **`AppScaffold.topBar` 槽的语义**：该槽由 `MiuixScaffold` 渲染在**顶部安全行之上**，
   仅适合「独立于安全行、需盖住内容」的顶栏（如毛玻璃浮动顶栏）。**页面标题类**内容
   不要放此槽，否则会与安全行顺序颠倒（本缺陷即此）。
2. **顺序正确的前提**：只要不使用 `topBar` 槽，顶部安全行由内容内边距自动落到最上，
   顺序天然与其它根页面一致——无需手工排序。
3. **二级页面复用**：动态页亦被 `showDynamicsPage` 以 push 形式打开（`canPop` 为真），
   此时顶部安全行显示**返回按钮**而非标题（`AppScaffold` 的 `canPop` 分支）；本次改动
   对该场景同样友好（Tab 栏仍在安全行之下）。
4. **同类排查**：本轮已核对其它根页面（首页 `title:'首页'` + body 内 `_HomeHeader`；
   历史 `title:'历史'`；消息 `title:'消息'`；我的 `title:'我的'`）均未使用 `topBar` 槽，
   顺序一致，无需改动。

## 七、总结

动态页把分类 Tab 栏误放进 `AppScaffold.topBar` 槽，而该槽渲染在顶部安全行（标题）**之上**，
造成「Tab 栏在上、标题在下」的顺序与其它根页面相反。本轮将该 Tab 栏改由 body 内的
`AppTabView` 承载，顺序回归「顶部安全行（标题「动态」）→ Tab 栏 → 内容」，与首页/历史/
消息/我的一致；改动仅 1 文件，`dart analyze` 0 错 0 警告，debug / release 双编译均通过。
