## 一、分析根因

### 1.1 为什么必须"换机制"而不是"调参数"

上轮复现结论：FFmpeg 的 loudnorm / dynaudnorm 是**动态滤镜**，必须前瞻缓冲才能工作：

| 滤镜 | 前瞻代价 | 实机表现 |
|---|---|---|
| `loudnorm=I=…:linear=true` | 线性模式需数秒前瞻 | 音频整体**滞后**（音画不同步） |
| `dynaudnorm=g=5:f=250` | ≈1.25s 前瞻 | **完全无声** |

⇒ 只要走滤镜链，实时链路就必然付出前瞻代价。**换机制 = 不进入滤镜链**。

### 1.2 D 的数据基础（B 站已提供，无需自研）

`lib/models/video/play_url.dart` 的 `Volume` 模型直接承载 playurl 返回的响度元数据：

```dart
final num measuredI;   // 实测整体响度（LUFS，负值）
final num measuredTp;  // 实测真峰值（dBTP）
final num targetI;     // 目标整体响度
final num targetTp;    // 目标真峰值
bool get isNotEmpty => …;   // 是否有有效实测数据
```

⇒ 静态增益可以**纯计算**得到，零运行时缓冲。

### 2.2 D：静态增益机制（无前瞻）

新增三个成员（`player_controller.dart`）：

```dart
double _normalizationGain = 1.0;                       // 静态增益（线性倍率）
double get _audioInstanceVolume =>                     // 第二实例应设的音量
    (volume.value / 100.0) * _normalizationGain;       //   用户音量 × 增益
void _recomputeNormalizationGain(Volume? v) { … }      // 按媒体元数据重算
```

**增益算法**：

1. 增益(dB) = `目标响度 − 实测响度`（如 −14 − (−20) = +6 dB）；
2. **真峰值余量**：放大后峰值不得超过 −1 dBTP（`gainDb ≤ −1 − measured_tp`）⇒ 防削顶失真；
3. **安全钳制**：`gainDb` 夹在 [−6, +12] dB 内 ⇒ 防极端放大/衰减；
4. `增益 = 10^(gainDb/20)`。

**无有效数据时**（`measured_i` 非负，说明该条流没有实测响度）或**禁用**时，增益恒为 1.0（不改变）。

**接线**（6 处音频实例音量写入点全部改为合成音量，避免"改了机制但某条路径漏乘"）：

| 位置 | 场景 |
|---|---|
| `_recomputeNormalizationGain` 调用点 | 双实例分支准备媒体时（按本次媒体元数据重算） |
| `ap.volume`（双实例分支） | 挂媒体时（闸门期间仍置 0） |
| `ap.volume`（`releaseStartupGate`） | 闸门释放恢复音量 |
| `ap.volume` ×2（音频实例自愈重挂） | 弱网/停摆恢复路径 |
| `_audioPlayer?.volume`（`setVolume`） | 用户调音量 |
| `ap.volume`（`setAudioNormalize`） | 用户切换模式时立即生效 |

### 2.3 覆盖探针

每次媒体准备重算增益时记录一条 `[W]` 级覆盖日志（`Coverage` 标签）：

```
Coverage: loudness gain: measuredI=… targetI=… tp=… → 1.995x
```

用途：让"静态增益是否真的生效、算出多少倍"可从**日志客观核对**，而不是只靠听感。

## 四、本轮修复总结

**改动面**：**1 个文件，+85 / -16 行**（`lib/pages/video/player_controller.dart`），另有本文档。

**行为预期**：

- 音频设置菜单恢复显示，音轨信息真实（B）；
- 响度对齐以**静态增益**实现：零前瞻、零延迟，**不进入滤镜链**，因此不触碰音画同步（D）；
- 增益带真峰值保护与安全钳制，极端元数据不会导致削顶或异常音量；
- 6 处音量写入点统一走 `_audioInstanceVolume`，避免"某条路径漏乘增益"的新分叉。

**遗留项**：

1. **UI 文案语义**：`1`（动态压缩 dynaudnorm）在当前实现下**退化为静态响度对齐**（动态压缩所需的前瞻缓冲实时不可用）。代码注释已说明，但**设置页/面板文案仍显示"动态压缩"**，建议后续调整为"响度对齐"或直接去掉该选项——属产品文案决策，待确认；
2. **主实例仍保留旧滤镜下发代码**（`_createPlayer` / `setMedia` 对主实例设 `audio.avfilter`）：在双实例下主实例为 video-only，该下发**恒为空操作**，属无害历史遗留；未删除以缩小改动面，后续可随"双实例硬编码"一并清理；
3. **三处页面 RenderFlex 溢出仍未定位**（收藏夹详情 16px / 历史记录 12px / 稍后再看 16px）：卡点是 `json_file_handler.dart:97` 的 `report.toJson()` 丢失了 Flutter 的「relevant error-causing widget + file:line」；建议后续链式挂 `FlutterError.onError` 记录完整诊断后再复现定位（详见回滚复盘文档附录）。
