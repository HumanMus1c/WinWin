# 切换显示器 / 修改分辨率后 UI 冻结修复复盘（2026-10-20）

## 一、现象

- 程序运行中**切换显示器**（把窗口所在屏幕改到另一台）或**修改屏幕分辨率**（同一显示器切到别的分辨率）后，界面**失去响应、无法操作**；鼠标可能仍可移动，但点击/输入无反应，只能强制结束进程。
- 日志特征：`D:\Documents\logs\runtime.log` 最后一条为 `19:01:06 … shared player teardown deferred by 400ms for raster drain`，此后**完全静默**（用户在 19:13 报告冻结）——**无 Dart 异常、无后续日志**，属典型 UI/线程挂死而非崩溃。
- 触发条件倾向 **release** 构建（上游同类回归同样仅 release 复现）。

## 二、定因

### 主因：Flutter Windows 默认「合并」UI isolate 与平台线程

- `windows/runner/main.cpp` 原先只设置了 `project.set_impeller_switch(flutter::ImpellerSwitch::Disabled)`，**未设置线程策略** → 走 `UIThreadPolicy::Default`。
- 引擎实现中，`Default` 实际等价于「UI 跑在平台线程」：`flutter/engine/…/flutter_windows_engine.cc` 里
  `if (ui_thread_policy() != RunOnSeparateThread) { custom_task_runners.ui_task_runner = &platform_task_runner; }`
  ——即**只有显式 `RunOnSeparateThread` 才是分离线程**；`dart_project.h` 中「Default 当前在独立线程运行」的注释是**过期的**，与引擎实现矛盾。
- 本项目是「**无边框（`TitleBarStyle.hidden`）+ 自研原生全屏 + fvp 外挂 D3D11 共享纹理**」的重窗口形态。切换显示器 / 改分辨率时，系统会集中投递 `WM_DPICHANGED` / `WM_SIZE`，并触发多路 `SetWindowPos(SWP_FRAMECHANGED)`（runner 的 `WM_DPICHANGED` + window_manager 的 `ForceChildRefresh()` + 全屏 `titleBarStyle` 切换），在**合并线程**下与 Dart 执行互相阻塞 → 线程级死锁。
- 上游同型回归：`flutter/flutter#176088`（官方已复现，3.35 / 3.37 均中招），复现配置即 `titleBarStyle.hidden` + 窗口操作，**仅 release**，官方 workaround 就是显式 `set_ui_thread_policy(RunOnSeparateThread)`。

### 次要候选（本次未处理，留作第二步）

- **fvp/MDK 的 D3D11 设备丢失**：`main.dart` 设了 `mdk.setGlobalOption('d3d11.sync.cpu', 1)`（CPU-GPU 同步栅栏），显示器/分辨率切换是 DXGI 设备重置的经典触发点，卡在同步栅栏会死锁。判别点：此因应「仅播放视频时」复现。
- 分辨率缩小后窗口落到屏外（启动期 `calcWindowPosition` 与 `WindowStateController.restoreAndListen` 两条恢复路径分叉）——只影响启动期，与「会话中冻结」不符，可排除。

## 三、方案

在 `windows/runner/main.cpp` 的 `set_impeller_switch` 之后**显式分离线程**：

```cpp
project.set_ui_thread_policy(flutter::UIThreadPolicy::RunOnSeparateThread);
```

- 成本一行、可逆、判别性强：若冻结消失 → 主因坐实；若仍冻结 → 转第二步 D3D 方向。
- 同时修复一处**既有** analyze 红（与本改动无关，见「五、遗留与踩坑」），单独提交，保持各 diff 最小。

## 五、遗留与踩坑

1. **既有 analyze 红（已单列修复）**：`test/theme/app_icons_test.dart:293` 构造 `SessionMoreMenuButton` 时缺必填参数 `onReport`。根因是 `5bcb56e`（把「举报」并入会话「更多选项」）为控件新增了 `required VoidCallback onReport` 但漏改该单测。与本次冻结修复无关，按「最小 diff + 独立提交」单独补 `onReport: () {}`。
2. **合并线程 → 分离线程后的回归面**：需观察启动速度、转场流畅度、播放器首帧与 raster 线程交互是否有观感变化（分离线程在历史上是 Flutter Windows 的默认，属「回到旧行为」，风险低但需实测确认）。
3. **第二步（若本步无效）**：临时在 `WM_DISPLAYCHANGE` / `WM_DPICHANGED` / `WM_SIZE` 与 MDK 拆除处加日志，并试 `d3d11.sync.cpu=0` 对照；实机复现时记录窗口 rect / 所在显示器 / DPR 的前后值。

## 六、总结

WinWin 的「切屏 / 改分辨率后冻结」首要根因是 **Flutter 3.35+ Windows 默认把 UI isolate 与平台线程合并运行**，叠加本项目**无边框 + 自研原生全屏 + fvp D3D11 纹理**的重窗口形态，在显示配置变更引发的窗口重构风暴下发生线程级死锁。修法是**一行显式声明分离线程**（对齐上游 `flutter/flutter#176088` 的官方 workaround），可逆、判别性强。本轮只做第一步，第二步（D3D 方向）作为备选待命。
