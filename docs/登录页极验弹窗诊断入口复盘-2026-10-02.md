## 一、分析根因（为什么需要诊断入口）

### 1.1 现象描述

material_ui 1.5.0 升级的实机验证清单中，「登录页极验 WebView 弹窗」是**唯一无法执行**的验证项：

- 极验弹窗仅在**未登录态**下、真实登录/短信请求遇风控（`code=-105` / `recaptcha_url`）时触发；
- 用户无其它账号、不愿退出当前登录 → 无法安全复现风控触发；
- 而该弹窗正是**兼容桥接（MaterialUiCompatibilityBridge）+ flutter_inappwebview WebView 链路**的核心验证点，不能跳过。

### 1.2 关键取证（取参通道现成可用）

| 事实 | 取证 |
|---|---|
| 真实触发路径 | `login_page.dart:274`（密码登录）与 `:510`（短信发送）→ `GeetestWebviewDialog.show(context, gt, challenge)` |
| **无需登录的取参接口** | `LoginHttp.preCapture()`（`login.dart:312`）= POST `Api.preCapture` → `{status, data:{gee_gt, gee_challenge, recaptcha_token}}`；短信发送兜底路径即用此接口（`login_page.dart:488-501`） |
| 弹窗与真实一致 | `GeetestWebviewDialog` 内部走 gettype.php 配置拉取 → 滑块 → success/error/close 回调，与真实链路共用同一实现 |

→ 诊断方案成立：**复用 `preCapture()` 取参 + 复用真实弹窗**，完全绕过风控触发，链路同构。

---

## 二、设计修复计划（关键决策）

1. **入口**：登录页 `AppBar.actions` 的 `IconButton`（`Icons.bug_report_outlined` + tooltip「诊断：极验弹窗（临时）」）——页面级、四 tab 通用；不 gate，Debug/Release 均可见（需覆盖双配置复测）。
2. **逻辑** `_debugShowGeetest()`：`preCapture()` → 校验 `gee_gt`/`gee_challenge` 非空（失败 toast code/msg）→ `GeetestWebviewDialog.show` → `null`=关闭/取消 toast、非 null=成功 toast。
3. **探针**：`AppLogger.w('Geetest', ...)` 两条（trigger / result），**只记字段存在性与长度，不落 token 全文**（沿用日志脱敏口径）。
4. **零副作用**：不写任何状态、不发登录/短信请求、不改既有流程；全部临时代码以 `TEMP(geetest-diagnostic)` 注释标记（含移除说明）。
5. **关键取舍**：不从外网硬编码测试 gt —— 用真实 `preCapture` 保证弹窗内行为与线上完全一致；探针不落全文防止 token 进入日志文件。
