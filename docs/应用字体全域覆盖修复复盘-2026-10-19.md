# 应用字体全域覆盖修复复盘-2026-10-19

> 主题：把应用字体（如「苹方-简 / PingFang SC」）从"仅 flutter_miuix 组件生效"扩展为**全应用生效**。
> 归属：B7-e 过渡主题摘除（`42993fa`）之后暴露的**字体覆盖回退**之补正。

## 一、现象

用户在实机观察：设置里选中的应用字体（自定义导入的 PingFang SC）**只在「我的」页、设置页以及弹窗等表层生效**；其他页面（动态页、历史页、消息页、视频/评论等深层页）以及大量正文文字，观感**不像该字体**，疑似"设置的字体没有覆盖到所有地方"。

## 二、定因（根因链）

1. **历史机制**：字体最初（`6c24092`，2026-08-09）经 `MaterialApp` 的
   `theme: AppTheme.xxxFor(fontFamily:)` 挂到 `ThemeData.fontFamily`，由 Material 全局默认
   文本样式承载 → 天然覆盖整树。
2. **回退点**：B7-e（`42993fa`，2026-10-18）把应用壳从 `MaterialApp` 改写为 widgets 层
   `WidgetsApp`（`AppShell`），并**删除**了 `theme: AppTheme.*For(fontFamily:)` 三行。
   自此 `ThemeData.fontFamily` 这条全局载体消失。
3. **残留路径**：字体随后**只剩一条**注入点——`main.dart` → `AppShell(fontFamily)` →
   `MiuixThemeScope` → `miuixBridgeTextStyles()`（`lib/theme/miuix_theme_bridge.dart:65`）
   把 `fontFamily` 写进 `MiuixTheme.textStyles` 的 14 个槽位。
4. **后果**：只有**flutter_miuix 内部**文字（`MiuixText` / `MiuixBasicComponent` /
   `MiuixButton` / `MiuixNavigationBar` / `MiuixTabRow` / `MiuixTextField` / Miuix 弹窗等）
   吃到字体；而**文本基底层**与**裸控件**全部落空——根 `DefaultTextStyle`
   （`app_shell.dart`，无 `fontFamily`）、`AppTransparentHost`（每页正文宿主，无 `fontFamily`）、
   项目自有 `AppTextStyles`（`AppThemeHost.text.*`，**冻结为仅 color/decoration**，
   全仓 **267 处**消费）、页面内联 `TextStyle`、以及 Toast / 对话框 / Chip / 弹层菜单 / 标题栏等
   自建 `DefaultTextStyle` 站点。
5. **为何「我的 / 设置」正常**：这两页由 `AppListItem` / `AppGroup` 主导 →
   `MiuixBasicComponent` → `MiuixText`，字体已注入，故"看着对"。其他页用裸 `Text` /
   `tokens.text.*` → 引擎默认字体，故"看着不对"。**用户观察准确。**

> 关键约束：`AppThemeHost` 位于 `MiuixThemeScope` **之上**，故 `AppTokens` / `AppTextStyles`
> 无法读取 `MiuixTheme`；但 `MiuixThemeScope` **之下**的文本基底层站点可以读。

## 三、方案（方案 B：字体唯一来源统一到 MiuixTheme，注入文本基底层）

**不**逐个改写控件（全仓裸 `Text(` 638 处 / 318 文件、`TextSpan` 37、`WidgetSpan` 16、
`Tooltip` 122，逐点改造爆炸半径过大且易漏）；而是**单点定源 + 基底注入**：

1. 新增唯一取源入口（`lib/theme/miuix_theme_bridge.dart`）：

   ```dart
   String? appFontFamilyOf(BuildContext context) =>
       MiuixTheme.maybeOf(context)?.textStyles.main.fontFamily;
   ```

   字体**唯一来源 = `MiuixTheme.textStyles.main`**（与 `miuixBridgeTextStyles` 同源）；
   `MiuixTheme` 未挂载时返回 `null`（不改变既有样式，测试宿主/无 scope 场景安全）。

2. 在**文本基底层**各处补 `fontFamily: appFontFamilyOf(context)`，让一切"继承基底"的文字
   （裸 `Text`、`Text.rich`、`SelectableText`、`tokens.text.*`、第三方控件）随继承获得字体：
   - `lib/core/shell/app_shell.dart`（应用根 `DefaultTextStyle`）——用 `Builder` 包裹以取到
     `MiuixThemeScope` **之内**的 `context`；
   - `lib/core/shell/app_transparent_host.dart`（每页正文宿主）；
   - `lib/core/app_messenger.dart`（Toast 卡）；
   - `lib/common/widgets/app_dialog_shell.dart`（`AppAlertDialog` / `AppSimpleDialog`，共 4 处）；
   - `lib/common/widgets/app_chip.dart`（标签样式）；
   - `lib/common/widgets/miuix_popup_menu.dart`（弹层菜单基底）；
   - `lib/ui/components/immersive_title_bar.dart`（标题条「WinWin」）。
   - `lib/pages/setting/widgets/select_dialog.dart` 用 `DefaultTextStyle.merge(subtitleStyle)`，
     **merge 保留继承**，无需改（已随父基底自动获得字体）。

3. 效果：字体单一来源（MiuixTheme），基底层一次注入即全域覆盖；Miuix 组件路径**不变**
   （仍走 `miuixBridgeTextStyles`），两条路径同源同值，不会割裂。

## 六、遗留与踩坑

1. **`MiuixTheme.maybeOf` 的取源位置**：应用根 `DefaultTextStyle` 在 `AppShell.build(context)`
   里求值，该 `context` 位于 `MiuixThemeScope` **之外**（`maybeOf` 会得 `null`）。
   解法：用 `Builder` 包一层拿到 **scope 内** `context` 再取字体（`app_shell.dart`）。
   其余站点（`AppTransparentHost` / Toast / 对话框 / Chip / 菜单 / 标题栏）本就在 scope 之下，直接取即可。
2. **不改 `AppTextStyles`**：其冻结口径（仅 color/decoration，B2-t1 零漂移派生）保持不变，
   字体经**继承**获得，避免改动 267 处消费点的既有语义。
3. **残余空白（预期之外）**：H5 / WebView 类页面（如登录极验）使用 HTML/CSS 字体，
   不受应用 `fontFamily` 影响——属平台边界，非本次缺陷。
4. **向后兼容**：`MiuixTheme` 未挂载（如部分测试宿主）时 `appFontFamilyOf` 返回 `null`，
   `TextStyle.copyWith(fontFamily: null)` 为"不改变"，**零回归**。

## 七、总结

B7-e 摘除 `ThemeData.fontFamily` 后，字体仅存 `MiuixTheme.textStyles` 一条路径，导致
flutter_miuix 组件之外（文本基底层 + 裸控件）丢失应用字体。本轮以**方案 B**：新增
`appFontFamilyOf()` 把字体唯一来源锚定到 `MiuixTheme`，并在根 `DefaultTextStyle` 与
7 处文本基底站点统一补 `fontFamily`，使全域文字随继承获得应用字体；Miuix 路径不变，
零回归、零逐控件改造。`dart analyze` 与 debug/release 双编译均 0 错 0 警告。
