# 播放器最大化文案与弹幕保持复盘（2026-11-15）

## 一、现象

1. 播放器控制栏「应用内铺满窗口」按钮的悬停提示仍为「网页全屏 / 退出网页全屏」，
   与桌面端「最大化」语义不一致（需求：改为「最大化」）。
2. 进入/退出该模式（以及原生全屏，二者共用同一布局分支）时，画面上正在飞行的弹幕
   会**瞬间清空**，随后只从右侧按新进度重新进入；已上屏的弹幕无法保持。

## 二、定因

### 2.1 文案

`player_panel.dart` 控制栏按钮 tooltip 写死 `'网页全屏' / '退出网页全屏'`；
`demo_player_chrome.dart`（演示播放器）、`live_room_page.dart`（直播控制栏）同源；
`detail_page.dart` / `bangumi_player_page.dart` 的 Esc 返回按钮提示写「退出网页全屏（Esc）」。

### 2.2 弹幕被重建（根因）

- `detail_page.dart` 的 `build` 以 `isFillWindow = _fullscreen || _inAppFullscreen` 在
  **两棵完全不同的 body 子树**间切换：
  - 普通布局：`LayoutBuilder → CustomScrollView → SliverPersistentHeader(VideoHeader)
    → _buildPlayerContent → PlayerPanel`；
  - 全屏/最大化：`Stack → Positioned.fill → PlayerPanel`。
- `PlayerPanel` 没有稳定身份（无 GlobalKey），切换时旧 Element/State 被卸载、
  新 Element/State 被创建，连锁反应：
  1. 旧 `_WinWinDanmakuState.dispose()` 解绑播放器信号，并把 `danmakuEngine` 置空；
  2. 内层 `DanmakuScreen`（canvas_danmaku 渲染引擎）State 被 dispose →
     `_clearDanmakus()` 清空滚动/静态/高级弹幕并停 ticker；
  3. 新 State `initState` 重新绑定，`_lastProgressMs = -1`，下一次 position 拍
     只执行 `getCurrentDanmaku(当前 100ms 分桶)`（通常 0~几条），
     已飞行的弹幕不会重建 → 表现为「清屏 + 从右重新排队」。
- 番剧播放页 `bangumi_player_page.dart` 的 `isFill` 双分支结构相同，同病。

结论：不是弹幕数据被重新拉取，也不是设置项变化导致，而是**承载渲染引擎的
Widget State 因布局分支切换被销毁重建**。

## 三、修复方案

1. **文案**
   - 视频播放器控制栏：`'网页全屏' → '最大化'`，`'退出网页全屏' → '退出最大化'`；
   - 演示播放器控制栏、直播控制栏同步；
   - 视频/番剧全局返回按钮 Esc 提示：`'退出网页全屏（Esc）' → '退出最大化（Esc）'`。
   - 代码内部仍保留 `inAppFullscreen` 标识与「网页全屏」注释，表示实现语义（铺满应用窗口）。
2. **弹幕保持**
   - `detail_page.dart`、`bangumi_player_page.dart` 各新增页面级
     `GlobalKey _playerPanelKey`，普通布局与全屏/最大化两个分支的 `PlayerPanel`
     共用同一 key。
   - Flutter 在同帧内通过 `_retakeInactiveElement` 把同一 Element/State 从旧父级
     搬移到新父级（GlobalKey 重新挂载），`DanmakuScreen` 的轨道、坐标、ticker、
     引擎实例全部保留；`WinWinDanmaku.didUpdateWidget` 仅按 `fullscreen` 更新
     `DanmakuOption`（如全屏字号缩放 1.7），不再清空。
   - 原生全屏（F / 显示器全屏）与最大化共用该分支，因此一并修复。

## 五、遗留与踩坑

1. **退出最大化时轨道收缩**：全屏字号缩放默认 1.7、窗口默认 1.4，退出后
   `_calcTracks()` 轨道数减少，`changeLength()` 会截断超出新轨道数的弹幕
   （本就落在可视区外，属引擎既有行为）。本轮修复的是「整屏清空 + 重新排队」，
   不是逐轨裁剪。
2. GlobalKey 复用整块 `PlayerPanel` State，控制条锁定、音量弹层等状态也会跨模式
   保持——与「同一播放器实例」语义一致。
3. 后续若再调整 body 分支结构或替换 `PlayerPanel`，必须保留该 key，否则问题回归。
4. `changeLength()` 截断时未 `dispose()` 被丢弃条目的 Paragraph，属引擎既有小泄漏，
   未在本次范围内处理。

## 六、总结

控制栏「网页全屏」文案已改为「最大化」（含演示/直播与 Esc 提示）。弹幕进出
最大化/全屏时被清空的根因是详情页/番剧页的两套 body 布局分支重建了 PlayerPanel，
导致弹幕渲染引擎 State 被销毁；现用 GlobalKey 让同一 PlayerPanel 在分支间搬移，
弹幕轨道与飞行状态得以连续保持。
