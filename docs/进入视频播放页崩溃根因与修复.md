# 进入视频播放页崩溃根因与修复

> 调查日期：2026-09-19
> 关联提交（肇事窗口）：`5a0cb39`（keep_open）、`7269ff7`（avsync.audio / 音视频同步优化）
> 结论：崩溃由 **`player.setProperty('avsync.audio', 'true')`** 触发（mdk 0.38.0 解析失败抛 `std::invalid_argument`），已通过禁用该属性修复。

---

## 1. 现象

- Debug 与 Release 构建在**进入视频播放页**时进程直接崩溃（无 Dart 层异常、无白屏兜底机会），必现于 Release。
- 症状与硬解/软解（设置项「开启硬解」）**无关**：关闭硬解后依旧崩溃。
- Windows 事件日志异常码：`0xc0000409`（STATUS_STACK_BUFFER_OVERRUN / fail-fast）。
- WER 崩溃签名：
  - Debug：崩在 **amdxx64.dll**（AMD D3D11 用户态驱动），偏移恒为 `0xfb6bd1`（另见 §6 遗留事项）。
  - Release：崩在 **ucrtbase.dll**，偏移 `0xa527e`，异常数据 `0x7` = `FAST_FAIL_FATAL_APP_EXIT`（abort）。

## 2. 关键证据链

### 2.1 应用日志

- `Documents/logs/runtime.log`：近两次 Release 崩溃（15:33、15:50）前**无任何 `[W]` 级日志**（`AppLogger.w/e` Release 必落盘）。
- Release 流程中第一条 `[W]` 是 `loadVideo` 里的 `setMedia video:` → 推出崩溃发生在 `_createPlayer()` 或 `loadVideo` 首段 setProperty 阶段。

### 2.2 WER 崩溃转储（`%LOCALAPPDATA%\CrashDumps`）

分析两份转储（硬解开/关各一次），调用栈逐字节一致：

```
ucrtbase!abort+0x4e
  ← ucrtbase!terminate+0x1e
  ← KERNELBASE!UnhandledExceptionFilter (未捕获异常)
  ← VCRUNTIME140!CxxThrowException            ← C++ 异常被抛出
  ← msvcp140!std::_Xinvalid_argument           ← std::invalid_argument
  ← mdk!SetGlobalOption(+0x9f0)                ← mdk 内部属性值解析
  ← mdk!Player::onPropertyChanged
  ← mdk!Property::set                          ← setProperty 入口
```

**根因定型**：mdk 0.38.0 在 `Player::setProperty` 处理属性时，对**无法解析的属性值**直接 `throw std::invalid_argument`；该 C++ 异常穿过 Dart FFI 边界逃逸（不被捕获）→ `std::terminate` → `abort()`。属于 mdk 库侧健壮性问题（Release 下任何一次该属性设置都会触发）。

### 2.3 提交差异定位

对照可正常运行的历史构建（2026-09-12 Debug，同一 mdk.dll 0.38.0 Sep 10 2026），崩溃窗口内播放器属性配置的**唯一新增项**：

| 提交 | 新增属性 | 值类型 | 处置 |
|---|---|---|---|
| `5a0cb39` | `player.setProperty('keep_open', '1')` | 数值字符串 | 二分排除：单独禁用仍崩 |
| `7269ff7` | `player.setProperty('avsync.audio', 'true')` | **非数值字符串** | ✅ 确认肇事：禁用后不再崩 |

其余属性（`avformat.*`、`avio.*`、`demux.*`、`video.decoder` 等）在 09-12 调试版均正常执行过，排除。

## 3. 二分验证过程

1. 快照检查点：改动前状态 `7269ff7`（干净工作区），`refs/snapshots/latest` = `7269ff7`。
2. **第 1 轮**：仅注释 `keep_open` → 双分支编译 → Release 复测 **仍崩** → 排除 keep_open。
3. **第 2 轮**：再注释 `avsync.audio` → 双分支编译 → Release 复测 **不再崩溃** → 坐实 `avsync.audio='true'`。
4. 每轮均通过 `dart analyze`（0 error / 0 warning）与 Debug、Release 双分支编译。

## 4. 修复内容（当前工作区状态）

`lib/pages/video/player_controller.dart`（`_createPlayer`）：

- **修复**：`player.setProperty('avsync.audio', 'true')` 已禁用（注释保留 `[BISECT]` 标记与说明）。
- **待定**：`player.setProperty('keep_open', '1')` 同样处于禁用状态（非肇事属性，但为保证复测纯净一并保留关闭；后续需决定安全恢复方案，见 §6）。

## 6. 遗留事项（建议跟进）

1. **keep_open 功能丢失**：`5a0cb39` 的「重播/从头播放」修复依赖 `keep_open=1`。当前被禁用后，重播/seek(0) 行为可能回归旧状。✅ **已解决（2026-09-19）**：音画同步修复（见 `docs/音画同步问题根因与修复.md`）中确认 `keep_open='1'` 为数值字符串、非崩溃肇事，已安全恢复。
2. **Debug 的 GPU 驱动崩溃（独立问题）**：Debug 构建在开启硬解时偶发崩于 `amdxx64.dll` 0xfb6bd1（近两月同签名多次，WER 有大量 GPU TDR/AMD_WATCHDOG 记录）。建议更新/重装 AMD Adrenalin 驱动（当前 32.0.31041.1004）或跟进 mdk D3D11 解码器在 AMD 上的兼容性；这是独立于本次 abort 的第二个问题。
3. **设置「开启硬解」当前为关闭态**：用户 A/B 验证期间已关闭。确认 avsync.audio 修复后可根据需要还原。
4. **minidump 采集能力**：`LocalDumps` 注册表因权限未开启；Windows 默认会在 `%LOCALAPPDATA%\CrashDumps` 留存用户态崩溃转储，本次分析即依赖该目录。

## 8. 崩溃转储分析方法（可复用）

```bash
# 工具：Microsoft Store 版 WinDbg 自带 cdb（%ProgramFiles%\WindowsApps\Microsoft.WinDbg_*\amd64\cdb.exe）
# 拷贝 cdb.exe/dbgeng.dll/dbghelp.dll/symsrv.dll 到本地目录后执行：
cdb -z "%LOCALAPPDATA%\CrashDumps\winwin.exe.<pid>.dmp" \
    -y "C:\...\fvp-0.38.1\windows\mdk-sdk\bin\x64;srv*<symcache>*https://msdl.microsoft.com/download/symbols" \
    -c ".ecxr; kn 60; q"
```

- mdk.pdb 随 fvp 包 mdk-sdk 提供（`windows/mdk-sdk/bin/x64/mdk.pdb`），加入符号路径即可还原 `mdk!*` 函数名。
- 关闭硬解的 A/B 测试用于排除解码路径；本问题的判定工具是**崩溃转储的调用栈**而非症状表象。
