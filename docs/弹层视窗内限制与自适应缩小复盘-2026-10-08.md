## 一、分析根因（现象 · 取证证据 · 根因链）

### 1.1 涉及的两个弹层与链路

| 弹层 | 入口 | 浮层实现 |
| --- | --- | --- |
| 视频卡片「更多操作」 | `VideoPopupMenu`（卡片三点按钮）→ `showVideoContextMenu` → `showMiuixContextMenu` | `lib/common/widgets/miuix_context_menu.dart` 的 `_MiuixContextMenuOverlay` |
| 会话「更多选项」 | `SessionMoreMenuButton` → `MiuixPopupMenu` | `lib/common/widgets/miuix_popup_menu.dart` 的 `_PopupOverlay` |

（会话列表右键「更多选项」同样走 `showMiuixContextMenu`；两者共用毛玻璃面板壳
`lib/common/widgets/miuix_overlay_panel.dart` 的 `MiuixOverlayPanel`。）

### 1.2 取证证据（代码级，含溢出量计算）

**① 右键菜单浮层 —— 硬编码 160px 高度估算 + 120px 地板 + 未计标题区**

```dart
final top = widget.position.dy.clamp(8.0, math.max(8.0, media.size.height - 160));
...
maxHeight: math.max(120.0, media.size.height - top - 24),   // 仅约束"列表区"
```

- `160` 是按"典型弹层高度"的估算值；视频卡片菜单最多 7 项 + 标题行，
  实际高度 >160px（列表区单项 ≈41px，7 项 ≈287px，加标题区 ≈73px，常态总高 ≈360px）；
- 实测场景：窗口 H=900、点击点 y=780（卡片位于三列网格底部）：
  `top = 780 → 面板 y 起点 = 784`，列表区 maxHeight = max(120, 900-780-24) = 136，
  面板总高 ≈ 136 + 73 = 209 → **底边 ≈ 993，底部溢出 93px**；
- `max(120, ...)` 地板：窗口过矮时（如 H=150）反而把列表区强制撑到 120px，
  面板总高 ≈193 → **溢出 55px**；且溢出发生在面板"底部边缘"（与滚动区无关）。

**② 弹层壳 —— 固定阈值 + 120px 地板 + 无最终位置 clamp**

```dart
final placeAbove = spaceBelow < 160;
final panelMaxHeight = math.max(120.0,
    math.min(maxHeight, placeAbove ? triggerRect.top - gap - screenInset : spaceBelow));
...
Positioned(bottom: media.size.height - triggerRect.top + gap, ...)   // 直接以空间值定位
```

- 实测场景：窗口 H=150、会话行按钮 top=100：`spaceBelow = 2 < 160 → 向上`，
  `panelMaxHeight = max(120, 100-6-12) = 120` → 面板 120px 高、底边锚定 y=94，
  **顶边 = -26，顶部溢出 26px**；
- 固定阈值 160 与面板实际高度无关：常态面板（标题 + 3 项 ≈190px）在
  "下方 160~190px"的窗口里会先按 160 判定方向，再溢出。

**③ 面板壳 —— 内容区无弹性收缩能力**

`MiuixOverlayPanel` 的 Column 里内容区是普通子项：即使外层给了小于内容的高度约束，
内容区也不会收缩；弹层"缩小"无从发生，只会溢出或被 `ClipRRect` 裁掉。

### 1.3 根因链

定位/定尺全部基于**估算值**（160）与**地板值**（120），且约束止步于"列表区"
（未覆盖标题区）→ 弹层实际高度超过估算时越界；面板壳又无收缩通道 →
修正只能靠"越界后裁剪"，于是表现为"超出视窗、显示不全"。

## 二、设计修复计划（方案与关键决策/取舍）

### 2.1 方案检索（移植优先）

- 本地/包源码：`flutter_miuix` 无弹层视窗约束实现；`material_ui` 的
  `PopupMenu`/`Tooltip` 等使用 **`CustomSingleChildLayout` + `SingleChildLayoutDelegate`**
  在布局阶段"先约束、后测量、再定位"；
- 全网：Flutter 官方 `_PopupMenuRouteLayout`（`popup_menu.dart`）即该模式的标准实现：
  `getConstraintsForChild` 限制尺寸 → `getPositionForChild(size, childSize)` 用实际尺寸
  做翻转与收敛。

→ 采用官方同款机制在两个浮层就地落地（不引第三方包）。

### 2.2 主方案（布局阶段精确定位）

两个浮层各新增文件内私有委托（`_MiuixContextMenuLayout` / `_PopupMenuLayout`），
`Stack` 中"面板层"由 `Positioned` 换成 `Positioned.fill(CustomSingleChildLayout(...))`：

1. **约束阶段** `getConstraintsForChild`：
   - 右键菜单：宽 tight = `min(300, W-16)`；高 `max(0, H-16)`；
   - 弹层壳：宽 `min(320, W-24)`、高 `min(420, H-24)`（`maxHeight` 参数保留为常态上限）；
   即**从约束层面保证面板可完整放入视窗**。
2. **定位阶段** `getPositionForChild(size, childSize)`：以面板实际尺寸定方向与位置：
   - 方向 = 上下可用空间较大侧（上 > 下 → 向上贴锚点上方；否则贴锚点下方）；
   - 最终位置 `clamp` 进视窗（边距：右键菜单 8 / 弹层壳 12）→ **四边硬保证不越界**；
3. **自适应缩小**：空间不足时面板随约束收缩，右键菜单列表区（既有
   `SingleChildScrollView`）与弹层壳条目区（既有 `Flexible + SingleChildScrollView`）滚动；
4. **面板壳**：`MiuixOverlayPanel` 内容区包 `Flexible` —— 受限高度下内容区可收缩；
   无界高度场景（`Positioned` 无高约束的弹幕样式/表情面板）Flexible 在无限主轴下
   分配不限空间，行为与改造前**等价**（回归面可控）。
5. 删除全部硬编码估算与地板：`160`、`max(120, ...)`。

### 2.3 关键决策与取舍

| 决策 | 取舍说明 |
| --- | --- |
| 方向 = 空间较大侧（而非"下方放得下优先"） | 位置与展开动画锚点共享同一判定，**永不出现"动画方向与落位相反"**；触发器位于视窗下半区时自动上翻，符合桌面菜单习惯 |
| 向上时动画锚点改 `bottomLeft` / `bottomRight` | 缩放原点贴住点击点/触发器一侧，对角线展开观感一致 |
| 边距沿用现状（右键 8 / 弹层壳 12）、宽度上限沿用现状（300 / 320） | 不改变常态视觉，只修正越界 |
| 不引入 `GlobalKey` 测量/两帧测量 | `CustomSingleChildLayout` 在**同一帧布局内**完成测量与定位，零闪烁、零额外帧 |

## 四、本轮修复总结

### 4.1 改动面

| 文件 | 说明 |
| --- | --- |
| `lib/common/widgets/miuix_context_menu.dart` | 面板层改 `CustomSingleChildLayout`；新增 `_MiuixContextMenuLayout`（约束 + 方向 + 视窗内 clamp）；删除 160 估算与 `max(120,...)`；动画锚点随方向 |
| `lib/common/widgets/miuix_popup_menu.dart` | 面板层改 `CustomSingleChildLayout`；新增 `_PopupMenuLayout`（同上）；删除 160 阈值与 `max(120,...)` 及旧 `Positioned` 分支 |
| `lib/common/widgets/miuix_overlay_panel.dart` | 内容区包 `Flexible`（受限高度可收缩；无界场景行为等价） |
| `docs/弹层视窗内限制与自适应缩小复盘-2026-10-08.md` | 本篇 |

自动受益（同一实现、无需改调用点）：会话列表右键「更多选项」、`member_space_page`
「更多选项」、`live_room_page` 画质/线路/比例、`login_page` 冠码、`player_panel` 画质/音轨/倍速。

### 4.2 行为预期

- 所有上述弹层在任意窗口尺寸下**四边不超出视窗**；
- 窗口过矮时面板随可用空间收缩，条目区滚动，仍可完整操作全部选项；
- 触发点下方空间不足时自动向上翻转展开；常态观感（材质、宽度、配色、动效时长）不变。

### 4.3 遗留项

1. 实机观感确认（上翻/收缩的动效是否符合预期，见 3.3 清单）；
2. 弹幕样式面板 / 表情面板（`MiuixOverlayPanel` 另两个使用方）仍按各自定位逻辑，
   不在本次"视窗内限制"范围内（本次仅等价化其面板壳内部弹性），如后续也要限制可同法处理；
3. 面板收缩后滚动区无显式滚动条（沿用系统默认行为），如需常显可另立项。
