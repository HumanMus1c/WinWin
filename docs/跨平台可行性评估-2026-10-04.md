# 跨平台可行性评估（Windows 以外）

> 日期：2026-10-04 ｜ 关联：本仓库新增 Windows CI/Release 工作流与安装器；平台立项时可直接移植上游（PiliPlus）对应工作流与 Linux WebView 方案

## 1. 结论速览

| 平台 | 可行性 | 主要阻塞 | 建议 |
| --- | --- | --- | --- |
| Windows x64 | 现状 | — | 当前唯一维护目标（本地 + CI + 安装器闭环） |
| Linux x64 | 中高 | ① WebView 需移植上游 Linux 方案（官方 flutter_inappwebview 无 Linux 支持）② 需新增 linux/ 工程与打包 ③ 标题栏/全屏原生路径需重写 | **第二平台首选** |
| macOS | 中高 | ① 需新增 macos/ 工程 ② 签名/公证缺失（未签名分发体验） ③ 原生标题栏路径替换 | 三期候选 |
| Android | 低-中 | 桌面交互范式需重构（多窗口/侧栏/键鼠/PiP/标题栏均不适用），构建链整体切换 | 长期，不优先 |
| iOS | 低 | 同 Android + 分发门槛（证书） | 不优先 |
| Web | 不可行 | `fvp` 无 Web 实现（播放内核缺失）；CORS 与桌面 API 全面缺失 | 不做 |
| HarmonyOS | 低（观察） | `fvp` 已支持，但 Flutter-OHOS 工具链属实验性 | 观察 |

## 2. 依赖层核查（`pubspec.yaml` + pub.dev 平台标签）

| 依赖 | Win | Linux | macOS | Android | iOS | Web | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| fvp（播放内核） | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | 唯一播放内核；README 另述 HarmonyOS 5.0+ |
| window_manager | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | 桌面三平台；代码已按桌面守卫 |
| screen_retriever | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | 桌面三平台 |
| flutter_inappwebview | ✅ | **❌** | ✅ | ✅ | ✅ | ✅ | 登录风控窗口；**Linux 无官方实现**（上游 PiliPlus 2.1.5 已支持 Linux 内嵌 WebView，见 §4） |
| flutter_miuix | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 全平台 |
| get / dio / hive_ce / file_picker / cached_network_image_ce / catcher_2 / logger 等 | ✅ | ✅ | ✅ | ✅ | ✅ | 视包而定 | 无平台阻塞 |

## 3. 代码层核查

### 3.1 已有的跨平台守卫（利于移植）
- `lib/main.dart` L112/L122/L136：桌面三平台判断（窗口初始化；`d3d11.sync.cpu` 仅 Windows）
- `lib/ui/app.dart` L46、`lib/core/window/desktop_fullscreen.dart`、`lib/core/storage/storage_pref.dart` L48/L103/L111、`lib/http/browser_ua.dart`、`lib/pages/video/player_controller.dart` L719
- `lib/core/window/title_bar_controller.dart`：非 Windows 直接 `return`（空操作）

### 3.2 Windows 专属实现（移植时需替换/降级）

| 能力 | 现状实现 | macOS / Linux 替代方案 |
| --- | --- | --- |
| 标题栏沉浸 | MethodChannel `winwin/window_title_bar` → Windows 11 DWM（`windows/runner` C++） | `window_manager.setBrightness` + 各平台原生扩展；或直接沿用系统标题栏 |
| 桌面全屏 | MethodChannel `winwin/fullscreen`（原生 Win32 Runner） | `window_manager.setFullScreen` 或平台原生 API |
| 桌面伪 PiP | `window_manager`（尺寸/置顶/对齐） | **直接可用**（跨桌面） |
| D3D11 同步屏障 | mdk `d3d11.sync.cpu`（Windows 专属选项） | 跳过（各平台图形栈自带路径） |

### 3.3 工程目录
- 当前仅有 `windows/`；其他平台需 `flutter create --platforms=...` 生成 runner，并把对应构建工作流移植自 PiliPlus（`linux_x64.yml` 含 tar.gz/deb/rpm/AppImage 打包；`mac.yml` 含 create-dmg）。

## 4. 平台分档说明

- **Linux（第二平台首选）**：WebView 不再是硬阻塞——**上游 PiliPlus 2.1.5 已支持「Linux 内嵌 WebView」（#3014，webkit2gtk 路线）**，立项时可移植其方案（其 Linux CI 已包含 `webkit2gtk-4.1` 等依赖安装）；在此之前可降级为「扫码 + Cookie 导入」。播放（fvp 自带 mdk/ffmpeg 动态库）、Miuix UI、窗口能力（window_manager）均可用；打包与 CI 有上游现成形态可抄。
- **macOS**：依赖层几乎无阻塞（fvp / inappwebview / window_manager / flutter_miuix 均支持）；成本集中在 macos/ 工程、原生标题栏/全屏近似实现与分发（未签名需用户手动放行，后续可补签名/公证）。
- **Android / iOS**：依赖基本齐（fvp / inappwebview / miuix 支持移动端），但信息架构是桌面优先（侧栏、快捷键、PiP、标题栏、多窗口），移动端近似重做，不建议在现架构上硬上。
- **Web**：`fvp` 无 Web 实现，播放不可用（核心功能缺失）；不做。
- **HarmonyOS**：`fvp` 已支持、但 Flutter-OHOS 生态实验性；保持观察。

## 5. 与 CI 的衔接
- 本次落地 Windows CI/Release（`.github/workflows/windows-x64-ci.yml`、`windows-x64-release.yml`）与安装器（fastforge + Inno Setup）。
- 平台立项时：Linux 移植 `linux_x64.yml` 全形态（依赖安装、四类安装包、产物上传）与 Linux WebView 方案；macOS 移植 `mac.yml`（create-dmg）。
