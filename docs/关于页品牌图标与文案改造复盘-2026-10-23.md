> 五要素结构。范围：程序自身**品牌 logo**（程序图标）统一为 Flutter 官方 `flutter_dash`，并同步「关于」页的品牌文案表述。
> 前置：2026-10-23 14:1x 用户指令「继续改造关于页面：1. 程序图标改用 Flutter 官方图标；2. 项目说明文案改写；3. 程序名副标题改写」。

> 定稿选择：**1①**（载体取 `Icons.flutter_dash`）+ **2②**（全量：关于页头部 + 标题栏 PNG + exe/任务栏 `.ico`）。

## 一、现象

1. 「关于」页头部大图标（88×88 圆角容器内）仍是**播放语义图标**（`AppIcons.play(active: true)`），并非「WinWin 程序自身的品牌 logo」。
2. 程序图标（exe / 任务栏 / 托盘 / 沉浸式标题栏）仍是旧品牌素材：`assets/app_icon.png`（48×48 天蓝播放三角）、`windows/runner/resources/app_icon.ico`（16/32/48/256）。
3. 「关于」页两处品牌文案为旧表述：
   - 程序名 `WinWin` 下方副标题 = `BiliPai Desktop Port`；
   - 「项目说明」副标题 = `WinWin 是基于 PiliPlus 的 Bilibili 桌面客户端移植版，使用 Flutter + fvp/mdk 内核构建。`

## 二、定因（`app_icon` 全部引用面）

- **界面语义图标体系**（`lib/theme/app_icons.dart` 的 `AppIcons`，152 个静态方法，全库 68 文件引用）与「程序自身 logo」是**两回事**：前者是 UI 语义（返回/首页/搜索…），载体一律 `CupertinoIcons.*` 并经 `AppIcon` 转 Miuix 矢量；后者是品牌标识。用户第 8 条澄清的正是这条边界。

## 三、方案与实现

**统一载体：Flutter 官方 `flutter_dash` 字形**（1①）
- `AppIcons` 新增 `appLogo()`，返回 `Icons.flutter_dash`。文件顶部新增 `import 'package:flutter/material.dart' show Icons;` —— **仅取字形码位**，`show Icons` 限定导入面，不引入任何第三方 Material 包（`material_ui` 已于 B7 封板退役，见 `pubspec.yaml` 注释）。
- 该字形走现有 `AppIcon` 渲染链：`miuixVectorForGlyph(Icons.flutter_dash)` 无对应（映射表键为 Cupertino 字形）→ 回退 `Icon(Icons.flutter_dash)`，由 SDK 内置 `MaterialIcons` 字体渲染（`uses-material-design: true` 保留，字体已随产物打包）。
- 语义边界写进方法文档注释：**仅供程序 logo 展示位引用，勿在 UI 处使用**。

**图标素材重绘（2② 全量两面）**
- 字形源：官方 `materialicons-regular.otf`（`flutter/bin/cache/artifacts/material_fonts/`），码位 `0xe2a0`（`codepoints` 文件佐证 = `flutter_dash_baseline`）。
- 渲染：1024px 母版 → 按字形 bbox 紧裁 + 8% 留白补方 → LANCZOS 降采样；取色为 **Flutter 官方蓝 `#42A5F5`**，背景透明。
- 产物：`assets/app_icon.png`（48×48，3 864 B）；`windows/runner/resources/app_icon.ico`（16/32/48/256 四档，38 209 B；经 `PIL` 校验 `sizes` 完整）。

**文案（2 处）**
- 副标题：`BiliPai Desktop Port` → `PiliPlus + BiliPai`。
- 项目说明：→ `WinWin 是以 PiliPlus 为主体框架，BiliPai 前端组件的桌面客户端，使用 Flutter + fvp/mdk 内核构建。`

## 六、遗留与踩坑

1. **`flutter build windows` 在沙箱 shell 中缺 `ProgramFiles(x86)` 会直接失败（根因级，修正旧结论）**：`flutter_tools/lib/src/windows/visual_studio.dart:264` 在环境缺 `PROGRAMFILES(X86)` 时 `throwToolExit('%PROGRAMFILES(X86)% environment variable not found.')`（用于拼 `vswhere.exe` 路径）。表现极具迷惑性：日志**仅此一行**、退出码 1。本机 Git Bash **无法以 shell 变量形式承载带括号的变量名**（`PROGRAMFILES(X86)` 非合法标识符），故必须经工具 `env` 参数显式注入 —— 经 `python -c "os.environ.get('PROGRAMFILES(X86)')"` 实证可穿透至子进程。**纪律：本项目 flutter 命令的 env 需同时含 `PUB_HOSTED_URL=https://pub.flutter-io.cn` 与 `PROGRAMFILES(X86)=C:\Program Files (x86)`。**（旧记忆称「build 不受影响、无需补齐」——**该结论已证伪并据此修正**。）
2. **Release 链接期 `LNK1104: 无法打开文件 ...\Release\winwin.exe`（第二类构建阻塞）**：上轮产物实例仍在运行 → 链接器无法覆写目标 exe。按 PID 结束后重跑即绿（`debug 31.2s` 后 `release` 首次 76.6s 失败 → 结束 PID 9088 → 重跑 18.3s 成功）。§2 既有规范已含「双编译前结束占用 `WebView2Loader.dll` 的残留 `winwin.exe`」，**本次为同源问题的另一表现面，建议扩展为「构建前一并结束占用 Release 目标 exe 的实例」**。
3. **PowerShell 工具侧观察（未深究）**：`pwsh` 下 `[Environment]::GetEnvironmentVariable('ProgramFiles(x86)')` 返回空、`flutter --version` 无输出 → 构建统一走 **Git Bash + `env` 注入**，勿依赖 PowerShell 工具跑 flutter。
4. **未做（待用户决策）**：`lib/main.dart:229` 窗口标题 `WinWin — BiliPai Desktop Port` 是否同步改为 `PiliPlus + BiliPai`（同一品牌串的另一展示面，属**窗口标题**语境，用户本轮未点名，故未擅自改动）。

## 七、总结

本轮把「程序自身品牌 logo」与「界面语义图标体系」两条**本质不同**的链路彻底分界：前者收敛到 `AppIcons.appLogo()` 单一入口（`Icons.flutter_dash`），并同步重绘标题栏 PNG 与 exe/任务栏 `.ico` 两面素材；后者（`AppIcons` 152 方法 / 68 文件）**零改动**。文案两处按用户给定文本落地，全库无残留。双编译与静态分析全绿、锁文件未被污染。最大的过程教训是**构建环境**：`ProgramFiles(x86)` 在沙箱 shell 中缺失会让 `flutter build windows` 以「一行日志 + 退出码 1」静默失败，此前记忆的相反结论已被本次实测证伪并修正。

## 八、补记（第二轮 · 同日 16:35：Logo 载体更正 —— 第一轮载体结论作废）

> ⚠️ **作废声明**：第三节「统一载体：Flutter 官方 `flutter_dash` 字形（1①）」**已证伪作废**。用户实机辨认反馈「你这个 Logo 我怎么没见过？难道不应该是蓝色的像旗帜的那个 Flutter 官方 Logo 吗？」
> 真相：`Icons.flutter_dash` 是 **Material 字体里的单色简化字形**，**不是 Flutter 官方 Logo 造型**（官方标志 = 两条浅蓝斜带 + 深蓝楔形组成的**双色**「旗帜」，`#39CEFD` / `#03569B`）。

### 现象与定因
1. **载体选错**：把 `flutter_dash`（Material Symbols 字形）当成了官方 Logo。依据仅为「名字像 + 项目已保留 `uses-material-design`」，**未与官方标志做任何逐形核对**。
2. **配色二次失真**：又按 Flutter 蓝 `#42A5F5` **整片单色填充**，抹掉了官方标志固有的**双色结构** → 更加无法辨认。
3. **旁证（关键）**：旧 `assets/app_icon.png` 主色 `(95,201,248)` 与 **SDK 自带官方位图**（`flutter\engine\src\flutter\docs\flutter_logo.png`，55×55）的配色**逐值一致** —— 说明**旧图标本来就是官方 Logo 造型（单色版）**，本轮第一轮替换掉的恰好是官方造型。
4. **决策过程缺陷**：第一轮把选项写成「1① `flutter_dash` / 1② SDK 内蓝色 logo（仅 55×55，做 256 会糊）」，用**素材质量**把用户引向 1①，却没去找**高清官方彩色素材**（它一直公开可用）。用户选了 1①，但这不构成「1① 是对的」——**我给了错误的选择集**。

### 方案与实现
- **素材源**：`https://docs.flutter.dev/assets/images/branding/flutter/logo/default.svg`（3637 B，`viewBox 0 0 839 1039`，用色 `#39CEFD` / `#03569B` / `#1A237E` / `#FFFFFF`）。
- **光栅化**：本机无 cairo / svglib / ImageMagick ⇒ 改用**无头 Chrome**（`--headless=new --default-background-color=00000000 --force-device-scale-factor=1 --window-size=1024,1024 --screenshot=...`）+ 居中包装 HTML → 1024×1024 **透明** PNG。
- **母版**：字形紧裁（775×959，宽高比 0.808 = SVG viewBox 0.807 ✅ 完整渲染）+ 10% 留白补方 = 1054×1054；LANCZOS 逐档降采样。
- **产物**：`assets/flutter_logo.png` 256×256（**新增**，关于页头部）；`assets/app_icon.png` 48×48（沉浸式标题栏）；`windows/runner/resources/app_icon.ico` 16/32/48/256（逐档独立降采样 / `append_images`，exe · 任务栏 · 托盘）。
- **代码**：`about_page.dart` 头部 → `Image.asset('assets/flutter_logo.png', width: 48, height: 48, filterQuality: FilterQuality.high)`；`app_icons.dart` 的 `appLogo()` 与 `import ... show Icons;` **整体撤销**（lib 回到零 Material 导入）；`pubspec.yaml` assets 增 `assets/flutter_logo.png`。

### 教训（方法论）
1. **品牌素材必须与官方原件核对**（逐形 / 逐色），不能凭「字形名听起来像」或「字面语义」推断；`flutter_dash` 之名极具误导性。
2. **不要用素材质量把用户引向次优解**：给选项前先穷尽官方高清来源（本次为 docs.flutter.dev branding SVG），确保每个选项**都能达到目标质量**。
3. **用户对可识别性极敏感**：品牌 logo 的验收标准是「一眼认出」，不是「技术上属于同一品牌体系」。
