# 全局返回按钮上提为壳层单实例 复盘（2026-10-21）

> 需求（CVO）：从深层页面返回根页面时，首页顶栏左上角**残留全局返回按钮**。
> 改进：二级及更深层页面**共用一个全局返回按钮**，不再跟随任意页面转场动画消失，
> **始终固定在默认位置**，返回到根页面时再隐藏消失。
> 决策：CVO 拍板「A 加 B 一起做」= 标准页 + 媒体/搜索页**全量统一**到同一个壳层按钮。
> 起点 HEAD `77cda2d`（改动前快照；`refs/snapshots/latest` 已指向）。

---

## 1. 现象

1. 从根页面（首页/动态/历史/消息/我的）进入任一二级页，再进入更深层（三级）页；
2. 逐级返回根页面：**首页顶栏左上角仍显示一个返回按钮**（不消失）；
3. 另：进出二级页时，该返回按钮**跟随页面转场（淡入 + 轻微上移）一起出现/消失**，并非固定不动。

---

## 2. 定因（源码取证）

### 2.1 按钮的渲染位置 = 每个页面自己的路由子树内（关键）

`lib/core/shell/app_scaffold.dart`（改动前）：

```dart
final canPop = widget.showBackButton &&
    (Navigator.maybeOf(context)?.canPop() ?? false);   // 构建期一次性快照
...
if (canPop) FloatingBackButton(tokens: tokens),          // 直接画在本页子树里
```

- 按钮在**当前路由的子树内** ⇒ 必然继承该路由的转场变换
  （`AppRoute` → `MiuixPageTransition`：`FadeTransition` + `SlideTransition`，
  `lib/core/shell/app_transition.dart`）⇒ 这就是「**跟随任意页面转场动画消失**」。
- 每个二级页各自实例化一个按钮 ⇒ 不是「共用」，是 N 个副本。

### 2.2 残留的直接原因 = `canPop()` 构建期快照 + 被覆盖页不重建

- `canPop()` 只在 `build` 时读一次，`AppScaffold` 未订阅任何路由变化。
- 首页（`lib/ui/home/home_page.dart` `AppScaffold(title: '首页')`）被压栈时被盖住；
  返回时重新可见，但其 `build` 结果里的 `canPop` 仍是「深度 ≥ 2 那一帧」的值
  ⇒ 首页左上角残留返回按钮（直到下一次意外重建才复原）。
- 根部壳 `AppRoot`（`lib/ui/app.dart`）已 `reserveTopStrip:false`，**不是**它画的。

---

## 3. 方案（A+B 全量统一）

### 3.1 核心机制（新增 `lib/core/shell/global_back_button.dart`）

- **`GlobalBackButtonController`**（`NavigatorObserver` + `ChangeNotifier`）：
  维护路由栈（栈深 / 栈顶路由 / 栈顶是否 `PopupRoute`），并收纳**每路由**的
  `BackButtonSpec` 注册表；变更通知**帧内合并**（`SchedulerPhase` 判定，构建/布局期改投
  post-frame），避免构建期触发重建。
- **`GlobalBackButton`**（壳层单实例）：挂在 `AppShell.builder` 内、**Navigator 之上**
  （与 `AppEscapeScope` 同层，`Stack[ routed, GlobalBackButton ]`）。
  - **位置固定**：`left: 8 / top: 4`（= 50 高安全行内居中 42×42），**外框恒定 42**；
  - **显隐只做淡入淡出**（`AnimatedOpacity` 180ms，不位移），隐藏时 `IgnorePointer`；
  - 显隐判据：`栈深 ≥ 2` **且**栈顶非 `PopupRoute` **且**本路由 `spec.visible`；
    栈顶为 `fullscreenDialog` 页路由时渲染「关闭」字形。
- **`BackButtonSpec`**：可覆盖字形/颜色/底色/阴影/尺寸/工具链提示/点击行为/返回前副作用；
  默认（`standard`）= 原标准观感。标准页**无需声明**。
- **`BackButtonOwner`**：页面便捷宿主（`child` 以引用透传 ⇒ 规格变化只重建宿主自身，
  不连带整页重建）；`listenable` 支持规格随滚动等状态变化。

### 3.2 接线与收口

| 文件 | 改动 |
|---|---|
| `lib/core/shell/global_back_button.dart`（**新增**）| 控制器 + 单实例按钮 + `BackButtonSpec` + `BackButtonOwner` + 应用级单例 |

| `lib/core/shell/app_scaffold.dart` | 删除安全行内的 `FloatingBackButton` 与 `showBackButton` 参数（返回键改由壳层承担）；安全行只保留 `title`（根页）/`actions` |

### 3.3 全量统一（B：媒体/搜索页一并接入）

| 页面 | 处置 |

## 6. 遗留与踩坑

1. **播放器片内全屏返回键未并入**（`player_panel.dart`）：它是与播放控制条同步显隐、受 `_locked`
   控制的**播放器控件**，并非页面级导航；本轮保留并在全屏时让壳层按钮隐藏。若 CVO 要求**连它也统一**
   （代价：壳层按钮需接收播放器控件可见性/锁定态，失去「始终可见」语义），可另起一轮。
2. **非标准页的纵向对齐做了微调**：搜索两页行顶内边距 `8 → 0`、详情/番剧顶栏加了 56 宽槽位
   （返回键走后，标题起点由 ~40 → 56）。属「固定位」的必然代价，已尽量取最小位移，需实机确认观感。
3. **按钮位置固定 ⇒ 覆盖层语义**：壳层按钮恒在 `left:8/top:4`（42×42），故页面左上角原处于
   `x∈[8,50]` 的内容需避让（本轮已处理各页；后续新增页面若在左上角放内容需同样避让）。
4. **`AppLeadingBackButton` 变为无引用**：作为 `app_icons.dart` 的公共组件保留（不删，避免多余改动）；
   若后续确认长期不用可另行收口。
5. `dart format` 全程未跑（项目硬约束）。

## 7. 总结

- **根因**：返回按钮由**每页各自**在**自身路由子树内**内联渲染，显隐依赖构建期快照的 `canPop()`
  ⇒ 既「跟随本页转场」，又在被覆盖页不重建时「回根页面残留」。
- **修复**：把返回按钮**上提为壳层单实例**（Navigator 之上）——不属任何路由 ⇒ 转场带不走；
  位置固定；显隐由**路由栈观察器**驱动 ⇒ 回根页面即隐藏。并按 CVO 要求**全量统一**（A+B）：
  标准页用默认规格，媒体/搜索页经 `BackButtonSpec` 声明各自的观感与副作用。
- **验证**：`analyze` 0/0、`test` 238 全绿、debug/release 双编译通过（各 0 警告）；实机待复验。
- **收益**：一处收口（P4 概念单处定义）——返回按钮的行为/观感/显隐从此只有**一个**来源，
  后续任何页面只需（可选地）声明一份规格，不再各画一份。

# R2 续（2026-10-21 同主题追加）

> CVO 续评两点：① 全局返回按钮外观从「不透明底」改为**首页顶栏那样的模糊背景**，并对
> 按钮内字形**加粗**以补偿背景半透明；② **视频播放页仍有返回键**未走统一共享的全局按钮。
> 起点 HEAD `376a50a`（R1 收尾）。

## R2-1 定因（续评②）

全量统一后，`lib/` 内仅剩**一处**返回键未走壳层全局按钮：

| 符号 | 处数 | 位置 |
|---|---|---|
| `AppBackButton(` | 1 | `pages/video/player_panel.dart:516`（全屏 / 网页全屏**播放器浮层**返回键） |

R1 曾把该键作为「播放器控件」有意保留（与播放控件条同步显隐、受 `_locked` 控制）。CVO
要求一并收口 ⇒ 本轮删除之，改由**页面**（视频详情 / 番剧播放）经 `BackButtonSpec` 声明。

## R2-2 方案

1. **外观（毛玻璃）**：默认（`standard`）按钮背景改为与**首页顶栏同源材质**——
   `AppTopBarSurface` 的 `surface×0.72` + backdrop 模糊 σ20。小圆按钮的模糊核（σ20，3σ≈60px）
   远大于按钮本体（42px）：直接以 `BackdropFilter` + 圆形裁剪会因核在边界夹断而在圆内形成
   一圈软边渐变。故复用 `MiuixFrostedSurface` 已有的「边缘无渐变（bleed 外扩）」实现——
   为其新增可选 `color`（默认沿用中性灰，行为零变化），按钮传
   `AppTopBarSurface.barColor(cs.surface)` + `blurSigma: AppTopBarSurface.blurSigma` +
   `borderRadius: 21`。**底色/模糊/技术三处均复用既有单一来源，未新造材质参数。**
2. **字形加粗**：项目图标字形走 Cupertino 字体与 Miuix 矢量两条渲染路径，**均无 w700 粗体面**
   ⇒ `fontWeight` 无效。改用 `_PseudoBoldGlyph`：把同一字形沿右下**错位 0.75px 叠绘**一次，
   等效加粗笔画（两条路径同时生效，且不引入模糊）。
3. **收口播放器全屏返回键**：删除 `player_panel` 自绘键；视频详情 / 番剧播放的 `BackButtonSpec`
   在 `_fullscreen || _inAppFullscreen` 时改为**可见**——白字 + 对比阴影 + `onPressed =
   _handleEscape`（退出全屏），`tooltip` 按全屏形态区分（「退出全屏（Esc）」/「退出网页全屏（Esc）」）。
4. **清理**：`BackButtonSpec` 移除已无用的 `ringShadow`（毛玻璃底不再需要外圈阴影；显式底色页
   的观感由 `background/color/shadows` 表达）。

# R3 续（2026-10-21 同主题追加）

> CVO 续评：**去除播放页的播放器顶栏、以及顶栏容纳的用户名称文本，只保留顶栏位置的全局返回按钮。**
> 起点 HEAD `c6b45f2`（R2 收尾）。

## R3-1 定因

视频详情页的「播放器顶栏」= `detail_page.dart` 的 `_buildGradientTopBar(upName)`：一条
`Style.toolbarHeight`(56) 高的**自绘覆盖条**，滚动位移=0 时透明（压在播放器上）、`opacity≥0.95`
时转固态毛玻璃吸顶；其内容 = `SizedBox(56)`（R2 起给全局返回键让位）+ **UP 名文本**
（演示/无 UP 名时回落「视频详情」）。它挂在常规左栏与错误态左栏两处 `Stack`。

## R3-2 方案

1. 删除 `_buildGradientTopBar` 方法本体与其两处挂载 ⇒ 播放区域**贴顶**，顶部不再有渐变压暗条、
   吸顶毛玻璃条与 **UP 名文本**；顶栏位置上**仅保留壳层全局返回按钮**（默认位 `left:8/top:4`、按栈深显隐）。
2. `upName` 随之失去用途 ⇒ 收口 `_buildLeftColumn` / `_buildErrorLayout` 的 `upName` 参数（避免死参数）。
3. `_topBarScrollOpacity` → **`_scrollProgress`**（顶栏已不存在，语义改为「播放区滚动进度」）：
   **仅**继续驱动全局返回按钮在「覆盖在播放器上（白字 + 阴影）」↔「滚动后落回页面背景（主题可读色）」
   之间的翻色——即顶栏移除后，返回键的反色行为**不变**。
4. 清理随之不再使用的 `import 'dart:ui'`（`ImageFilter` 是顶栏毛玻璃的唯一使用点）。

> **范围**：本轮只动**视频详情播放页**（CVO 所指「用户名称文本」= UP 名）。番剧播放页的同款顶栏承载
> 的是「剧集标题 + **查看番剧详情**入口」（含导航功能），未一并删除，待 CVO 明确（见 R3-5）。

# R4 续（2026-10-21 同主题追加）

> CVO 续评两问：①「为什么滚动播放页，播放器上的全局返回按钮**还变暗了**？不应该保持不变吗？」
> ②「为什么播放页的播放器上的全局返回按钮看起来是**纯透明**的？而不是首页顶栏那种可见的模糊背景？」
> 起点 HEAD `92b6e55`（R3 收尾）。

## R4-1 定因（两现象同源）

两问都出在同一处：播放页通过**页面级 `BackButtonSpec` 覆盖了壳层默认外观**（`_backButtonSpec`）：

| 现象 | 直接原因 |
|---|---|
| 「纯透明」 | `background: AppColors.transparent` ⇒ 无底色，只剩字形（壳层默认 `background == null` 才走毛玻璃） |
| 「滚动变暗」 | `color` 由左栏滚动进度驱动：`_scrollProgress() < 0.5` 时 `white` + `glyphShadows`，≥0.5 时 `barContrast.contentColor`（浅色主题下为深色）⇒ **白 → 深** = 观感变暗 |

它是**顶栏时代的遗留**：当年顶栏随滚动由「透明渐变」转「不透明毛玻璃吸顶」，按钮为配合背景变化而跟着翻色；
顶栏已在 R3 整体移除，这套翻色机制遂成**无源之木**（背景不再变化，按钮却在变色）。

## R4-2 方案

**播放页只声明语义，外观全交壳层默认**：

1. `video/detail_page.dart` 的 `_backButtonSpec` 去掉 `color/background/shadows/iconSize`
   ⇒ `background == null` 走 `GlobalBackButton` 的 `frosted` 分支 = **首页顶栏同源材质**
   （`AppTopBarSurface.barColor(surface)` × `blurSigma 20` + 半径 21 圆裁剪 + `outline/shadow: false`），
   字形取 Token `onSurfaceVariant` + 伪粗体叠绘；滚动/全屏切换外观**恒定**。
   仅保留语义：浏览态 `tooltip:'返回'` + `onBeforePop`（暂停/解绑播放器）；全屏态 `tooltip:'退出全屏（Esc）'`
   + `onPressed:_handleEscape`。
2. `bangumi/bangumi_player_page.dart` 同口径（保留其顶栏仍在所需的 `_topBarScrollOpacity`）。
3. 清理随之失效的滚动翻色链路（两页）：`_scrollRatio` 不再驱动规格（字段/dispose/两处赋值收敛）、
   detail_page 的 `_scrollProgress()` + `_kTopBarAbsorbMin/Max` 删除、`BackButtonOwner` 去掉 `listenable`、
   `onScrollRatioChange` 收敛为 tear-off、detail_page 两个失效 import（`contrast_policy` / `glass_contrast_widgets`）删除。

> **口径变化**：R1→R3 的「媒体叠加页用透明底 + 对比色字形」在**播放页**被 R4 推翻（CVO 要求可见模糊底）。
> 个人空间/直播全屏仍保留半透明黑圆底（未涉及，见 R4-4）。
