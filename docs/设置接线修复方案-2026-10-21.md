## 〇、一句话背景

设置页（外观/播放/音视频/其它四组）是从上游 PiliPlus 照搬的 UI 骨架，**值能写入 Hive 并持久化**，但对应的消费端在 WinWin 桌面化改造中未同步接线，导致"看起来能设、实际不生效"。本方案把每个未接线项落到具体文件与函数，按优先级分批次修复。

## 一、接线通用模式（三类断裂）

| 类型 | 特征 | 涉及项 |
|---|---|---|
| **A｜仅 UI+key，无 getter** | `setKey` 写了值，`storage_pref.dart` 连 getter 都没建 | `uiScale`、`showTrayIcon`、`minimizeOnExit`、`isPureBlackTheme`、`showFsLockBtn`、`showFsScreenshotBtn`、`pauseOnMinimize` |
| **B｜有 getter，无调用者** | `Pref` getter 存在，但全库零消费 | `defaultTextScale`、`autoPlayEnable`、`enableAutoEnter`、`enableAutoExit`、`enableBackgroundPlay`、`enableOnlineTotal`、`hardwareDecoding`、`videoSync` |
| **C｜值被硬编码覆盖** | 消费端写死常量，忽略用户值 | `appRcmd`（`rcmd/controller.dart:10` 写死 `true`） |

**标准接线动作**：① 补 `Pref` getter → ② 在消费端读取并生效 → ③ 需要热生效的挂 `ValueNotifier` 重建 → ④ 补实机验证点。

## 二、修复清单（按优先级）

### P0｜桌面窗口 / 托盘（桌面端最高感知，**需新增依赖**）

> 现状：`pubspec.yaml` **无任何托盘依赖**，全库无托盘代码。这是本次唯一需要引入新依赖的批次。

#### P0-1 显示托盘图标 `showTrayIcon`
- **接线点**：新建 `lib/core/window/tray_controller.dart`；`lib/main.dart`（windowManager 就绪后初始化）；`storage_pref.dart` 补 getter。
- **改动**：
  1. `pubspec.yaml` 新增 `tray_manager`（Windows 支持，与现有 `window_manager 0.5.2` 兼容性需先验证）。
  2. `TrayController`（单例）`init()`：读 `Pref.showTrayIcon`，为真则 `trayManager.setIcon(assets/app_icon.png)` + 菜单「显示主窗口 / 退出」。
  3. 设置页 `SwitchModel.onChanged` → 实时创建/销毁托盘（热生效，免重启；去掉 `needReboot`）。
- **依赖/风险**：新依赖引入需评估（原生 Win32 调用、打包体积）；备选方案是 `windows/runner` 原生 `Shell_NotifyIcon`（成本高，不推荐首轮）。
- **验证**：开启 → 任务栏通知区出现图标；右键菜单可显示窗口；关闭 → 图标消失（需重启则记录）。

#### P0-2 退出时最小化到托盘 `minimizeOnExit`
- **接线点**：`lib/core/window/window_state_controller.dart` 的 `onWindowClose`（`:155`）；`tray_controller.dart` 的「退出」菜单。
- **改动**：
  1. 启动时 `windowManager.setPreventClose(true)`。
  2. `onWindowClose`：若 `Pref.minimizeOnExit && Pref.showTrayIcon` → `await windowManager.hide()`（最小化到托盘）并落盘窗口状态；否则放行真正退出。
  3. 托盘菜单「退出」置一次性 flag → 允许真正 `destroy()`。
  4. 与 P0-1 联动：`showTrayIcon=false` 时该开关应失效（无托盘可最小化到）。
- **验证**：开启后点关闭按钮 → 窗口隐藏、进程仍在；托盘「退出」→ 进程结束。

### P1｜外观与全局缩放（**一次接线影响全 UI**）

#### P1-1 纯黑主题 `isPureBlackTheme`
- **接线点**：主题构建处 `lib/theme/`（AppShell 的 isDark 主题生成）+ `storage_pref.dart` 补 getter。
- **改动**：深色主题背景基色按开关替换为纯黑（`#000`）；用 `ValueNotifier` 触发整树重建实现热生效（去掉 `needReboot`）。
- **风险**：需核对所有 `surface/background` 派生 token，避免仅局部变黑出现色差。
- **验证**：开启 + 深色模式 → 页面底色纯黑；切换开关即时生效。

#### P1-2 字体大小 `defaultTextScale`
- **接线点**：`lib/main.dart` 的 `WinWinApp.build`（AppShell 外层）；`storage_pref.dart` 已有 `defaultTextScale` getter。
- **改动**：AppShell 外包 `MediaQuery(data: MediaQuery.of(context).copyWith(textScaler: TextScaler.linear(Pref.defaultTextScale)), child: ...)`；用 `ValueNotifier` 热生效（现有 UI 文案"重启生效"可去掉）。
- **验证**：拖动滑块 → 全局字号即时变化；重启后保留。

#### P1-3 界面缩放 `uiScale`
- **接线点**：同 P1-2 位置；`storage_pref.dart` **需补 getter**。
- **改动**（**设计决策点，需确认**）：
  - 方案 A（推荐）：整树包 `Transform.scale` + 逻辑视口补偿（`SizedBox(w/uiScale, h/uiScale)`），实现"整体缩放"。
  - 方案 B：与 P1-2 合并为统一缩放通道（仅文字，语义偏窄）。
- **风险**：方案 A 需实机验证**命中测试（点击坐标）与滚动行为**是否随缩放正确映射；与字体大小叠加时的相互影响需明确。
- **验证**：缩放 0.8/1.5 → 控件与文字整体变化，点击响应位置正确。

### P2｜播放器内核（影响播放质量/兼容性）

#### P2-1 硬件解码模式 `hardwareDecoding`
- **接线点**：`lib/pages/video/player_controller.dart` 的 `_createPlayer()`（`:702` 现仅按 `Pref.enableHA` 二选一）。
- **改动**：按 `Pref.hardwareDecoding` 映射 `videoDecoders`：
  - `auto` → `['MFT:d3d=11','D3D11','DXVA','CUDA','hap','FFmpeg','dav1d']`（当前 auto 行为）
  - `auto-copy` → 同 auto，另加复制语义属性
  - `d3d11va` → `['D3D11','FFmpeg']`；`dxva2` → `['DXVA','FFmpeg']`；`no` → `['FFmpeg','dav1d']`
  - `enableHA=false` 时强制 'no'（**总开关优先**于具体模式）。
- **验证**：debug 日志观察 mdk 实际选择的 decoder；分别播放 H.264/H.265/AV1。
- **风险**：与 `enableHA` 语义重叠，需在设置页注明层级关系。

#### P2-2 视频同步模式 `videoSync`
- **接线点**：同 `_createPlayer()`（现固定 `avsync.audio.adaptive=0`）。
- **改动**：把四个选项（`audio`/`display-resample`/`display-desync`/`display-vdrop`）映射到 mdk 的 `video.sync`/`avsync.*` 属性。
- **⚠️ 前置**：**mdk 属性名与支持度必须先确认**（查 fvp/mdk wiki 或源码）。若 mdk 不支持对应属性 → **不接线，改为隐藏该设置项**，避免"改了没反应的假设置"。
- **验证**：确认属性可用后，逐模式播放观察音画同步（配合已有 Seek 探针）。

### P3｜播放器行为（进入/退出/后台）

#### P3-1 自动播放 `autoPlayEnable`
- **接线点**：`lib/pages/video/detail_page.dart`（`initState :323` / 播放器就绪回调）。
- **改动**：先确认**当前默认是否已自动播放**：若默认自动播，则该开关控制"进入详情页是否自动起播"；否则控制"加载后是否自动 start"。
- **验证**：开/关各进一次详情页观察是否自动播放。

#### P3-2 自动进入全屏 `enableAutoEnter`
- **接线点**：`detail_page.dart` 进入详情页首帧后（已有 `DesktopFullscreen.enter()` 于 `:1030`）。
- **改动**：进入视频后 `if (Pref.autoEnterFullScreen) DesktopFullscreen.enter();`。
- **验证**：开启 → 进详情页自动全屏。

#### P3-3 自动退出全屏 `enableAutoExit`
- **接线点**：`player_controller.dart` 播放自然结束回调（stream completed / ended）。
- **改动**：结束时 `if (Pref.autoExitFullscreen && DesktopFullscreen.isFullScreen) DesktopFullscreen.exit();`。
- **验证**：全屏下待播放结束 → 自动退出全屏。

#### P3-4 后台播放 `enableBackgroundPlay` + P3-5 暂停时最小化 `pauseOnMinimize`
- **接线点**：新增**窗口最小化监听**（`detail_page.dart` 已 `with WindowListener`，补 `onWindowMinimize`；或在 `WindowStateController` 广播全局事件供播放器订阅）。`storage_pref.dart` **需补 `pauseOnMinimize` getter**。
- **改动（两开关同一触发点，需定义优先级）**：
  - 窗口最小化时：`pauseOnMinimize=true` → 暂停；
  - 否则 `enableBackgroundPlay=true` → 保持播放；
  - 否则 → 暂停（默认安全）。
- **风险**：托盘「隐藏」是否等同"最小化"，需与 P0-2 统一口径。
- **验证**：最小化窗口，观察音频是否按设置继续/暂停。

## 三、批次划分与执行顺序

| 批次 | 内容 | 预估风险 | 依赖 |
|---|---|---|---|
| **批次 1** | P0 托盘（依赖引入 + 控制器 + 两开关） | 高（新依赖） | 需先验证 tray_manager |
| **批次 2** | P1 纯黑主题 / 字体大小 / 界面缩放 | 中（影响全 UI） | uiScale 方案需确认 |
| **批次 3** | P2 硬解模式 / 同步模式 | 中 | 同步模式需先探测 mdk 属性 |
| **批次 4** | P3 自动播放 / 进·退全屏 / 后台 / 暂停最小化 | 中 | 需先确认当前自动播行为 |
| **批次 5** | P4 全屏控件显隐 + P5 在线人数 | 低 | 在线人数需对齐 API 参数 |
| **批次 6** | P6 其余顺手接线 | 低 | 无 |

**每批次固定流程**（遵循项目规范）：持久化快照 → 改动 → `dart analyze`(0/0) → `flutter build windows --debug` → `flutter build windows --release` → 启动产物由 CVO 实机验证 → 提交（带签名 `[小通/deepseek-v4.1-flash]`）→ 写复盘入 `docs/`。

## 五、风险与回滚

- 全程持久化快照，回滚 `git reset --hard <快照SHA>`。
