## 1. 现象描述（批次目标）

`InputDecoration(` 17 处（随后两者处置消解）。形态普查发现六类：

另：10 处 SelectableText 均已在 B7-c1 补丁#3 接入桌面 Handle 控件 + Miuix 菜单
（其选择菜单经 EditableText 体系），替换替身须保住该行为。

## 2. 根因与设计

- 残留成因：输入控件是 B7 分族中独立一族（c3 位），前序批次未触及；
  `SelectableText`/`TextField`/`InputDecoration` 均为 material 专有（widgets 层
  无等价物），须经语义替身过渡。
- 替身设计（对已有素材取最小扩展）：
  - `AppTextField`（已存在：MiuixTextField + MiuixCompat + 格式化器控制器桥接）
    ——**补 7 个透传参数**（autofocus/enabled/readOnly/textInputAction/textStyle/
    cursorColor/colors）；
  - **`AppCapsuleTextField`（新）**：以 MiuixTextField 的 `cornerRadius(100)`/
    `insideMargin(紧凑)`/`colors` 复刻胶囊条；`fillColor` 传透 + `insideMargin`
    zero + `borderColor` 传透 即"透明档"（外层容器已有样式的直播条/发弹幕面板）；
    `onPressed` 经外层 `Listener(onPointerDown)` 捕获（**MiuixTextField 无 onTap**，
    用于登录守卫）；
  - **`AppSelectableText`（新）**：`SelectableRegion`（cupertino 桌面 Handle 控件
    + `buildMiuixTextSelectionContextMenu`）+ `Text`（maxLines 时 ellipsis）。
- 上游参数面缺口处置：无 `inputFormatters`（既有控制器桥接补偿）→
  **无 `maxLength`** 以 `LengthLimitingTextInputFormatter(100)` 等效替代（发送面板
  两处）；无 `onTap` → Listener；无 `textAlign` → 保留形态（demo_editable）。
