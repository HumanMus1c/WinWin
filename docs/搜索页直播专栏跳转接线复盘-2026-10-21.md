# 搜索结果页「直播 / 专栏」跳转接线复盘（2026-10-21）

> 承接搜索链路文档链：《搜索页顶栏就地扩充复盘-2026-10-19》→《搜索态扩充动效与合并栏阴影复盘-2026-10-21》
> →《搜索封面加载失败复盘-2026-10-21》。
> 本轮是 CVO 反馈的**搜索结果页「直播」「专栏」分类点不进去**缺陷修复：为两处仍打桩的卡片接上真实跳转出口，
> 并顺带补齐「视频」分类里直播条目的同类缺口。**不改数据口径与列表布局**。

## 一、现象描述

CVO 反馈（2026-10-21 16:25）：搜索结果页的**直播**和**专栏**调整——目前无法跳转至对应页面。

实机表现（结合源码核对）：

1. 搜索结果页切 **「直播」** tab，点击任意直播间卡片：只弹一句
   `直播功能暂未接入：{主播名} 的直播间` 提示，**不进入直播间**。
2. 搜索结果页切 **「专栏」** tab，点击任意专栏卡片：只弹一句
   `专栏功能暂未接入：{标题}` 提示，**不进入专栏正文**。
3. 附带的同类缺口：**「视频」** tab 中 `type == live_room` 的直播条目，点击后**静默无响应**
   （既不跳转、也不提示）。

> 同页 **「用户」「番剧」「影视」** 卡片跳转正常。

## 二、问题定因

**根因一句话**：`lib/pages/search/search_panel.dart` 里直播卡片（`_buildLiveCard`）与专栏卡片
（`_buildArticleCard`）的 `onPressed` **从未接线**，只 `showToast` 打印"暂未接入"
占位提示；而项目内**跳转落点页面早已存在**（`LiveRoomPage` / `ArticlePage`，历史页、动态页、
个人空间页均在用），属于"端口已竣工、只差一根引线未接"。

### 2.1 证据链（逐环可查）

1. **直播卡片打桩** — `lib/pages/search/search_panel.dart`（改动前 `:388-395`）：
   ```dart
   onPressed: () {
     // 直播间跳转暂未实现，显示提示
     showToast(context, '直播功能暂未接入：${item.uname} 的直播间', ...);
   },
   ```
   注释自陈"暂未实现"，即占位态而非缺陷态。

2. **专栏卡片打桩** — 同文件（改动前 `:604-610`）：
   ```dart
   onPressed: () {
     showToast(context, '专栏功能暂未接入：${item.title}', ...);
   },
   ```

3. **落点页面已就绪** — 全仓调用点（`grep "LiveRoomPage(" / "ArticlePage("`）：
   - `LiveRoomPage(roomId, {title, uname, cover})`：`pages/history/history_page.dart:341`、
     `pages/dynamics/view.dart:1099/1735/2189`、`pages/member/member_space_page.dart:3089` 等 8 处；
   - `ArticlePage(id, {title, cover, desc})`：`pages/history/history_page.dart:318`、
     `pages/dynamics/view.dart:1108/1635`、`pages/member/member_space_page.dart:3017` 等 6 处。
   —— 两页的构造签名与既有用法**已经稳定**，搜索面板只是漏接。

4. **模型字段充足，无需补数据层** — `lib/models/search/result.dart`：
   - `SearchLiveItemModel` 带 `roomid` / `title` / `uname` / `cover` / `cateName`；
   - `SearchArticleItemModel` 带 `id` / `title` / `desc` / `imageUrls`；
   - `SearchVideoItemModel` 带 `isLive` + `roomId`（`type == 'live_room'` 时置位，
     见 `:78-87`）。
   跳转所需 ID 全部已在模型内，故本轮为**纯接线**，不动 HTTP/模型。

5. **「视频」tab 直播条目静默无响应** — `_buildVideoCard` 的 `onTap` 只判 `item.bvid != null`；
   直播条目无 `bvid`（走 `type == live_room` 分支），落到 `if` 之外即**无分支、无提示**，
   点下去毫无反应。

## 三、修复方案

统一改在 `lib/pages/search/search_panel.dart`，三处 `onPressed/onTap` 接上既有落点页面，
并保留 ID 缺失时的兜底提示（防脏数据点击无响应）：

### A｜直播卡片 → `LiveRoomPage`

```dart
onPressed: () {
  final roomId = item.roomid;
  if (roomId == null) {
    showToast(context, '暂不支持打开该直播间', ...);
    return;
  }
  Navigator.push(context, AppRoute(builder: (_) => LiveRoomPage(
    roomId: roomId, title: item.title, uname: item.uname, cover: item.cover,
  )));
},
```

### B｜专栏卡片 → `ArticlePage`

```dart
onPressed: () {
  final articleId = item.id;
  if (articleId == null) {
    showToast(context, '暂不支持打开该专栏', ...);
    return;
  }
  Navigator.push(context, AppRoute(builder: (_) => ArticlePage(
    id: articleId.toString(),
    title: item.title,
    cover: hasImg ? item.imageUrls!.first : null,
    desc: item.desc,
  )));
},
```

### C｜视频卡片补直播条目分支（同类一并修全，避免留半截）

```dart
if (item.isLive && item.roomId != null) {
  Navigator.push(context, AppRoute(builder: (_) => LiveRoomPage(roomId: item.roomId!)));
  return;   // 直播条目无 bvid，必须提前返回，否则落到下方 bvid 判空静默无响应
}
```

新增两条 import：`package:winwin/pages/article/article_page.dart`、
`package:winwin/pages/live/live_room_page.dart`。

> **影响面**：只改点击出口，列表渲染、分页、封面、演示模式分支一字未动；
> `ImageUtils.thumbnailUrl` 与模型归一化均不涉及。

## 五、遗留与踩坑

1. **本轮未做实机 UI 验证**：项目约定实机 UI 验证由 CVO 手动完成（不走自动化操控），
   本轮仅完成静态分析 + 双编译；跳转是否真正落到可播放/可阅读页面**待 CVO 实机确认**。
2. **跳转未登记访问用户**：搜索面板的"视频/用户"卡片会 `SearchHistoryService().addVisitedUser`，
   本轮直播/专栏接线**未同步登记**（保持最小 diff，不引入未要求的行为变更）。
   若 CVO 希望搜索过的直播/专栏也进"点过的用户"胶囊，可另起一轮补。
3. **直播条目"未开播"态未区分**：`LiveRoomPage` 自身处理离线/轮播态，搜索列表不再前置拦截
   `live_status`；如遇大面积"该直播间不存在"提示，需回看搜索接口对已下播房间的返回口径。
4. **同类隐患扫描**：搜索结果页其余分类（番剧/影视/用户/视频）跳转此前已接线且本轮复核正常；
   本仓其他列表页是否存在"打桩卡未接线"的同类残留，留作跟进队列（本轮仅按 CVO 所指的搜索页收口）。
