- 弹层布局破坏：全局挂载后，弹层 / 面板内的滚动视图同样被预留 12px 通道 ⇒ 抢布局。
- **结论**：「直角硬矩形条」＝预留通道透出**父级非页面背景的灰色表面**；反馈轮 5 的「框架 `RawScrollbar` 方角条」归因**不成立**（自绘条本身圆角、且通道透明无填充），该归因保留其独立价值：桌面 SDK 默认条确为方角（`radius/trackRadius = null → drawRect`），抑制仍有意义。

**修法**（2 文件，仍在 `AppScrollBar` 内单一收口）：
1. **通道按页面背景色着色**：`_buildLane` 取 `AppThemeHost.of(context).colors.background`，用 `ColoredBox` 包住 `laneBox` ⇒ 通道与页面背景一致，**不再透出父级灰底**（硬带消失）；
2. **新增 `AppScrollBar.pageLevelExtentRatio = 0.5`**：仅「页面级」滚动视图（主轴向尺寸 ≥ 窗口主轴向 × 0.5）预留通道；弹层 / 面板 / 局部小列表改走新增的 `_suppressFrameworkBar(child)` —— **不预留通道、不抢布局**（修复弹层布局破坏），仅关掉框架方角条；
3. **无界约束路径**同样改走 `_suppressFrameworkBar`（原先直接 `return widget.child`，会漏掉框架方角条）。

## 反馈轮 7（2026-10-17，实机）

**反馈**：反馈轮 6（通道着色 + 页面级阈值）**未解决**：① 仍在「滑动条**轨道默认占位**显示为灰色直角矩形」；② 视频卡片「更多操作」弹层**容器高度被撑高**。

**定因（机制性两条，互为因果）**：
- ② **`CrossAxisAlignment.stretch` 撑高**：通道版布局是 `Row(crossAxisAlignment: CrossAxisAlignment.stretch, children: [Expanded(内容), 通道])`；`stretch` 会把交叉轴尺寸取到**约束上限** ⇒ 在「高度受上限约束、内容本应自适应」的弹层容器里，直接把内容撑到最大高 ⇒ 容器高度被撑高。且被撑高后其主轴向尺寸反超窗口 50%，**页面级阈值反而拦不住它** —— 两个症状同源。
- ① **"占位"本身就是根因**：只要「预留 12px 通道」存在，就必然有一条通高、近似直角的带子占据该占位；且 painter 在 hover / 滚动时还会画**通高轨道**（`showTrack: e > 0.15`，半径 = thickness/2 ⇒ 5~9px 宽通高带），视觉即"灰色直角矩形"。反馈轮 6 只改「通道该显示什么颜色」，未解决「存在占位」。

**修法（取消占位 ⇒ 覆盖层；取消轨道）**：
1. 通道布局 `Row(stretch)` → **`Stack` + `Positioned` 覆盖层**（`Stack[内容, Positioned(右/下 0, 宽/高 12, 滚动条)]`）：Stack 以**非定位子**定尺寸 ⇒ 内容尺寸**完全不变**，既不抢宽度也不撑高度（修 ②）；
2. **不存在独立通道占位** ⇒ 不再有任何"被占位的通高带"（修 ①）；
3. painter **删除轨道绘制**（`showTrack` 字段 / 构造参数 / 两个绘制分支 / `shouldRepaint` 项一并移除），只保留**圆角滑块**，杜绝通高近似直角观感；
4. 保留：页面级阈值（弹层 / 局部小列表不挂条）、`_suppressFrameworkBar` 框架方角条抑制、无界约束降级。

**验证**：`dart analyze` **No issues found!** / `flutter test` **All tests passed! (+174)** / `windows --debug` **√ Built 35.1s** / `windows --release` **√ Built 76.2s**（本次无需结束进程）。闸门保持 **5**。

**已知代价（待实机确认）**：覆盖层会压住内容最外侧约 11px；页面普遍已有等宽内边距（`Style.safeSpace = 12`），实际落在留白上。本轮以"消除占位与撑高"为先。

## 现象收尾结论（2026-10-17，实机验收通过）

### 一、现象时间线（7 轮，同一族问题）
| 轮 | 用户现象 | 当轮动作 | 结果 |

### 二、最终根因（两条机制，互为因果）
- **A·撑高**：`Row(crossAxisAlignment: CrossAxisAlignment.stretch)` 会把交叉轴尺寸取到**约束上限** ⇒ 撑满"高度有上限、内容本应自适应"的弹层容器；被撑高后其主轴向尺寸反超窗口 50%，又使页面级阈值失效 ⇒ **"弹层被撑高"与"阈值拦不住"是同一病根**。
- **B·灰直角矩形**："预留 12px 通道"这一**占位**必然占出一条通高带；painter 还在 hover/滚动时画**通高轨道**（半径 = 厚度/2 ⇒ 5~9px 宽通高 ⇒ 近直角）。焦点应是「**存在占位**」，而非「通道显示什么颜色」。

### 三、被推翻的两个错误归因（核心教训）
1. **轮 5**：判"硬条 = 桌面 SDK 默认 `RawScrollbar`（`radius/trackRadius = null → drawRect` 方角）"—— **形态吻合 ≠ 根因相符**：该条出现在**已手动包裹**的番剧页内部（框架条已被抑制），且自绘 painter 无填充、通道透明可透出父级底色 ⇒ 像素取证与代码互斥。（框架方角条抑制仍有独立价值，保留。）
2. **轮 6**：判"通道透出父级灰底，改通道颜色即可"—— 只治表象：占位仍在、轨道仍在，故用户复验"没有修复"。
3. **元教训**：连续两轮都从"条长什么样"出发猜绘制者，而未先回答"**这个占位是否该存在**"。后续遇同类"形态问题"，先问"占位/布局是否本就不该有"，再谈样式。

### 四、最终实现口径（现行准则，勿回退）
1. **不预留占位**：`Stack + Positioned` 覆盖层 —— 内容尺寸完全不变（不抢宽、不撑高、无占位带）；
2. **只画圆角滑块，无轨道**；
3. 三态：空闲 5px/α0.35 → hover 或滚动 9px/α0.68 → 拖拽 11px/α0.92（拖拽再 `lerp(onSurface, black, 0.25)` 加深），170ms 补间、700ms 防抖回落、`DragStartBehavior.down` 跟手、拖动期间零 `setState`；
4. **页面级阈值** `pageLevelExtentRatio = 0.5`：仅页面级滚动视图挂条；弹层 / 面板 / 局部小列表只抑制框架方角条、不加条；
5. `_NoFrameworkScrollBar` 抑制嵌套框架条；`LayoutBuilder` 无界约束降级返回。

### 五、代价与边界
- 覆盖层压住内容最外侧约 11px；页面普遍有 `Style.safeSpace = 12` 内边距兜底 ⇒ 实际落在留白上，观感等同"内容区与窗口边缘之间"；
- **例外处理**：若某页内容无尾部内边距导致轻微重叠，给该页滚动视图**单独**留 12px 内边距（不影响其它页），勿再回到"全局预留通道"。
