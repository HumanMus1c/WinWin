# 上游采纳批次 B：播放健壮性（2026-11-11）

> 口径：PiliPlus 基线 `bb2d86ca2` → `c7ff9683c`；BiliPai 基线 `70a6eeccb` → `4f32bba`。本批只落地逐条复核后确认缺失的播放健壮性与桌面交互项。

## 一、现象

1. CDN 自愈只会按 `(index + 1) % n` 轮换候选：同一坏节点会在下一轮再次被撞上，弱网下表现为反复卡顿、反复重挂。
2. 加载失败一律进入自动重试：DRM、版权/地区限制、登录失效等重试也不会成功的错误，仍会消耗 4 次退避重试，用户迟迟看不到明确原因。
3. 桌面端长按 ← 只触发一次快退；→ 已支持长按倍速，左右方向键交互不对称。

## 三、方案（逐文件）

### B1 · CDN 候选失败记忆与按候选冷却

- 新增 [cdn_failover_policy.dart](file:///d:/Documents/GitHub/WinWin/lib/core/policy/cdn_failover_policy.dart)（纯逻辑）：
  - `recordFailure` / `recordSuccess`：按候选 URL 记录连续失败，成功清零；
  - `shouldSkip`：30 秒 → 2 分钟 → 10 分钟指数退避（3 次以上维持 10 分钟）；
  - `nextIndex`：优先跳过冷却中的候选；`excludeCurrent` 保证自愈必须换源；全部冷却时退回顺序轮换；
  - 失败记录上限 64 条，超限按最近失败时间淘汰。
- 接入 [player_controller.dart](file:///d:/Documents/GitHub/WinWin/lib/pages/video/player_controller.dart)：
  - 加载时从列表头选择首个非冷却候选；
  - 自愈轮换前记录当前音视频候选失败，再取下一可用候选；
  - 自愈成功清零新候选失败记忆；
  - 快退重开路径同样跳过冷却候选（`excludeCurrent` 仅在多候选时启用）；
  - `prepare` 硬失败记录失败，供自动重试时换源。

### B2 · 加载错误分类

- 新增 [playback_error_classifier.dart](file:///d:/Documents/GitHub/WinWin/lib/core/policy/playback_error_classifier.dart)（纯逻辑）：
  - 网络/连接超时、5xx、429、未知异常 → 可重试；
  - 取消、证书错误、4xx、DRM、版权/地区/登录限制 → 不可重试；
  - `userMessage` 过滤原始异常/堆栈/超长文案，只展示干净单行提示。
- 接入 `player_controller.dart`：
  - `playurl` 为空时优先展示接口可读文案（如 DRM 提示），并按文案判定是否重试；
  - 加载异常改用分类器决定 `_loadFailureRetryable`，非瞬态错误不再进入 4 次退避重试。
- 无法识别的文案默认保持可重试，避免改变既有弱网红错行为。

### B3 · 长按 ← 连续快退

- [player_focus.dart](file:///d:/Documents/GitHub/WinWin/lib/pages/video/player_focus.dart)：
  - 短按行为不变（单次快退 10 秒）；
  - 按住 200ms 后进入长按态，每 200ms 累加一个快退步长；
  - 松开时一次性提交 seek，避免连续触发底层 seek；
  - 吸收 Windows 键盘自动 repeat 的重复 KeyDown；dispose 时取消定时器。

## 六、遗留与踩坑

1. **长按 ← 无进度预览**：当前只累加目标位置，松开后一次性跳转；未复用 `seekPosition` 做预览，避免与真实 seek 冻结窗口混用。若后续需要 PiliPlus 式跟手预览，建议新增独立的 `seekPreview` 通道。
2. **CDN 失败记忆仅内存级**：重载后 B 站下发的是新签名 URL，旧记录自然失效；无需持久化，也不会跨会话误伤。
3. **错误分类依赖关键词**：服务端文案变化时需补充 `playback_error_classifier.dart` 的关键词表；无法识别时仍按可重试处理，属安全兜底。
4. **上游已覆盖项不重复移植**：音频/视频分源、缓冲期暂停、Seek 超时、倍速保缓冲、目标画质、桌面时间字号均已具备，见 §二。
5. **B4/B5 暂缓**：滚轮调音量、深链 `dm_progress` 提前 3 秒、评论时间戳跳转属功能新增，留待后续批次评估。

## 七、实机验证结果（2026-11-13）

- 环境：Release 实例（2026-11-12 13:11 启动），日志 `D:\Documents\logs\runtime.log` 与 `D:\Documents\logs\trace.log`。
- 正常播放：连续打开多个视频，`playurl` / `prepare ret=0` 正常，心跳与历史进度持续上报；无 `[E]`、无崩溃、无播放器冻结。
- B1：2026-11-13 14:20:25 弱网触发 `Buffering stall detected`，随后 `Switching CDN candidate: line=2/2`，说明失败记忆与换源路径已实际执行；本次只发生一次换源，未观察到反复命中同一候选。
- 弱网恢复：14:20~14:28 期间缓冲反复进入 hold，音频实例多次自愈；14:28:35 `BUFFER-HOLD-RESUME-PUSH` 后恢复，14:29:28 时 buffer 已增长到约 175 秒、`avgRate≈0.96`、`buffering=0`，播放恢复正常。
- B2：本轮未出现 `LOAD-RETRY`，弱网异常仍按预期进入自动重试；DRM/版权限制内容未在本轮实测中触发，分类逻辑由单测覆盖。
- B3：用户实机确认长按 ← 连续快退可用；日志不记录按键事件，未出现异常 seek 或播放中断，短按行为未观察到回归。
- 崩溃日志：最新一条为 2026-11-13 14:02:25 的 `RenderFlex overflowed by 22 pixels`，来自 debug 0.1.2（build 26110301）旧实例，早于本批 Release 验证，不归因于批次 B。

结论：批次 B 无回归；CDN 换源与弱网自愈路径实际生效。观察项：弱网恢复期约 8 分钟，期间界面仅有缓冲态、没有「网络较慢」提示，非本批回归，建议后续评估低速提示。
