# HTTP 响应体 cast 统一收敛复盘（2026-10-18）

> 范围：新增 `lib/http/response_map.dart`（共享抽象）+ 8 个 http 文件收敛 + 测试更名。
> 关联：本文件为「非 B7 项」审计轨迹，不计入 B7 批次；闸门（`lib` 内 `import 'package:material_ui` 文件数）保持 **5**。

## 一、现象 / 背景

上一轮（`member.dart`）修复 `MemberSpace: topPhoto` 崩溃后，遗留「同型裸 cast」提案：全站仍有 **27 处**
顶层裸 `res.data as Map<String, dynamic>`，分布于
`live(9) / dyn(5) / history(4) / fav(4) / toview(3) / user(1) / article(1)`。

风险同源：任一接口在**风控 / 限流 / 接口异常**时返回**非 JSON** 响应体（HTML 错误页、空体、`text/plain`），
裸 cast 抛 `type 'String' is not a subtype of type 'Map<String, dynamic>' in type cast`，
被外层 `catch` 吞成「加载失败」，用户与日志均看不到根因。

## 二、定因

- **解析口径分散**：各 http 文件各自裸 cast，未共用「非 JSON 降级」策略；`search.dart` / `video.dart`
  用 `is Map` 守卫、其余裸 cast —— 同类问题多种写法，漏改即为崩溃点。
- **双定义隐患**：上一轮把降级逻辑临时内置为 `MemberHttp.asJsonMap`（member.dart 私有），
  若其它文件各自再抄一份，将违反「概念单点定义」（家规 P4）。
- 结论：需要把「响应体安全解析」抽为**共享抽象**，全站单点定义、统一降级。

## 三、方案

- 新增 `lib/http/response_map.dart`：顶层函数 `Map<String, dynamic> asJsonMap(dynamic body)`（**唯一实现**）：
  - `Map` → 原样返回（happy path 零拷贝）；
  - `String` → 尝试 `jsonDecode`（兼容 content-type 未标 JSON 的 JSON 文本）；
  - 其余（含解析失败）→ 记 `AppLogger.w`（含 `runtimeType`，保留可诊断线索）并返回**空 Map**。
- **收敛**：
  - `member.dart`：删除临时 `MemberHttp.asJsonMap` 静态定义与 `dart:convert` import，13 处改调共享 `asJsonMap`；
  - 7 文件 **27 处**裸 cast → `asJsonMap(res.data)`，各补 `import 'package:winwin/http/response_map.dart';`。
- **调用约定**：空 Map 使调用方惯用的 `data['code'] == 0` 自然为假 → 落入既有的失败 / 默认分支，
  **不新增文案、不新增分支**，happy path 行为完全不变。
