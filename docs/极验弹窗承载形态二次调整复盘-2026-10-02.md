# 极验弹窗承载形态二次调整复盘（2026-10-02）

**范围**：承载形态从「无边框全屏白页」二次调整为「**灰蒙层 + 近全屏内容区**」（对齐 BiliPai 现款）。
**背景**：用户实机反馈"现在是新开一个全屏页面承载，而不是灰色半透明的不可见控件区承载"——期望**登录页仍隐约可见（被灰色半透明压暗）**，极验内容以无边框形式覆盖其上；经选项确认选定本形态（Plans 面板 AskUserQuestion 记录）。
**取代关系**：本形态取代同日「无边框全屏」（`e62ce5f`）——全屏白页把登录页完全盖住，缺少"覆盖层"感。

---

## 一、分析根因

### 1.1 现象描述

全屏白页（`e62ce5f`）把登录页完全盖住，观感上像"新开了一个页面"，不符合用户期望的"灰色半透明的不可见控件区承载"。

### 1.2 期望形态取证（BiliPai = 本项目 Android 原型，逐行核对）

| 事实 | 取证 |
|---|---|
| 灰色半透明蒙层 | `CaptchaManager.kt:122-136`：`setDimAmount(0.42)`（暗化 42%） |
| 承载控件区"不可见" | 同处：`setBackgroundDrawable(ColorDrawable(Color.TRANSPARENT))`（窗口背景透明、无可见容器） |
| 近全屏内容区 | `LoginPhonePolicy.resolveCaptchaDialogLayoutPolicy`：宽 = 屏宽 × 0.96、高 = 屏高 × 0.88、居中（四周露出蒙层与底层页面） |

### 1.3 备选（未采用）

webview 透明背景（`transparentBackground`，Windows C++ 已支持 alpha=0）+ 内容背景全透明（登录页连内容间隙处也透出）——观感风险高、收益不明确，用户选择近全屏内容区方案。

---

## 二、设计修复计划（关键决策）

| 决策 | 选择 | 说明 |
|---|---|---|
| 蒙层 | `barrierColor = Colors.black@0.42`（显式） | 对齐 BiliPai `setDimAmount(0.42)`；由 `showDialog` 的 barrier 提供 |
| 内容区 | `Center` + `FractionallySizedBox(0.96, 0.88)` + 白底 `Material` | 无边框/无圆角；四周露出蒙层与登录页 |
| 关闭按钮 / 加载态 | 保持在内容区内（左上角 / 居中） | 与 PiliPlus / BiliPai 一致 |
| 契约 | `showDialog` / `await` 返回值 / Esc layer1 / `barrierDismissible:false` **不变** | 调用点与诊断按钮零改动 |
| 改动面 | 仅 `geetest_webview_dialog.dart` | 外层不再绘制背景（透明），由路由 barrier 压暗 |
