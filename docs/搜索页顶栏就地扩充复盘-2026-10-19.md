# 搜索页顶栏就地扩充复盘 —— 让「搜索」不再跳页，而在原地长出来

- 日期：2026-10-19
- 快照基准：改动前 HEAD = `662ebad`（设计文档 v3；worktree clean，回滚见第五节）
- 触发：CVO 指令「开始设计改造搜索页，将其从二级页面改为首页顶栏的变形高度扩充（非搜索框高度撑开），隐藏分类 TAB 栏，将扩充的区域用于展示搜索历史和热搜……搜索历史中的直接从历史搜索访问的用户胶囊需要和搜索历史词要完整继承和保留」（设计见 `docs/搜索页顶栏就地扩充-设计文档-2026-10-19.md`；批准后「开始改造」）

## 一、现象

设计定案前没有可复现的「缺陷」，要复现的是**目标形态**：

| 观测 | 改造前 | 目标 |
|---|---|---|
| 点首页搜索框 | `Navigator.push(SearchPage())` 跳二级页 | **原地**在顶栏长高一块，不跳页 |
| 长高的是谁 | — | **整块顶栏容器**（搜索框行恒 38 不变） |
| 分类 TAB | 常驻 | 搜索态**收起**，退出**原样恢复**（位置 + 选中项） |
| 扩充区内容 | — | 自上而下：搜索历史（词）→ 用户胶囊 → 大家都在搜（两列网格） |
| 提交搜索 | 停在搜索页 | 保存历史 → **收起搜索态 → 进搜索结果页** |
| 背景 | 无 | 顶栏后方内容**压暗（含首页「首页」标题行）**，点遮罩收起 |
| 扩充区高度 | — | **设上限、绝不顶出屏幕**；超出时**末尾省略**（不溢出、不硬塞滚动条） |
| 热搜排版 | 带 1/2/3 序号的竖列（`MiuixBasicComponent`） | **照搬上游 PiliPlus 新排版**：两列网格、无序号 |
| 数据 | 历史词 + 用户胶囊（存档于二级页） | **只换展示位置**，读写/去重/上限/顺序/字段全照旧 |

## 二、定因

不是"坏在哪"，而是"为什么必须这样拆"。三条结构性原因，决定了本次改动面：

1. **压暗压不到「首页」标题行**。该行是 `AppScaffold` 的顶部安全行（`topStripHeight = 50`），在骨架里位于 `Column[strip, Expanded(body)]` 的**第一段**；页面 `body` 再怎么 `Stack` 也覆盖不到它。⇒ 只能在骨架里开一个**浮层槽位**（`overlayBuilder`），让页面把自己的浮层画在「安全行 + 内容」之上。
2. **内容一分为二（首页 + 独立搜索页）会立刻漂移**（违 P4）。「历史 + 用户胶囊 + 热搜 + 联想」若各写一份，必然两边口径不同。⇒ 抽成**唯一实现** `SearchContentPanel`（默认参数下即有内边距），两个宿主共用：首页顶栏（传 `maxHeight` 限高）/ 独立搜索页（外层可滚动）。
3. **数据口径唯一来源已是现成的**（`lib/pages/search/services/search_history_service.dart`：`SearchKeywordHistory` 键 `searchHistory`、上限 20、去重前置；`SearchHistoryService` 键 `searchHistoryUsers`、上限 20、四字段 `mid/name/face/timestamp`）。⇒ 契约即"**不动它**"，宿主只调用，`search_panel.dart` 的写入点也保留。

热搜还差两件事：模型缺字段（`show_name` / `show_live_icon`）、上游排版是 Material 写的（`InkWell` + `Material(transparency)` + `livingRect` 位图资源），搬到本项目必须自绘。

### 3. 实机验证步骤（用户操作）

1. 打开本轮 Release 产物 `build\windows\x64\runner\Release\winwin.exe`，首页点搜索框 → 顶栏**原地长高**（不跳页），搜索框行高度不变，分类标签收起，背景压暗。
2. 长出来的块自上而下应是：**搜索历史（词）→ 点过的用户胶囊 → 大家都在搜（两列网格、无序号）**。
3. 点历史词 / 热搜词 → 直接进搜索结果页，搜索态收起。
4. 输入词后按回车（或点「搜索」）→ 进结果页；返回首页再点搜索框，历史里能看到刚搜的词（第 2 条）。
5. 点历史词上的 ✕ 单删；点右侧垃圾桶清空；长按用户胶囊删除；点用户胶囊进其空间。
6. 按 `Esc` / 点暗色遮罩 → 收起搜索态，分类标签原样恢复（位置 + 选中项不变）。
7. 热搜标题行点「完整榜单 ›」→ 打开独立搜索页（完整热搜网格）；在独立搜索页搜词后返回，历史同步。
8. 把窗口缩到很矮（如 400px 高）：扩充块**不顶出屏幕**，末尾热搜被省略。
9. 演示模式（设置里开）下：搜索态只出骨架占位，不跑真实历史/热搜。

## 遗留与踩坑

- **两处与设计文档的轻微偏差**（照实登记，不偷偷改文档）：
  - 「分类标签**淡出 + 收高**」→ 本轮只做了**收高**（`AnimatedSize`），未加淡出。观感上收高已足够，若要淡出可在 `AnimatedSize` 内叠 `AnimatedOpacity`。
  - 「点**返回**收起」→ Windows 桌面**无系统返回键**，该路径实际由 `Esc` + 点遮罩承担（设计文档已列三者，本轮落地为后两者）。
- **「完整榜单 ›」映射为独立搜索页**：WinWin 无独立热搜榜单页，故映射为 push `SearchPage`（该页保留并复用面板）；面板 `onOpenFullRank == null` 时不显示该项（独立页自身即不显示）。
- **直播标：上游用 `Assets.livingRect`（48×15 位图），本项目无该资源** → 以 `_LiveTag`（「直播」文字小胶囊，`primary` α0.14 底 + α0.5 描边 + 10px 字）替代，语义一致、不新增二进制资源。
- **搜索态下 feed 不可滚动**是遮罩的副作用（遮罩盖住正文并吞掉指针），与设计文档 R1「搜索态下顶栏不放飞」同向：本轮搜索态下顶栏只在 `strip` 收起时上移（`AnimatedPositioned(top: stripH)`），**不额外放飞**；因遮罩拦截输入，实际也不会触发滚动。
- **`AppScaffold.overlayBuilder` 是新增槽位**：浮层默认 null，对其它所有页面**零影响**；默认浮层不吸事件（未命中处 `HitTestBehavior` 下穿），只有首页搜索态的遮罩显式 `opaque`。
- **环境坑（沿用）**：`flutter build` 在 bash 下必须注入 `LOCALAPPDATA` / `PUB_CACHE` / `PROGRAMFILES(X86)` 等环境变量，否则分别报「Could not find the pub cache」「%PROGRAMFILES(X86)% environment variable not found」；`grep` 工具因缺 `rg` 不可用（用 bash `grep`）；`edit_file` 前必须 `read_file`（本轮 sed 改过文件后再 `edit_file` 被拒一次）。
- **未跑 `flutter test`**（本机测试宿主历史性崩溃，沿用静态分析 + 双编译替代）。

## 总结

这次要的不是「修一个 bug」，而是**把一个交互形态搬个家**：搜索从"跳出去开一个二级页"变成"在首页顶栏原地长高一块"。真正决定改动面的是三条结构事实——**首页标题行在骨架安全行里（页面 body 盖不到，只能由骨架开浮层槽）**、**同一份内容将来有两个宿主（不抽唯一实现必然漂移）**、**数据口径已经有唯一来源（那就一个字都别动它）**。于是本轮没有新写任何数据逻辑，而是：给骨架开一个默认 null 的浮层槽（全部零回归）→ 把「历史 + 用户胶囊 + 热搜 + 联想」抽成唯一实现 `SearchContentPanel`（顺手把独立搜索页从 556 行瘦到 ~130 行，它反而更干净）→ 补齐热搜两个字段与上游两列网格排版（去 Material 化）→ 在首页顶栏用 `AnimatedSize`/`AnimatedPositioned`/`AnimatedOpacity` 三件套完成「长高 + 收起 TAB + 压暗背景」的形变。历史词与用户胶囊**只换位置、口径零改**（AC-6/7/8 逐条核过），`dart analyze` 0/0、Debug 59.4s / Release 82.9s 双 √，可一键回到 `662ebad`。
