# 搜索页顶栏就地扩充复盘 —— 让「搜索」不再跳页，而在原地长出来

- 日期：2026-10-19
- 快照基准：改动前 HEAD = `662ebad`（设计文档 v3；worktree clean，回滚见第五节）
- 触发：CVO 指令「开始设计改造搜索页，将其从二级页面改为首页顶栏的变形高度扩充（非搜索框高度撑开），隐藏分类 TAB 栏，将扩充的区域用于展示搜索历史和热搜……搜索历史中的直接从历史搜索访问的用户胶囊需要和搜索历史词要完整继承和保留」（设计见 `docs/搜索页顶栏就地扩充-设计文档-2026-10-19.md`；批准后「开始改造」）

## 一、现象

设计定案前没有可复现的「缺陷」，要复现的是**目标形态**：

| 观测 | 改造前 | 目标 |
|---|---|---|
| 点首页搜索框 | `Navigator.push(SearchPage())` 跳二级页 | **原地**在顶栏长高一块，不跳页 |
| 长高的是谁 | — | **整块顶栏容器**（搜索框行恒 38 不变） |
| 分类 TAB | 常驻 | 搜索态**收起**，退出**原样恢复**（位置 + 选中项） |
| 扩充区内容 | — | 自上而下：搜索历史（词）→ 用户胶囊 → 大家都在搜（两列网格） |
| 提交搜索 | 停在搜索页 | 保存历史 → **收起搜索态 → 进搜索结果页** |
| 背景 | 无 | 顶栏后方内容**压暗（含首页「首页」标题行）**，点遮罩收起 |
| 扩充区高度 | — | **设上限、绝不顶出屏幕**；超出时**末尾省略**（不溢出、不硬塞滚动条） |
| 热搜排版 | 带 1/2/3 序号的竖列（`MiuixBasicComponent`） | **照搬上游 PiliPlus 新排版**：两列网格、无序号 |
| 数据 | 历史词 + 用户胶囊（存档于二级页） | **只换展示位置**，读写/去重/上限/顺序/字段全照旧 |

## 二、定因

不是"坏在哪"，而是"为什么必须这样拆"。三条结构性原因，决定了本次改动面：

1. **压暗压不到「首页」标题行**。该行是 `AppScaffold` 的顶部安全行（`topStripHeight = 50`），在骨架里位于 `Column[strip, Expanded(body)]` 的**第一段**；页面 `body` 再怎么 `Stack` 也覆盖不到它。⇒ 只能在骨架里开一个**浮层槽位**（`overlayBuilder`），让页面把自己的浮层画在「安全行 + 内容」之上。
2. **内容一分为二（首页 + 独立搜索页）会立刻漂移**（违 P4）。「历史 + 用户胶囊 + 热搜 + 联想」若各写一份，必然两边口径不同。⇒ 抽成**唯一实现** `SearchContentPanel`（默认参数下即有内边距），两个宿主共用：首页顶栏（传 `maxHeight` 限高）/ 独立搜索页（外层可滚动）。
3. **数据口径唯一来源已是现成的**（`lib/pages/search/services/search_history_service.dart`：`SearchKeywordHistory` 键 `searchHistory`、上限 20、去重前置；`SearchHistoryService` 键 `searchHistoryUsers`、上限 20、四字段 `mid/name/face/timestamp`）。⇒ 契约即"**不动它**"，宿主只调用，`search_panel.dart` 的写入点也保留。

热搜还差两件事：模型缺字段（`show_name` / `show_live_icon`）、上游排版是 Material 写的（`InkWell` + `Material(transparency)` + `livingRect` 位图资源），搬到本项目必须自绘。

# 第二轮（实机反馈修复）—— 扩充区高度冗余 + 失焦/Esc 退出失效

- 日期：2026-10-19
- 快照基准：改动前 HEAD = `856185a`（worktree clean；回滚见 §十）
- 触发：CVO 实机反馈（截图 `1792423636694-ff096869.png` 宽屏 / `1792423636697-fd145923.png` 窄屏）：「① 点击搜索框进入搜索态后，扩充的区域有些冗余了，宽屏和窄屏形态下，扩充区域都超出了『大家都在搜』最后一行好几行的空余；② 搜索态的搜索框失去焦点后没有退出搜索态，导致点击到导航栏时即便搜索框丢失了焦点但搜索态没有退出，导致按键 `Esc` 无法退出搜索态，降低了操作效率。」

## 六、现象

| # | 观测 | 量化 |
|---|---|---|
| 1 | 扩充区下方**恒有多余空白**，宽屏 / 窄屏都有 | 空白 = 上限高度 − 内容高度，**与内容多少无关**（内容越少空白越多） |
| 2 | 搜索框失焦后搜索态**不退出**；此后 `Esc` 也**无法**退出 | 两条症状同源：退出路径缺"失焦"这条，且 `Esc` 被绑死在焦点链上 |

## 七、定因

1. **高度冗余 = 布局原语默认值**（不是数值写错）。限高链 `ClipRect > ConstrainedBox(maxHeight) > OverflowBox(topCenter)` 里的 `OverflowBox` **默认 `fit: OverflowBoxFit.max`**；Flutter 源码 `rendering/shifted_box.dart`（`RenderConstrainedOverflowBox`）实证：
   ```dart
   bool get sizedByParent => switch (fit) {
     OverflowBoxFit.max => true,          // ← 默认走这支
     OverflowBoxFit.deferToChild => false,
   };
   Size computeDryLayout(constraints) => switch (fit) {
     OverflowBoxFit.max => constraints.biggest,   // ← 取"最大"而非"内容"
     OverflowBoxFit.deferToChild => child?.getDryLayout(constraints) ?? constraints.smallest,
   };
   ```
   ⇒ 该框**永远占满上限高度**，与内容无关。原实现的"限高"只保证了"不超出屏幕"，没保证"不冗余"。
2. **`Esc` 失效 = 键事件只沿当前主焦点节点的祖先链派发**。原实现把 `Esc` 挂在搜索态子树的 `CallbackShortcuts` 上：焦点在输入框 / 面板内时生效；焦点一旦被抢走，搜索态子树不在链上，事件继续上抛给**既有全局路由器** `AppEscapeScope`（`lib/core/input/app_escape_scope.dart`，挂在 `MaterialApp.builder`，四层：①栈顶弹层 → ②`EscapeLayerRegistry` 二级浮层 → ③输入框失焦 → ④`maybePop`）。此刻 ①无弹层、②搜索态**未登记**、③`isTextInputFocused()` 为假、④无可返回路由 → 落到 `Esc unhandled (root)`，搜索态纹丝不动。**违背 P4：同一个"Esc 关闭"概念被定义了两处。**
3. **失焦不退出**：退出路径原本只有 `Esc` / 点遮罩 / 提交三条，缺"失焦"。而导航栏与底栏在 `MainLayout` 里位于页面 body **之外**（宽屏 `AppNavRail(80)`、窄屏 `Positioned` 底栏），压暗遮罩盖不到 ⇒ 点它们既走不到任何退出路径，又抢走焦点。

## 八、方案

**改动面 2 文件**（+ 本文档 + 进度表）：

| # | 文件 | 动作 | 要点 |

## 遗留与踩坑（第二轮）

- **"失焦即退出"是本轮新增的产品口径**（原设计文档只写了 `Esc` / 遮罩 / 返回三个出口）。两重护栏及依据：① Windows 上点击普通区域**不会**抢焦点（`EditableText` 的默认 `onTapOutside` 在桌面端是空实现）⇒ 不会因点面板内「刷新 / 清空 / 历史 ✕」而误收起（`MiuixPressable` 内部的 `FocusableActionDetector` 也不请求焦点，已查依赖源码）；② 窗口失活时 `FocusManager` 会**挂起主焦点**（`_suspendedNode`，源码实证）⇒ 加 `lifecycleState != resumed` 时忽略，避免"切到别的应用再回来，搜索态没了"。
- **点设置齿轮**（若其内部请求焦点）会顺带收起搜索态 —— 属可接受的"离开搜索上下文"语义；若 CVO 认为不妥，下一轮把它纳入"面板内部"白名单。
- **`lifecycleState` 护栏依赖时序**：`WidgetsBinding` 先落状态再广播监听（`FocusManager` 作为 `AppLifecycleListener` 后收到），故失焦回调里读到的已是新状态。若后续 Flutter 调整该顺序，本护栏需复核。
- **仍未做「改动后截图 vs 原截图」逐像素回归**（本会话无 VQA / OCR 工具：`read_file` 读 png 直接报错、连接器无可用 OCR）⇒ 高度是否"贴底"只能由 CVO 实机复看。
- **未跑 `flutter test`**（本机测试宿主历史性崩溃，沿用静态分析 + 双编译替代）。

## 总结（第二轮）

两个问题，根因完全不同。一个是**布局原语默认值**的坑：`OverflowBox` 默认"撑满父级"（`fit: max`），我们把它当"限高容器"用，语义正好相反 —— **"限高"于是退化成"恒为上限高"**；这种退化在任何分辨率下都表现为"多出空白"，且与内容无关，所以宽屏窄屏一起中招。修法不是调数值，而是把 `fit` 显式钉成 `deferToChild`，让它回到"按内容、上限截断"。另一个是**重复造了一条 Escape 旁路**：项目早有全局 `Esc` 分层路由器（`AppEscapeScope` + `EscapeLayerRegistry`），搜索态本就属于"无路由承载的 Stack 伪浮层"，该登记进第 2 层；原实现自挂 `CallbackShortcuts`，等于把 `Esc` 绑死在焦点链上，焦点一被导航栏抢走就失效，正违 P4。两处修完：`dart analyze` 0/0、Debug 31.2s / Release 80.4s 双 √，可一键回到 `856185a`。

**一句话教训**：先读源码确认"看起来对"的默认值，再决定要不要自己动手 —— 本轮两个问题，一个吃默认值、一个吃重复实现。
