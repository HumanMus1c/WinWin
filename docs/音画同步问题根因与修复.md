# 音画同步问题根因与修复

> 调查日期：2026-09-19
> 关联提交（修复）：`819637c`
> 关联文档：`docs/进入视频播放页崩溃根因与修复.md`（两个独立问题：本档只记录音画同步，「播放页崩溃」见前者）

---

## 1. 现象

- 音频已播放完毕，视频画面与进度条却未走到头（停在结尾前，如 01:45 / 01:50）。
- seek 或加载缓冲时，总是音频先出声，视频画面要缓存较久才出现，随后追赶音频。
- 时间显示/进度条读的是 `player.position`，完成时卡在低于总时长的位置。

## 2. 根因分析

### 2.1 MDK 音画同步机制（官方 Global-Options 文档）

| 选项 | 默认值 | 含义 |
|---|---|---|
| `avsync.audio.adaptive` | 0 | **视频解码/缓冲落后时放慢音频节奏**，让视频追上 |
| `avsync.audio.duration_diff` | 800ms | 音视频时长差 ≤ 该值时才以音频时钟为主时钟 |

- MDK 默认以**音频时钟**为主时钟，且 `adaptive=0`：当视频解码慢 / 视频流缓冲不足时，音频以 1.0x 速度继续独跑，视频只能追赶 → 「音频先播完」「音频先出画面慢出」。
- B 站 DASH 为音视频分离双轨：音频流体积小、缓冲就绪快，视频流（尤其高码率 HEVC/AV1）就绪慢，放大了上述漂移。

### 2.2 与「播放页崩溃」的区别

- **播放页崩溃**：`player.setProperty('avsync.audio', 'true')`（字符串值）触发 mdk 0.38.0 解析抛 `std::invalid_argument`，Release 必崩，已废弃该属性。详见崩溃文档。
- **音画不同步**：崩溃排查时**无辜连带禁用**了 `keep_open`（数值字符串，非肇事）。`keep_open=0` 时播放完毕 MDK 直接 Stopped 并释放解码器，`player.position` 冻结在视频 PTS（< 总时长）→ 进度条/时间显示停住不满。

## 3. 修复内容

`lib/pages/video/player_controller.dart`（`_createPlayer` / `_handlePlaybackEnded` / `_startPolling`）：

1. **启用 `mdk.setGlobalOption('avsync.audio.adaptive', 1)`**（替代废弃的字符串属性）
   - 官方 int32 全局选项，与已稳定运行的 `d3d11.sync.cpu`（代码同路径 `MDK_setGlobalOptionInt32`）一致，无字符串解析崩溃风险。
   - 视频落后时放慢音频节奏，从根上消除音频时钟超前漂移。
   - `avsync.audio.duration_diff` 保持默认 800ms（B 站 DASH 双轨时长基本一致）。
2. **恢复 `player.setProperty('keep_open', '1')`**
   - 崩溃排查已证实其为数值字符串、非肇事属性（肇事者是 `avsync.audio='true'`）。
   - 播放完毕 MDK 转入 Paused 并置位 `MediaStatus.end`，`position` 自然收敛到总时长，重播/seek(0) 恢复可用；同时解决了崩溃文档遗留事项 #1。
3. **完成态进度归一（应用层兜底）**
   - `_handlePlaybackEnded()` 将 `position` 收敛到 `duration`；
   - `_startPolling()` 增加 completed 冻结（底部 PTS < duration 时不再回写 position），防止轮询把已归一进度往回拖。
   - 保证「播放完毕 ⇒ 进度条走满 / 时间显示到头」。

```dart
// _createPlayer() 内
mdk.setGlobalOption('avsync.audio.adaptive', 1);
player.setProperty('keep_open', '1');
```
