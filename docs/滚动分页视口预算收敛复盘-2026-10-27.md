# 滚动分页视口预算收敛复盘（2026-10-27）

## 一、现象

CVO 反馈：程序冷启动首次加载时，部分页面一次拉回远超当前窗口可视行数的内容（如消息中心对话列表、动态页），冷启动网络与渲染压力偏大；要求所有需要滚动加载内容的页面统一收敛为：

- 冷启动首批：最多加载「当前视口可容纳条数 × 2」（当前视图 + 额外一倍）；
- 滚动补批：每次最多加载「当前视口可容纳条数 × 1」；
- 距底不足 1 屏才触发补货。

## 二、定因

1. **根壳一次性构建全部根页面**：`lib/ui/app.dart` 的根 `IndexedStack` 直接列出首页 / 动态 / 历史 / 消息 / 我的 5 个页面，冷启动即全部 `initState` ⇒ 动态流首批、历史首批、私信会话列表、未读等请求同时发出。首页分类 tab 早已是「访问即建」，根页面反而没有。
2. **会话列表固定取 100 条**：`session_list_page.dart`、`session_list_section.dart` 均传 `size: 100`；会话行高约 72px，常见窗口仅 9~12 行，单次请求约为视口的 **8~10 倍**。
3. **动态流服务端固定批量**：`/x/polymer/web-dynamic/v1/feed/all` 不开放每页条数（PiliPlus 同样不传），单批约 20 条；瀑布流常见窗口一屏仅 2~4 张卡，首批约为视口的 **5 倍**。
4. **推荐流并发补货无预算**：`RcmdController._prefetchBatches = 4` 一次并发 4 批，且 `rcmd/view.dart` 在距底 1.5 屏就触发；小窗口下单次补货可能超过 2 屏。
5. **其余列表页大小 20~30**：历史 / 热门 / 搜索 / 直播 / 收藏 / 空间 / 探照 / 番剧 / 评论 / 私信消息等多为固定 20~30 条，且 `hasMore` 判断也写死同一数值；小窗口或高行高列表（评论、聊天）仍可能超过 2 屏。

## 三、方案

### 3.1 新增共享口径

新增 `lib/utils/viewport_load_budget.dart`（`ViewportLoadBudget`）：

- `windowLogicalHeight / windowLogicalWidth`：从 `PlatformDispatcher` 取物理尺寸，按 `ScaledWidgetsFlutterBinding.devicePixelRatioScaled` 换算，与 MediaQuery 同一坐标空间（含界面缩放）；读不到时回退 720×1280。
- `viewportExtentOf(controller, reservedHeight)`：已布局时用真实 `ScrollPosition.viewportDimension`，否则用「窗口高度 − 页面固定占位」。
- `visibleRows` / `gridColumns` / `visibleGridItems`：按行高、网格 `maxCrossAxisExtent`（列数 ceil，与 `SliverGridDelegateWithExtentAndRatio` 同口径）估算一屏容量，单屏行数上限 20。
- `capRequestItems(fallback, visibleItems, firstPage)`：`firstPage ? 2× : 1×`，且 **只收紧、不放大**（原页大小更小则保留原值）。
- `pageSizeFor(...)`：列表页便捷入口。
- `shouldLoadMore(position, bufferScreens: 1.0)`：距底不足 1 屏才触发。

### 3.2 根壳懒加载

`lib/ui/app.dart` 新增 `_visitedPages`：未访问的根页面先放 `SizedBox.shrink()`，首次切换才实例化；`IndexedStack` 继续常驻保留已访问页状态。冷启动只加载首页（推荐流 + 热搜预取）。

### 3.3 页面接入

- **私信会话列表**（`session_list_page.dart` / `session_list_section.dart`）：`size` 改为预算值（首批 ≤2 屏、补批 ≤1 屏）；置顶重复页仍由 `SessionPaginationPolicy` 去重重试兜底。
- **推荐流**（`rcmd/controller.dart` / `rcmd/view.dart`）：批次数按视口卡片容量收敛（`ceil(预算 / 单批约 8)`，上限 4，两轮重试合计不超过 4 批）；滚动触发从 1.5 屏收紧为 1 屏。
- **历史**（`history_page.dart` / `http/history.dart`）：`ps` 参数化 + 预算；`hasMore` 阈值改用本次 `pageSize`。
- **搜索**（`search_panel.dart` / `http/search.dart`）：`page_size` 参数化 + 预算；阈值同步。
- **直播**（`live/view.dart`）：关注 / 推荐两处 `pageSize` 预算；推荐页原 `>=20` 阈值改为 `>=pageSize`。
- **番剧**（`pgc/view.dart` / `http/pgc.dart`）：`pagesize` 参数化 + 预算；阈值同步。
- **稍后再看**（`toview_page.dart` / `http/toview.dart`）：`ps` 参数化 + 预算。
- **收藏夹**（`fav_page.dart`）：`userFavFolder(ps:)` 预算。
- **热门**（`hot/controller.dart`）：`ps` 预算。
- **空间投稿**（`member_space_page.dart` / `http/member.dart`）：`spaceArchive(ps:)` 预算；Web 兜底 `isEnd` 改用 `pageNum * ps`。
- **评论**（`video/detail_page.dart`、`bangumi_player_page.dart`、`article_page.dart`、`dynamics/detail_page.dart`）：`replyMain(ps:)` 预算；楼中楼 `replyReplyList(ps:)` 同步。
- **私信聊天记录**（`chat_detail_page.dart`）：`sessionMsg(size:)` 预算。
- **系统消息**（`sys_msg_page.dart`）：`msgFeedNotify(pageSize:)` 预算；阈值同步。

### 3.4 固定批量接口（无法调小每批）

动态流、关注流、回复/艾特/点赞消息、点赞详情接口不开放每页条数。约束改为：

- 单批在途（`_loading` 守卫，不并发多批）；
- 距底 240px（＜1 屏）或列表尾项进入视口缓存区才请求；
- 冷启动不打开对应根页面就不请求（根壳懒加载）。

## 六、遗留与踩坑

1. **固定批量接口存在下限**：动态 / 关注流单批约 20 条，极端高窗口下仍可能超过 2 屏；本轮按 CVO 选择「接受单批下限」，不再做显示层裁剪（网络拉取量不会因裁剪下降）。
2. **`hasMore` 写死阈值是隐性坑**：历史 / 搜索 / 直播 / 系统消息原先以 `>=20` / `>=30` 判定末页，页大小变小后会把满页误判为末页；本轮已全部改为「本次请求的 pageSize」，后续新增分页页必须同源。
3. **`_checkAutoLoad` 仍保留**：内容不足一屏时继续补货直到填满视口；每次补货已受 1 屏预算约束，总量约 1~2 屏。
4. **网格页多为「无操作」收敛**：热门 / 直播 / 番剧 / 收藏 / 空间 / 搜索等桌面窗口一屏容量常 ≥20~30，预算 ≥ 原页大小 ⇒ 取值不变；仅小窗口或高行高列表实际收紧。
5. **未覆盖**：横向预览区（如个人页 `ps: 10` 横向卡片）不走纵向滚动分页；成员关系 / 合集详情等网格页一屏容量已 ≥ 原页大小，未额外改值。
6. **窗口尺寸近似**：首批请求可能发生在首帧布局前，`devicePixelRatioScaled` 尚未写入时按原始 DPR 估算，界面缩放 >1 时首批预算会略偏大；已布局后的补批使用真实 `viewportDimension`。
7. **未跑全量 `flutter test`**：测试宿主历史性不稳定；本轮仅跑新增纯函数单测。

## 七、总结

冷启动不再一次性构建 5 个根页面，只加载当前首页；所有可调每页条数的滚动列表统一按「首批 ≤2 屏、补批 ≤1 屏」取数，`hasMore` 阈值与请求页大小同源；动态 / 关注 / 消息等固定批量接口保证单批在途、不并发多批。静态分析与 Windows Debug/Release 双编译均通过。
