## 二、实现内容

| 文件 | 说明 |
|---|---|
| `lib/core/download/download_transport.dart` | 传输抽象 `DownloadTransport`（probe/fetchRange/close）+ `DownloadCancelledException` |
| `lib/core/download/dio_download_transport.dart` | 基于 dio 的流式 Range 实现；独立 `Dio` 实例（不套 JSON 解码/账户拦截器） |
| `lib/core/download/download_engine.dart` | `DownloadEngine` 编排 + `DownloadProgress` / `DownloadOutcome` / `DownloadFinishStatus` |
| `test/core/download/download_engine_test.dart` | 15 例单测（注入 `FakeTransport`，真实临时文件 IO） |

**关键设计决策**：
1. **传输抽象隔离网络**：引擎对网络栈零硬依赖，`FakeTransport` 注入确定性字节即可离线覆盖续传/分片/进度/取消全路径（可验证才算完成）。
2. **复用批次1 策略**：`DownloadResumePolicy`（续传计划）、`DownloadRangePolicy`（分片区间/阈值/Content-Range 解析）、`DownloadRangeProbe`（探测结果）——概念单处定义，引擎只做编排。
3. **并行分片、串行落盘**：分片并发拉取（网络为瓶颈），写入经 `_WriteMutex` 串行化到同一 `RandomAccessFile`，按绝对偏移写入，避免句柄竞争。
4. **免预分配**：`FileMode.write` 打开后按偏移写入，跨越 EOF 的写入自动扩展文件，无需 `setLength`。
5. **长度校验**：总大小已知时落盘长度不符即判 `failed`；未知时以实际落盘长度为准。
6. **离线格式口径**：承接批次1 约束——本仓无 ffmpeg/assets 二进制，DASH 分离流无 muxer，引擎只处理**单文件字节流**（DURL `fnval=1` MP4），不涉及音视频合并。

## 四、遗留与踩坑

**踩坑（已解决）**：
1. `RandomAccessFile.setLength` 不存在（分析器报 undefined_method）→ 改用「按偏移写入、跨 EOF 自动扩展」，既满足分片又免预分配。
2. `StateError`（未注入传输）被 probe 的 `try/catch` 吞成 `failed` outcome → 传输实例解析**前移到 try 之外**，配置错误直接抛出（测试 `未注入传输实现时抛 StateError` 由红转绿）。
3. dio 流块类型恒为 `Uint8List`（`is List<int>` 恒真）→ 去掉多余类型判断与死代码，消除两条分析告警。

- 引擎未接 Hive 持久化与队列调度（`DownloadQueuePolicy` 已就绪，待批次3 与 UI 接线）。
- 取消粒度为「分块级」（块边界检查），未做传输层即时中断。
