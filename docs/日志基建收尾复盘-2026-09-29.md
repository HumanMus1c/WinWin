# 日志基建收尾复盘（2026-09-29）

**范围**：修复后日志审计遗留清单第 1–5 项（轮转上限 / ApiBlackbox 定界 / 死代码清理 / geetest 弃用字段）。

## 一、分析根因（证据链）

1. **崩溃报告无上限**：`.winwin_logs.json` 已 4.13MB / 588 条，`json_file_handler.dart` 追加写入、无任何大小控制；
2. **trace 无上限**：`trace.log` 已 6.62MB，`sync_trace.dart` 仅追加、无滚动；
3. **ApiBlackbox 半接线**：c366e6e（8/31「恢复纯净启动链路」）从 main.dart 移除了 `ApiBlackbox.init()`，但 http/init.dart 的拦截器未同步移除——release 构建仍把每次请求摘要写入内存缓冲（上限 512 条、永不落盘）；
4. **死文件**：`startup_blackbox.dart` 全库无引用（原生侧 8/31 已移除）；
5. **弃用字段**：geetest 的 `clearCache` / `saveFormData` 为 Android/iOS 专属弃用字段（Windows no-op），是 analyzer 仅存的两条弃用 info。

## 二、设计修复计划与实现

1. **轮转上限（各 5MB、单代 `.old`）**：
   - JsonFileHandler：写入前 `raf.length()` 检查，超限 close → 删除旧 `.old` → rename → 重开追加句柄；轮转失败降级为继续追加原文件，绝不阻断报告写入；
   - SyncTrace：同规格同步实现（lengthSync / closeSync / renameSync / openSync）；归档失败回退继续追加。
2. **ApiBlackbox 定界 debug-only**：拦截器（http/init.dart）与 `init()`（main.dart）均以 `kDebugMode` 门控——debug 保留完整深度排障（请求/响应/异常 + Cookie 脱敏），release 零开销；同时消除 release 下无意义的内存缓冲。
3. **死代码清理**：删除 `lib/core/log/startup_blackbox.dart`（删除前后全库引用检查：仅剩自身 → 零）。
4. **geetest**：删除两个弃用字段（缓存卫生由 `incognito: true` 覆盖；该字段对 Windows 本就无效）。
