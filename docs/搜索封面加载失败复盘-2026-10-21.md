# 搜索结果封面加载失败复盘（2026-10-21）

> 承接搜索链路文档链：《搜索页顶栏就地扩充复盘-2026-10-19》→《搜索态扩充动效与合并栏阴影复盘-2026-10-21》。
> 本轮是 CVO 反馈的**搜索结果页封面不显示**缺陷修复，不改数据口径与交互出口。

## 一、现象描述

CVO 反馈（2026-10-21 16:02，附两张截图）：

1. 搜索结果页 **「直播」** 分类：封面图加载失败（显示占位/错误图标）。
2. 搜索结果页 **「专栏」** 分类：封面图加载不出来。

同页 **「视频」「用户」** 封面正常显示。

> 说明：本轮运行环境未提供图片理解工具，无法读取截图像素；结论基于文字描述 + 全量相关源码 / 上游参考库（PiliPlus、BiliPai）/ 等价逻辑复现推导得出，非回避取证。

## 二、问题定因

**根因一句话**：B 站搜索接口返回的封面是**协议相对 URL**（`//i0.hdslb.com/...`，无 `http:`/`https:` scheme）；
WinWin 把「协议归一化」放在**模型层**做，但**直播 cover、专栏 imageUrls、番剧 cover 三处漏做**；
而缩略图工具 `ImageUtils.thumbnailUrl` **自身只补 `http://`、不处理 `//`**（无兜底）——
于是无 scheme 的 URL 被拼上 `@…w_…h_1c.webp` 后直通渲染层，`CachedNetworkImage` 抛
`No host specified in URI` → 命中 `errorBuilder` → 封面不显示。

### 2.1 证据链（逐环可查）

1. **缩略图工具不处理协议相对 URL** — `lib/utils/image_utils.dart:18`
   原 `String url = src.replaceFirst('http://', 'https://');`：只把 `http://` 补成 `https://`，
   对 `//host/...` 无动作；后续 `url.contains('.hdslb.com')` 为真 → 返回
   `//i0.hdslb.com/…jpg@144w_81h_1c.webp`（整串仍**无 scheme**）。

2. **模型层归一化只覆盖一半字段** — `lib/models/search/result.dart`

   | 字段 | 是否归一化 | 证据 |
   |---|---|---|
   | 视频 `pic` | ✅ `_http2https()` | `:67` |
   | 视频 `upic` / 用户 `upic` / 用户 `uface` | ✅ `_http2https()` | `:72` / `:122` / `:156` |
   | 直播 `cover` | ❌ 裸装 `json['cover']` | `:158` |
   | 番剧/影视 `cover` | ❌ 裸装 `json['cover']` | `:204` |
   | 专栏 `imageUrls` | ❌ 裸装 `e as String` | `:246-248` |

   文件内自带的 `_http2https()`（`:311`）**明确写了** `if (url.startsWith('//')) return 'https:$url';`
   —— 作者清楚 B 站会返回 `//`，却只把它用在了部分字段上。

3. **卡片把裸值直接喂给缩略图工具** — `lib/pages/search/search_panel.dart`
   - 直播：`:410` → `thumbnailUrl(item.cover, width:144, height:81)`
   - 专栏：`:623` → `thumbnailUrl(item.imageUrls!.first, width:120, height:94)`
   - 番剧/影视：`:524` → `thumbnailUrl(item.cover, width:80, height:114)`

4. **等价逻辑复现（已跑）**：输入 `//i0.hdslb.com/bfs/live/abcd1234.jpg`
   → 输出 `//i0.hdslb.com/bfs/live/abcd1234.jpg@144w_81h_1c.webp`，`has_scheme=False`。
   无协议头 URL 交给 `CachedNetworkImage` 必抛 `No host specified in URI`。

5. **上游佐证**（同类问题上游均已收口，证明该形态真实且需处理）
   - PiliPlus：`ImageUtils.thumbnailUrl` / `safeThumbnailUrl` **末尾统一 `return src.http2https`**
     （`lib/utils/image_utils.dart:207/233`）；其 `http2https` 正则为 `^(http:)?//`，即协议相对也归一化。
   - BiliPai：专栏仓库 `ArticleRepository.normalizeImageUrl` 明确 `value.startsWith("//") -> "https:$value"`
     （`ArticleRepository.kt:176`），全仓 20+ 处同款处理。

### 2.2 为什么「视频正常、直播/专栏坏」

「正常」与「异常」的分界线**恰好等于模型层有无归一化**——视频/用户字段做了 `_http2https`，
直播/专栏/番剧没做。这与 CVO 观察到的现象完全吻合，可反证根因。

## 三、修复方案（A+B 同批）

### A｜单一收口：`ImageUtils.thumbnailUrl` 补 `//` 归一化

`lib/utils/image_utils.dart` 入口新增：

```dart
String url = src.replaceFirst('http://', 'https://');
// 协议相对 URL：必须补齐 https scheme，否则无 scheme 的 URL 交给
// CachedNetworkImage 会抛 `No host specified in URI` 导致封面加载失败。
if (url.startsWith('//')) url = 'https:$url';
```

一处改动即让**所有**调用点免疫（含番剧、以及未来任何新字段），符合「概念只在一处定义」。

### B｜补齐模型层约定：三类字段套 `_http2https()`

`lib/models/search/result.dart`：

- 直播 `cover` → `_http2https(json['cover'] as String?)`；
- 番剧/影视 `cover` → `_http2https(json['cover'] as String?)`；
- 专栏 `imageUrls` → `(json['image_urls'] as List?)?.map((e) => _http2https(e as String)).whereType<String>().toList()`。

使「模型层归一化」口径完整一致，并覆盖非缩略图用途（后续长按保存/跳转直链）。

> **影响面**：纯 URL 字符串处理，无视觉/交互/数据结构变化；已归一化字段与 `.gif`/非 hdslb 域名分支不受影响。

3. **`//` 形态的更强样本未采集**：受本机域名访问与接口签名（WBI）限制，未直接抓取线上返回体；
   上游两库（PiliPlus/BiliPai）的统一归一化是「该形态真实存在」的旁证。若后续想彻底闭环，
   可在搜索请求处加一次性日志打印原始 `cover`/`image_urls` 取证。
4. **同类隐患扫描**：本仓其余读图字段（动态/评论/收藏等）是否也存在「裸 `//` 未归一化」，
   留作跟进队列——本轮仅按 CVO 所指的搜索结果页封面收口（A 已在工具侧兜底，故风险敞口已收敛）。

## 六、总结

本轮是**协议归一化遗漏**导致的封面不显示：B 站搜索接口的直播/专栏/番剧封面为协议相对 URL（`//`），
而 WinWin 的归一化只在模型层部分字段实现、缩略图工具又不兜底 `//`，故三类封面直通渲染层失败。
修复采用 **A+B**：A 在 `ImageUtils.thumbnailUrl` 单一收口补 `//→https`（治本、防复发、覆盖全类），
B 在模型层补齐直播/番剧/专栏三类字段的 `_http2https()`（口径一致、覆盖非缩略图用途）。
数据口径与交互出口**一字未动**，`dart analyze` 0/0、Debug/Release 双 √，改动仅 2 文件 +8/−3。
