# 弱网播放容错修复复盘（2026-09-29）

**范围**：用户弱网实机复测（首页提示截图 + 播放器错误截图）。目标：弱网下播放器不闪加载错误、保持缓冲（封面占位）状态并自动重试；最终以友好中文提示收尾；封面作为第一帧占位平滑过渡。

## 一、分析根因（现象 + 取证 + 根因链）

- **现象与取证**（用户截图）：
  1. 首页刷新：底部 SnackBar 已显式提示「请求错误：网络连接超时，请检查网络设置」+ 请求 URL（`account_mgr.dart:201`）——已生效，维持现状；
  2. 播放器：弱网取流请求 receive 超时（全局 10s，`http/init.dart:41`）→ `VideoHttp.videoUrl` 抛出 DioException（`http/video.dart:231` 无捕获）→ 控制器 catch 直接 `error.value = '播放失败：$e'`（`player_controller.dart:2723`）→ 面板 `_buildError` 原样展示英文 DioException 长文 + 重试按钮；播放区灰屏（封面未显示）。
- **根因链**：`_openWithQuality` 对网络类失败**零重试**（取流失败/异常/prepare 硬错误/渲染面失败 → 立即写 error）；异常文案直拼 `$e` 且 catch 无日志；面板封面仅在 `!hasFrame` 时作为底层显示，错误态转圈被替换、首帧就绪硬切。

## 二、设计修复计划与实现

1. **自动重试（保持缓冲态）**：`load()` 失败按 **1.5s/3s/5s/8s** 退避重试，最多 **4 次**（共 5 次尝试）；等待期间清空 error → 面板保持「封面+转圈」，不闪加载错误；任一次成功即正常起播（续播定位不受影响）；「未获取到可播放的视频流」（服务端明确不可播）不重试、快速失败；不作用于 `switchQuality`（画质回滚语义独立）。
2. **友好文案**：异常路径改用 `dioErrorMessage(e)`（`lib/http/dio_error_message.dart`，如「响应超时，请稍后重试！」）；非 Dio 异常统一「播放失败，请稍后重试」；catch 补 `AppLogger.e` 日志；重试耗尽才显示错误（附既有重试按钮）。
3. **封面占位与过渡**：封面层常驻置顶——闸门/无首帧（加载+缓冲+重试）期间不透明度 1 遮盖（无封面时黑底兜底）；首帧就绪后 **240ms 淡出**完成过渡（替代硬切）——即「从视频封面作为第一帧视频画面开始过渡」。
4. **续播协同**：`resumeTo` 等待就绪不再因瞬时 error 提前放弃（重试期间 error 会被清空），兜底 15s→30s 覆盖重试窗口。
5. **取证**：`SeekProbe 'LOAD-RETRY #n delay=… err=…'` + `AppLogger.w`（重试与耗尽均留痕，trace/runtime.log 可见）。
