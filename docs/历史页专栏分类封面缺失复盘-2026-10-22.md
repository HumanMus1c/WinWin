# 历史页「专栏」分类封面缺失复盘-2026-10-22

> 日期：2026-10-22
> 快照基准：`0376fab`（改动前 [snapshot]，回滚命令：`git reset --hard 0376fab`）
> 作者：小通（通用助手）

## §1 现象描述

- 历史页切换到「专栏」分类（官方 `type=article`）时，列表卡片封面一直停留在灰底占位（`NetworkImgLayer` 的 `_placeholder`），无法加载出封面。
- `全部` 分类中凡属专栏 / 文集的条目，同样无封面。
- 用户提供实机截图：`uploads/1792673066151-308dec2f.png`。

## §2 问题根因（已确认，非猜测）

**根因：卡片封面只读了 `HistoryItem.cover`，而专栏条目的封面服务端只下发在 `covers` 数组中。**

根因链：

1. `lib/pages/history/history_page.dart` 卡片封面为 `NetworkImgLayer(src: item.cover)`，只取 `HistoryItem.cover` 单字段。
2. 官方接口 `/x/web-interface/history/cursor` 字段语义（多源证据见下）：
   - `cover`（str）备注 **"用于专栏以外的条目"**；
   - `covers`（有效时 array / 无效时 null）备注 **"仅用于专栏"**。
3. 故专栏（`article` / `article-list`）条目的 `cover` 恒为空 → `NetworkImgLayer._buildImageLayer` 命中 `src?.isNotEmpty != true` → 走 `_placeholder` 灰块 → 封面无法显示。
4. WinWin 模型 `HistoryItem` 其实**已解析** `covers`（`history_models.dart` L80），但**全页 UI 从未读取**（`grep item.covers` 在 `lib/pages/history/` 命中为 0）——字段被解析却空置，是典型"解析到位、接线缺失"。

**多源证据（代码 + API 文档 + 参考实现）**：

| 来源 | 证据 |
|---|---|
| API 文档 bilibili-API-collect `docs/historytoview/history.md` | `cover` 备注"用于专栏以外的条目"；`covers` 备注"仅用于专栏"；`covers` 项为 str（封面图片） |
| 上游参考 PiliPlus `lib/pages/history/widgets/item.dart` L72-74 | `src: item.cover?.isNotEmpty == true ? item.cover : item.covers?.firstOrNull ?? ''`（即上游已做 `covers` 回退，WinWin 移植时漏掉该口径） |
| 本仓其它专栏封面点 | `lib/pages/dynamics/detail_page.dart` L965、`lib/pages/dynamics/view.dart` L1615、`lib/pages/member/member_space_page.dart` L2994 均为 `article.covers.isNotEmpty ? article.covers.first : null`，口径一致 |

## §3 修复方法

**P4「每个概念只在一处定义」：把取值口径收口到模型层，UI 只引用。**

1. `lib/models/history/history_models.dart`：`HistoryItem` 新增 getter `coverUrl` —— 优先 `cover`，回退 `covers.first`，均空则 null（含来源注释）。
2. `lib/pages/history/history_page.dart`：5 处 `item.cover` 统一改为 `item.coverUrl`：
   - 卡片封面 `NetworkImgLayer.src`（1 处）；
   - 跳转页入参 `cover:`（文章 / 直播 / 番剧 / 视频，共 4 处）。

非专栏条目 `cover` 非空，`coverUrl` 与旧行为逐字等价（零回归）；专栏条目回退取 `covers` 首图，封面恢复。

改动文件：`lib/models/history/history_models.dart`、`lib/pages/history/history_page.dart`（2 文件）。

## §5 遗留与踩坑

1. **API 字段语义坑（本质）**：B 站历史接口对专栏条目**不给 `cover`，只给 `covers`**。凡在历史链路展示封面处，必须走 `coverUrl` 收口，不得再直读 `cover`。
2. **移植漏点**：上游 PiliPlus 的 `covers` 回退在 WinWin 移植 `#f8c76fa`（历史页多类型分类）时未一并带入，属"移植时字段解析完整、渲染接线遗漏"，是同类可比回归点，后续移植需比对上游渲染层取值链。
3. **沙箱环境坑（勘误）**：本轮实测 `flutter build windows` 在缺失 `ProgramFiles(x86)` 时**会**直接退出并打印 `%PROGRAMFILES(X86)% environment variable not found.`（此前 `dev-workflow-spec` 记作"build 不受影响"，**本轮证伪**）。正确解法：构建前补齐 `env "LOCALAPPDATA=..." "APPDATA=..." "USERPROFILE=..." "ProgramFiles(x86)=C:\Program Files (x86)" "HOME=..." flutter build windows --debug/--release`。
4. `_openItem` 传入文章页的 `cover` 也已改为 `coverUrl`，使文章页首屏占位 / Hero 有图可用。

## §6 总结

历史页专栏分类封面缺失的根因是**渲染层只读 `cover`、漏用服务端专为专栏下发的 `covers` 图组**，属移植时的接线遗漏而非接口或网络问题。修复以**模型层新增唯一取值口径 `coverUrl`（cover 优先、covers 回退）**收口，UI 5 处引用统一替换；对非专栏条目零行为变化。`dart analyze` 全绿、Debug/Release 双编译通过，待用户实机确认专栏封面恢复。
