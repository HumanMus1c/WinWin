# 插件系统与插件管理器复盘（2026-11-14）

## 一、背景与目标

WinWin 的 Phase 6 长期处于 0%。本轮目标：

- 以 PiliPlus 的插件式模块组织为代码基底；
- 按 BiliPai 的插件管理模型实现插件生命周期、状态存储、能力声明、插件中心与外部规则包安装；
- 实现当前在 Windows 桌面端真正可用的内置插件与可安装 JSON 规则包。

## 二、事实核对与设计决策

### 2.1 PiliPlus 没有面向用户的插件系统

核对 `D:\Documents\GitHub\PiliPlus`：

- `lib/plugin/pl_player` 是播放器内核模块，`lib/plugin/canvas_danmaku` 是弹幕渲染模块；
- 全仓没有插件 manifest、注册表、安装/启用状态或插件管理 UI；
- 历史提交中的 “插件升级” 均指 `pl_player` 内部模块。

因此本轮把 “PiliPlus 插件系统” 落地为它的**自包含模块组织方式**：

- 每个插件一个目录（`lib/plugin/<scope>/<id>/`）；
- 插件自带 models / policy / settings，对外只暴露入口；
- 不把插件逻辑散落到页面层。

### 2.2 管理方式按 BiliPai

移植以下核心抽象：

- `Plugin` 生命周期：`onEnable` / `onDisable` + `PluginCapabilityManifest`；
- `BuiltinPluginRegistry`：串行注册/启停、启用失败回滚、未注册插件延迟应用；
- `PluginStore`：`enabled.*` / `config.*` / `data.*` 三类 key；
- `PluginManager`：单例调度、按类型查询、生效提示；
- 插件中心：已安装列表、可安装规则包、已安装规则插件、外部导入、提示开关；
- 外部安装只接受**声明式 JSON 规则包**，不执行外部代码。

## 三、实现内容

### 3.1 内核

| 文件 | 职责 |
|---|---|
| `lib/plugin/api/plugin_capability.dart` | 12 种能力与 manifest |
| `lib/plugin/api/app_plugin.dart` | `AppPlugin` / `BuiltinPlugin` / `PluginInfo` |
| `lib/plugin/api/plugin_state_store.dart` | 状态存储抽象 + Hive `plugin` box 实现 |
| `lib/plugin/api/builtin_plugin_registry.dart` | 串行注册/启停/失败回滚/延迟启用 |
| `lib/plugin/api/plugin_manager.dart` | 单例、查询、生效提示、日志 |

存储使用独立 Hive `plugin` box，不污染 `setting/video/localCache`，也不随全局
`GStorage.clear()` 清空（避免误删插件配置）。

### 3.2 规则引擎

- `lib/plugin/rules/json_rule_plugin.dart`：旧格式与 `condition` 复合条件解析、导入校验；
- `lib/plugin/rules/rule_engine.dart`：AND/OR 递归、11 种操作符、hide/highlight；
- `lib/plugin/rules/rule_regex_cache.dart`：正则 LRU 缓存、限长、编译失败不抛异常；
- `lib/plugin/rules/rule_target_adapter.dart`：推荐流 / 弹幕字段映射；
- `lib/plugin/rules/rule_plugin_manager.dart`：加载、安装、卸载、启停、统计、过滤。

### 3.3 内置插件（4 个）

| 插件 | ID | 默认 | 说明 |
|---|---|---|---|
| 空降助手 | `sponsor_block` | 开 | 包装既有 `SponsorBlockUseCase`，补分段类型配置 |
| 推荐流过滤 | `bilipai_feed_filter` | 关 | 移植 BiliPai 时长/播放量/点赞率/关键词/屏蔽用户/白名单 |
| 护眼模式 | `eye_protection` | 关 | 全应用暖色 + 压暗叠色，支持夜间时段 |
| 初见推荐 | `home_feed_anonymizer` | 关 | Web 首页推荐流不带登录 Cookie |

旧版本只有 `enableSponsorBlock` 一个开关，首次升级时迁移为插件状态，之后以插件状态为准。

### 3.4 可安装规则包（4 个）

随包分发到 `assets/plugins/`：

- 标题关键词过滤；
- 高级过滤器（AND/OR）；
- 短视频过滤；
- 弹幕净化（隐藏 + 颜色/字重高亮）。

安装后落盘到 `<ApplicationSupport>/plugins/rules/<id>.json`；支持本地 `.json`
与 http/https 链接导入，安装前预览类型、规则数、能力与描述。

### 3.5 运行时接线

| 能力 | 接线位置 |
|---|---|
| 推荐流匿名 | `RcmdController._fetchPage` 按插件开关传 `anonymous: true` |
| 推荐流过滤 | `RcmdController._applyPlugins`：内置过滤 → JSON 规则过滤 |
| 弹幕隐藏/高亮 | `WinWinDanmakuController._applyRenderFilters` |
| 空降助手 | `WinWinPlayerController.sponsorBlockEnabled` 改为 getter 读取插件状态 |
| 护眼叠色 | `AppShell` 根部 `EyeProtectionOverlay`（IgnorePointer，不拦截输入） |
| 启动恢复 | `bootstrap._run`：初始化内置管理器 → SponsorBlock 迁移 → 注册 → 加载规则插件 |

### 3.6 插件管理器 UI

- 设置左栏新增「插件」分类；
- 插件中心：概览、内置插件、可安装插件、已安装规则插件、外部导入、提示设置；
- 内置插件详情：身份、能力标签、插件自带设置；
- 规则插件详情：规则摘要、命中统计、打开所在文件夹、删除。

## 五、实机验证步骤

1. 打开「设置 → 插件」；
2. 确认 4 个内置插件显示，空降助手默认开启；
3. 在「可安装插件」依次安装 4 个规则包；
4. 开启「推荐流过滤」，回首页刷新，确认短视频/关键词命中被隐藏；
5. 打开任意视频，确认空降助手仍能自动跳过段落；
6. 开启「护眼模式」，调整压暗/暖色，确认全应用着色且可正常点击；
7. 开启「初见推荐」，刷新首页，确认推荐流请求为匿名；
8. 在规则插件详情重置统计、删除插件，确认文件与状态被清理；
9. 回看 `D:\Documents\logs\runtime.log` 中 `PluginManager` / `RulePluginManager` 日志。

## 六、已知限制与遗留

- 不支持 JS / Kotlin / 皮肤插件：Windows 端没有对应运行时；JS 可后续评估 WebView2 沙箱。
- Anime4K、DLNA、GoogleCast 未移植：依赖 mdk 着色器 / 平台投屏能力。
- 今日观看、CDN 优选：需要新增统计页或测速选流链路，延后。
- 护眼模式只覆盖 Flutter 内容区，不含 Windows 原生标题栏；截图会包含滤镜。
- App 推荐流没有 `tname`，分区关键词规则只对 Web 流生效。
- 规则插件统计每 2 秒批量落盘，异常退出可能丢失最后少量计数。
- 插件状态不参与“设置导入导出”，也不随“清除设置”清空。
