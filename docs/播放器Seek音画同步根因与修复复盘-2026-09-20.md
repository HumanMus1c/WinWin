## 1. 现象

1. **向后（快进）Seek**：音频先出声，视频画面要几秒才出现。
2. **往回（快退）Seek**：视频从落点高速倍速「追赶」回 seek 前的当前时间点，音频则从当前时间点前几秒开始**慢放**爬到当前时间点 —— 快退近乎被抵消。

## 2. 取证方法（本轮新增）

| 组件 | 作用 |
|---|---|
| `lib/core/player/seek_probe.dart` | 运行时变体开关（`Documents/logs/seek_probe.json`）、逐 seek 事件/阶段/position 采样/结论行，经 `SyncTrace` 同步落盘 `Documents/logs/trace.log` |

| 结论字段 | `dragBack`（时钟回落到 target-1500 以下）、`catchUp`（速率≥1.5x）、`audioSlow`（速率≤0.7x）、`frameLateMs`、`posMin/posMax/rateMin/rateMax` |

变体矩阵（`variant` 取值）：

| 变体 | 含义 | 目的 |
|---|---|---|

## 3. 已有实证（上一轮运行日志 `D:\Documents\logs\runtime.log` 复盘）

> 说明：上一轮 `AVSyncTrace` 只在 seek 窗口内采样，且日志把 `position()` 当作「音频主时钟」观测。

### 3.1 `position()` 在 seek 后是**假归位**（MDK 0.23.0 起 `position()` = 本次 seek 请求目标）

```
01:06:25.395  SEEK => target=92047 flags=2 curPos=480210 frozen=true
01:06:26.307  SEEK <= res=92050 posAfter=92050ms state=paused        ← 返回即目标
01:06:26.307  clock settled after main seek: pos=92050 target=92047, skip remount   ← 53fca0a 的跳过判定
01:06:26.440  seekPoll pos=480499 rate=1299x state=playing           ← 解冻后 130ms 时钟回跳旧位置
01:06:27.040  seekPoll pos=480599 rate=0.33x                         ← 从旧位置慢速推进（adaptive 压速）
01:06:27.110  seek clock not settled (target=92047 pos=480599), resync external audio track
```

**结论**：`posAfter≈target` 不能证明外挂音轨已归位；`53fca0a` 的「已归位则跳过重挂」判定会被该假象骗过，导致唯一的补救动作被跳过 —— 这正是用户当前仍能复现快退问题的直接原因。

### 3.2 事后重挂（时间预算方案）只带来 ~1s 的假归位，随后仍回跳

```
23:41:37.463  SEEK => target=40725 flags=2 curPos=123488 frozen=true
23:41:38.030  SEEK <= res=40733 posAfter=40733ms state=paused
23:41:38.031  backward seek: force resync external audio track to 40725 (frozen)
23:41:38.094  seekPoll pos=40725 rate=0.00x                          ← 重挂后时钟在目标
23:41:38.995  seekPoll pos=123888 rate=280x                          ← ~1s 后回跳旧位置
23:41:39.294  seekPoll pos=124188 rate=1.00x                         ← 从旧位置 1.0x 继续
23:41:39.597  seekPoll pos=124469 rate=0.93x state=playing           ← 解冻，仍在旧位置
23:41:40.160  seek clock not settled (target=40725 pos=124469), resync   ← 第三次重挂
23:41:40.436  seekPoll pos=40725 rate=-154x                          ← 第三次重挂把时钟拉回目标
```

**结论**：问题不在「seek 是否返回」，而在**外挂音轨的渲染管线残留旧音频**：`setMedia(audio)+seek` 能把时钟短暂置到目标，但旧音频被消费后时钟被拖回旧位置（「跳回」）。**冻结（暂停）期间旧音频无法排空，因此「等 1200ms 再重挂」的时间预算方案在冻结态下注定失效**。

### 3.3 快退 flags：`keyFrame|Backward` 完全不驱动音轨；`Accurate` 会动但随后回跳

```
22:19:14.912  SEEK => target=39313 flags=65794(=Backward|KeyFrame|FromStart) curPos=142950
22:19:15.411  SEEK <= res=35000 posAfter=143376ms                    ← 时钟根本没动
```

```
22:58:03.694  SEEK => target=538478 flags=2(=Accurate) curPos=995033
22:58:04.460  SEEK <= res=538500 posAfter=994231ms                   ← 返回即旧位置
（07d2cfa 之前）冻结缺失，重挂舞步照常执行
```

### 3.4 快进 seek 的真实耗时与落点

| 时间 | target | res（落点） | seek 耗时 |
|---|---|---|---|
| 21:33:39.069 | 32579 | 35000 | 1.93s |
| 22:19:02.347 | 133489 | 135000 | 2.89s |
| 22:57:40.054 | 168481 | 170000 | 2.52s |
| 22:57:56.789 | 990318 | 994900 | 2.38s |
| 23:41:19.886 | 110774 | 115000 | 1.92s |

**结论**：① 快进 seek 本身要 **1.9~3.5s**（网络 Range + 关键帧解码），期间音频（小流）先就绪 → 用户听到「音频先出、视频晚到」；② keyFrame 定位落点**越过目标最多约 4s**，进度条/时间显示会向前偏移。

### 3.5 `render.video/1st_frame` 事件**只在媒体打开时触发一次**，不能作为 per-seek 门控

全部 10 次出现均在 `setMedia/prepare` 打开阶段（`code=0/33`），seek 后从未出现 →
原始设计里「以首帧上屏事件作为解冻门控」不可行，需改用 `MediaStatus` 迁移 + 主时钟收敛判定。

## 4. 根因（当前结论，待 E 矩阵确认）

- **RC-1（快退）**：双轨（主视频 + 外挂音轨）下，快退后**外挂音轨的渲染管线未随 seek 清空**；旧音频缓冲被继续消费并把主时钟（音频）拖回 seek 前的旧位置 → 视频向旧时钟高速追赶（倍速观感）+ `avsync.audio.adaptive=1` 压速音频（慢放观感）。现有三次补救（跳过判定 / 时间预算重挂 / 800ms 自愈）都建立在「`position()` 能证明音轨已归位」与「暂停态下旧缓冲会排空」两个错误前提上。
- **RC-2（快进）**：seek 的真实耗时（1.9~3.5s）内音频先就绪；冻结只覆盖到「seek 返回」，而 `setState(paused)` 是异步请求且 MDK 的 seek 回调只保证首帧**解码**、不保证上屏 → 解冻即出现音频先响、画面后到。

## 5. 修复计划（Phase 2，按 E 矩阵结论定型）

主路线候选（`converge` 变体已在代码中就位，待实测）：

1. **快退**：seek 窗口内不暂停（保持播放让旧音频排空）但 `mute` 静音 → 先重挂外挂音轨（无 seek 在途，规避死锁）→ 单次主 seek（flags 由 E5 定型）→ **轮询等待主时钟真正收敛到目标**（±1500ms 连续两次采样，4s 上限）→ 再解冻 + 恢复音量。
2. **快进**：保留 in-place seek（keyFrame/inCache），同样以「主时钟收敛」作为解冻门控，消除音频先出窗口。
3. **删除**：已归位跳过判定、1200/300ms 时间预算、二次重挂、800ms 事后自愈、`_audioRemountInFlight` 读位抑制；取证探针在验证通过后删除。
4. 兜底（若主路线实测不成立）：`reopen` 变体（整体重开定位），需先解决同 URL `setMedia` 不真正重载的问题。
