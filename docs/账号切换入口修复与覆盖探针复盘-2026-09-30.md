# 账号切换入口修复 + SelectDialog 日志覆盖 + 六项会话覆盖探针复盘（2026-09-30）

**本轮三项需求**：
1. 「我的」页面「账号切换」入口点击后**立即进入账号登录页面**；
2. 日志覆盖**增强到 SelectDialog 控件**；
3. 解决上一轮会话**未覆盖**的六项：UI 风格切换、明暗主题切换、Esc 分层、播放器菜单、直播页、图片浏览。

本文档按五要素记录（根因 / 方案 / 验证 / 总结 / 提交与回滚）。

## 一、分析根因

### 1.1 第 1 项：账号切换「已登录态失效」

**现象**：在已登录状态下点击「我的 → 账号切换」，**没有任何反应**。

**取证链**（`lib/ui/profile/profile_page.dart`）：

| 位置 | 内容 |
|---|---|
| `:525-541` | `NormalItem(title: '账号切换')` 的 `onTap` = `onGuarded(context, (_) {})` —— 第二个参数是回调，此处传入的是**空操作** |
| `:153-172` | `_guarded` 逻辑：未登录 → `LoginGuard.requireLogin` 弹登录页 → `If (!…) return;` **中止**；已登录 → 返回 `true` → 执行 `onLoggedIn(context)` |
| — | **根因链**：已登录 → `requireLogin` 返回 true → 调用 `onLoggedIn(context)` → 而该回调是 `(_) {}` → **无任何行为** |

⇒ 未登录时"偶然可用"（是 `requireLogin` 内的 `showLoginPage` 起了作用），**已登录时该入口完全是死的**。

**既有可复用入口**：`showLoginPage(context)`（`lib/pages/login/login_page.dart:39`，push `LoginPage`，`fullscreenDialog: true`），头像区（`profile_page.dart:233`）与 `LoginGuard`（`login_guard.dart:27`）都在使用，属项目既有范式。

**附带缺口**：`_guarded` 内三条动作日志走 `ApiBlackbox.log('ProfilePage', …)`，而 `ApiBlackbox` 仅在 `kDebugMode` 初始化（`lib/main.dart`）→ **Release 复测日志中该路径完全不可见**（这正是上一轮日志看不到"我的"页活动的原因）。

### 1.2 第 2、3 项：覆盖盲区的根因是"日志门控 + 无埋点"

- `lib/core/log/app_logger.dart:23`：`static bool get enableVerboseLog => kDebugMode;`（**硬编码**）→ **Release 只落盘 `[W]` / `[E]`**；
- 佐证：9/29 19:34 / 21:40 会话出现 `[D] HistoryPage`（那是 Debug 构建），而上一轮复测跑的是 Release（`build\windows\x64\runner\Release\winwin.exe`），日志中只有 `[W]`/`[E]`；
- ⇒ 上一轮报的六个"会话未覆盖"盲区，本质是**这些路径没有任何埋点**（或埋点在 Release 不可见），导致"日志既不能证明测过、也不能证明没测过"。

**解决思路**：在这六条路径的**单一汇聚点**各插一条 `[W]` 级覆盖探针，使复测后 `grep 'Coverage:'` 即可得到完整覆盖矩阵。

## 二、设计修复计划与实现

### 2.1 统一探针通道：`[W]` 级 + 标签 `Coverage`

- 消息格式统一为 `Coverage: <area> <event> <details>`，一条 grep 即得覆盖矩阵；
- **必须用 `[W]`**：Release 只落盘 w/e；项目既有先例是 `PlayerController` 的生命周期日志也走 `[W]`；
- **被否决的替代方案**：实现 `app_logger.dart` 注释里挂起的 "L7 阶段接入 `Pref.enableVerboseLog`" 后用 `[I]` 记录 —— 否决理由：需要每次复测前手动开启 verbose，忘开则整轮探针失效，与"解决会话覆盖"的初衷相悖。

### 2.2 第 1 项实现

`lib/ui/profile/profile_page.dart`：

1. `:538-541` 账号切换 `onTap` → 直接 `showLoginPage(context)`（**无论是否已登录**），并前置一条覆盖探针；
2. `_guarded` 三条 `ApiBlackbox.log` → `AppLogger.w('Coverage', …)`（Release 可见），并将 `api_blackbox.dart` import 换成 `app_logger.dart`；
3. 移除 `_SettingsGroup.onGuarded` **死参数**（字段声明 / 构造参数 / 调用实参三处）——改造后它再无使用点；`_guarded` 方法**保留**（`_StatsRow` 仍在用）。

### 2.3 第 2 项实现（SelectDialog 探针）

`lib/pages/setting/widgets/select_dialog.dart` 的 `showSelectDialog`：

- 入口记 `Coverage: SelectDialog open <标题> (options=N, current=<当前值>)`；
- 出口记 `Coverage: SelectDialog close <标题> → <选中值>` 或 `→ cancelled`；
- 选此处作为**唯一汇聚点**可一次性覆盖 10 处调用点；因控件是"点选即提交"（`RadioGroup.onChanged` 直接 pop），返回值**就是**用户所选，故无需在控件内部重复记录。

### 2.4 第 3 项实现（六项探针）

| 覆盖项 | 探针位置 | 记录内容 |
|---|---|---|
| UI 风格切换 | `lib/theme/ui_style_notifier.dart:45` `setStyle` | `uiStyle <旧> → <新>` |
| 明暗主题切换 | `lib/pages/setting/theme_notifier.dart:43` `setMode` | `themeMode <旧> → <新>` |
| Esc 分层 | `lib/core/input/app_escape_scope.dart:95/101/107/113/117` | `Esc layer1 popup-route` / `layer2 overlay` / `layer3 unfocus` / `layer4 back` / `unhandled (root)` |
| 播放器菜单 | `lib/pages/video/player_panel.dart:1366/1621/2171` | `player menu quality/audio/speed opened` |
| 直播页 | `lib/pages/live/live_room_page.dart:112` + `:1393/1463/1536` | `live room entered roomId=…` + `live menu quality/line/ratio opened` |
| 图片浏览 | `lib/common/widgets/image/image_gallery_viewer.dart:28/163` | `gallery opened images=N initialIndex=K` + `gallery closed at index=K` |

**探针选点依据**：均为单一汇聚点（如 `setStyle`/`setMode` 是全局唯一写入口；`_onKeyEvent` 是全局唯一 Esc 路由器），避免在多处重复埋点；

**可行性预先核实**：`MenuAnchor` 的 `onOpen` 回调在 material_ui 1.0.0 中确实存在（缓存包 `lib/src/menu_anchor.dart:277/386`）；图片画廊**未自带 Esc 键处理**（该文件无 `LogicalKeyboardKey.escape`），故画廊内按 Esc 会落到 `AppEscapeScope` 第 1 层，探针可拍到。

**隐私口径**：只记枚举名、计数、索引、roomId 等低敏字段；**不含** URL、账号名、Cookie、用户内容。

### 3.6 本轮日志审计新发现的既有缺陷（**非本轮引入，待定处置**）

**现象**：崩溃账本（`.winwin_logs.json`）于 **18:13:11.994** 新增 1 条
`setState() or markNeedsBuild() called during build`。

**定位**（崩溃报告自带完整堆栈，直接指到行）：

```
#3 _MemberSpacePageState._loadMoreVideos (lib/pages/member/member_space_page.dart:312)
#4 _MemberSpacePageState._buildVideosTab.<anonymous closure> (lib/pages/member/member_space_page.dart:1329)
#7 SliverMultiBoxAdaptorElement.createChild / #16 RenderSliverGrid.performLayout
```

**根因链**：

1. `member_space_page.dart:1325-1333` 的 `SliverChildBuilderDelegate` itemBuilder 中，
   当 `index == _videos.length - 1`（滚动到最后一项）时**同步**调用 `_loadMoreVideos()`；
2. `_loadMoreVideos()`（`:310-312`）虽声明为 `async`，但 **`setState` 在第一个 `await` 之前**——
   async 函数体在首个 await 前是**同步执行**的，因此 `setState` 落在 **build/layout 阶段**；
3. `SliverChildBuilderDelegate` 的 builder 正是在 layout 阶段被调用的 → 触发
   `setState() or markNeedsBuild() called during build` 断言。

**为何长期未暴露**：该断言包裹在 `assert(() {…}())` 内，**只在 debug 生效**；
此前复测均跑 Release 构建，故静默通过（多一次冗余重建，通常无害）。本次跑 Debug 才暴露。

**非本轮引入的证据**：
- 本轮 4 笔提交**未触碰** `member_space_page.dart`（`git log 21932d0..HEAD -- <file>` 为空）；
- 该行由 `b53db78 [snapshot] 视频详情页评论完整功能`（**2026-08-06**）引入；
- 整本崩溃账本中该签名历史计数为 **0**（首次出现，因首次跑 Debug 复测）。

**项目内既有同构解法（修复范式）**：`lib/pages/whisper/session/session_list_section.dart:322-324`
已在同场景使用 `WidgetsBinding.instance.addPostFrameCallback`，并留有注释
「使用 addPostFrameCallback 避免在 build 中调用 _load」。建议按同一范式修复
`member_space_page.dart:1329`：

```dart
if (index == _videos.length - 1) {
```

**定级**：**必修（must-do）** —— 属真实运行时缺陷（非风格问题），有精确行号定位与
既有范式可循；Release 下虽不报错但会产生构建期冗余重建。
