# 动态互动三按钮 / 评论加载 / 表情面板体验修复复盘（2026-09-28）

> 任务来源：本次对话。用户实机测试后报告三个问题：
> ① 表情面板展开方向不符合直觉（应自按钮相邻的左下/右下角向对角展开）、背景应参考"弹幕样式"面板、渲染不流畅；
> ② 动态页各类型动态卡片与详情页的 转发/评论/点赞 三按钮无法点击交互，且评论始终显示"暂无评论"（标题却显示"全部评论(49)"）；
> ③ 动态详情页评论发送栏未对齐居中正文宽度。
> 改动面：8 个文件（2 新增 + 6 修改）；快照基准 `0253c212`。

## 1. 分析根因

### 1.1 问题②-B：评论始终"暂无评论"（根因已实测取证）

**现象**：动态详情页标题显示"全部评论(49)"（数字来自动态详情接口 `module_stat.comment.count`），
但评论区恒为空态"暂无评论，来发表第一条评论吧~"。

**取证链**：
1. 代码审查：`lib/pages/dynamics/detail_page.dart::_loadReplies` 硬编码 `type: 11` + `oid: 动态id`
   （`_effectiveId`），与视频页（type=1）、专栏页（type=12）相比，动态页的评论参数来源错误。
2. 实机 API 探测（curl 游客态，对真实动态 id 直接请求）：
   - `GET /x/v2/reply/main?type=11&oid=1251551756423266342` → `{"code":-404,"message":"啥都木有"}`；
   - 对照组 `GET /x/v2/reply/main?type=1&oid=80433022`（视频）→ `code:0`，正常返回 3 条评论；
   - 动态 feed 原始 JSON 中每条动态的 `basic` 节点自带正确的评论定位字段：
     - 视频动态 `DYNAMIC_TYPE_AV` → `"comment_type":1, "comment_id_str":"117320588531711"`（=视频 aid）；
     - 图文动态 `DYNAMIC_TYPE_DRAW` → `"comment_type":11, "comment_id_str":"404112956"`（=相簿 id）；
     - 转发动态 `DYNAMIC_TYPE_FORWARD` → `"comment_type":17, "comment_id_str":"1248889675504943123"`（=动态 id）。
3. 根因链：

```
评论区 oid/type 与动态类型解耦（basic.comment_type / comment_id_str 才是正确来源）
  → 硬编码 type=11 + oid=动态id 对 >非图文动态 必然 -404【根因1】
  → replyMain 三级容灾回退（登录/游客/legacy）全部沿用同一错误参数，全链路失败
  → _loadReplies 的 Error 分支静默置空（无错误态 UI、无重试入口）【根因2】
  → 失败被伪装为"真·空评论"，与标题数字（另一条数据链）形成矛盾现象
```

### 1.2 问题②-A：三按钮无法点击交互（功能未接线）

- 卡片（`view.dart::_buildStatRow`）与详情页（`detail_page.dart::_buildStatItem`）的
  转发/评论/点赞均为**无任何手势回调的裸 Row**（无 IconButton/InkWell/GestureDetector）；
- 卡片上点击按钮被父级卡片 `InkWell` 吸收，表现为"跳详情页"；详情页无父手势容器，表现为"完全无反应"；
- 网络层无动态点赞/转发接口：`Api.thumbDynamic` 仅声明未接线，`DynStat` 无点赞态字段，
  `DynItemModel` 无评论定位字段；转发接口（`Api.createDynamic`）存在但无调用方。

### 1.3 问题①：表情面板体验

- 现实现为 `PopupMenuButton` + 固定 `offset(0,-220)`：
  - 无自定义展开动画（框架默认淡入），视觉上无明显锚点，不符合"自按钮相邻角向对角展开"的直觉；
  - 面板定位与按钮实际屏幕位置无关联（魔法偏移量）；
  - 纯色圆角背景，与视频页"弹幕样式"面板（毛玻璃质感）不一致；
  - 表情图 `cacheWidth` 固定 64（未按 DPR）、无预取，首次打开逐个 pop-in。

### 1.4 问题③：评论发送栏宽度

- `detail_page.dart` 的 `Success` 分支为 `Column(stretch)`，`SimpleCommentInputBar` 是其直接子节点且无宽度约束
  → 横向撑满全屏；正文区受 `Center + ConstrainedBox(maxWidth: 820)` 约束，两者不对齐。
- 同类问题：专栏页（正文 maxWidth 860）输入栏同样撑满。

## 2. 设计修复计划（已按此实施）

| # | 决策 | 依据 |
|---|---|---|
| 1 | `DynItemModel` 新增 `commentType/commentIdStr`（解析 `basic` 节点）、`DynStat` 新增 `liked`（`module_stat.like.status`） | PiliPlus `DynamicDetailController` 同款数据来源；实测 basic 字段必现 |
| 2 | 评论区 oid/type 改为 `_resolveCommentTarget()`：basic 字段优先；缺失/为 0 时重拉动态详情兜底；仍失败则报"无法定位评论区" | 对标 PiliPlus；覆盖转发嵌套等容错场景 |
| 3 | 评论失败不再伪装空态：新增 `_replyError` 状态，显示"评论加载失败：xxx + 重试" | 直击"数字有评论列表空"的误导性现象 |
| 4 | 新建共享组件 `DynActionBar`（`lib/common/widgets/dyn/dyn_action_bar.dart`）：转发/评论/点赞三键；点赞走 `DynHttp.thumbDynamic`（up=1/2）+ LoginGuard + 高亮(active 图标+biliPink)+计数±1；评论回调由宿主决定；转发弹 `DynRepostDialog` | 卡片/详情页/空间页三处一次接线，防第三份复制 |
| 5 | 新建 `DynRepostDialog`（`lib/common/widgets/dyn/dyn_repost_dialog.dart`）：被转发内容预览 + 转发理由输入（可空）+ 提交，转发目标对"转发动态"取 `orig`（避免链式转发） | 对标 PiliPlus RepostPanel 精简桌面版 |
| 6 | `DynHttp` 新增 `thumbDynamic`（`/x/dynamic/feed/dyn/thumb`，参数/JSON body/设备头复刻 PiliPlus）与 `repostDynamic`（`/x/dynamic/feed/create/dyn`，scene=4 + `web_repost_src`） | 直接移植成熟实现参数 |
| 7 | 列表页点赞记忆：`_likedState/_likeCountState` Map 存于页面 State，滚动重建不丢失；刷新时清空 | 瀑布流卡片会随滚动销毁重建 |
| 8 | 评论按钮行为：卡片/空间页 → 打开详情页并自动聚焦评论输入框（新增 `focusComment` 参数）；详情页 → 聚焦当前输入框 | 对标 PiliPlus `pushDynDetail(viewComment: true)` |
| 9 | 表情面板重写（`emote_picker.dart`）：手写 Overlay + 位置锚定（按钮上方，左/右半区对齐按钮左/右缘，clamp 屏幕边距；上方不足翻转到下方）+ ScaleTransition 自相邻角（左下/右下）向对角展开（180ms easeOutCubic）+ 毛玻璃样式 1:1 复刻"弹幕样式"面板（BackdropFilter16/0xD9 底色/圆角12/边框/阴影）+ 标题行 + 7 列网格 | 用户明确要求；风格单一样板 |
| 10 | 表情图性能：`decodeClamp(28)` 按 DPR 解码、打开时 `precacheImage` 预取全部 28 个、`gaplessPlayback` + frameBuilder 淡入 | 消除首次逐个 pop-in 与闪跳 |
| 11 | 详情页/专栏页输入栏外包 `Center + ConstrainedBox(820/860)`，与正文列对齐 | 最小改动；两页同构 |
| 12 | 明确不做：动态点赞动效（飞入动画）、转发配图/表情、评论楼中楼 | 控制改动面，按需再迭代 |
