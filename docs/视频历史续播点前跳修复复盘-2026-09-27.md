# 视频历史续播点「向前跳跃几秒」修复复盘（2026-09-27）

> 用户报告：播放视频时直接返回上一级，再继续播放这个视频，历史播放点会向前跳跃几秒，没有正确记忆播放时间点。
> 改动面：2 个文件（`lib/pages/video/player_controller.dart`、`lib/core/player/seek_probe.dart`，+99 / -35）。
> 改动前快照/回滚基准：提交 `5cf5d2e`（工作区干净，无待快照改动；`refs/snapshots/latest` 同点）。

## 1. 分析根因

### 1.1 现象描述

播放视频至中途 → 直接返回上一级（pop）→ 重新进入同一稿件继续播放 → 续播起点比退出位置**靠后几秒**（"历史播放点向前跳跃几秒"）。

### 1.2 取证证据

**（a）保存侧无正向偏移（排除）**：
退出上报取 `position.value.inSeconds`——`reportCurrentProgress()`（`player_controller.dart:1991`）：

```dart
final posSec = position.value.inSeconds;   // 向下取整：最多比实际小 <1s，绝不偏大
await makeHeartBeat(targetProgress, playType: ..., isManual: true);      // /x/click-interface/web/heartbeat
await VideoHttp.reportHistory(aid: ..., cid: cid, progressSec: posSec);  // /x/v2/history/report
```

两条上报均直传该值（`lib/http/video.dart:579-582 / 617`），无 `+N` 偏移；`.inSeconds` 只会让保存值**偏小**。

**（b）恢复侧走「非精确落点」（根因）**：
`resumeTo()`（`player_controller.dart:2051`，历史续播主路径）直接调底层 seek、**未传 flags**：

```dart
await player.seek(position: position.inMilliseconds);   // 修复前
```

而 fvp 的签名默认即关键帧定位（已核对 `fvp-0.38.1` 源码）：

```dart
// player.dart:543-545
Future<int> seek({ required int position, SeekFlag flags = const SeekFlag(SeekFlag.defaultFlags) }) async
// global.dart:111
/// defaultFlags is keyFrame|fromStart|inCache
static const defaultFlags = MDKSeekFlag.MDK_SeekFlag_Default;
```

**（c）项目自身实测数据**（既有复盘/探针，证据链闭合）：

- 「keyFrame 定位落点**越过目标最多约 4s**，进度条/时间显示会**向前偏移**」——`docs/播放器Seek音画同步根因与修复复盘-2026-09-20.md:96`；
- 09-25 P0 A/B（`SeekProbe` 33+36 次实测）：keyFrame 落点误差 **-4950ms ~ +4077ms**；精确落点（去 KeyFrame）**36 次误差全部 0ms**（`lib/core/player/seek_probe.dart:373-383`）。

**（d）同类裸 seek 共 4 处**（同一缺陷类，一并修复）：

| 位置 | 场景 |
|---|---|
| `player_controller.dart:901` | `_pendingSeek` 补偿（prepare 返回 -1 后 buffered 事件补定位） |
| `player_controller.dart:2081` | `resumeTo()` 历史续播（本次报告主路径） |
| `player_controller.dart:2505` | `_openWithQuality(start:)` didPopNext 重载恢复 |
| `player_controller.dart:2751` | 卡顿自愈重挂后 resumePos 恢复 |

### 1.3 根因链

```
pop 退出 → reportCurrentProgress 上报 floor(position)（无正向偏移，≤1s 取整）
重进 → _applyPlayInfo 拉 playInfo.last_play_time → ctrl.resumeTo()
  → player.seek(position:) 未传 flags
  → fvp 默认 keyFrame|fromStart|inCache（关键帧定位）
  → 落点越过目标最多约 4s ⇒ 续播点/进度条「向前跳跃几秒」
交互式 seek 已于 2026-09-25 A/B 切换精确落点，但续播/起播/自愈路径从未同步迁移 → 长期遗留
```

## 2. 设计修复计划

### 2.1 方案与关键决策

| # | 决策 | 依据 / 取舍 |
|---|---|---|
| 1 | 抽取 `_seekFlagBits()`：seek flags **单一事实来源** | 从 `_processSeekQueue` 逐字等价提取，交互式 seek 与起播/续播/自愈定位共用同一策略，杜绝再次分叉（本次缺陷正源于"两条 seek 路径各自演化"） |
| 2 | 新增 `_seekPrecise(targetMs, {timeout})`：主实例非交互定位统一入口 | 同源 flags + `SeekProbe` 取证行（`START-SEEK target/flags/pos/buffered/state`）+ 可选超时（-99）；返回底层 seek 结果 |
| 3 | 替换 4 处裸 seek（:901 / :2081 / :2505 / :2751） | 各站点原有 `_lastSeekFinishTime`／失败判定语义保持不变；超时语义与原实现一致 |
| 4 | 配套加固：`SeekProbe._loadConfig` 的 `accurateSeek = raw['accurateSeek'] != false` | 旧写法 `== true` 使"存在配置文件但未写该键"的用户静默回退 keyFrame（与本修复目标直接冲突），且与字段注释「默认精确落点；配置 false 可回退」矛盾 |
| 5 | 已评估放弃：`resumeTo` 直接调用交互式 `seek()` | 会把「暂停冻结 + 音轨重挂舞步」首次引入启动路径，且 `seek()` 强制 `_userIntentPlaying=true` 会覆盖"加载窗口内用户手动暂停"，回归面大于收益 |

### 2.2 关键代码

```dart
// player_controller.dart（新增，起播/续播/自愈共用）
Future<int> _seekPrecise(int targetMs, {Duration? timeout}) async {
  final player = _player;
  if (player == null || _disposed) return -99;
  final currentPosMs = player.position;
  final bufMax = player.buffered();
  final flagBits = _seekFlagBits(targetMs: targetMs, currentPosMs: currentPosMs, bufMax: bufMax);
  SeekProbe.note('START-SEEK target=$targetMs flags=$flagBits pos=$currentPosMs buffered=$bufMax state=${player.state}');
  final future = player.seek(position: targetMs, flags: mdk.SeekFlag(flagBits));
  return timeout == null ? future : future.timeout(timeout, onTimeout: () => -99);
}

// 四处调用替换：unawaited(_seekPrecise(pending.inMilliseconds)) / await _seekPrecise(position.inMilliseconds)
//             await _seekPrecise(startMs) / await _seekPrecise(resumePosMs, timeout: 10s)
```

- **改动面**：2 文件（`player_controller.dart` +99/-35、`seek_probe.dart` +5/-1）。
