# 搜索页顶栏就地扩充 — 设计文档

> Status: design（待评审） ｜ Owner: 小通 ｜ 关联模块：首页顶栏、搜索页、消息中心顶栏（AppTopBarSurface）
> 上游参考：PiliPlus `lib/pages/search/*`、`lib/pages/search/widgets/hot_keyword.dart`、`lib/models_new/search/search_trending/*`

---

## 一、背景与目标

### 1.1 需求原文（CVO）

> 开始设计改造搜索页，将其从二级页面改为首页顶栏的**变形高度扩充**（**非搜索框高度撑开**），**隐藏分类 TAB 栏**，将扩充的区域用于展示**搜索历史 + 热搜**；热搜排版**上游已经重新设计，请你参考**；搜索历史中的**直接从历史搜索访问的用户胶囊**需要和**搜索历史词**要**完整继承和保留**。先编写设计文档。

### 1.2 目标（To-Be）

1. **入口就地化**：首页顶栏搜索框的点击**不再 push 二级路由** `SearchPage`，改为在**原位**进入「搜索态」。
2. **变形高度扩充**：进入搜索态时，顶栏**容器**纵向展开（morph 展开），**搜索框行自身高度保持不变（38px）**——即"非搜索框高度撑开"，扩充出的区域承载历史与热搜。
3. **隐藏分类 TAB**：搜索态下收起来源分类 TAB 行（推荐/关注/热门/番剧/直播），退出后恢复。
4. **扩充区内容**：**搜索历史（词 + 直达用户胶囊）+ 热搜（大家都在搜）**。
5. **热搜排版对齐上游重设计**：采用 PiliPlus 现版 `SliverHotKeyword` 的 **2 列网格**排版（详见 §三）。
6. **数据完整继承**：原有「搜索历史词」与「搜索后直达的用户胶囊」两类记录在改造后**字段、容量口径、增删清空行为全部保留**（详见 §六）。

### 1.3 非目标（Out of Scope）

- 不改动搜索结果页 `SearchResultPage`（其仍为二级路由）。
- 不改动搜索后端接口语义（`searchByType` / `searchSuggest` / `searchTrending`）。
- 不引入「搜索发现（rcmd）」二级板块（上游有，本项目本期不做，见 §十一 开放问题）。

## 二、现状（As-Is）

### 2.1 首页顶栏（`lib/ui/home/home_page.dart`）

- 页面骨架：`AppScaffold(title: '首页')` → 顶部安全行显示「首页」标题（可随滚动收缩）+ body。
- body = `Stack[ feed(IndexedStack 5 tab), Positioned(top:0) 浮层顶栏 ]`。
- 浮层顶栏 `_HomeHeader` 由 **`AppTopBarSurface`**（毛玻璃材质单一来源，`padding` 水平 `Style.lg(16)` / 垂直 `Style.sm(8)`，底色 `surface×0.72`，backdrop 模糊 20，圆角 `chrome.containerRadius`）包一个 `Column`：
  - **Row1 搜索框行**：`SizedBox(height: 38)` 圆角 100 容器（搜索图标 20 + 提示文案"搜索视频、UP主..." 13px）＋ `SizedBox(width: 8)` ＋ 设置图标按钮。**onTap 当前为 `Navigator.push(AppRoute(builder: (_) => const SearchPage()))`**。
  - `SizedBox(height: 6)`。
  - **Row2 分类 TAB 行**：`SizedBox(height: 32)` 横向 `ListView`，5 个 `HomeTabType`（推荐/关注/热门/番剧/直播）pill。

### 2.2 搜索页（`lib/pages/search/search_page.dart`，二级路由）

- `AppScaffold(reserveTopStrip: false, topBar: 自绘搜索行)`：`Padding(LTRB 0,8,8,8)` → `Row[ AppLeadingBackButton, Expanded(AppCapsuleTextField autofocus, hint '搜索视频、UP主...', prefix 搜索图标, suffix 清空), SizedBox(8), MiuixTextButton('搜索') ]`。
- body：
  - 输入非空 → 联想建议列表 `_buildSuggestsList()`。
  - 否则 → 主内容 `ListView(padding: all 12)`：**搜索历史**（标题 + 清空图标；词胶囊 `AppInputChip` 可删）→ **直达用户胶囊行**（`SizedBox(height: 34)` 横向 `ListView`，头像 24 + 名称 12px，长按删，点击进 `MemberSpacePage`）→ **大家都在搜**（标题 + `MiuixBasicComponent` 列表：`startAction` 序号（前三 `biliPink` 加粗）＋ keyword ＋ recommendReason）。
- 演示模式（`Pref.demoMode`）：历史用骨架胶囊、用户胶囊用本地演示卡、热搜用骨架行。

### 2.3 数据层（现有，本次**复用不改口径**）

| 数据 | 真源文件 | 存储 | 口径 |
|------|----------|------|------|
| 搜索历史词 | `search_history_service.dart` → `SearchKeywordHistory` | Hive `localCache` key `'searchHistory'` | `maxEntries = 20`，去重后前插 |
| 直达用户胶囊 | `search_history_service.dart` → `SearchHistoryService` | Hive `localCache` key `'searchHistoryUsers'` | 上限 20，`SearchHistoryUser{mid,name,face,timestamp}`，`addVisitedUser` 去重前插 |

### 2.4 热搜模型

- 现有：`lib/models/search/result.dart` → `SearchTrendingItemModel{ keyword, icon, recommendReason }`（解析 `keyword` / `icon` / `recommend_reason`，`·`→空格）。
- 上游已扩展：`keyword / showName / icon / showLiveIcon / recommendReason`（解析 `show_name` / `show_live_icon`）。

## 三、上游参考：热搜排版重设计（硬参考）

**来源：PiliPlus `lib/pages/search/widgets/hot_keyword.dart`（`SliverHotKeyword` + `_HotKeywordGrid`）**

1. **两列网格**：`crossAxisCount: 2`，`mainAxisSpacing: 5`，`crossAxisSpacing: 0.4`；列宽 `(maxWidth - 5×(2-1)) / 2` 均分；行高取首个 cell 高度（`childHeight`），`row = ceil(count/2)`。
2. **单元格**（自左至右）：
   - `showName`（14px，`maxLines:1`，ellipsis，`Tooltip=showName`）；
   - 其后依次取其一：
     - `icon` 非空 → `CachedNetworkImage` 高 15（`memCacheHeight = dpr×15`）；
     - 否则 `showLiveIcon == true` → 直播矩形资源 `width 48 × height 15`；
     - 否则 `recommendReason` 非空 → 文本（14px，`colorScheme.outline`）。
3. **标题行**（搜索页 `_buildHotSearch`）：`「大家都在搜」` + `「完整榜单 ›」`（→ `/searchTrending`）+ `「刷新」(Icons.refresh_outlined)`；标题 25px 上边距、左右 10/4。
4. **无序号**：上游单元格**不显示 1/2/3 序号**（与 WinWin 现版"序号 + 标题 + 推荐理由"列表**不同**，本次改造按上游对齐）。
5. 上游另有 `「搜索发现」`（rcmd）板块与 `recordSearchHistory` / 历史导入导出入库能力——本期**不纳入**（§1.3、§十一）。

> 本项目落地时：`CachedNetworkImage` 用 `cached_network_image_ce`，`Material/InkWell` 须换 `MiuixPressable`/自绘（应用侧零 Material 消费，见 `docs/B7门槛升级-应用侧零Material消费-2026-10-19.md`），`ColorScheme.of(context)` 换 `AppThemeHost.of(context).colors`。

## 五、交互与状态机

### 5.1 状态

- `HomeHeaderState`：`idle（常态）` ↔ `searching（搜索态）`。
- 载体建议：`HomePage` 持有 `bool _searchMode` + `FocusNode`/`TextEditingController`；或抽 `HomeSearchController`（`ChangeNotifier`）以便顶栏与 scrim 同步。**（倾向后者，符合 P4 单点定义）**

### 5.2 进入

- 常态点击搜索框 → `_searchMode = true`：容器高度 morph 展开、分类 TAB 收起、扩充区显现、`Field` 自动聚焦、scrim 显现、加载历史 + 热搜（若未缓存）。

### 5.3 退出

- 触发：`Esc` / 点击 scrim / 点击返回（`AppEscapeScope` 分层）/ 再次点击搜索框空白处（可选）。
- 行为：收起扩充区与 TAB 恢复（反向下沉动画）、取消聚焦、清空一次输入态（历史保留）。
- Esc 语义沿用 `AppEscapeScope`：**先取消聚焦、再收起**（`lib/core/input/app_escape_scope.dart`）。

### 5.4 提交与跳转

| 动作 | 行为 |
|------|------|
| 提交关键词（回车 / 「搜索」按钮） | `SearchKeywordHistory.push` 保存 → `push` `SearchResultPage(keyword)` → 返回后刷新历史 |
| 点击历史词 | 直接 `push` `SearchResultPage(word)`（同时按现行为置顶历史）；**不关闭搜索态**（返回后仍在搜索态，可继续） |
| 点击热搜词 | 同上 |
| 点击直达用户胶囊 | `push` `MemberSpacePage(mid)`（同时 `addVisitedUser` 已存在，不重复） |
| 删除历史词 / 删除用户胶囊 / 清空历史 | 与 `search_page.dart` 现行为 **1:1**（清空时 `SearchKeywordHistory.clear()` + `SearchHistoryService().clearVisitedUsers()`） |

> 说明：提交后是否收起搜索态——**推荐"提交即收起、进入结果页"**（更贴近"搜索页=临时态"的直觉）；若 CVO 倾向保留搜索态以便连续搜索，二选一，见 §十一。

## 六、数据继承与保留（硬性契约）

> CVO 明确要求："搜索历史中的直接从历史搜索访问的用户胶囊需要和搜索历史词要完整继承和保留。"
> 改造**只替换展示容器（二级页 → 顶栏扩充区）**，**数据读取/写入/容量/顺序口径零变更**。

### 6.1 字段与口径对照表（改造后必须逐项保持）

| 项 | 改造前 | 改造后（要求） | 判定 |
|----|--------|----------------|------|
| 历史词存储键 | `localCache['searchHistory']` | 不变 | ✅ 必须 |
| 历史词上限 | 20 | 不变 | ✅ 必须 |
| 历史词去重/前插 | `SearchKeywordHistory.push` | 不变 | ✅ 必须 |
| 用户胶囊存储键 | `localCache['searchHistoryUsers']` | 不变 | ✅ 必须 |
| 用户胶囊上限 | 20 | 不变 | ✅ 必须 |
| 用户胶囊字段 | `mid/name/face/timestamp` | 全字段保留 | ✅ 必须 |
| 用户胶囊点击 | `MemberSpacePage(mid)` | 不变 | ✅ 必须 |
| 用户胶囊长按删 | `removeVisitedUser(mid)` | 不变 | ✅ 必须 |
| 清空 | 词 + 用户一起清 | 不变 | ✅ 必须 |
| 新增来源 | 搜索后点视频/用户卡时 `addVisitedUser`（`search_panel.dart`） | 不变 | ✅ 必须 |

### 6.2 迁移/兼容

- **不做数据迁移**：新旧共用同一 `localCache` 键，改造后首次进入搜索态即读取到既有数据。
- **不丢字段**：解析保留 `mid/name/face/timestamp`；展示沿用头像 `ImageUtils.thumbnailUrl(face, type:'avatar')`。
- **降级**：`face` 为空时回退 `AppIcons.profile()` 占位（与现行为一致）。

## 八、动画与视觉口径

- **曲线/时长**：沿用项目顶栏动画口径 `MiuixMotion`（`AppScaffold` 安全行用 `MiuixMotion.standardDecelerate`，220ms）。建议扩充展开/收起 **220ms `standardDecelerate`**，与既有观感一致。
- **搜索框行**：`height 38` **恒定**，不参与高度补间（满足"非搜索框高度撑开"）。
- **TAB 行**：`height 32 → 0`（`ClipRect` + 高度补间）或 `AnimatedOpacity` 淡出（与上游 `AnimatedContainer` 手法一致）。
- **材质**：扩充区仍在 `AppTopBarSurface` 内，底色/模糊/圆角不变。
- **scrim**：`cs.scrim`（或 `onSurface` 低透明）覆盖 feed，`AnimatedOpacity` 淡入淡出；点击收起。
- **字号/间距**：热搜网格 14px、列间距 5、行间距 0.4（对齐上游）；历史标题/清空沿用现 `titleSmall` 加粗 + `AppIcons.delete()`。

## 九、边界与兼容

1. **滚动联动**：`MainLayout` 的底栏随 feed 滚动隐藏（`_bottomBarVisible`）。搜索态建议**冻结底栏/顶栏吸附**（搜索态不随滚动收起），退出后恢复。
2. **骨架标题**：首页 `AppScaffold(title:'首页')` 安全行——搜索态是否抑制该行，见 §十一。
3. **演示模式**：`Pref.demoMode` 下保持现骨架/占位行为（历史骨架胶囊、演示用户卡、热搜骨架行），**不得**跑真实历史/热搜。
4. **宽/窄屏**：`MainLayout` 宽屏走 `AppNavRail`、窄屏走底栏；顶栏扩充两态一致。
5. **输入法/焦点**：Windows 桌面 `autofocus` + `Esc` 先取消聚焦再收起；I/O 会话无桌面弹窗。
6. **零 Material 消费**：新增/改造代码不得引入 `material_ui`（沿用 `AppIcon/AppIcons`、`MiuixPressable`、`AppThemeHost`）。
7. **图标**：新图标一律 `AppIcon(AppIcons.语义())`，**不加 `const`**（运行时映射）。

## 十、验收标准（AC）

- [ ] **AC-1**：首页点击顶栏搜索框**不再 push 新路由**，在原位进入搜索态。
- [ ] **AC-2**：进入搜索态时**搜索框行高度不变**，顶栏**容器高度淡入式/补间式扩充**（"变形高度扩充"）。
- [ ] **AC-3**：搜索态下**分类 TAB 行隐藏**；退出搜索态后**原样恢复**（位置/选中态）。
- [ ] **AC-4**：扩充区自上而下依次为 **搜索历史（词）→ 直达用户胶囊 → 大家都在搜（2 列网格）**；输入非空时切换为联想建议。
- [ ] **AC-5**：热搜排版与上游一致（2 列网格、无序号、showName + 图标/直播标/推荐理由、含「完整榜单 / 刷新」入口）。
- [ ] **AC-6**：**历史词**：读取/去重/前插/上限 20/单删/清空 —— 与改造前逐项一致。
- [ ] **AC-7**：**直达用户胶囊**：字段（mid/name/face/timestamp）完整；点击进空间、长按删、上限 20、与词同批清空 —— 逐项一致。
- [ ] **AC-8**：新旧数据**共用存储键，无需迁移**，改造后首次进入即可看到既有历史与用户胶囊。
- [ ] **AC-9**：`Esc` / 点击 scrim / 返回均可收起搜索态；`Esc` 先取消聚焦。
- [ ] **AC-10**：演示模式不触发真实历史/热搜，保持占位行为。
- [ ] **AC-11**：`dart analyze` 零错误零警告；`flutter build windows --debug` 与 `--release` 均成功。
- [ ] **AC-12**：应用侧零 `material_ui` 消费；图标全部走 `AppIcons`。
