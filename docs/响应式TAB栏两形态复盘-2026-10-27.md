# 响应式 TAB 栏两形态（宽屏胶囊轨道 / 窄屏宽体页签）复盘 — 2026-10-27

## 一、现象（需求）

同一语义的「分类切换 TAB」在项目里长出了三套形态：

| 位置 | 原实现 | 尺寸 / 交互 |
|---|---|---|
| 首页合并栏 | `_HomeHeader` 手写横向 `ListView` 胶囊 | 32 高、内距 14、字号 13、选中 `primary 28%`；**无 hover / 无手型光标 / 无滚轮横滚** |
| 历史分类栏 | `_buildTabBar` 另写一套 | 行高 40、胶囊 14/5、字号 12.5、选中 `primary 18% + 1px 边框`；有 press sink，**无 hover** |
| 动态页 | `AppTabView(floating)` + `AppTabBar` → `MiuixTabRow` | 42 高（面板内距后净行高 34）、项宽 76–98、胶囊选中；有 hover / press，毛玻璃 |

CVO 要求：**宽屏桌面端用首页 / 历史那种紧凑胶囊轨道（鼠标友好），窄屏用动态页那种宽体页签（手指友好）**，并把 P0（组件与三处接线）+ P1（首页顶部预留收口、宽屏关闭鼠标拖动翻页）落地。

## 二、定因

1. **三处各自手写**：尺寸、配色、hover/滚轮能力互不相同；首页、历史根本没有鼠标语义。
2. **没有宽度策略**：动态页在宽窗下 4 项只占左上约 330px，右侧大片空白；反之窄窗下首页 / 历史胶囊只有“文字宽 + 28”，手指难命中。
3. **顶部预留分散写死**：`rcmd / follow / hot` 写 120，`pgc / live` 写 112，首页搜索面板的 `fixed` 写 88——分类行一旦换高，首屏卡片会被浮动顶栏压住。
4. **宽屏鼠标拖动会翻页**：根壳 `AppScrollBehavior.dragDevices` 含 mouse，`PageView` 在桌面可被“按住拖动”切页，与“点选为主”的桌面惯例冲突。

## 三、方案

### 3.1 统一形态判定

新增于 `lib/ui/components/app_tab_view.dart`：

- `enum AppTabForm { auto, rail, wide }` + `kAppTabBreakpoint = 700`；
- `resolveAppTabForm(context, form, breakpoint)`：读 **`MediaQuery.sizeOf(context).width`（整窗宽）**。选整窗而非控件约束，是为了让首页、历史、动态在同一窗口宽度下**同时**切换；选 700 是因为窗口最小宽度 640（`main.dart` 的 `minimumSize`），600 实际不可达、840 会把 800×600 桌面误判为移动形态。

### 3.2 表现层组件 `AppTabStrip`

只认 `tabs / selectedIndex / onSelected`，不持有控制器（历史分类由服务端下发、数量会变，`AppTabController.length` 是 `final`，不适合）：

- **宽屏 rail**：行高默认 32；项宽随文字、左对齐；胶囊选中 `primary 18% + 1px 45% 边框`；hover 6% / press sink 0.98 / 手型光标；`PointerSignalResolver` 把纵向滚轮映射为横向滚动（仅在轨道确实溢出时接管）；选中项按 `RenderAbstractViewport.getOffsetToReveal` 只在被裁切时滚入可见。
- **窄屏 wide**：`_AppWideTabRow` 封装 flutter_miuix `MiuixTabRow`（76–98 × 42、胶囊选中、库内 275ms 自动居中），保留原 hover/press 补齐（库无 hover）与 outline 置透明。
- 选 `SingleChildScrollView + Row` 而非 `ListView.builder`：选中项滚入需要 `GlobalKey` 的 `currentContext`，未构建项拿不到（分类数量最多十余项，全量构建成本可忽略）。

### 3.3 组合层 `AppTabBar`

改为 `StatelessWidget`，内部把 `AppTabStrip` 塞进原有毛玻璃面板：

- `railHeight` / `wideHeight` 都取 `_rowHeight = preferredHeight - panelPadding.vertical`，**面板总高恒为 42**（`AppTabBar.defaultHeight` 作为“高度上限”不变量），番剧播放页 `SliverPersistentHeader(extent: 42)`、空间页 `tabBandHeight`、动态页 `floatingTopReserve` 全部无需改动；
- `railPadding / widePadding` 显式置零，内缩由面板 `Padding` 承担（否则窄屏页签整体右移 12px）。
- `form` / `breakpoint` 对外暴露，页面可按语义强制形态。

### 3.4 `AppTabBody`

宽屏（≥700）套 `_AppTabPageScrollBehavior`（`dragDevices` 仅 `touch / stylus`）关闭**鼠标拖动**翻页；滚轮 / 触摸不受影响。窄屏保持全设备可滑。

### 3.5 页面接线

- **首页**（`lib/ui/home/home_page.dart`）：Row2 的手写 `ListView` 换成 `AppTabStrip`，宽屏 32 / 窄屏 42，`AppTabBar` 同款胶囊配色。
- **历史**（`lib/pages/history/history_page.dart`）：`_buildTabBar` 改 `AppTabStrip`（`type` ↔ index 映射），宽屏 40（胶囊上下缩 5 保持 30 高）、窄屏 42。
- **动态**：零改动，`AppTabBar` 自动在宽屏变紧凑轨道。
- **P1 顶部预留收口**：新增 `lib/ui/home/home_chrome_metrics.dart`（`HomeChromeMetrics`），`topReserveOf(context)` = 宽屏 120 / 窄屏 130；`headerFixedOf(context)` = 88 / 98。`rcmd`、`follow`、`hot`、`pgc`、`live` 五处的 120 / 112 全部改为该单一来源（`edgeOffset`、`SliverPadding`、登录守卫的 top padding）。

## 六、遗留与踩坑

遗留：

1. 实机观感待 CVO 复看：窄屏首页合并栏 +10px、历史行高 40、宽屏动态页由宽体页签变紧凑轨道、窄屏选中胶囊由主题色改库默认中性色。
2. `AppTabBar` 窄屏净行高仍为 34（面板内距 4×2 占用），独立 `AppTabStrip` 窄屏为 42，两者差 8px——这是“保持面板总高 42 / 固定宿主不破”的取舍。
3. 首页 `baseHeaderFixed` 沿用旧口径 88（近似值），宽屏零变化、窄屏精确 +10；若日后重算为实际内容高会再挤占搜索面板可用高度。
4. P2 未做：两端渐隐、选中项滑动胶囊（当前逐项淡入）、其余页面 `form` 覆盖、键盘左右键。
5. `_AppWideTabRow` 仍镜像 flutter_miuix 私有 `_calculateTabWidth` 做 hover 命中，升级库后需复核。

踩坑：

1. **滚轮映射的委托顺序**：外层 `Listener(onPointerSignal:)` 能抢到纵向 delta，前提是内层横向 `Scrollable` 对该事件不注册（其 `_pointerSignalEventDelta` 对横向轴只取 dx，dy 为 0 即放弃）；若内层先注册，事件被吞。
2. **`AppTabBar` 的 `widePadding` 默认值**：`AppTabStrip` 默认给 12px 侧距，放进已有 `panelPadding` 的面板会让窄屏整体右移，必须显式 `EdgeInsets.zero`。
3. **选中项滚入**用 `getOffsetToReveal(0/1)` 判断是否被裁切，再居中；不能用 `ensureVisible(alignment: .5)` 无脑居中，否则每次换项轨道都会跳。
4. 首页页签高度变化走 `AnimatedSize`（220ms Miuix 弹簧曲线），resize 跨 700 时高度平滑过渡。

## 七、总结

TAB 体系从“三套手写 + 一套面板封装”收敛为“一个表现层组件 `AppTabStrip` + 两套密度”：宽屏（≥700）紧凑胶囊轨道（hover / 手型 / 滚轮 / 选中滚入），窄屏宽体页签（76–98 × 42、库内自动居中）；`AppTabBar` 保持面板总高 42 的上限不变量，固定 extent 宿主零改动；首页五处顶部预留收口到 `HomeChromeMetrics`（宽屏 120 / 窄屏 130），宽屏同时关闭鼠标拖动翻页。
