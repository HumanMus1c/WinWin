# 楼中楼「查看更多回复」重复加载修复复盘（2026-10-22）

> 任务来源：本次对话。用户实机反馈：视频评论点击「查看更多回复」时，**重复把已展示的第一批回复又加载一遍**，而不是接着加载剩余回复（列表出现重复条目、计数不推进）。
> 改动面：4 个文件（模型 1 / 网络层 1 / 视频详情页 1 / 番剧播放页 1）；快照基准 `9af0580`（改动前工作树 clean，基线即 HEAD）。

---

## 1. 现象

视频详情页与番剧播放页评论区的楼中楼，点击「查看更多回复 (n/rcount)」后：

- 列表里出现**与已展示内容完全相同的重复回复**；
- `已加载/总数` 计数不向 `rcount` 收敛；
- 按钮持续可点，每次点击都重复同一批数据。

即：点击并非「加载剩余回复」，而是「再取一遍第一页」。

## 2. 定因（含取证）

### 2.1 根因链

```
楼中楼接口 /x/v2/reply/reply 是「页码分页」(pn/ps)，响应只有 page{num,size,count}，无 cursor
  → 模型 ReplyMainData.fromJson 只读 json['cursor'] → 该接口 cursor 恒为 null
  → _loadSubReplies 用 response.cursor?.nextOffset 更新 _subNextOffset → 偏移恒为 null
  → 请求侧又用 pagination_str:{offset:null→''}（该接口忽略 offset）→ 每次都请求第 1 页
  → _subReplies[rpid].addAll(...) 无去重 → 第 1 页被反复追加 = 重复条目
  → _subEnd = cursor?.isEnd ?? replies.isEmpty → 只要非空恒为 false → 按钮永不消失
```

### 2.2 API 实测取证（curl 游客态，oid=2 / root=495059）

| 探测 | 结果 |
|---|---|
| `reply/reply` 响应顶层键 | `page, upper, replies, root, config, control` —— **无 `cursor`** |
| `page` 字段 | `{"num":1,"size":20,"count":1545}` —— 经典页码模型 |
| `pn=1` 首条 rpid | `164517433` |
| `pn=2` 首条 rpid | `907918983`（**变化 → `pn` 生效**） |
| `pagination_str={"offset":20}` | 仍返回 `num:1`（**offset 被忽略**） |
| `pn=78` / `pn=79` | 5 条 / 0 条 → 末页判据 `num*size >= count` |

对照：一级评论接口 `/x/v2/reply/main` 才是**游标分页**（`cursor.pagination_reply.next_offset`，实测 `CAEiAggC`）。楼中楼与一级评论**分页模型不同**，这正是原实现混淆之处。

### 2.3 影响面

- `lib/http/video.dart::replyReplyList` —— 用错分页参数；
- `lib/models/video/reply_item.dart::ReplyMainData` —— 只解析 `cursor`，缺 `page`；
- `lib/pages/video/detail_page.dart` 与 `lib/pages/bangumi/bangumi_player_page.dart` —— 同一份错误的翻页/去重逻辑被复制了两处；
- 因 `ps=20`，多数线程首屏一次取完且 `cursor` 为 null → 凡回复数 ≥3 的楼中楼评论都会触发。

## 3. 方案（保留原结构增量改）

1. `reply_item.dart`：新增 `ReplyPage{num,size,count}` 与 `ReplyMainData.page`（保留 `cursor` 供 `reply/main` 用）；`ReplyPage.isEnd(loadedOnThisPage)` 以 `num*size>=count` 判末页。
2. `http/video.dart::replyReplyList`：参数由 `nextOffset` 改为 `pn`（int，默认 1），仍带 `ps:20`，移除被忽略的 `pagination_str`。
3. `detail_page.dart`：`_subNextOffset` → `_subPage`（记录待请求页码）；`_loadSubReplies` 按 `pn` 翻页、用 `page.num/size/count` 判末页、追加时按 `rpid` 去重（`putIfAbsent` + `where`）。
4. `bangumi_player_page.dart`：同上同步修复。

## 5. 遗留与踩坑

- 番剧播放页与视频详情页的楼中楼逻辑是**复制粘贴**关系，本次两处同修；后续若抽公共 Widget/Controller 可消除此类重复。
- 楼中楼与一级评论分页模型不同（页码 vs 游标）是易踩坑点，已在 `replyReplyList` 与 `ReplyMainData.page` 处就地注释说明。
- 新增的按 `rpid` 去重是**防御性**措施：即便日后接口分页行为再变，也不会再出现重复条目。

## 6. 总结

根因是「用游标分页的字段去驱动一个页码分页的接口」——`reply/reply` 根本不返回 `cursor`，导致偏移恒为空、每次点击都从头取同一页并重复追加。修复按接口真实语义改为 `pn` 页码翻页 + `page` 末页判定，并加去重兜底，视频页与番剧页两处同步落地；全量 analyze 与 Debug/Release 双编译均通过，实机验证步骤见 §4。
