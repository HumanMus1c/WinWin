# 上游 PiliPlus 界面缩放实现调查（供 WinWin 参考）

> 日期：2026-10-22　｜　调查人：小通　｜　触发：CVO 要求「先调查上游 piliplus 是如何做界面缩放的」
> 上游仓库：`D:\Documents\GitHub\PiliPlus`（origin = HumanMus1c/PiliPlus，与 WinWin 同源），HEAD `65d5bf8fc`
> 关联：`docs/界面缩放方案A失效与回退复盘-2026-10-22.md`（WinWin 方案 A 失效）

## 一、结论先行

上游**完全不用 `Transform.scale`**。它在 **Flutter Binding 层**覆盖 `devicePixelRatio`（`ScaledWidgetsFlutterBinding`，adapted from `scaled_app`），并在 `App.builder` 内**同步缩放 `MediaQuery`**。因此**整棵树（含 `Overlay`、弹层、指针/手势坐标空间）天然一致**——这正是 WinWin 方案 A 缺失的一环。

## 二、上游三层实现

### 1) Binding 层：`ScaledWidgetsFlutterBinding`（`lib/common/widgets/scale_app.dart`）

- 继承 `WidgetsFlutterBinding`，**重写 `createViewConfigurationFor(RenderView)`**：

  ```dart
  final devicePixelRatio = view.devicePixelRatio;
  devicePixelRatioScaled = devicePixelRatio * _scaleFactor;
  final physicalConstraints = BoxConstraints.fromViewConstraints(view.physicalConstraints);
  return ViewConfiguration(
    physicalConstraints: physicalConstraints,
    logicalConstraints: physicalConstraints / devicePixelRatioScaled,  // 逻辑尺寸随缩放变化
    devicePixelRatio: devicePixelRatioScaled,                          // ← 真正改变渲染 DPR
  );
  ```

- `set scaleFactor(...)` → `handleMetricsChanged()` 触发布局重建（**热生效**）。
- **关键补充**：重写 `initInstances()`，把 `platformDispatcher.onPointerDataPacket` 指向自己的 `_handlePointerDataPacket`；指针数据经 `PointerEventConverter.expand(packet.data, _devicePixelRatioForView)` 转换，其中 `_devicePixelRatioForView(_) => devicePixelRatioScaled`。
  ⇒ **命中测试 / 手势坐标与缩放后的 DPR 一致**（否则 `GestureBinding` 会用未缩放的 `implicitView.devicePixelRatio` 计算，导致点击错位）。
- 提供 `ScaledWidgetsFlutterBinding.ensureInitialized({scaleFactor})`。

### 2) 启动：`lib/main.dart`

```dart
ScaledWidgetsFlutterBinding.ensureInitialized();          // :95
...
ScaledWidgetsFlutterBinding.instance.scaleFactor = Pref.uiScale;  // :105
```

### 3) App.builder 内同步 `MediaQuery`：`lib/main.dart:_builder`

```dart
final uiScale = Pref.uiScale;
final mediaQuery = MediaQuery.of(context);
final textScaler = TextScaler.linear(Pref.defaultTextScale);
if (uiScale != 1.0) {
  child = MediaQuery(
    data: mediaQuery.copyWith(
      textScaler: textScaler,
      size:          mediaQuery.size        / uiScale,
      padding:       tmpPadding ?? mediaQuery.padding    / uiScale,
      viewInsets:    mediaQuery.viewInsets   / uiScale,
      viewPadding:   tmpPadding ?? mediaQuery.viewPadding / uiScale,
      devicePixelRatio: mediaQuery.devicePixelRatio * uiScale,   // 与 binding 保持一致
    ),
    child: child!,
  );
} else {
  child = MediaQuery(data: mediaQuery.copyWith(textScaler: textScaler, padding: tmpPadding, viewPadding: tmpPadding), child: child!);
}
```

> 即：**binding 改实际渲染 DPR**，**builder 改 `MediaQuery` 观感**，二者同比例（`size/uiScale` 且 `dpr*uiScale`）协同，`Overlay`/弹层/自绘控件读到的 `MediaQuery` 与真实渲染空间**完全一致**。

## 三、设置项与存储（`style_settings.dart` / `storage_pref.dart` / `storage_key.dart`）

- 「界面缩放」：`NormalModel` → `_showUiScaleDialog`，**范围 0.5–2.0**，`Slider`（`secondaryTrackValue: 1.0`，`divisions=(2.0-0.5)*20`）+ 可输入文本框，`toPrecision(2)` 取值。
- 「字体大小」：跳转独立页 `/fontSetting`（`lib/pages/setting/pages/font_setting.dart`）。
- 存储：`uiScale`(默认 1.0)、`defaultTextScale`(默认 1.0)；键名 `SettingBoxKey.uiScale='uiScale'`、`defaultTextScale='textScale'`。

## 四、与 WinWin 方案 A（已回退）的对比

| 维度 | 上游 PiliPlus | WinWin 方案 A（已回退） |
|------|---------------|--------------------------|
| 缩放手段 | Binding 层改 **真实 `devicePixelRatio`** | `Transform.scale`（**仅改绘制**） |
| 逻辑尺寸来源 | `physical / (dpr·scale)`（binding 统一） | `MediaQuery.size` 覆盖 + `Transform` 放大 |
| 指针/命中测试 | **同步缩放**（`onPointerDataPacket` 覆写） | 未处理 → 与弹层坐标空间错配 |
| Overlay / 弹层 | 与内容**同一空间**（MediaQuery+binding 一致） | `localToGlobal` 含缩放 vs 窗口空间 → **偏移** |
| 窗口控件/底部入口 | 正常 | 漂出窗口 / 被裁 |
| 热生效 | 是（`handleMetricsChanged`） | 是（但坐标错乱） |

**根因定性**：WinWin 方案 A 的失败不在"覆盖被吞"，而在**只缩放绘制、未缩放坐标空间**；上游从 **binding 层 DPR + 指针转换层**根治了该问题。

## 五、WinWin 移植要点（下一步建议，待 CVO 拍板后实施）

1. 新增 `ScaledWidgetsFlutterBinding`（移植 `scale_app.dart`，去掉 `scaled_app` 三方依赖，自实现核心）。
2. `main.dart` 启动改用 `ScaledWidgetsFlutterBinding.ensureInitialized()`（替换 `WidgetsFlutterBinding.ensureInitialized()`，`lib/main.dart:56`）。
3. 在 `AppShell`（`WidgetsApp.builder` 内）按上游方式以 `MediaQuery.copyWith(...)` 同步 `size/padding/viewInsets/viewPadding/devicePixelRatio`（**移除 `Transform`**）；`textScaler` 仍走 `Pref.defaultTextScale`。
4. 恢复设置项「界面缩放」（范围建议对齐上游 0.5–2.0），并接 `ScaledWidgetsFlutterBinding.instance.scaleFactor` 实现**热生效**。
5. 验证重点：弹层锚定触发点、窗口控件不漂移、底部入口可见、各 DPI 下指针命中准确。

## 六、风险与注意

- `ensureInitialized` 必须**在任何 binding 使用之前**、`runApp` 之前调用（当前 WinWin `main.dart:56` 即该位）。
- 指针 DPvoice 覆写需与 `GestureBinding` 一致；升级 Flutter SDK 时需复核 `PointerEventConverter.expand` / `ViewConfiguration` 签名（上游代码即依此适配）。
- 桌面端 `padding/viewPadding` 用 `tmpPadding` 统一，勿叠加系统 padding。
- 与 `window_manager`（全屏/窗口尺寸）无冲突，因为缩放只改 Flutter 内部 DPR，不动物理窗口。

## 七、总结

上游 PiliPlus 的界面缩放 = **Binding 层 `devicePixelRatio * scaleFactor`（真实渲染缩放）+ 指针数据同 DPR 转换 + builder 内 `MediaQuery` 同比例同步**。它从坐标空间层面根治了 WinWin 方案 A 的"弹层偏移 / 控件漂移"结构性问题，且天然支持热生效。WinWin 若要恢复「界面缩放」，**应移植此 scaled-binding 方案，而非 `Transform`**。
