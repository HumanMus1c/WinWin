## 1. 需求与定因

为 README 补 5 张「程序演示模式」展示图：**根页面 / 播放页 / 用户空间 / 番剧页 / 设置页**。

口径（用户定，含一次修正）：

- 原型：每页产出**一张**图、浅色在左深色在右；尺寸 1600×900、每半 800×900。
- **修正后（本版实际口径）**：
  1. 截图分辨率统一 **1920×1080**；
  2. 使用**宽屏模式**窗口（宽 ≥ 900 → 左侧导航栏布局）；
  3. 拼图法：取**浅色截图的左半** + **深色截图的右半**，左右拼接为**一张 1920×1080**。
- 截图须为**演示模式**下的干净画面（云端内容与账号标识已换成占位，无第三方素材）。

## 2. 方案与关键决策

演示模式（`设置 → 其它设置 → 演示模式`）本就是为「README 干净截图」而建（见 `docs/演示模式复盘-2026-10-07.md`），开关持久化在 Hive `setting` box 的 `demoMode`。

**决策：采用「应用内临时巡航 + 内部截帧」，而非桌面点击 / 外置截屏。**

原因：

- 单实例互斥体（`windows/runner/main.cpp`，`Local\winwin-single-instance-v1`）要求先关闭在跑实例才能起受控实例；
- 桌面截屏依赖窗口几何 + 点击坐标，且窗口被应用自身 `WindowStateController` 反复施加保存尺寸 → 尺寸不稳、盲点不可靠；
- 应用内 `RenderRepaintBoundary.toImage()` 出图**确定性、不点击、不依赖窗口尺寸/DPI**，且可写进度文件自证。

**尺寸精确化（两处关键坑）**：

1. 直接把 `SizedBox(1920,1080)` 放根，会被父级**紧约束**覆盖（`BoxConstraints.enforce` 取 `max(min, incoming.min)`）→ 实际得到窗口逻辑尺寸（曾实测 656×744 / 1073×969）。
2. 用 `Align`（松约束）仍会被窗口尺寸**上界**压制（窗口逻辑高度不足 1080 时被裁剪）。
   → 最终用 **`Align → UnconstrainedBox → RepaintBoundary → SizedBox(1920×1080)`**：`UnconstrainedBox` 施加**无界约束**，使 `SizedBox` 精确生效、完全不受窗口大小影响；`RepaintBoundary` 尺寸即 1920×1080，`toImage(pixelRatio: 1.0)` 得到精确 1920×1080。1920 宽 ≥ 900 断点 → 自动走**宽屏（左侧导航栏）**布局。

## 5. 复现步骤（如需重出图）

1. 关闭在跑实例（按 **PID**，勿按镜像名——按名会命中宿主保护）。
2. 预置设置（Hive 路径 `%APPDATA%\com.winwin\winwin\hive`）：

3. 打临时巡航补丁（`main.dart` 还原前的那版；核心如下），`flutter build windows --release`。

   ```dart

   Align(
     alignment: Alignment.topLeft,
     child: UnconstrainedBox(
       alignment: Alignment.topLeft,
       child: RepaintBoundary(
         key: _shotBoundaryKey,
         child: SizedBox(width: 1920, height: 1080, child: WinWinApp(...)),
       ),
     ),
   )
   // _runAutoShot()：等首帧 → 对每个主题/每页 push→截帧→pop
   //   截帧：_shotBoundaryKey.currentContext!.findRenderObject() as RenderRepaintBoundary
   //         → toImage(pixelRatio: 1.0) → toByteData(png) → 落盘
   //   页面：VideoDetailPage(bvid:...) / MemberSpacePage(mid:...) / PgcPage() / SettingPage()
   ```

4. 启动（继承环境变量）：

   ```powershell
   $env:WINWIN_AUTOSHOT='1'; Start-Process build\windows\x64\runner\Release\winwin.exe
   ```

   进度与异常写入 `assets/screenshots/_raw/shot_progress.txt`（`OK <name> WxH` / `ERR` / `FATAL`）。

5. 拼接（Pillow，浅色左半 + 深色右半）：

   ```python
   from PIL import Image
   for key, out in [('home','01-home.png'),('player','02-player.png'),
                    ('space','03-space.png'),('bangumi','04-bangumi.png'),
                    ('setting','05-setting.png')]:
       l = Image.open(f'.../_raw/light_{key}.png').convert('RGB')
       d = Image.open(f'.../_raw/dark_{key}.png').convert('RGB')
       w, h = l.size; half = w // 2
       c = Image.new('RGB', (w, h))
       c.paste(l.crop((0, 0, half, h)), (0, 0))      # 浅色：左半
       c.paste(d.crop((half, 0, w, h)), (half, 0))   # 深色：右半
       c.save(f'assets/screenshots/{out}')
   ```

6. **还原 `lib/main.dart`**、还原用户原设置、清理临时件。

## 9. 追加（2026-10-26）：演示区改为表格网格 + 烘焙卡片阴影

### 9.1 现象与需求

上一版 README 演示区是散排的 `<p align="center">`：第 1 张通栏、其余 4 张按 `<img width="45%">` 两两换行，仅靠 `&nbsp;` 撑间距——**不成网格**（左右列不对齐、缩略图大小依赖文本流），且**无卡片感**，每张图只有一行汇总式说明（「其余页面：播放页 · 用户空间 · 番剧页 · 设置页」），没有逐图标题。

用户要求：按**可见网格的表格**排列、图片加**悬浮阴影**、**每张图带独立描述标题**。

### 9.2 定因（关键约束）

GitHub 渲染 README 时会**剥离 `style` 属性等 CSS**（markup 消毒走 `Sanitize::Config::RELAXED` 白名单，属性级 `style` 不在白名单内），因此 `:hover { box-shadow }` 这类纯 CSS 悬浮阴影**在 GitHub 网页端必然失效**。也就是说「悬浮阴影」只有两条可行路径：烘焙进图片（静态），或接受它在网页端退化为无阴影。

### 9.3 方案（经用户选择定稿）

1. **网格**：用原生 `<table>`（第 1 行 `colspan="2"` 放首页大图，其后两行各 2 格），单元格 `width="50%"` + `align="center" valign="top"`，图用 `width="100%"` 填满单元格 → 天然对齐、左右两列等宽。GitHub 的表格样式会给 `td` 加 1px 边框，正好形成**可见网格**。
2. **阴影**：采纳用户的「仅烘焙静态阴影」——用 Pillow 在每张图外扩留白并按图宽等比烘焙柔和投影，任何渲染环境（GitHub 亮/暗主题、本地预览器、终端网页）都能看到卡片悬浮感。
3. **逐图标题**：每个单元格 `<img>` 后接 `<br>` + `<sub><b>页面名</b>：要素说明</sub>`，替代原来的汇总式单行说明。

### 9.4 改动面

- `README.md`：`## 🖼️ 程序演示模式截图` 区（原 35~48 行）整段替换为表格网格版块；说明区补两行（浅/深对照口径 + 阴影为烘焙静态实现的原因）。
- `assets/screenshots/*.png`（5 张）：原地重写为「外扩留白 + 烘焙阴影」版本，视觉内容未改。
  - 生成脚本 `scratch/screenshot-2026-10-26/bake_shadow.py`（gitignored 不入库；原图备份在同目录 `originals/`）。
  - 参数：扩散半径 = 图宽 × 1.5%，留白 = 扩散半径 × 2.8，核心不透明度 0.34，高斯模糊 σ = 扩散半径 × 0.6，垂直下移 = 扩散半径 × 0.35（模拟顶部光源），圆角 = 图短边 × 0.8%（仅用于阴影轮廓，不裁切画面内容）。
- 产物尺寸：`01-home.png` 1920×1080 → **2082×1242**；其余 4 张 480×270 → **520×310**。

### 9.5 验证

- 无 Dart / Flutter 代码改动，且 `assets/screenshots/` **未列入 `pubspec.yaml` 的 assets**（应用内只打包 `app_icon.png` / `flutter_logo.png`）→ 本轮**不涉及构建**，无需跑 analyze 与双编译。
- 图片核验：5 张均为「留白对称、阴影柔和无硬边、画面内容零裁切」，见脚本输出的新尺寸与体积。
- README 结构核验：表格行/单元格标签闭合正确，首页行 `colspan="2"`、其余两行 2 格，每格均带独立 `<sub>` 标题。
- GitHub 实际渲染效果（表格边框、暗色主题下阴影可见度）需用户在仓库网页端确认。

**提交与回滚**：改动前工作区干净，基准提交 `421cdaa`；如需整轮回滚执行 `git reset --hard 421cdaa`（会一并撤销本轮的 README 与 5 张图重写）。

### 9.6 踩坑

1. **GitHub 剥 CSS**：最初想用 `style="transition; box-shadow"` 做悬浮效果，确认网页端会被消毒剥离；改为烘焙静态阴影并把原因写进 README 注释，避免后人误以为漏做。
2. **阴影重烘焙不可叠加**：脚本首版直接读取 `assets/screenshots/*.png` 再写回，第二次调参重跑会把旧阴影当原图再烤一遍（阴影发虚、留白翻倍）→ 改为**固定从 `originals/` 备份烘焙到目标路径**，保证可重复调参。
3. **首版阴影偏「光晕」**：σ = 0.85×扩散半径、α 0.28 时边缘过散，卡片感弱；收紧到 σ = 0.6、α 0.34 后轮廓清晰且仍柔和。
4. **README 行尾含 NBSP**：旧版图片行尾部是「空格 + 3×U+00A0」，用整段字符串替换时不易精确匹配；改用行号定位（Python 行级替换）并保留 LF 行尾、无 BOM。

### 9.7 总结

演示区从「散排图片 + 汇总说明」改为「原生表格网格 + 逐图标题 + 烘焙卡片阴影」：网格由 `td` 边框与等宽单元格保证对齐，阴影因 GitHub 禁止 CSS 而改为烘焙进 PNG（任何渲染环境一致），逐图标题替代原来的汇总单行。仅动 README 与 5 张 PNG，不涉及代码与构建。
