# B6 实机反馈 #5 修正复盘：刷新指示器位置口径 — 2026-10-10

> 承接 `B6实机反馈修复轮-2026-10-10.md`（四项）；本片为第 5 项反馈的
> 口径确认与修正。

## 1. 现象描述

用户复测后反馈：**首页与消息中心的下拉刷新指示器应该在"可滚动区域的
顶部"开始出现**；且首页指示器**仍被"搜索框 + 二级分类器"组合控件遮挡**
（上一轮给首页设了 `edgeOffset: 88`，组合控件实际总高约 100–116，
故指示器仍在其下缘后方）。

## 2. 根因

- 「可滚动区域的顶部」按用户语义 = **可见滚动区域的顶部**（浮动组合控件
  下方、内容真正开始处），页内既有留白口径为 120（`SliverPadding(top: 120)`）；
  上一轮 `edgeOffset: 88` 低于组合控件真实下缘 → 仍遮挡；
- 上轮同时把**消息中心/会话列表的刷新上提为整页级**（指示器浮到入口行
  之上），与"在可滚动区域顶部出现"相悖 → 需回退为列表级。

## 3. 修复方案

- 首页五个 Tab 共享同一浮动组合控件（搜索框 38 + 间距 6 + 分类行 32 +
  内外边距 ≈ 100–116），页内内容留白 120：
  - `hot` / `rcmd` / `follow`：`RefreshIndicator` 增加
    `edgeOffset: 120` + `displacement: 12` —— 指示器在可见滚动区域顶部
    （组合控件下缘之下）开始出现，不再被遮挡；
  - `pgc` / `live` 的刷新指示器包在 112 留白之后、天然位于组合控件下方，
    无需调整。
- **消息中心（whisper）与会话列表页回退**：恢复为包裹列表自身的
  `AppRefreshIndicator` / `RefreshIndicator`（指示器位于列表顶部；
  即"可滚动区域顶部"），撤销上轮的整页级上提。

## 5. 遗留与踩坑

- 踩坑：`edgeOffset` 取值须对齐**浮动组合控件的真实下缘**（含内外边距），
  凭"52+36"的估数（88）会仍差 ~30px 被遮；口径上以页面内容留白
  （120/112）为准更稳。

## 6. 总结

指示器位置口径修正落地：首页三 Tab 指示器下移出自组合控件下方、
消息中心/会话列表回退到列表顶部；分析、测试、双分支构建全绿。
