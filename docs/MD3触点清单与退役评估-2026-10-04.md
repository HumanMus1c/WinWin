## 二、退役分层（按替换成本从低到高）

1. **L1 已有双轨、仅冻结**（miuix 分支已由 flutter_miuix 驱动）：
   组件 M3 分支（AppComponents/frosted_bottom_bar/simple_scaffold）、
   菜单 M3 分支（会话/播放器×3/live_room×3/用户空间/登录/视频卡片 showMenu）、
   面板 M3 分支（弹幕样式/表情/字体弹窗）——**脱离动作=删 else 分支**，风险低。
2. **L2 Token 与主题**（38+13 触点）：`AppShapes/AppChrome/AppTypography` 双轨、
   `AppTheme.light/darkFor(style)`——需先将 miuix 分支的取值固化（自研件当前
   消费 Token），再收敛为单轨。
3. **L3 图标映射**（55 触点，`app_icons.dart`）：`*Of(style)` 分发在 miuix 收编后
   可直接删 M3 分支（保留 AppIcons API 签名与否需单独决策——影响约 50 调用点）。
4. **L4 枚举与入口**（`UiStyle.material3` 枚举值、设置页风格切换、`UiStyleScope`
   双态、测试双态基线）：**最后执行**；切换入口需保留至用户拍板移除节点。

## 三、5e：MD3-only 控件补全清单（纪律第 1 步的存量盘点）

- 现状：核心组件/弹层/面板均已双轨（本轮及此前各阶段完成）；
- 待补候选（须逐项核对）：`showMenu` 特例的 M3-only 使用点是否仍有非冻结调用、
  个别 M3 原生控件直用处（Chip/Slider/Switch/Checkbox 等）在 miuix 分支下的
  Miuix 对应物——盘点后按"先补 flutter_miuix → 测试 → 再脱离"顺序滚动执行。

## 四、工作量与风险

- L1（删分支）为主工作量，估计 1–2 批即可完成；L2/L3 为中等重构（Token 固化 +
  图标映射收敛）；L4 影响枚举/入口/测试基线，属**重大重构，单独立项**。
- 主要风险：M3 冻结分支删除期仍需保证**双风格切换可用**（用户在移除节点前仍可
  切换）；测试基线双重断言需同步改造。

## 五、建议推进顺序（待用户拍板）

1. 先做 5c 玻璃 A/B（结论已具备：loaded=6 error=none）→ 决定玻璃启用范围；
2. 再执行 L1（逐文件删 else 分支，每步流水线）；
3. 然后 L2/L3（Token 固化与图标收敛）；
4. 最后 L4 立项（移除 `UiStyle.material3` 全链路）。
