# 播放器音质切换替换均衡控制（2026-11-14）

## 一、现象与需求

1. 播放器控制条的音频菜单里是「智能响度均衡 (loudnorm) / 动态压缩 (dynaudnorm) / 禁用」三项均衡设置。
2. 需求：将该控制项替换为**音质切换**，尤其是部分视频真实下发的【杜比音频】高清音轨，交互与档位口径对齐上游 PiliPlus 的「选择音质」。
3. 现状缺口：
   - `Pref.defaultAudioQa` 设置项早已存在，但播放链路从未读取，设置不生效；
   - `Dash` 只解析 `audio` 与 `dolby.audio`，未解析 `flac.audio`（Hi-Res 无损），且选流策略硬编码「Hi-Res > 杜比 > 最高码率」，用户无法干预；
   - 音频菜单被响度均衡三项占用，没有音质入口。

## 二、定因

上游 PiliPlus 的音质控制由三部分构成：

1. **模型合并**（`models/video/play/url.dart`）：`Dash.fromJson` 把 `flac.audio`（单对象）、`dolby.audio`（列表）、`audio`（列表）合并进同一候选音轨列表。
2. **档位选流**（`utils/video_utils.dart`）：`findTargetAudio` 按 `AudioQuality.rank` 取「不超过偏好档位的最高可用档」，若全部高于偏好则回退最低档；默认偏好 30251（Hi-Res）。
3. **控制入口**（`widgets/header_control.dart` -> `showSetAudioQa`）：列出当前视频真实下发的全部音质（含杜比全景声 / Hi-Res），点击后更新 `cacheAudioQa` 并重建播放器，同时持久化 `defaultAudioQa`。

WinWin 侧对应缺口即第二节第 3 条所列：模型缺 `flac.audio`、选流无视偏好、UI 无入口。

## 三、方案

### 1. 音质档位模型（[audio_quality.dart](file:///d:/Documents/GitHub/WinWin/lib/models/common/audio_quality.dart)）

移植 PiliPlus `AudioQuality`：

| code | 档位 | rank |
|---|---|---|
| 30251 | Hi-Res 无损 | 60 |
| 30255 / 30250 | 杜比全景声 | 50 |
| 30280 | 192K | 40 |
| 30232 | 132K | 30 |
| 30216 | 64K | 20 |

`badgeLabel` 提供控制条短徽标（`Hi-Res` / `杜比`），普通 AAC 返回 null。

### 2. 播放地址模型（[play_url.dart](file:///d:/Documents/GitHub/WinWin/lib/models/video/play_url.dart)）

- `Dash.flacAudio` 解析 `dash.flac.audio`（单对象，Hi-Res 无损）；
- `DashAudio.codecs` 解析编解码标识（`ec-3` / `flac` / `mp4a.40.2`），用于菜单副标题；
- `Dash.allAudios` = flac + dolby + audio，过滤无直链、按 id 去重、按档位/带宽降序，作为唯一候选列表。

### 3. 选流策略（[stream_selection_policy.dart](file:///d:/Documents/GitHub/WinWin/lib/core/policy/stream_selection_policy.dart)）

- `selectBestAudio` 改为按 rank 档位选择（对齐 PiliPlus `findTargetMedia`）；
- `selectStreams` 新增 `preferredAudioQuality`，从 `dash.allAudios` 选轨；
- `identifySpecialAudio` 按 id 识别杜比（30250/30255）与 Hi-Res（30251），供调试日志。

默认偏好 30251，行为与旧逻辑一致（有 Hi-Res 选 Hi-Res，否则杜比，再否则最高码率），但用户显式选低档位时不再抢占高码率。

### 4. 播放器控制器（[player_controller.dart](file:///d:/Documents/GitHub/WinWin/lib/pages/video/player_controller.dart)）

- `_openWithQuality` 调 `selectStreams(preferredAudioQuality: Pref.defaultAudioQa)`，并记录实际选中的 `_currentAudioQa`；
- 新增 `audioQualityOptions`（当前视频真实可用音质 + 编码标签）、`currentAudioQualityCode`、`switchAudioQuality(code)`：
  - 复用同清晰度 playurl（10 分钟内缓存命中则不重新请求），保留当前进度与播放/暂停意图；
  - 切换前写入 `Pref.defaultAudioQa`，与 PiliPlus 一致；
- HLS 单源清单的 `codecs` 跟随真实音轨（EAC3/FLAC），避免按 AAC 初始化失败；
- 删除播放器内已无入口的 `setAudioNormalize` / `toggleAudioNormalize`；设置页的响度均衡与静态增益后端逻辑保留。

### 5. 播放器控制条（[player_panel.dart](file:///d:/Documents/GitHub/WinWin/lib/pages/video/player_panel.dart)）

- 音频菜单第二组由均衡三项替换为音质列表：`杜比全景声 · EAC3`、`Hi-Res 无损 · FLAC`、`192K · AAC` 等，仅列出当前视频真实下发的档位，当前档位打勾；
- 控制条徽标由「均衡」改为「杜比」/「Hi-Res」，普通 AAC 不显示徽标；
- 无 DASH 音轨（如 durl 兜底）时保留编码标签，不弹空菜单。

### 6. 演示模式（[demo_player_chrome.dart](file:///d:/Documents/GitHub/WinWin/lib/common/widgets/demo_player_chrome.dart)）

同步为同一组音质选项与徽标，本地状态、不写 `Pref`，与正常模式布局 1:1。

## 六、遗留与踩坑

1. 音质列表来自当前 playurl 响应：未登录/非大会员时服务端不下发杜比/Hi-Res，菜单只显示普通档位（与 PiliPlus 一致）。
2. 切换音质走同清晰度重载（缓存命中则不请求），有短暂加载态；缓存过期时会重新拉 playurl。
3. 设置页「默认音质」仍使用原有文案（ATMOS 全景声 / 杜比环绕声等），与播放器菜单「杜比全景声」指向同一批 code，后续可统一文案。
4. 响度均衡保留在设置页；播放器内不再提供快捷切换。
5. 杜比 Atmos 的 JOC 高度声道是否被 mdk 完整解码取决于 FFmpeg 构建；基础 5.1 核心可正常解码。

## 七、总结

播放器音频菜单的响度均衡三项已替换为音质切换：模型补齐 `flac.audio` 并合并 Hi-Res/杜比/普通音轨，选流改为按 `defaultAudioQa` 档位选择，菜单仅展示当前视频真实可用档位，切换时保留进度并持久化偏好；演示模式同步。静态分析零问题，Windows debug/release 双编译通过，待实机验证杜比音轨切换。
