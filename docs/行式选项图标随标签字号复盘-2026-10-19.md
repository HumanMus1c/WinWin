# 行式选项「图标随标签字号」统一复盘 —— 图标不该只吃名义字号

- 日期：2026-10-19
- 快照基准：`refs/snapshots/latest` = `68c6e51`（改动前 HEAD，worktree clean；回滚见第五节）
- 触发：CVO 实机截图 `uploads/1792410104342-81db2369.png`，指令「为所有的 icon lable 的组合行的选项，将它们的 icon 大小对齐 lable 文本文字大小」

## 一、现象

截图为**暗色主题 373×613** 的面板。本会话**无 VQA / OCR 工具**（`read_file` 对 png 直接报错；连接器无可用 OCR），改用 Pillow/numpy 做**像素剖面 + 逐字模板匹配**（模板 = `msyh.ttc` 渲染、候选集 = `git grep` 出 lib/ 全部中文字符 665 字、24×24 归一化比对）：

| 观测 | 值 |
|---|---|
| 面板内容 | cols x42–371、rows y0–568；y68–69 近全宽分隔线（面板标题分隔） |
| 标题行 y28–51 | 4 汉字、步进 ≈23.6px ⇒ 识别「更多操作」 |
| 条目 | item2「复制视频链接」、item3「稍后再看」、item1 起于「复制…」 |
| 墨迹带 | 8 个 = 1 标题 + **7 条**（第 1/4/7 条为两行，单行行距 ≈59px） |
| 单行标签 | 字形步进 ≈24 设备 px、墨迹高 ≈23 |
| 前导图标 | 墨迹宽 ≈**15–16** 设备 px，列 x≈42–56；文本起 x≈72 |

**判位**：7 项与 `buildVideoCardActions()`（`lib/common/widgets/video_card/video_context_menu.dart`）逐项吻合，动态后缀的 1/4/7 项正好对应三处换行 ⇒ 该面板 = **视频卡片「更多操作」右键菜单**。现象即：**图标墨迹明显小于标签字高**（≈16 vs ≈23 设备 px）。

## 二、定因

根因链（全部有代码依据，且经实机数值反证）：

1. `AppTextStyles`（`lib/core/shell/app_theme_host.dart`）**只带 color/decoration，不带 fontSize** ⇒ 菜单行 `rowTextStyle.fontSize` 恒 `null`。
2. `miuix_context_menu.dart` / `miuix_popup_menu.dart` 原写 `iconSize = rowTextStyle.fontSize ?? 14` ⇒ 图标名义尺寸**恒 14**，且**不过 TextScaler**。
3. 行标签经 `Text(style: rowTextStyle.copyWith(...))` 渲染，fontSize 仍 `null` ⇒ 继承氛围 `DefaultTextStyle`，其字号 = **14**（`lib/core/shell/app_shell.dart:139` 根 `DefaultTextStyle(fontSize: 14, height: 1.4)`）。
4. 本机 **Windows 系统文本缩放 = 140%**（注册表 `HKCU\Software\Microsoft\Accessibility\TextScaleFactor = 140`）⇒ 标签**实际**渲染 14×1.4 = **19.6** logical px，图标仍 14 ⇒ **标签比图标大 1.4 倍**。
5. 反证吻合：标签步进 ≈24 设备 px = 14 名义 × 1.4 文本缩放 × 1.25 DPR ⇒ 24.5 ✓；图标墨迹 15–16 ≈ 14×1.25 = 17.5 再内缩 ✓。

⇒ 旧注释「图标与选项文本同大小」在 **TextScaler ≠ 1** 时失效。次级失配（同类）：设置行 `IconThemeData(size: 22)` 硬编码，与标签字号（Miuix `headline1 = 17`）脱钩。

## 三、方案

**一条口径、一处定义**（P4）：在 `lib/theme/app_icons.dart` 新增

```dart
/// 「图标 + 标签」组合行里的图标尺寸：与行标签文本**实际渲染**字号同口径。
double appRowIconSize(BuildContext context, [double? labelFontSize]) {
  final nominal =
      labelFontSize ?? MiuixTheme.of(context).textStyles.headline1.fontSize ?? 17;
  return MediaQuery.textScalerOf(context).scale(nominal);
}
```

- 缺省（不传 `labelFontSize`）即 **Miuix 行式选项标准标题字号 = headline1(17)**，故「图标 + 标题」行不必各自复述口径；
- 标签字号自成一体的行（菜单行取 `rowTextStyle`/氛围、split 设置行取 `titleStyle`、条款行取 `titleSmall`）显式传名义字号。

**命中点（9 文件 12 处）**：

| 文件 | 处 | 改动 |
|---|:---:|---|
| `lib/theme/app_icons.dart` | 1 | 新增 `appRowIconSize`（唯一口径） |
| `lib/common/widgets/miuix_context_menu.dart` | 2 | 面板菜单 / 文本选择菜单：`iconSize = appRowIconSize(context, 行标签名义字号)` |
| `lib/common/widgets/miuix_popup_menu.dart` | 1 | `_buildRows` leading 同上 |
| `lib/pages/setting/widgets/normal_item.dart` | 1 | `size: 22` → `appRowIconSize(context)` |

**未纳入及原因（据实声明，避免被理解为遗漏）**：
- **按钮内的 icon+label**（`MiuixButton(child: Row(AppIcon(size:16), Text))`，如 `video_context_menu.dart:381/415/513`、`bangumi_detail_page`、`bangumi_player_page`、`download_page`、`member_space_page`）：其「图标+文字」是**按钮内容整体**、标签字号由按钮自身口径决定，不是「行式选项的前导图标」——改它属按钮级决定，本轮不动。
- **非图标的前导**：搜索热榜行的序号 `SizedBox(width:28, Text('1'))`（前导是文字，非图标）。
- **纯图标控件 / 装饰性图标**：`whisper/view.dart:336` 圆底按钮、`app_empty_state`、`profile_horizontal_section`、`app_chip` 删除图标、搜索框 prefix/suffix、`miuix_overlay_panel` 面板标题图标（16，标题非行选项）、菜单选中勾（18，状态指示）。
- 有意不动：选中勾、分隔、几何（仅改图标尺寸，不动行高/间距/命中区）。

## 遗留与踩坑

- **图标尺寸是「规则后果」不是「拍脑袋数值」**：设置行/条款行图标由硬编码 `22`/`20` 改为「行标题名义字号 × TextScaler」。在本机 140% 下设置行 22 → 23.8（微增），若系统缩放为 100% 则变为 17（**变小**）。这是「图标=标签字号」的直接后果；若用户希望保留 100% 下的 22，需改口径（例如给行式图标设下限）。
- **未纳入按钮内 icon+label**（见第三节清单）：若 CVO 认为「组合行」也应含按钮内容，下一轮按同一 `appRowIconSize` 口径补（其标签字号需先确认由谁定义：`MiuixButton` 的默认文本样式）。
- **看不清图（沿用本轮硬约束）**：无 VQA/OCR 工具 ⇒ 面板身份靠「7 项逐项吻合 + 三处换行动态后缀 + 步进/DPI 反算」三源交叉确认；未做「改动后截图 vs 原截图」逐像素回归（需实机截图）。
- **`appRowIconSize` 的缺省值耦合 Miuix 行标题**：若后续 `MiuixBasicComponent` 换字号（上游 1.3.0 → 更新），缺省自动跟随；但显式传字号的行（菜单行/split 行/条款行）不会跟随，需留意。
- **环境坑（沿用）**：`flutter build` 须注入 6 个环境变量；`git grep` 可用而 `grep` 工具因缺 `rg` 不可用；`edit_file` 前必须 `read_file`（本轮在 `app_components.dart` 上踩到）；`flutter_miuix` 受限 `show` import 的文件取不到 `MiuixTheme`（本轮首跑 analyze 踩到，已用缺省参数化解）。
- **未跑 `flutter test`**（环境需补齐 `LOCALAPPDATA` 等，且本机测试宿主历史性崩溃；以静态分析 + 双编译替代）。

## 总结

用户报的是「图标比选项文字小」这一个观感问题，根因却不是某处数值写错，而是**图标与标签各自走了一条字号通道**：标签的字号在绘制时被 `TextScaler` 放大（本机 140%），图标却只吃**名义**字号（且菜单壳连名义字号都没有，硬兜底 14）。两边口径一拆，差 1.4 倍，越放大越明显。本轮没有逐处调数值，而是把「**行式选项图标 = 该行标签名义字号经 TextScaler 换算**」定成**一条口径、一处函数**，再把全库「图标 + 标签的行式选项」按实际渲染路径拉齐（菜单行、设置行、列表行、搜索建议行、图片操作行、条款行，共 9 文件 12 处）。`dart analyze` 0/0、Debug 39.8s / Release 70.1s 双 √，可一键回到 `68c6e51`。
