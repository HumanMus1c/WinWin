# Communication preferences

- Commit messages follow `[type](scope): 中文简述` (e.g., `[refactor](player-ui): ...`, `[docs](player-ui): ...`) with a bullet-pointed Chinese body describing the change and a `Co-authored-by:` trailer. Confidence: 0.55
- Communicates in Chinese, with a concise summary at the end of a completed task (what was done / verification results / commits & rollback / what the user should verify). Confidence: 0.5
- Before making a repo public, expects the project docs to give thorough provenance for what the project *directly* derives from: every upstream repository it references or ports from must be explicitly named, linked and thanked (plus the libraries in use), and he weights the README so that this attribution/credits section is the bulk of it while the project's own differences from upstream and its pros/cons are deliberately the smaller part. The scope is the *direct* bases (PiliPlus, BiliPai), not the full ancestry chain: he had the README's "上游的上游（一并致敬）" section and every transitive reference removed (including the license table's PiliPala / PiliPalaX rows). Confidence: 0.55
- Public-facing docs stay understated about the project's own merits: he had the README's self-praising "优点 / advantages" section deleted outright (keeping only the "不足与局限" section) rather than merely trimmed. Confidence: 0.45
- In legally sensitive public-facing wording he prefers indirection over explicit statements: the GitHub About description must not declare outright that the project is a third-party bilibili client, but instead use bilibili's internet nicknames/黑话 (小破站, 阿b, 小电视, 弹幕, 一键三连, 投币充电, 大会员, 干杯 etc.) so that only deep internet users can tell what it is — and he expects the agent to research those aliases from the wider web rather than reuse a stock phrasing. Confidence: 0.55
- Expects the project's stated identity/provenance in public docs to match its *current* reality, verified against primary evidence (current code, the in-app "关于" page, commit history), not the framing inherited from early commits: when the README plan called the project "BiliPai 的 Windows 移植" he corrected it to "mainly derived from PiliPlus — a Windows desktop branch that swapped the player core and has kept reworking the visual design", demoting BiliPai to "strategy/interaction logic port + early visual reference". Stale self-descriptions that survive in `pubspec.yaml` / window titles are expected to be flagged and unified with the corrected positioning. Confidence: 0.5
- Wants the README's provenance to be broken down module-by-module as a table — one row per functional module mapping it to its upstream source (PiliPlus / BiliPai / flutter_miuix / bilibili-API-collect / BilibiliSponsorBlock / third-party libs) plus what was ported, so a reader can see exactly which upstream each capability came from, rather than a prose-level summary of the derivation. Confidence: 0.5
- Wants public docs to openly disclose that the project is developed by *vibe coding* (AI-assisted programming), stated in two places: the opening project overview and the disclaimer (with the disclaimer noting the code is AI-collaborated, run-verified and human-reviewed but may still carry unknown defects, so users assess risk themselves) — transparency about the AI-assisted development method is expected, not hidden. Confidence: 0.5
- Expects an explicitly stated requirement to be honored on the first implementation without being restated, and calls it out bluntly when a previously stated constraint is violated ("我不是说了…吗？为什么还是…？") — being told the rule once should be enough, and the burden is on the agent to apply it across every affected surface rather than only where it was first wired in. Confidence: 0.5
- Wants the docs to carry the project's forward-looking direction and the rationale behind deliberate deviations from upstream, not just the present state: he explicitly asked that the README note that Material 3 is planned to be removed with Miuix (and possibly Liquid Glass) becoming the maintained style, and that the player-core replacement (media_kit → fvp/libmdk) be documented together with *why* it was made — so a reader understands where the project is heading and on what grounds. Once a stated direction is actually realized he has the wording flipped to the present tense — when Material 3 was fully removed he had the "Material 3 与 Miuix 双风格运行时热切换 / 演进中 / 逐步移除" framing replaced by a plain "Miuix is the sole maintained style; MD3 fully removed" — and asks for the README layout to be tidied in the same pass (contiguous section numbering, unified section dividers between major sections). Confidence: 0.5
