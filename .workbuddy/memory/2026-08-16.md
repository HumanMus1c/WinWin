## 播放中点返回崩溃：二次排查（真根因 + 修复）

### 现象
0772189 的「dispose 前 state=stopped」修复无效：18:29:03 仍崩溃，且与旧版本崩在同一位置。

### 证据链（决定性）
1. **Windows 事件日志**（5 次崩溃，含修复版）：`flutter_windows.dll` 固定偏移 `0x2C55F7`，`0xC0000005`。
2. **崩溃转储 `winwin.exe.3688.dmp`**（18:29 那次）手动解析：
   - 崩溃线程 = 光栅线程（栈上 d3d11.dll + 引擎合成帧）
   - **RCX=0**（this 为空）+ 读取地址 0 → 空对象上的虚调用
   - RIP 落在 **.pdata 段**（不可执行异常目录）→ 通过已释放对象的悬空函数指针跳入数据区
3. **fvp 0.37.3 源码** `windows/fvp_plugin.cpp` ReleaseRT：`UnregisterTexture(texId)` 后**立即** `players_.erase()` 销毁 TexturePlayer（D3D11 纹理/表面描述符/回调表），不等光栅线程排空。
4. 弹幕 60fps 滚动 → 光栅线程几乎每帧都在合成视频纹理 → 返回时必然竞态 → 5/5 必崩。

### 根因
页面 dispose → fvp `Player.dispose()` → ReleaseRT → UnregisterTexture + 立即销毁纹理对象；引擎光栅线程仍在用该纹理合成（正在渲染的帧持有悬空指针）。**state=stopped 无效**因为它只停 mdk 解码回调，与引擎光栅合成无关（waitFor(stopped) 同理，故 457199d 无效）。

### 修复（player_controller.dart dispose 归零分支）
- 置 stopped（保留）+ **延迟 400ms** 再 `player.dispose()`：页面 dispose 发生在 pop 转场结束后，纹理已离开 layer tree，400ms（>20帧@60fps）足以让光栅管线排空残留帧，竞态窗口关闭。
- Debug 已重编（kernel_blob.bin 19:32），待人工验证：播放中点返回 ×N 次无崩溃。

### 排查技巧
- WER 转储：`%LOCALAPPDATA%\CrashDumps\*.dmp`；事件日志 `Get-WinEvent Id=1000` 可拿到故障模块+offset。
- minidump 手动解析：异常流(rva=目录表 type 6)取 ThreadId+CONTEXT(RIP@0xF8/RSP@0x98)；MemoryListStream(type 5) 逐 region 扫栈；模块列表配 on-disk DLL 反汇编定位段属性。

## 播放中点返回崩溃：三段式排查最终结论（修正两次误判）

### 最终根因（已实测验证）
**Flutter 3.47.0 在 Windows 默认启用 Impeller(OpenGLESSDF) 渲染后端，fvp 外部视频纹理（DXGI shared handle GPU surface）在路由转场场景变化时光栅线程空指针崩溃。**

证据链：
1. 崩溃时间线：事件日志 `0x2C55F7` 崩溃首次出现于 8/14 14:00（升级 3.47.0 后），之前从未发生。
2. 崩溃签名（两个转储一致）：flutter_windows.dll+0x2C55F7，`mov rax,[rcx]` 且 rcx=0（null this 虚调用），引擎线程递归场景树处理。
3. 同步 trace（trace.log）：崩溃发生在点击返回瞬间、`Navigator.pop` 之前，dispose 从未执行——排除播放器释放路径。
4. 对照实验：拦截 WM_GETOBJECT 禁用无障碍桥（stderr 无 AXTree 错误验证生效）→ 仍崩溃同一偏移 → 排除无障碍桥。
5. **决定性实验：`set_impeller_switch(ImpellerSwitch::Disabled)` 回退 Skia → 返回全程无崩溃，trace 完整走完 dispose + 延迟释放，进程存活。**

### 误判复盘（重要经验）
- 误判1（fvp 纹理释放竞态）：0772189 与 400ms 延迟释放均无效——崩溃点在 dispose 之前，异步日志丢失尾部导致误读。**教训：瞬死场景必须用同步 flush 日志（SyncTrace）定位死亡现场。**
- 误判2（无障碍桥 #175041）：栈形似 + stderr AXTree 错误误导；对照实验排除。**教训：栈帧只有偏移无符号时，相似 ≠ 相同；每个假设必须用实验证伪。**

### 最终修复（保留项）
1. **`windows/runner/main.cpp`：`project.set_impeller_switch(ImpellerSwitch::Disabled)`**（核心修复，TODO 标注升级后移除）
2. `player_controller.dart` 延迟 400ms 释放共享 player（防御性，fvp ReleaseRT 理论竞态仍存在）
3. `lib/core/log/sync_trace.dart` 同步追踪工具 + 关键路径埋点（保留，以后排查瞬死用）
4. WM_GETOBJECT 拦截：已验证无效且破坏无障碍，**已移除**。AXTree 错误洪流同样**决定不拦截**：该错误仅打在引擎 C++ 侧 stderr，不进应用日志（trace.log/runtime.log 均为 Dart 侧写入），Release GUI 程序无控制台天然不可见；唯一能压住它的 WM_GETOBJECT 拦截会禁用整个无障碍功能，native 层加 stderr 过滤钩子又给刚稳定的崩溃修复引入新风险。开发时被控制台刷屏用 `grep -v` 过滤即可。
5. 产物：Debug 20:29 / Release 20:30 均含修复
