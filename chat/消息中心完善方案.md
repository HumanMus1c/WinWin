## 一、现状盘点

### WinWin 当前实现

| 层 | 文件 | 状态 |
|---|---|---|
| HTTP 数据层 | `lib/http/msg.dart` | **已较完整**（移植自 PiliPlus），覆盖 reply/at/like feed、like_detail、sys_notify、unread、ack、setTop、dnd、push_ss、im_user_infos、report 等 |
| API 常量 | `lib/http/api.dart` | sessionList / sessionMsg / sendMsg 三个端点**已定义但未在 msg.dart 接线** |
| UI 页面 | `lib/pages/whisper/view.dart` | **仅入口枢纽**：4 圆形入口（回复/艾特/点赞/系统）+ 私信/系统汇总 + 未读角标；点击任意入口只弹「待后续集成」Snack |
| 控制器 | — | 无消息专用控制器（项目有可复用的 `CommonListController<R,T>` 分页骨架） |

**关键设计取舍**：WinWin 的 `msg.dart` 注释明确写道「返回原始 JSON，不引入 PiliPlus 的 MsgReplyData/MsgAtData 等模型」。完善方案须延续此约定——用轻量 Map 适配器 + 预览解析器，而非整套类型化模型，避免引入大量样板代码。

## 三、分阶段实施计划

### 阶段 A · 补全 HTTP 数据层（地基，无 UI 改动）✅

> **已完成（2026-08-10）**：`lib/http/msg.dart` 新增 `sessionList` / `sessionMsg` / `sendMsg` / `sendTextMsg` / `withdrawMsg` 五个方法 + `_sendMsgErrorMsg` 错误码映射 + `_getDevId` UUID v4 缓存。新增 `import 'package:uuid/uuid.dart'`。Debug 26.9s / Release 104.8s，0 errors。snapshot 检查点 `02f59bb`（起始）。

**目标**：把 `api.dart` 已定义但未接线的三个端点接入 `msg.dart`，并补齐发送消息的错误码映射。

**改动文件**：`lib/http/msg.dart`

新增方法：

1. `sessionList({int sessionType = 4, int? endTs, int size = 20})`
   - 端点 `Api.sessionList`（get_sessions）
   - 参数：`session_type`（4=全部/9=关注/2=未关注/8=陌生人/3=粉丝团/5=拦截/7=系统）、`end_ts`（分页游标）、`size`
   - 返回 `LoadingState<Map<String,dynamic>>`（含 `session_list`、`has_more`、`last_ts`）

2. `sessionMsg({required int talkerId, int sessionType = 1, int? beginSeqno, int? endSeqno, int size = 20})`
   - 端点 `Api.sessionMsg`（fetch_session_msgs）
   - 返回消息列表（含 `msg_type`、`content`、`timestamp`、`sender_uid`）

3. `sendMsg({required int receiverId, int receiverType = 1, int msgType = 1, required String content})`
   - 端点 `Api.sendMsg`（web_im/send_msg）
   - 需 `sender_uid`、`dev_id`（UUID v4 缓存）、`timestamp`、`csrf`
   - **错误码映射**（移植自 BiliPai `MessageRepository`）：
     - `-101` 请先登录 / `-400` 参数错误
     - `21007` 消息过长 / `21015` 需绑定手机号
     - `21020` 发送过快 / `21026` 不能给自己发
     - `21046` 发送过于频繁，24h 后再试
     - `21047` 对方未关注你，最多发 1 条
     - `25003` 对方隐私设置限制 / `25005` 已拉黑对方

**验收**：三个方法可独立调用返回数据；不改动任何 UI；编译 Debug + Release 通过、0 errors。

### 阶段 D · 聊天详情 + 发送消息 + 会话设置

**目标**：闭环私信——能看历史、能发消息、能配置会话。

**新增文件**（`lib/pages/whisper/session/`）：

| 文件 | 职责 |
|---|---|
| `chat_detail_controller.dart` | 调 `MsgHttp.sessionMsg` 拉历史（`begin_seqno`/`end_seqno` 双向分页）；`sendMsg` 发送；进入即调 `ackSessionMsg` 标记已读 |
| `chat_detail_page.dart` | 气泡式聊天 UI（自己右侧/对方左侧），支持文本/图片/撤回/表情/卡片消息渲染（msg_type 分支）；底部输入框 + 发送按钮；发送失败按错误码映射提示 |
| `session_settings_page.dart` | 会话设置：免打扰开关、推送开关、清空消息、举报、拉黑（调 `imMsgReport` / `setMsgDnd` / `setPushSs`） |

**发送消息流程**（移植 BiliPai `MessageRepository.sendMessage`）：
1. 校验 csrf + senderUid
2. 生成/复用 dev_id（UUID v4）
3. POST `sendMsg`，timestamp = 秒级
4. 失败按错误码映射抛 `Exception(中文提示)`
5. 成功后乐观追加到消息列表 + 触发 `ackSessionMsg`

**验收**：进入会话自动拉历史并标记已读；可发文本消息；撤回/图片/卡片消息有占位渲染；发送频率超限等错误有中文提示；会话设置可切换免打扰/推送。

## 四、技术约定（沿用 WinWin 既有规范）

1. **不引入类型化模型**：延续 `msg.dart` 的 raw Map 风格，仅做必要的轻量适配，避免 PiliPlus `models_new/msg/*` 那套上百个文件的模型负担。
2. **状态管理**：统一 GetX，控制器继承 `CommonListController<R,T>`；cursor 分页场景覆写 `queryData`。
3. **消息流分页**：reply/at/like 用 `cursor`+`cursorTime` 游标（非 page 翻页），到达 `has_more=false` 置 `isEnd`。
4. **UI 组件**：复用项目 `AppRefreshIndicator`、`Style` 间距、`iosBlue/iosOrange/iosPink/iosTeal` 配色，与 WhisperPage 现有风格一致。
5. **错误处理**：所有 HTTP 方法返回 `LoadingState`，UI 层 `switch(loadingState)` 处理 Loading/Success/Error 三态（参照 PiliPlus 模式）。
6. **编译要求**：每阶段结束同时编译 Debug + Release，0 errors 才算完成；编译前打 `[snapshot]` 检查点。

## 五、风险与取舍

| 风险 | 应对 |
|---|---|
| sendMsg 的 `dev_id` 校验严格，错则 2100x | 复用 BiliPai 已验证的 UUID v4 生成 + 缓存逻辑 |
| 会话列表 `session_type` 枚举多、字段杂 | 先只接「全部/关注/拦截/系统」4 类，其余后续补 |
| 桌面端无推送通道，免打扰/推送设置收益低 | 阶段 D 的会话设置可降级为「只读展示 + 删除/举报」 |
| gRPC IM 通道（PiliPlus 用的 `grpc/bilibili/im`）WinWin 未集成 | 本方案全程走 REST（session_svr/web_im），不依赖 gRPC，规避集成成本 |
| msg_type 卡片解析字段多 | MessagePreviewParser 先覆盖高频类型（1/2/5/6/11/14），其余 fallback「[消息]」 |

## 六、阶段优先级建议

- **阶段 A** 是其余所有阶段的地基，必须最先做，且可独立交付（纯数据层，0 UI 风险）。
- **阶段 B** 性价比最高——让已存在的 4 个入口立刻可用，复用分页骨架，工作量最小。
- **阶段 C** 是体量最大、价值最高的一块（私信是消息中心核心），BiliPai InboxScreen 提供了可直接参照的完整 UI。
- **阶段 D** 依赖 A+C，作为收尾闭环。

建议按 **A → B → C → D** 顺序推进，每阶段独立编译验收、独立提交。
